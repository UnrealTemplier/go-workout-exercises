Упражнение #1

Классическая каскадная конструкция if / else if / else для анализа знака числа

📌 Условие задачи

Напиши программу, которая читает целое число из консоли и сообщает: положительное оно, отрицательное или ноль. Используй конструкцию if / else if / else.

💡 Теоретический фундамент и концепция

Условный оператор if в Go:

1. Круглые скобки вокруг условия (x > 0) запрещены (линтер и компилятор требуют if x > 0);
2. Фигурные скобки { ... } строго обязательны, даже если в блоке всего одна строка (в отличие от C/C++/Java);
3. Ключевое слово else или else if обязано находиться на той же строке, что и закрывающая фигурная скобка } предыдущего блока: } else if { (из-за правила автоматической вставки точек с запятой компилятором).

🔍 Пошаговый ход решения и ход мысли инженера

1. Считываем число из консоли через fmt.Scan.
2. Проверяем условие n > 0, n < 0 и ветку else для нуля.
3. Выводим соответствующий вердикт.
📄 main.go 
package main

import "fmt"

func CheckNumberSign(n int) string {
	if n > 0 {
		return "Число положительное"
	} else if n < 0 {
		return "Число отрицательное"
	} else {
		return "Число равно нулю"
	}
}

func main() {
	var num int
	fmt.Print("Введите целое число: ")
	if _, err := fmt.Scan(&num); err != nil {
		fmt.Println("Ошибка ввода:", err)
		return
	}

	result := CheckNumberSign(num)
	fmt.Printf("Результат для %d: %s\n", num, result)
}
ℹ️ Каскадный if / else if / else
📄 Терминал

# Введите целое число: -42
# Результат для -42: Число отрицательное
ℹ️ Пример работы
⚙️ Под капотом Go (Compiler, Linker & Runtime)

Компилятор Go преобразует цепочку if-else в узлы SSA-графа с инструкциями условного перехода JGT (Jump if Greater) и JLT (Jump if Less) с оптимизацией предсказания ветвлений (Branch Prediction).

⚠️ Частые грабли и ошибки новичков
  • Перенос else на новую строку:

`go

if x > 0 {

// ...

}

else { // ОШИБКА КОМПИЛЯЦИИ: syntax error: unexpected else

}

`

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему в Go фигурные скобки {} обязательны даже для однострочных if?»

Ответ: Это защищает от знаменитого критического бага Apple SSL goto fail (CVE-2014-1266), когда пропущенные скобки привели к ложному безусловному переходу и взлому проверки SSL-сертификатов.

Упражнение #2

Базовая проверка четности числа через оператор остатка %

📌 Условие задачи

Базовый if-else: Считай из консоли число. Напиши проверку: если оно четное, выведи "Четное", иначе "Нечетное" (используй оператор остатка от деления %).

💡 Теоретический фундамент и концепция

Оператор остатка от деления %:

  • n % 2 == 0 — число четное;
  • n % 2 != 0 — число нечетное;
  • Важно для отрицательных чисел: в Go знак остатка совпадает со знаком делимого (например -5 % 2 == -1), поэтому проверка на нечетность пишется как n % 2 != 0, а не n % 2 == 1.

🔍 Пошаговый ход решения и ход мысли инженера

1. Запрашиваем число у пользователя.
2. Проверяем условие num % 2 == 0.
3. Печатаем результат.
📄 main.go 
package main

import "fmt"

func main() {
	var num int
	fmt.Print("Введите целое число: ")
	if _, err := fmt.Scan(&num); err != nil {
		fmt.Println("Ошибка ввода:", err)
		return
	}

	if num%2 == 0 {
		fmt.Printf("Число %d — Четное\n", num)
	} else {
		fmt.Printf("Число %d — Нечетное\n", num)
	}
}

# Число 18 — Четное
ℹ️ Вывод
⚙️ Под капотом Go (Compiler, Linker & Runtime)

Для деления на степень двойки компилятор Go оптимизирует инструкцию деления IDIV в быструю битовую операцию TEST 1, reg (проверка младшего бита).

⚠️ Частые грабли и ошибки новичков
  • Написание if num % 2 == 1 для проверки нечетности: для числа -3 остаток равен -1, и условие ложно вернет "Четное". Всегда проверяйте num % 2 != 0.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как проверить четность целого числа без операции деления %?»

Ответ: Побитовой операцией (n & 1) == 0. Если младший бит равен нулю — число четное.

Идиоматичная валидация ввода и классификация четности

📌 Условие задачи

Базовый if-else: Напишите программу, которая запрашивает у пользователя целое число и выводит в консоль, является ли оно четным или нечетным.

💡 Теоретический фундамент и концепция

Закрепление паттерна if-else с чистой изоляцией бизнес-логики в отдельную функцию IsEven(n int) bool.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем функцию-предикат IsEven(n int) bool.
2. Вызываем её в конструкции if IsEven(num).
📄 main.go 
package main

import "fmt"

func IsEven(n int) bool {
	return n%2 == 0
}

func main() {
	testNumbers := []int{-4, -3, 0, 7, 12}

	for _, n := range testNumbers {
		if IsEven(n) {
			fmt.Printf("%3d: Четное\n", n)
		} else {
			fmt.Printf("%3d: Нечетное\n", n)
		}
	}
}

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как компилятор Go решает, инлайнить ли функцию?»

Ответ: Компилятор использует систему подсчета веса AST-узлов (AST budget). Если сложность тела функции меньше порогового значения (обычно около 80 операций), функция инлайнится. Наличие defer, go или неинлайнируемых вызовов блокирует инлайнинг.

Упражнение #4

Простое форматирование Even / Odd с английской локализацией

📌 Условие задачи

Простое условие: запросите у пользователя целое число и выведите Even / Odd через if-else.

💡 Теоретический фундамент и концепция

Стандартный вывод на английском языке Even (четное) / Odd (нечетное).

🔍 Пошаговый ход решения и ход мысли инженера

1. Считываем число.
2. Проверяем условие num % 2 == 0.
3. Печатаем "Even" или "Odd".
📄 main.go 
package main

import "fmt"

func main() {
	var val int
	fmt.Print("Enter integer: ")
	if _, err := fmt.Scan(&val); err != nil {
		fmt.Println("Invalid input")
		return
	}

	if val%2 == 0 {
		fmt.Println("Even")
	} else {
		fmt.Println("Odd")
	}
}

Вопрос с собеседования: «Почему в Go не приветствуется конструкция else, если в ветке if есть return?»

Ответ: Это правило уменьшения вложенности (Indent Error Flow). Если блок if завершается через return, последующий код пишут на верхнем уровне функции без блока else.

Упражнение #5

Конструкция if с инициализацией (if with short statement) и область видимости

📌 Условие задачи

Напиши программу с if с инициализацией: if x := rand.Intn(100); x > 50 { ... }. Покажи, что переменная x недоступна за пределами блока if. Попробуй обратиться к ней ниже — получи ошибку компиляции.

💡 Теоретический фундамент и концепция

if с короткой инициализацией:

Синтаксис: if init_stmt; condition { ... }

1. Переменная инициализируется непосредственно перед вычислением условия;
2. Область видимости (Scope) переменной ограничена только блоками if, else if и else;
3. За пределами конструкции переменная не существует, предотвращая загрязнение пространства имен функции.

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем псевдослучайное число x := rand.Intn(100) прямо в if.
2. Проверяем x > 50.
3. Показываем, что в блоке else переменная x также доступна.
4. Демонстрируем ошибку компиляции при попытке чтения x после блока.
📄 main.go 
package main

import (
	"fmt"
	"math/rand"
	"time"
)

func main() {
	r := rand.New(rand.NewSource(time.Now().UnixNano()))

💡 Теоретический фундамент и концепция

Идиома обработки ошибок в Go:

1. Ошибки в Go — это обычные значения интерфейса error;
2. Функция возвращает (T, error);
3. Вызывающий код проверяет err != nil;
4. В Go нет исключений (try / catch / throw), что делает поток управления явным, детерминированным и легко читаемым.

📄 main.go 
package main

import (
	"errors"
	"fmt"
)

var ErrDivisionByZero = errors.New("деление на ноль невозможно")

func Divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, ErrDivisionByZero
	}
	return a / b, nil
}

func main() {
	// 1. Успешный вызов
	if result, err := Divide(100, 4); err != nil {
		fmt.Println("Ошибка:", err)
	} else {
		fmt.Printf("100 / 4 = %.2f\n", result)
	}

	// 2. Ошибочный вызов
	if result, err := Divide(10, 0); err != nil {
		fmt.Println("Ошибка:", err)
	} else {
		fmt.Printf("Результат: %.2f\n", result)
	}
}

📌 Условие задачи

💡 Теоретический фундамент и концепция

Механика Shadowing в if:

  • Внешняя переменная x = 10 находится в Function Scope;

  • Внутри блока if доступен только внутренний x (значение 5);

	}

	fmt.Println("3. Внешний x после if:    ", x)
}

💡 Теоретический фундамент и концепция

Ключевое слово fallthrough:

1. Принудительно передает управление на первую строку следующего case, игнорируя проверку его условия;
2. Должно быть последней инструкцией в блоке case;
3. Запрещено в финальном case или default (некуда проваливаться);
4. Запрещено внутри type switch.

🔍 Пошаговый ход решения и ход мысли инженера

	case 3, 4, 5:
		return "Весна 🌸"
	case 6, 7, 8:
		return "Лето ☀️"

		return "Осень 🍁"

	}

}

}

Упражнение #27

Переключатель типов Type Switch над интерфейсом any (interface{})

📌 Условие задачи

Напиши программу с type switch: функция принимает interface{} (или any) и определяет тип значения (int, string, bool, float64). Для каждого типа выводит сообщение с форматированным значением. Добавь default.

💡 Теоретический фундамент и концепция

Type Switch (switch v := x.(type)):

1. Специальная форма switch, работающая только с интерфейсными типами (any / interface{});
2. Конструкция .(type) разрешена только внутри заголовка switch;
3. Внутри каждого блока case T: переменная v автоматически получает точный статический тип T!

🔍 Пошаговый ход решения и ход мысли инженера

2. Используем switch v := val.(type).
3. Обрабатываем int, string, bool, float64 и default.
📄 main.go 
package main

import "fmt"

func InspectType(val any) {
	switch v := val.(type) {
	case int:
		fmt.Printf("Целое число (int): %d | Удвоенное: %d\n", v, v*2)
	case string:
		fmt.Printf("Строка (string):    %q | Длина: %d\n", v, len(v))
	case bool:
		fmt.Printf("Флаг (bool):        %t | Инверсия: %t\n", v, !v)
	case float64:
		fmt.Printf("Дробное (float64):  %.2f | Квадрат: %.2f\n", v, v*v)
	default:
		fmt.Printf("Неизвестный тип:    %T (значение: %v)\n", v, v)
	}
}

func main() {
	InspectType(42)
	InspectType("Golang")
	InspectType(true)
	InspectType(3.14)
	InspectType([]int{1, 2, 3})
}

Упражнение #31

Локальное связывание типов в Type Switch (case int: v * 2)

📌 Условие задачи

Напиши программу с type switch, где в каждом case извлекается значение с тем же именем переменной: case int: fmt.Println(v * 2). Покажи, что переменная v в каждом case имеет тип конкретного case'а.

💡 Теоретический фундамент и концепция

Type Narrowing (Сужение типа):

В конструкции switch v := item.(type):

  • Внутри case int: переменная v имеет тип int (к ней применимы операции v * 2, v + 1);
  • Внутри case string: переменная v имеет тип string (применимы strings.ToUpper(v), len(v));
  • Внутри case []byte: переменная v имеет тип []byte.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем функцию ProcessItem(item any).
2. В каждом case выполняем операции, специфичные для конкретного типа.
3. Проверяем компиляцию без ручного приведения типов.
📄 main.go 
package main

import (
	"fmt"
	"strings"
)

func ProcessItem(item any) {
	switch v := item.(type) {
	case int:
		// v здесь строго int:
		fmt.Printf("Число: %d -> Удвоенное: %d\n", v, v*2)
	case string:
		// v здесь строго string:
		fmt.Printf("Строка: %q -> В верхнем регистре: %s\n", v, strings.ToUpper(v))
	case []int:
		// v здесь строго []int:
		fmt.Printf("Срез: %v -> Длина среза: %d\n", v, len(v))
	default:
		fmt.Printf("Другой тип %T: %v\n", v, v)
	}
}

func main() {
	ProcessItem(50)
	ProcessItem("gopher")
	ProcessItem([]int{10, 20, 30})
}

💡 Теоретический фундамент и концепция

Финальное закрепление:

  • Обычный case изолирован и завершается сам;

	case 2:
		fmt.Println("Ветка 2 выполнена (хотя val != 2!)")
	}
}

	fmt.Println()
	FallthroughSwitch(1)
}

Имитация тернарного оператора через функцию Max и философия отсутствия ?:

📌 Условие задачи

Напиши программу, которая имитирует тернарный оператор через if / else. В Go нет ?: — объясни, почему (философия языка: явность лучше краткости). Напиши функцию Max(a, b int) int без тернарного оператора.

💡 Теоретический фундамент и концепция

Почему в Go принципиально нет тернарного оператора cond ? val1 : val2?

1. Философия языка: «Явность лучше неявности, а простота важнее краткости»;
2. Вложенные тернарные операторы (a ? b : c ? d : e) в других языках часто превращаются в нечитаемый спагетти-код;
3. Для нахождения максимума пишется простая, легко оптимизируемая функция Max(a, b int) int (начиная с Go 1.21 встроена max(a, b)).

// Каноническая функция Max в Go
func Max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func Min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func main() {
	x, y := 42, 99

	fmt.Printf("Числа: x = %d, y = %d\n", x, y)
	fmt.Printf("Максимум: %d\n", Max(x, y))
	fmt.Printf("Минимум:  %d\n", Min(x, y))
}

📌 Условие задачи

💡 Теоретический фундамент и концепция

3. fallthrough переносит исполнение на case 3 (без проверки val == 3);

Рефакторинг глубокой вложенности (Pyramid of Doom) через паттерн Guard Clauses

📌 Условие задачи

Напиши программу с вложенными if (3 уровня вложенности): проверка доступа к системе (активен ли пользователь, есть ли права админа, не истёк ли срок действия). Затем перепиши через guard clauses (ранние return) — сравни читаемость.

💡 Теоретический фундамент и концепция

Паттерн Guard Clauses (Защитные условия / Ранний возврат):

  • Инвертирует условия ошибок и возвращает управление немедленно (if !isActive { return err });
  • Устраняет антипаттерн «Пирамида вложенности / Arrow Anti-pattern»;
  • Основной позитивный сценарий («Happy Path») выполняется на нулевом уровне отступа слева;
  • Является главным стандартом чистоты кода в Go.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем структуру UserSession.
2. Пишем валидацию с глубокой вложенностью if.
3. Переписываем ту же валидацию через Guard Clauses.
4. Сравниваем читаемость.
📄 main.go 
package main

import (
	"errors"
	"fmt"
	"time"
)

type UserSession struct {
	IsActive  bool
	IsAdmin   bool
	ExpiresAt time.Time
}

// ❌ Плохой стиль: Глубокая вложенность (Pyramid of Doom)
func ValidateAccessNested(s UserSession) (bool, error) {
	if s.IsActive {
		if s.IsAdmin {
			if time.Now().Before(s.ExpiresAt) {
				return true, nil
			} else {
				return false, errors.New("срок сессии истек")
			}
		} else {
			return false, errors.New("требуются права администратора")
		}
	} else {
		return false, errors.New("пользователь деактивирован")
	}
}

// ✅ Идеальный идиоматичный Go: Guard Clauses (Плоский код)
func ValidateAccessGuard(s UserSession) (bool, error) {
	if !s.IsActive {
		return false, errors.New("пользователь деактивирован")
	}
	if !s.IsAdmin {
		return false, errors.New("требуются права администратора")
	}
	if time.Now().After(s.ExpiresAt) {
		return false, errors.New("срок сессии истек")
	}

	// Happy Path на верхнем уровне:
	return true, nil
}

func main() {
	validSession := UserSession{
		IsActive:  true,
		IsAdmin:   true,
		ExpiresAt: time.Now().Add(1 * time.Hour),
	}

	ok, err := ValidateAccessGuard(validSession)
	fmt.Printf("Доступ разрешен: %t, ошибка: %v\n", ok, err)
}

Досрочное прерывание выполнения ветки case с помощью оператора break

📌 Условие задачи

Принудительный выход из switch: Напишите switch, проверяющий тип операции (например, строка "sum"). Внутри одной из веток case добавьте условие: если дополнительный параметр равен нулю, прервать выполнение этой ветки досрочно с помощью break, не выполняя оставшуюся часть кода в этом case.

💡 Теоретический фундамент и концепция

Оператор break внутри case:

  • Немедленно прерывает выполнение текущей ветки case;
  • Передает управление за пределы блока switch;
  • Позволяет защититься от выполнения тяжелой постобработки при особых граничных условиях.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем функцию ProcessOperation(op string, val int).
2. Внутри case "sum": проверяем if val == 0 { break }.
3. Убеждаемся, что код после break пропускается.
📄 main.go 
package main

import "fmt"

func ProcessOperation(op string, val int) {
	fmt.Printf("Операция '%s' с val = %d: ", op, val)

	switch op {
	case "sum":
		if val == 0 {
			fmt.Println("параметр 0 -> досрочный выход через break")
			break // Немедленно выходим из всего switch!
		}
		// Тяжелая операция выполняется только если val != 0:
		fmt.Printf("успешно вычислено sum = %d\n", val*10)
	case "multiply":
		fmt.Printf("вычислено multiply = %d\n", val*val)
	}
}

func main() {
	ProcessOperation("sum", 0)
	ProcessOperation("sum", 5)
	ProcessOperation("multiply", 4)
}

Упражнение #39

Золотой стандарт Go: инверсия условий и плоский стиль Guard Clauses

📌 Условие задачи

Паттерн "Guard Clauses" (Ранний возврат): Напиши функцию с глубокой вложенностью (if a { if b { if c { return true } } }). Перепиши её в "плоском" стиле, инвертируя условия и используя return для раннего выхода (if !a { return false }). Это золотой стандарт чистого кода в Go.

💡 Теоретический фундамент и концепция

Инверсия условий:

  • Было: if condition { do_logic() }
  • Стало: if !condition { return } do_logic()
  • Делает код линейным и понятным с первого взгляда.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем функцию валидации транзакции.
2. Проверяем баланс, лимиты и статус карты.
3. Оформляем в виде последовательных Guard Clauses.
📄 main.go 
package main

import (
	"errors"
	"fmt"
)

type Account struct {
	Balance   int
	IsBlocked bool
	DailyUsed int
	DailyMax  int
}

func ProcessPayment(acc Account, amount int) error {
	// Guard 1: Проверка блокировки
	if acc.IsBlocked {
		return errors.New("карта заблокирована банком")
	}

	// Guard 2: Проверка суммы
	if amount <= 0 {
		return errors.New("некорректная сумма списания")
	}

	// Guard 3: Проверка баланса
	if acc.Balance < amount {
		return errors.New("недостаточно средств на счете")
	}

	// Guard 4: Проверка суточного лимита
	if acc.DailyUsed+amount > acc.DailyMax {
		return errors.New("превышен суточный лимит операций")
	}

	// Успешное выполнение:
	fmt.Printf("✔ Успешное списание %d руб. Новый баланс: %d руб.\n",
		amount, acc.Balance-amount)
	return nil
}

func main() {
	acc := Account{Balance: 15000, IsBlocked: false, DailyUsed: 2000, DailyMax: 10000}

	err := ProcessPayment(acc, 5000)
	if err != nil {
		fmt.Println("Ошибка платежа:", err)
	}
}

package main

import "fmt"

type OrderStatus int

const (
	StatusPending OrderStatus = iota
	StatusProcessing
	StatusShipped
	StatusDelivered
	StatusCancelled

func ProcessOrder(status OrderStatus) {
	switch status {
	case StatusPending:
		fmt.Println("⏳ Заказ ожидает подтверждения оплаты")

		fmt.Println("📦 Заказ комплектуется на складе")

		fmt.Println("✅ Заказ успешно вручен клиенту")
	case StatusCancelled:
		fmt.Println("❌ Заказ аннулирован")
	default:
		fmt.Printf("⚠️ Неизвестный статус заказа: %d\n", status)
	}
}

func main() {
	ProcessOrder(StatusPending)
	ProcessOrder(StatusShipped)
	ProcessOrder(StatusDelivered)
}

Упражнение #41

Сложное логическое условие и доказательство эффекта Short-Circuit Evaluation

📌 Условие задачи

Напиши программу с сложным логическим условием: проверка допуска на мероприятие. Условие: (возраст >= 18 || есть_сопровождение) && есть_билет && !в_чёрном_списке. Покажи short-circuit evaluation: создай функции-предикаты с fmt.Println внутри и убедись, что при false в левой части && правая часть не вычисляется.

💡 Теоретический фундамент и концепция

Короткое замыкание (Short-Circuit Evaluation):

  • Для A && B: если A == false, выражение B никогда не вычисляется (результат уже гарантированно false);
  • Для A || B: если A == true, выражение B никогда не вычисляется (результат уже гарантированно true);
  • Это предотвращает лишние тяжелые вызовы к базам данных и защищает от разыменования nil (ptr != nil && ptr.Value > 0).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем логирующие функции-предикаты hasTicket(), isBlacklisted(), checkAge().
2. Составляем сложное логическое условие.
3. Анализируем логи консоли, доказывающие пропуск вызовов.
📄 main.go 
package main

import "fmt"

func checkAge(age int) bool {
	fmt.Printf("   [Call] checkAge(%d)\n", age)
	return age >= 18
}

func hasGuardian(has bool) bool {
	fmt.Printf("   [Call] hasGuardian(%t)\n", has)
	return has
}

func hasTicket(has bool) bool {
	fmt.Printf("   [Call] hasTicket(%t)\n", has)
	return has
}

func isBlacklisted(blacklisted bool) bool {
	fmt.Printf("   [Call] isBlacklisted(%t)\n", blacklisted)
	return blacklisted
}

func main() {
	fmt.Println("--- ТЕСТ 1: Взрослый с билетом не в черном списке ---")
	// Возраст >= 18 -> true (hasGuardian не вызывается!)
	if (checkAge(20) || hasGuardian(false)) && hasTicket(true) && !isBlacklisted(false) {
		fmt.Println("✔ Допуск разрешен!")
	}

	fmt.Println("\n--- ТЕСТ 2: Ребенок без билета (short-circuit на билете) ---")
	// hasTicket вернет false -> isBlacklisted даже не будет вызван!
	if (checkAge(15) || hasGuardian(true)) && hasTicket(false) && !isBlacklisted(false) {
		fmt.Println("✔ Допуск разрешен!")
	} else {
		fmt.Println("❌ Допуск запрещен (isBlacklisted не вызывался)!")
	}
}

	}
}

📌 Условие задачи

Напиши программу с guard clause для валидации пароля: функция ValidatePassword(p string) error проверяет длину (≥8), наличие цифры, заглавной буквы и спецсимвола. Каждая проверка — отдельный if с return fmt.Errorf(...). В конце return nil.

💡 Теоретический фундамент и концепция

Эталонная валидация безопасности:

1. Длина $\ge 8$;
2. Наличие цифры unicode.IsDigit;
3. Наличие заглавной буквы unicode.IsUpper;
4. Наличие спецсимвола unicode.IsPunct / unicode.IsSymbol.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем вспомогательные сканеры символов.
2. Оформляем ValidatePassword(p string) error серией защитных условий.

📄 main.go 
package main

import (
	"errors"
	"fmt"
	"unicode"
	"unicode/utf8"
)

func ValidatePassword(p string) error {
	// Guard 1: Минимальная длина
	if utf8.RuneCountInString(p) < 8 {
		return errors.New("пароль должен содержать минимум 8 символов")
	}

	var hasDigit, hasUpper, hasSpecial bool
	for _, r := range p {
		switch {
		case unicode.IsDigit(r):
			hasDigit = true
		case unicode.IsUpper(r):
			hasUpper = true
		case unicode.IsPunct(r) || unicode.IsSymbol(r):
			hasSpecial = true
		}
	}

	// Guard 2: Цифра
	if !hasDigit {
		return errors.New("пароль должен содержать хотя бы одну цифру (0-9)")
	}

	// Guard 3: Заглавная буква
	if !hasUpper {
		return errors.New("пароль должен содержать хотя бы одну заглавную букву (A-Z, А-Я)")
	}

	// Guard 4: Спецсимвол
	if !hasSpecial {
		return errors.New("пароль должен содержать хотя бы один специальный символ (!@#$%^&*)")
	}

	return nil
}

func main() {
	passwords := []string{"short", "nocaps123!", "NOLOWER123!", "ValidPass2026!"}

	for _, pass := range passwords {
		err := ValidatePassword(pass)
		if err != nil {
			fmt.Printf("Пароль '%s': ❌ %v\n", pass, err)
		} else {
			fmt.Printf("Пароль '%s': ✔ Надежный пароль!\n", pass)
		}
	}
}

2. В цикле обновляем значения при val < minVal или val > maxVal.

📄 main.go 
package main

import (
	"errors"
	"fmt"
)

func FindMinMax(numbers []int) (int, int, error) {
	if len(numbers) == 0 {
		return 0, 0, errors.New("срез пуст")
	}

	minVal := numbers[0]
	maxVal := numbers[0]

	for _, v := range numbers[1:] {
		if v < minVal {
			minVal = v
		}
		if v > maxVal {
			maxVal = v
		}
	}

	return minVal, maxVal, nil
}

func main() {
	nums := []int{24, -5, 108, 0, -42, 87}

	minVal, maxVal, err := FindMinMax(nums)
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}

	fmt.Printf("Исходный срез: %v\n", nums)
	fmt.Printf("Минимум:       %d\n", minVal)
	fmt.Printf("Максимум:      %d\n", maxVal)
}

package main

import "fmt"

func DescribeDynamicValue(x any) {
	switch v := x.(type) {
	case int:

	}
}

func main() {
	var data any

	data = 100
	DescribeDynamicValue(data)

	data = "Теперь это строка"
	DescribeDynamicValue(data)
}

💡 Теоретический фундамент и концепция

Unix File Permissions в восьмеричной системе (Octal):

  • 0400 (Read by Owner);
  • 0200 (Write by Owner);
  • 0100 (Execute by Owner);
  • Проверка: if (perm & 0400) != 0 { ... }.

1. Задаем битовую маску прав os.FileMode(0755).

package main

import (
	"fmt"
	"io/fs"
)

const (
	OwnerRead    fs.FileMode = 0400
	OwnerWrite   fs.FileMode = 0200
	OwnerExecute fs.FileMode = 0100
)

func CheckPermissions(perm fs.FileMode) {
	fmt.Printf("Права файла: %04o (%s)\n", perm, perm)

	if (perm & OwnerRead) != 0 {
		fmt.Println("✔ Владелец имеет право на ЧТЕНИЕ (0400)")
	}
	if (perm & OwnerWrite) != 0 {
		fmt.Println("✔ Владелец имеет право на ЗАПИСЬ (0200)")
	}
	if (perm & OwnerExecute) != 0 {
		fmt.Println("✔ Владелец имеет право на ИСПОЛНЕНИЕ (0100)")
	}
}

func main() {
	CheckPermissions(0755) // rwxr-xr-x
}

Консольный калькулятор арифметических операций на switch

📌 Условие задачи

switch с bool-выражениями: реализуйте калькулятор: спросите два числа и операцию (+, -, *, /), затем через switch operation выполните вычисление.

💡 Теоретический фундамент и концепция

Калькулятор четырех арифметических действий с перехватом деления на ноль.

🔍 Пошаговый ход решения и ход мысли инженера

1. Принимаем a, op, b.
2. В switch op выполняем сложение, вычитание, умножение, деление.
3. Выводим результат с плавающей точкой.
📄 main.go 
package main

import (
	"errors"
	"fmt"
)

func CalculateCLI(a float64, op string, b float64) (float64, error) {
	switch op {
	case "+":
		return a + b, nil
	case "-":
		return a - b, nil
	case "*":
		return a * b, nil
	case "/":
		if b == 0 {
			return 0, errors.New("ошибка: деление на ноль")
		}
		return a / b, nil
	default:
		return 0, fmt.Errorf("неизвестная операция %q", op)
	}
}

func main() {
	res1, _ := CalculateCLI(10, "+", 5)
	res2, _ := CalculateCLI(20, "/", 4)
	_, err := CalculateCLI(15, "/", 0)

	fmt.Println("10 + 5 =", res1)
	fmt.Println("20 / 4 =", res2)
	fmt.Println("15 / 0 ->", err)
}

Упражнение #61

Таблица диспетчеризации (Dispatch Table) на map[string]func()

📌 Условие задачи

Таблица диспетчеризации (Dispatch Table): Замените огромный switch или цепочку if/else на мапу функций (map[string]func()), где ключ — это строка-команда, а значение — функция, которая должна выполниться.

💡 Теоретический фундамент и концепция

Паттерн Dispatch Table (Таблица диспетчеризации):

  • Заменяет огромные разрастающиеся switch на map[string]CommandHandler;
  • Реализует принцип Open/Closed (SOLID): новые команды регистрируются без модификации существующего кода;
  • Время поиска команды составляет $O(1)$ в хэш-таблице.

🔍 Пошаговый ход решения и ход мысли инженера

1. Определяем тип обработчика type CommandHandler func(args []string) error.
2. Создаем мапу dispatchTable = make(map[string]CommandHandler).
3. Регистрируем обработчики "ping", "stats", "exit".
4. Выполняем диспетчеризацию по строковому ключу.
📄 main.go 
package main

import (
	"fmt"
	"strings"
)

type CommandHandler func(args []string)

func main() {
	// Таблица диспетчеризации команд
	handlers := map[string]CommandHandler{
		"ping": func(args []string) {
			fmt.Println("PONG! Задержка: 1.2 мс")
		},
		"echo": func(args []string) {
			fmt.Printf("ECHO: %s\n", strings.Join(args, " "))
		},
		"version": func(args []string) {
			fmt.Println("Service Version: v2.4.0 (Go 1.22)")
		},
	}

	// Симуляция вызова команд:
	execute := func(cmd string, args []string) {
		if handler, ok := handlers[cmd]; ok {
			handler(args)
		} else {
			fmt.Printf("❌ Неизвестная команда: %s\n", cmd)
		}
	}

	execute("ping", nil)
	execute("echo", []string{"Hello", "BigTech", "Workout!"})
	execute("unknown", nil)
}
ℹ️ Dispatch Table на базе map[string]func()
📄 Терминал

# ECHO: Hello BigTech Workout!
# ❌ Неизвестная команда: unknown
ℹ️ Вывод
⚙️ Под капотом Go (Compiler, Linker & Runtime)

Значения мапы хранят 8-байтные указатели на функции. Вызов handler() компилируется в косвенный вызов CALL (reg).

⚠️ Частые грабли и ошибки новичков
  • Вызов handlers[cmd]() без проверки ok: если ключа нет, вызов nil() вызовет немедленную панику.

Упражнение #63

Конечный автомат (State Machine) игрового NPC на базе for и switch

📌 Условие задачи

Конечный автомат (State Machine): Реализуйте простую логику NPC в игре (состояния: "Патруль", "Тревога", "Атака"), используя for для тиков времени и switch для перехода между состояниями в зависимости от событий.

💡 Теоретический фундамент и концепция

Конечный автомат (Finite State Machine / FSM):

  • Состояния: StatePatrol, StateAlert, StateAttack;
  • Переходы зависят от событий (дистанция до игрока);
  • switch state определяет поведение NPC на каждом тике игрового цикла.

🔍 Пошаговый ход решения и ход мысли инженера

1. Задаем состояния FSM через iota.
2. В цикле тиков симулируем изменение дистанции до цели.
3. В switch state меняем состояние NPC.
📄 main.go 
package main

import "fmt"

type NPCState int

const (
	StatePatrol NPCState = iota
	StateAlert
	StateAttack
)

func (s NPCState) String() string {
	return [...]string{"Патрулирование", "Тревога", "Атака"}[s]
}

func main() {
	state := StatePatrol
	// Симуляция дистанции до игрока на каждом тике:
	distances := []int{50, 25, 8, 4, 30}

	for tick, dist := range distances {
		fmt.Printf("Тик %d (дистанция %2d м) | Текущее состояние: %-15s -> ",
			tick+1, dist, state)

		switch state {
		case StatePatrol:
			if dist < 30 {
				state = StateAlert
				fmt.Println("Замечен шум! Переход в состояние ТРЕВОГА")
			} else {
				fmt.Println("Спокойный обход периметра")
			}

		case StateAlert:
			if dist < 10 {
				state = StateAttack
				fmt.Println("Враг близко! Переход в состояние АТАКА ⚔️")
			} else if dist >= 30 {
				state = StatePatrol
				fmt.Println("Угроза исчезла. Возврат к ПАТРУЛИРОВАНИЮ")
			} else {
				fmt.Println("Осмотр сектора с оружием наготове")
			}

		case StateAttack:
			if dist >= 10 {
				state = StateAlert
				fmt.Println("Цель отступила. Переход в режим ТРЕВОГИ")
			} else {
				fmt.Println("Нанесение урона цели!")
			}
		}
	}
}

Упражнение #64

Интерактивное консольное меню с бесконечным циклом for и switch

📌 Условие задачи

Меню с бесконечным циклом и switch: программа постоянно показывает пункты меню, выполняет действие по вводу и выходит по "quit".

💡 Теоретический фундамент и концепция

Паттерн REPL / CLI Menu:

  • for { ... } — бесконечный цикл обработки пользовательских команд;
  • switch choice — маршрутизация действий;
  • Выход из цикла через return или именованный break Loop.

🔍 Пошаговый ход решения и ход мысли инженера

1. Запускаем бесконечный цикл for.
2. Считываем команду.
3. В case "quit": делаем return или break.
📄 main.go 
package main

import (
	"fmt"
	"strings"
)

func main() {
	// Симуляция потока ввода команд пользователя:
	commandStream := []string{"help", "status", "unknown", "quit"}
	cmdIdx := 0

	fmt.Println("=== ДОБРО ПОЖАЛОВАТЬ В CLI СИСТЕМУ ===")

MainMenuLoop:
	for {
		if cmdIdx >= len(commandStream) {
			break MainMenuLoop
		}
		rawCmd := commandStream[cmdIdx]
		cmdIdx++

		cmd := strings.ToLower(strings.TrimSpace(rawCmd))
		fmt.Printf("\n[Prompt] > %s\n", cmd)

		switch cmd {
		case "help":
			fmt.Println("Доступные команды: help, status, restart, quit")
		case "status":
			fmt.Println("Все сервисы работают в штатном режиме: OK")
		case "restart":
			fmt.Println("Перезапуск сервиса...")
		case "quit", "exit":
			fmt.Println("Завершение сеанса. До свидания!")
			break MainMenuLoop // Выход из бесконечного цикла for!
		default:
			fmt.Printf("Неизвестная команда '%s'. Введите 'help' для списка.\n", cmd)
		}
	}

	fmt.Println("Программа штатно завершена.")
}
