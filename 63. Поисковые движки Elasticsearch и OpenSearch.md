# Поисковые движки Elasticsearch и OpenSearch

В этом файле собраны уникальные упражнения по теме **"Поисковые движки Elasticsearch и OpenSearch"**, отсортированные по возрастанию сложности.

---

1. Подними Elasticsearch в Docker. Подключись клиентом. Создай индекс `articles`.

2. **[Index Document]**: Индексируй документ (статью) с ID=1. Обнови поле `views`, увеличив его на 1 (через скрипт `_update`).

3. **Mapping и CRUD.**: Создайте индекс с explicit mapping: `title` (text + keyword multi-field), `status` (keyword), `created_at` (date). Индексируйте документы через official Go client. Объясните, почему `dynamic: strict` предпочтительнее в production (mapping explosion).

4. **[Bulk API]**: Напиши код, который загружает 10 000 статей через Bulk API. Формируй тело запроса как NDJSON (Newline Delimited JSON).

5. **Bulk API и refresh.**: Индексируйте 100 000 документов через `_bulk`. Сравните `refresh=wait_for`, `refresh=false`, `refresh=true`. Объясните translog, segments и почему `refresh=false` даёт максимальный throughput, но данные видны только после следующего refresh (1 сек по умолчанию).

6. **Анализаторы и токенизация.**: Создайте custom analyzer: `standard` tokenizer + `lowercase` + `russian_morphology` (или `stemmer`). Покажите `_analyze` API: как «бегущие» превращается в токен «бег». Объясните разницу `match` (analyzed) vs `term` (not analyzed) запросов.

7. **[Full-text Search]**: Выполни поиск по полю `title` с использованием `match` query. Изучи, как Elasticsearch токенизирует текст (стандартный анализатор разбивает на слова в нижнем регистре).

8. **[Mapping]**: При создании индекса задай строгий маппинг: поле `title` типа `text` (с анализатором), поле `tags` типа `keyword` (для точного поиска и агрегаций), поле `views` типа `integer`.

9. **Bool-запросы и nested.**: Постройте сложный `bool` query: `must` (title содержит «go»), `filter` (status = published, date range), `must_not` (deleted = true). Добавьте `nested` query для массива объектов `comments` с `inner_hits`. Объясните, почему `nested` нужен для массивов объектов (independent indexing).

10. **[Bool Query]**: Напиши сложный запрос: найти статьи, где в `title` есть слово "Go", но `tags` не содержит "tutorial" (`must` + `must_not`).

11. **Агрегации.**: Постройте dashboard-запрос: `date_histogram` (по дням) + `terms` (по статусу) + `avg` (rating) + `derivative` (рост от дня к дню). Объясните разницу между bucket aggregations (группировка) и metric aggregations (вычисления).

12. **[Aggregations]**: Выполни поиск по всем статьям и запроси агрегацию `terms` по полю `tags`, чтобы получить топ-5 самых популярных тегов.

13. **Index Templates и ILM/ISM.**: Создайте index template с pattern `logs-*`. Настройте ILM (Index Lifecycle Management): rollover при 50 GB или 1 день → warm (сжатие) → cold (только чтение) → delete (30 дней). Объясните hot-warm-cold архитектуру для логов.

14. **[Каверзный кейс — Deep Pagination]**: Попробуй сделать пагинацию через `from` и `size` (например, `from: 10000, size: 10`). Поймай ошибку Elasticsearch `max_result_window`. Перепиши пагинацию на `search_after` (используя sort values последнего документа).

15. **Typed API vs Raw API**: В драйвере ESv8 есть два клиента. Изучи `esapi` (сырой, работает с JSON в виде `strings.Reader`) и `TypedClient` (строго типизированный, с билдерами запросов). Создай `TypedClient` и сделай пинг кластера.

16. **Подключение**: Используйте `github.com/elastic/go-elasticsearch/v8`. Настройте connection с TLS и authentication.

17. **Шардирование и маршрутизация.**: Создайте индекс с 3 primary shards и 1 replica. Покажите `_cat/shards`. Используйте custom routing (`_routing=user_id`) для co-location документов одного пользователя на одном шарде. Объясните, когда это ускоряет `term` query, а когда создаёт hot shard.

18. **Index mapping**: Создайте index с explicit mapping (не полагайтесь на dynamic mapping в production). Определите типы полей: `text`, `keyword`, `integer`, `date`, `geo_point`.

19. **[Reindex API]**: Создай новый индекс `articles_v2` с обновленным маппингом (например, добавь поле). Используй Reindex API для асинхронного переноса данных из старого индекса в новый. Настрой alias (алиас `articles_current` указывает на старый, затем переключи на новый).

20. **Text vs Keyword**: Поймите ключевую разницу: `text` анализируется (для full-text search), `keyword` — нет (для filtering, aggregations, sorting).

21. **Analyzers**: Используйте standard, simple, whitespace, keyword analyzers. Создайте custom analyzer с `tokenizer` + `filter` (например, lowercase + stopwords + stemming).

22. **Индексация документов с маппингом.**: Подключитесь к Elasticsearch через `olivere/elastic` или официальный клиент. Создайте индекс `products` с явным маппингом полей (текст с анализатором, keyword, float). Индексируйте 1000 товаров.

23. **CRUD operations**: Используйте `Index`, `Get`, `Update`, `Delete` API. Изучите `versioning` для optimistic concurrency control.

24. **Snapshot / Restore.**: Настройте S3 repository (`_snapshot/my_s3_repo`). Создайте snapshot, восстановите в другой индекс. Покажите инкрементальный snapshot (только новые segments). Объясните, почему snapshot — не backup в классическом смысле (pointer-based, не копия).

25. **Создание индекса и маппинга**: Подключите официальный клиент Elasticsearch для Go: `github.com/elastic/go-elasticsearch/v8`. Напишите код инициализации клиента. Создайте индекс `products` и явно передайте JSON-схему маппинга (mapping), настроив текстовые поля на использование анализатора русской морфологии (`"analyzer": "russian"`).

26. **Bulk API**: Используйте `BulkIndexer` для массовой индексации документов (ключ к производительности).

27. **[Высокая сложность — Custom Analyzer]**: Создай индекс с кастомным анализатором: добавь фильтр `ngram` (разбивает слова на подстроки длиной 2-4 символа). Проиндексируй слово "GoLang" и убедись, что поиск по строке "Lan" находит этот документ ( автодополнение / search-as-you-type).

28. **Search API**: Используйте `Search` с `BoolQuery`. Поймите `must`, `should`, `must_not`, `filter` clauses.

29. **Full-text search**: Используйте `match`, `multi_match`, `match_phrase`, `query_string`. Изучите `fuzziness`, `operator`, `minimum_should_match`.

30. **Индексация документа**: Создай Go-структуру `Product`. Преврати её в JSON и отправь в ES через API `Index`. Задай ID документа явно (например, взяв его из базы данных).

31. **Deep pagination и поисковая оптимизация.**: Реализуйте экспорт 1 млн документов тремя способами: `from/size` (покажите OOM на больших offset), `scroll` (context-heavy), `search_after` (stateless, preferred). Объясните `query_then_fetch` vs `dfs_query_then_fetch`.

32. **Term-level queries**: Используйте `term`, `terms`, `range`, `exists`, `prefix`, `wildcard`, `regexp`.

33. **Highlighting**: Используйте `highlight` для подсветки найденных слов в результатах.

34. **Полнотекстовый поиск с ранжированием.**: Выполните запрос `match` по полю `description`. Добавьте `fuzziness`, `minimum_should_match`, `boost` для разных полей. Объясните, как работает BM25.

35. **Aggregations**: Используйте `terms`, `histogram`, `date_histogram`, `avg`, `sum`, `min`, `max`, `percentiles`, `cardinality`.

36. **Nested aggregations**: Используйте вложенные aggregations для сложных аналитических запросов.

37. **Bulk Indexer (Пакетная загрузка)**: Использовать голый `Index` для 1000 товаров медленно. Используй пакет `esutil.BulkIndexer`. Добавь в него документы через метод `Add()`. Убедись, что индексатор сам собирает их в пачки и отправляет в фоне (попутно обрабатывая ошибки).

38. **Geo search**: Используйте `geo_point` и `geo_shape` для поиска в радиусе (`geo_distance`) и внутри полигонов (`geo_polygon`).

39. **Сложный полнотекстовый поиск (Bool Query)**: Реализуйте поисковую строку для каталога товаров. Напишите функцию, которая принимает поисковый запрос от пользователя и собирает сложный JSON-запрос для Elasticsearch:
    * Секция `must`: текстовый поиск по полям `title` и `description` с поддержкой нечеткого соответствия (`"fuzziness": "AUTO"`).
    * Секция `filter`: ограничение по диапазону цен (`range`) и категории товара (`term`).
    * Секция `highlight`: подсветка найденных слов в результатах выдачи.

40. **Parent-child relations**: Используйте `join` field type для parent-child связей (альтернатива nested).

41. **Reindexing**: Используйте `_reindex` API для изменения mapping существующего индекса (создание нового + копирование).

42. **Index Lifecycle Management (ILM)**: Настройте hot-warm-cold-delete tiers для time-series данных. Автоматический rollover при достижении размера/возраста.

43. **Full-Text Search (Match)**: Напиши запрос полнотекстового поиска (тип `match`) по слову `телефон`. Изучи объект ответа (структура `Hits`). Выведи `_score` (релевантность) для каждого найденного документа и сами данные из `_source`.

44. **Агрегации: terms, histogram, nested.**: Подсчитайте количество товаров по категориям (terms agg). Постройте гистограмму цен с интервалом 10. Используйте `nested` агрегацию для работы с вложенными документами (например, варианты товара).

45. **Bool Query (Must vs Filter)**: Тебе нужно найти "телефон" (поиск) в категории "электроника" (фильтр). Напиши составной `bool` запрос. В `must` положи `match`, а в `filter` положи `term` по категории. *Осознай архитектурное правило: блок `filter` кэшируется в ES и не влияет на `_score` (релевантность), что делает запрос сильно быстрее!*

46. **Пакетное индексирование через Bulk API**: Для импорта тысяч товаров в поисковую систему поштучные запросы не подходят. Напишите код пакетного импорта с помощью утилиты `esutil.NewBulkIndexer` [570]. Настройте автоматическую отправку пакетов (флаги `FlushBytes` и `FlushInterval`) [570], а также добавьте обработчики коллбэков успешного индексирования и ошибок (`OnSuccess`, `OnFailure`) для каждого отдельного документа [570].

47. **Обновление по запросу и скрипты.**: Увеличьте цену всех товаров определённой категории на 10% с помощью `update_by_query` и Painless скрипта. Проверьте атомарность.

48. **Fuzzy Search (Поиск с опечатками)**: Сделай запрос с опечаткой (например, "тлефон"). Используй параметр `fuzziness: "AUTO"` в `match` запросе. Убедись, что ES находит нужный товар, исправляя опечатку благодаря расстоянию Левенштейна.

49. **Агрегации (Faceting)**: При поиске товаров в интернет-магазинах пользователю нужно выводить боковые фильтры с количеством товаров в каждой категории. Напишите поисковый запрос, содержащий секцию `aggs` (aggregations). Реализуйте группировку результатов по брендам (`terms` агрегация) и ценовым диапазонам (`histogram` агрегация). Распакуйте результаты агрегаций из JSON-ответа Elasticsearch в структуры Go.

50. **Шардирование, репликация и восстановление.**: Настройте индекс с 3 primary shards и 2 replicas. Симулируйте падение узла, проверьте доступность данных. Выполните `_cat/recovery`.

51. **Агрегации (Terms Aggregation)**: Сделай запрос (без поиска, или поиск `match_all`). Добавь в тело запроса агрегацию по полю `category`. В ответе (в поле `aggregations`) распарси список категорий и количество товаров в каждой (это основа для сайдбара с фильтрами в любом интернет-магазине).

52. **Scroll / Point in Time (Глубокая пагинация)**: По умолчанию ES не отдает больше 10 000 результатов (параметры `from` и `size` падают с ошибкой). Чтобы выгрузить весь индекс (миллионы записей), используй API `Scroll` или современный `Point In Time (PIT)` в цикле (передавая `search_after`).

53. **Снапшоты и резервное копирование.**: Зарегистрируйте snapshot repository (например, fs). Создайте snapshot индекса, удалите индекс, восстановите из snapshot.

54. **Паттерн Update By Query**: У тебя поменялась бизнес-логика. Тебе нужно добавить всем товарам из категории "X" новое поле `is_archived: true`. Напиши скрипт на языке Painless (встроенный в ES) и выполни его для миллионов документов через API `UpdateByQuery` прямо из Go.

---

55. **Performance tuning: refresh_interval, translog, кэши.**: Измерьте скорость индексации при `refresh_interval=-1`. Настройте `translog` durability. После массовой загрузки включите refresh. Оцените влияние на поисковые запросы.

56. **Mapping first, data later.**: Dynamic mapping в production — это техдолг. Всегда определяйте explicit mapping.

57. **Text vs Keyword.**: 90% ошибок новичков — использование `text` для filtering/aggregations. Используйте `keyword` для точных совпадений.

58. **Bulk API обязателен.**: Single-document indexing в 100x медленнее. Используйте `BulkIndexer` с оптимальным flush interval.

59. **ILM для time-series.**: Автоматический rollover, shrink, delete по возрасту. Без ILM вы утонете в management overhead.

60. **Filter context > Query context.**: В bool query используйте `filter` для того, что не влияет на score (кэшируется, быстрее).
