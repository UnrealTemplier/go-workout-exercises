# Time-Series СУБД, сжатие Gorilla и IoT-телеметрия на Go

В этом файле собраны уникальные упражнения по теме **"Time-Series СУБД, сжатие Gorilla и IoT-телеметрия на Go"**, отсортированные по возрастанию сложности.

---

1. **Специфика данных временных рядов (Time-Series Data)**: Изучите фундаментальные особенности временных рядов: постоянный поток поступающих данных (Append-Only), строгая сортировка по временным меткам, высокая частота (тысячи точек в секунду от одного источника), отсутствие обновлений прошлых данных и запросы по временным диапазонам. Сравните с классическими реляционными нагрузками (OLTP).

2. **Модель данных временного ряда**: Спроектируйте базовую модель временного ряда на Go: структура Sample со свойствами Timestamp time.Time, Value float64 и срез меток Labels map[string]string (Metric Name + Tags). Объясните, почему для хранения временных рядов миллисекундная/наносекундная точность таймстемпов критична.

3. **Почему реляционные B-Tree индексы деградируют на временных рядах**: Продемонстрируйте проблему вставки миллиардов временных точек в стандартную таблицу PostgreSQL с B-Tree индексом по времени: постоянный рост размера индекса, превышение объема RAM, частые сбросы страниц на диск и деградация скорости вставки на порядки.

4. **Алгоритм сжатия Facebook Gorilla: основы**: Изучите классическую статью инженеров Facebook «Gorilla: A Fast, Scalable, In-Memory Time Series Database». Разберите ключевую идею: раздельное побитовое сжатие временных меток (Timestamps) и вещественных значений (Float64 Values), снижающее расход памяти в 10–12 раз.

5. **Сжатие временных меток: алгоритм Delta-of-Delta**: Большинство датчиков шлют данные с постоянным интервалом (например, каждые 10 секунд). Вычислите первую разность D_i = T_i - T_{i-1} и вторую разность (Delta-of-Delta) D' = D_i - D_{i-1}. Покажите, что при идеальном интервале D' = 0, что можно закодировать ровно одним битом 0!

6. **Реализация BitWriter для побитовой записи на Go**: Стандартный io.Writer оперирует байтами. Напишите низкоуровневую структуру BitWriter: методы WriteBit(bit byte) и WriteBits(val uint64, numBits int). Обеспечьте эффективную побитовую упаковку в байтовый срез []byte без лишних аллокаций.

7. **Кодирование Delta-of-Delta временных меток**: Реализуйте полный алгоритм кодирования таймстемпов по спецификации Gorilla: если D'=0 -> пишем 0; если -63 <= D' <= 64 -> пишем 10 + 7 бит значения; если -255 <= D' <= 256 -> пишем 110 + 9 бит; если -2047 <= D' <= 2048 -> пишем 1110 + 12 бит; иначе -> пишем 1111 + 32 бита значения.

8. **Сжатие вещественных значений (Float64 Values) через XOR**: Значения телеметрии (температура, загрузка CPU) обычно плавно меняются во времени, поэтому их IEEE 754 представления имеют схожие старшие биты экспоненты и мантиссы. Вычислите XOR = V_i ^ V_{i-1} с использованием math.Float64bits. Покажите, что при одинаковых значениях результат равен 0.

9. **Реализация XOR-сжатия значений по спецификации Gorilla**: Напишите алгоритм сжатия float64: если XOR = 0 -> пишем бит 0; если XOR != 0 -> пишем бит 1. Если количество ведущих и замыкающих нулей совпадает с предыдущим блоком -> пишем бит 0 и только значащие биты; иначе пишем 1 + 5 бит числа ведущих нулей + 6 бит длины + значащие биты (с использованием bits.LeadingZeros64).

10. **Разработка BitReader для побитового чтения**: Напишите парную структуру BitReader: методы ReadBit() (byte, error) и ReadBits(numBits int) (uint64, error). Обеспечьте субнаносекундное чтение отдельных бит из упакованного байтового буфера.

11. **Декомпрессия временного ряда Gorilla на Go**: Реализуйте полный алгоритм декомпрессии потока: декодирование временных меток через Delta-of-Delta и восстановление точных значений float64 через обратное применение XOR. Напишите юнит-тест, проверяющий побитовую идентичность исходных и распакованных данных без потери точности.

12. **Бенчмарк степени сжатия Gorilla на реальной телеметрии**: Напишите бенчмарк: сгенерируйте 1 000 000 точек телеметрии серверов (CPU, память, диск). Сохраните в несжатом виде (16 байт на точку = 16 МБ). Сожмите алгоритмом Gorilla. Замерьте итоговый размер (ожидается 1.3–2.0 байта на точку = экономия памяти более 85%) и скорость кодирования (миллионы точек/сек на ядро CPU).

13. **Архитектура TSDB: MemTable Chunk Buffer и сегменты диска**: Спроектируйте архитектуру встраиваемой TSDB: входящие точки накапливаются в оперативной памяти в блоках (Chunks) фиксированной длительности (например, 2 часа). По истечении 2 часов сжатый чанк закрывается для записи, становится неизменяемым (Immutable) и сбрасывается на диск в файл сегмента.

14. **Встраиваемый TSDB Chunk Buffer на чистом Go**: Реализуйте потокобезопасный буфер чанка: структура ChunkBuffer хранит сжатые байты Gorilla, заголовок с минимальным и максимальным временем (MinTime, MaxTime), количество точек и мьютекс sync.RWMutex для параллельного чтения.

15. **Обратный индекс меток (Inverted Tag Index)**: Как быстро найти нужный временной ряд среди миллионов серий? Реализуйте обратный индекс: отображение TagKey=TagValue -> []SeriesID. При поиске по селектору {service="auth", env="prod"} найдите пересечение списков серий.

16. **Пересечение множеств индексов через Roaring Bitmaps**: Поиск пересечения списков []uint32 при миллионах серий создает высокую нагрузку на CPU. Подключите библиотеку RoaringBitmap/roaring. Покажите, как битовые операции пересечения (AND) выполняются в микросекунды с использованием аппаратных инструкций процессора.

17. **Интеграция с TimescaleDB: гипертаблицы и партиционирование**: Разверните расширение TimescaleDB для PostgreSQL. Создайте таблицу metrics (time TIMESTAMPTZ NOT NULL, device_id INT, temperature DOUBLE PRECISION). Преобразуйте ее в гипертаблицу с помощью вызова SELECT create_hypertable('metrics', 'time', chunk_time_interval => INTERVAL '1 day') через Go-драйвер pgx.

18. **Агрегация временных рядов (Time Bucketing / Downsampling)**: Напишите SQL-запрос построения графика загрузки за сутки с 5-минутными интервалами: используйте функцию time_bucket('5 minutes', time) AS five_min, агрегируя avg(temperature), max(temperature) и min(temperature).

19. **Непрерывные материализованные агрегаты (Continuous Aggregates)**: Постоянный пересчет средних значений по миллиардам строк замедляет дашборды Grafana. Настройте Continuous Aggregate в TimescaleDB: автоматический инкрементальный расчет 1-часовых агрегатов в фоновом режиме по расписанию.

20. **Политики автоматического удаления устаревших данных (Retention Policies)**: Телеметрия с секундной детализацией требуется только за последние 14 дней. Настройте политику хранения: автоматический вызов add_retention_policy('metrics', INTERVAL '14 days'). Объясните, почему удаление целого чанка в TimescaleDB происходит мгновенно как удаление файла на диске без блокировок.

21. **Колоночное сжатие чанков в TimescaleDB**: Включите нативное сжатие чанков: ALTER TABLE metrics SET (timescaledb.compress, timescaledb.compress_segmentby = 'device_id'). Настройте политику сжатия данных старше 3 дней. Замерьте сокращение дискового пространства на 90%.

22. **Прием IoT-телеметрии по протоколу MQTT на Go**: Подключите библиотеку eclipse/paho.mqtt.golang. Реализуйте MQTT-клиент на Go, подписывающийся на топик devices/+/telemetry, декодирующий бинарный полезный груз и передающий данные в буфер записи.

23. **Пакетная вставка телеметрии: буферизация на каналах**: Никогда не выполняйте INSERT в базу данных на каждый отдельный MQTT-пакет! Реализуйте воркер пакетной вставки: накопление до 10 000 точек или сброс по таймеру каждые 500 мс через pgx.CopyFrom (максимально быстрый бинарный протокол PostgreSQL).

24. **Интерполяция и заполнение пропусков в данных (Gap Filling)**: Если датчик временно терял связь, на графике образуются пустоты. Напишите алгоритм заполнения пропусков в Go: метод LOCF (Last Observation Carried Forward — повторение последнего известного значения) и линейную интерполяцию между соседними точками.

25. **Расчет производных метрик (Rate / Derivative)**: Для счетчиков (Counters, например общее количество байт трафика) абсолютное значение монотонно растет. Напишите функцию расчета скорости изменения (Rate): Delta Value / Delta Time. Обеспечьте корректную обработку сброса счетчика при перезагрузке сервера.

26. **Прием метрик по протоколу Prometheus Remote Write**: Напишите HTTP-эндпоинт на Go, принимающий метрики от агентов мониторинга по стандарту Prometheus Remote Write: распаковка сжатых данных алгоритмом Snappy (klauspost/compress/snappy) и десериализация Protobuf-сообщений prompb.WriteRequest.

27. **Кольцевой буфер оперативных метрик в памяти (Near-Realtime Cache)**: Для отображения графиков в реальном времени с нулевой задержкой реализуйте кольцевой буфер (Ring Buffer) на Go: хранение последних 15 минут телеметрии в RAM для мгновенного чтения без походов на диск.

28. **Проблема высокой кардинальности (High Cardinality) и защита TSDB**: Если разработчик случайно добавит UserID или случайный UUID в теги метрики, количество уникальных временных рядов вырастет до миллионов, переполнив обратный индекс TSDB. Реализуйте лимитер кардинальности: автоматическое отбрасывание новых лейблов при превышении порога уникальных серий.

29. **Стресс-тестирование TSDB на экстремальные объемы записи**: Напишите генератор синтетической нагрузки: имитация 10 000 IoT-устройств, генерирующих 500 000 точек в секунду. Замерьте задержку вставки, утилизацию CPU и пропускную способность дисковой подсистемы.

30. **Собственная встраиваемая Time-Series база данных на чистом Go**: Спроектируйте и реализуйте полнофункциональный прототип TSDB на Go: прием точек телеметрии по HTTP, сжатие чанков алгоритмом Gorilla, хранение обратного индекса меток, сброс 2-часовых сегментов на диск, поддержка поиска по диапазону времени и базовые агрегации (avg, min, max).
