# Обработка ошибок (Error Handling)

В этом файле собраны уникальные упражнения по теме **"Обработка ошибок (Error Handling)"**, отсортированные по возрастанию сложности.

---

1. Используйте `fmt.Errorf("failed to process user %d: %w", id, err)` для оборачивания (wrap) ошибки с сохранением контекста и цепочки вызовов.

2. Напишите функцию деления, которая возвращает `(float64, error)`. При делении на ноль возвращайте `errors.New("division by zero")`.

3. **Кастомная ошибка**: Создай структуру `AppError` с полями `Code int` и `Message string`. Реализуй для неё метод `Error() string`. Верни её из функции.

4. **Базовые ошибки**: Используй `errors.New("bad input")` и `fmt.Errorf("user %s not found", name)` для создания простых ошибок.

5. Создайте Sentinel-ошибку `var ErrNotFound = errors.New("not found")`. Используйте `errors.Is(err, ErrNotFound)` для проверки, даже если ошибка была обернута несколько раз.

6. Вызови функцию `Divide` и проверь ошибку стандартным `if err != nil`.

7. **Sentinel Errors (Маркерные ошибки)**: Объяви на уровне пакета `var ErrNotFound = errors.New("not found")`. Верни её из функции. В `main` сравни результат строго: `if err == ErrNotFound`.

8. Используй `fmt.Errorf("reading %s: %v", filename, err)` для добавления контекста. Покажи, что `%v` просто вставляет текст ошибки.

9. Напишите функцию, которая возвращает несколько разных типов ошибок, и корректно обработайте их в `main` с помощью `switch` и `errors.As`.

10. Используй `fmt.Errorf` с глаголом `%w` (Go 1.13+): `fmt.Errorf("processing failed: %w", err)`. Покажи, что ошибка **обёрнута** (wrapped) и сохраняет оригинал.

11. **Кастомная структура ошибки**: Создайте структуру `ValidationError` с полями `FieldName string` и `Value any`. Реализуйте метод `Error() string` для этой структуры, чтобы она удовлетворяла интерфейсу `error`.

12. **Обертывание (Wrapping)**: При получении ошибки в функции (например, от базы данных), не возвращай её как есть. Оберни её: `return fmt.Errorf("failed to get user: %w", err)`.

13. **[Каверзный кейс]**: Оберни ошибку: `fmt.Errorf("db query failed: %w", err)`. Проверь исходную ошибку с помощью `errors.Is` (она "пробьется" через обертку `%w`).

14. Используйте `errors.As(err, &validationErr)` для безопасного извлечения вашей кастомной ошибки из глубины обернутых ошибок.

15. Напиши функцию, возвращающую обёрнутую ошибку. В `main` используй `errors.Is(err, target)` для проверки: является ли ошибка (возможно, глубоко обёрнутая) конкретной sentinel-ошибкой.

16. Создайте цепочку функций: `readFile -> parseJSON -> validate`. Каждая возвращает ошибку. Пробросьте ошибку вверх, добавив контекст с помощью `fmt.Errorf("...: %w", err)`.

17. Реализуйте паттерн повторных попыток (Retry): если функция вернула определенную ошибку (например, "timeout"), вызовите ее снова до 3 раз с экспоненциальной задержкой.

18. Создай **sentinel error**: `var ErrNotFound = errors.New("not found")`. Используй её в нескольких функциях. Проверь через `errors.Is` в разных уровнях обёртки.

19. **Распаковка `errors.Is`**: Получив обернутую ошибку из упр. 204, используй `errors.Is(err, ErrNotFound)`, чтобы проверить, есть ли в цепочке обертываний наша маркерная ошибка. (Простое `==` тут уже не сработает).

20. **Оборачивание ошибок (Wrapping)**: Напишите функцию `ReadFileConfig()`, которая вызывает `os.Open`. Если возникает ошибка, оберните её с помощью `fmt.Errorf("не удалось прочитать конфиг: %w", err)` (используя спецификатор `%w`).

21. Изучите функцию `errors.Join` (Go 1.20+), чтобы собрать несколько ошибок, возникших при валидации разных полей формы, в одну агрегированную ошибку.

22. **Извлечение типа `errors.As`**: Оберни свою структуру `AppError` (из упр. 202) через `%w`. В `main` используй `errors.As(err, &myAppErr)`, чтобы достать её из обертки и прочитать конкретный HTTP `Code`.

23. Создай **кастомный тип ошибки** `type NotFoundError struct { Resource string; ID int }`. Реализуй `Error() string`. Используй `errors.As` для извлечения конкретного типа из цепочки ошибок.

24. Напиши функцию, возвращающую разные sentinel errors: `ErrInvalidInput`, `ErrNotFound`, `ErrPermissionDenied`. В вызывающем коде используй `switch` с `errors.Is` для разной логики обработки.

25. **Проверка ошибок через `errors.Is`**: Объявите глобальную ошибку-маркер (sentinel error) `var ErrPermissionDenied = errors.New("доступ запрещен")`. Напишите функцию, которая глубоко в цепочке вызовов возвращает эту ошибку (обернутую другими ошибками). В функции `main` проверьте наличие этой конкретной ошибки в цепочке с помощью `errors.Is`.

26. Создай кастомный тип ошибки (структуру, реализующую метод `Error() string`).

27. Напиши функцию с **guard clauses**: функция выполняет 3 проверки (валидация входных данных, проверка существования файла, проверка прав). Каждая проверка — `if err != nil { return ..., err }`. Избегай вложенных `if/else`.

28. **Множественные ошибки (Join)**: В цикле валидации данных у тебя накопилось 3 разных ошибки. Используй `errors.Join(err1, err2, err3)` (Go 1.20+), чтобы склеить их в одну ошибку, и выведи её.

29. Напишите функцию, которая вызывает `panic` при критическом сбое, и используйте `defer` + `recover` на верхнем уровне (`main` или HTTP-хендлере), чтобы перехватить панику и превратить ее в обычный лог или HTTP 500.

30. Напиши функцию с **deferred error handling**: `func DoSomething() (result int, err error)`. В `defer` проверяй `err != nil` и выполняй cleanup (закрытие файла, откат транзакции) только при ошибке.

31. Верни кастомную ошибку из функции, обернув её через `%w`. Извлеки оригинальный тип ошибки с помощью `errors.As`.

32. **Распаковка кастомной ошибки через `errors.As`**: Напишите функцию, которая возвращает обернутую ошибку `ValidationError`. В вызывающем коде с помощью функции `errors.As` извлеките исходную структуру ошибки и выведите в консоль имя поля `FieldName`, в котором произошла ошибка.

33. Напиши функцию `SafeParseInt(s string) (int, error)`, использующую `panic/recover` для защиты от неожиданных ситуаций (хотя `strconv.Atoi` и так возвращает ошибку, сымитируй через `panic`). Обсуди, когда `recover` уместен, а когда — нет.

34. **Паника vs Ошибка**: Напиши пакет `config`. Сделай функцию `LoadConfig() error` (которая читает файл и возвращает ошибку, если файла нет) и функцию `MustLoadConfig()`, которая вызывает `LoadConfig` и если есть ошибка — делает `panic()`. Это классический паттерн "Must".

35. Сравните подход "возвращать ошибки" (как в Go) и "бросать исключения" (как в Java/Python). Попробуйте написать функцию без `if err != nil` и осознайте, почему в Go это считается плохой практикой.

36. Напиши функцию `MustOpen(filename string) *os.File`, которая паникует при ошибке (паттерн `Must`). Покажи, когда это уместно: `init`, глобальные переменные, константные конфигурации.

37. Реализуйте функцию, которая может вернуть несколько ошибок (слайс ошибок). Используйте `errors.Join` (Go 1.20+) для объединения.

38. Напиши функцию, выполняющую несколько независимых операций. Собери все ошибки в `[]error`. Верни aggregated error через `fmt.Errorf("multiple errors: %w", errors.Join(errs...))` (Go 1.20+) или просто склей строк.

39. **Игнорирование ошибок**: Вызови `fmt.Println` (он возвращает кол-во записанных байт и ошибку). Проигнорируй возврат с помощью `_, _ = fmt.Println(...)`. Пойми, когда это допустимо, а когда — преступление.

40. **Паника против Ошибки**: Напишите парсер конфигурационного файла. Если файл поврежден, функция должна возвращать `error`. Если же в кодовой базе переданы некорректные системные параметры (например, пустой путь к конфигурационному файлу), вызовите `panic`. Опишите в комментариях философию Go: когда нужно использовать панику, а когда возвращать ошибку.

41. Напиши функцию `Retry(operation func() error, attempts int, delay time.Duration) error`, которая повторяет операцию при ошибке с задержкой. Логируй каждую попытку.

42. **[Каверзный кейс]**: Напиши функцию, которая возвращает несколько ошибок одновременно. (Можно использовать `errors.Join` из Go 1.20+). Проверь наличие конкретной ошибки в объединенной ошибке через `errors.Is`.

43. **Отложенный Recover**: Напиши функцию, которая может запаниковать (например, деление на 0). В начале функции добавь `defer func() { if r := recover(); r != nil { fmt.Println("Спасены от:", r) } }()`.

44. Напиши функцию `Timeout(operation func() error, timeout time.Duration) error`, используя `context.WithTimeout`. Отменяй операцию по таймауту и возвращай `context.DeadlineExceeded`.

45. Используй `defer` и `recover()` внутри функции для перехвата паники. Верни перехваченную панику как обычную `error` из функции.

46. Создайте sentinel-ошибки (пакетные переменные) `ErrNotFound`, `ErrPermission`. Возвращайте их и проверяйте снаружи.

47. **Объединение ошибок (`errors.Join`)**: Напишите валидатор формы регистрации. Напишите несколько независимых проверок (валидация email, пароля, возраста). Соберите все возникшие ошибки в один пакет с помощью функции `errors.Join` (доступна в современных версиях Go) и верните результат вызывающему коду.

48. Напиши функцию `CloseResource(c io.Closer)`, которая вызывает `c.Close()` и паникует, если закрытие вернуло ошибку (используй `log.Panic` или `panic(err)`).

49. **Централизованный хэндлер**: Напиши функцию-роутер, которая вызывает 3 другие функции (которые могут вернуть ошибки). Если любая из них возвращает ошибку, роутер логирует её и возвращает "HTTP 500", не дублируя код обработки логов каждый раз.

50. Напиши программу с двумя стратегиями: **fail fast** (при первой ошибке всё падает) и **best effort** (продолжается с логированием ошибок, собирает все). Сравни подходы.

51. **Игнорирование ошибок**: Напишите код, в котором вы умышленно игнорируете возвращаемую ошибку с помощью `_`. Напишите комментарий, почему в продакшн-кодовой базе это является критически опасной практикой.
