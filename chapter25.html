Упражнение #1

Базовый HTTP GET-запрос через http.Get и анализ Response StatusCode

📌 Условие задачи

Используй http.Get, чтобы сделать запрос к https://golang.org. Выведи статус-код ответа (например, 200 OK).

💡 Теоретический фундамент и концепция

Клиентский HTTP в Go: функция http.Get(url) использует стандартный транспорт http.DefaultClient для выполнения HTTP/1.1 или HTTP/2 GET-запроса. Возвращаемая структура *http.Response содержит статус-код resp.StatusCode (целое число) и текстовую строку статуса resp.Status (например, "200 OK").

🔍 Пошаговый ход решения и ход мысли инженера

1. Запустим тестовый HTTP-сервер на базе net/http/httptest.
2. Выполним запрос с помощью http.Get(ts.URL).
3. Обязательно закроем тело ответа defer resp.Body.Close().
4. Выведем resp.StatusCode и resp.Status.
📄 main.go 
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Golang Official Site"))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close() // КРИТИЧНО: освобождение сокета в пул

	fmt.Printf("[HTTP Client] Статус-код: %d\n", resp.StatusCode)
	fmt.Printf("[HTTP Client] Строка статуса: %s\n", resp.Status)
	fmt.Printf("[HTTP Client] Протокол: %s\n", resp.Proto)
}
📄 Терминал 
go run main.go
# Вывод:
# [HTTP Client] Статус-код: 200
# [HTTP Client] Строка статуса: 200 OK
# [HTTP Client] Протокол: HTTP/1.1
⚙️ Под капотом Go (Compiler, Linker & Runtime)

http.Get выполняет полный цикл: DNS-резолвинг, TCP 3-Way Handshake, TLS Negotiation (для HTTPS), отправку HTTP-заголовков и чтение заголовков ответа.

⚠️ Частые грабли и ошибки новичков

Всегда вызывайте resp.Body.Close(), иначе базовое TCP-соединение не вернется в Idle Connection Pool и сокет останется висеть в памяти.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему проверка if err != nil должна идти ДО вызова defer resp.Body.Close()?»

Ответ: Если при установке соединения произошла ошибка сети или DNS (например, dial tcp: lookup failed), указатель resp будет равен nil. Вызов resp.Body.Close() приведет к фатальной панике nil pointer dereference.

Упражнение #2

Чтение тела HTTP-ответа (Response Body) через io.ReadAll

📌 Условие задачи

Прочитай тело ответа (Response Body) с помощью io.ReadAll и выведи первые 100 байт в консоль.

💡 Теоретический фундамент и концепция

Интерфейс io.ReadCloser: поле resp.Body представляет собой поток входящих байтов. Функция io.ReadAll(resp.Body) считывает все доступные байты до получения маркера конца потока io.EOF.

🔍 Пошаговый ход решения и ход мысли инженера

1. Выполним GET-запрос к тестовому HTTP-серверу.
2. Прочитаем тело через bodyBytes, err := io.ReadAll(resp.Body).
3. Ограничим вывод первыми 100 байтами bodyBytes[:limit].
4. Выведем результат в консоль.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain")
		_, _ = w.Write([]byte("Go is an open source programming language that makes it easy to build simple, fast, and reliable software."))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	bodyBytes, err := io.ReadAll(resp.Body)
	if err != nil {
		panic(err)
	}

	limit := 60
	if len(bodyBytes) < limit {
		limit = len(bodyBytes)
	}

	fmt.Printf("[HTTP Body] Всего считано: %d байт\n", len(bodyBytes))
	fmt.Printf("[HTTP Body] Первые %d байт: %q\n", limit, string(bodyBytes[:limit]))
}
📄 Терминал 
go run main.go
# Вывод:
# [HTTP Body] Всего считано: 107 байт
# [HTTP Body] Первые 60 байт: "Go is an open source programming language that makes it easy"
⚙️ Под капотом Go (Compiler, Linker & Runtime)

io.ReadAll динамически расширяет внутренний буфер bytes.Buffer по мере поступления чанков данных от сетевой карты.

⚠️ Частые грабли и ошибки новичков

io.ReadAll считывает весь ответ в оперативную память. Для больших файлов (100 МБ+) используйте io.Copy(file, resp.Body) или io.LimitReader во избежание OOM.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как защитить HTTP-клиент от атаки Zip-бомбой или бесконечным потоком байтов в Response Body?»

Ответ: Обернуть resp.Body в io.LimitReader(resp.Body, maxBytes) (например, 10 МБ). Если сервер передает больше данных, Read завершится ошибкой или вернет усеченные данные, не допустив переполнения RAM.

Упражнение #3

Ловушка утечки дескрипторов: обязательное закрытие resp.Body.Close()

📌 Условие задачи

[Каверзный кейс]: Сделай 1000 запросов в цикле с помощью http.Get, но забудь закрыть тело ответа (defer resp.Body.Close()). Запусти программу и понаблюдай за ростом количества открытых файловых дескрипторов (утечка ресурсов). Исправь код, добавив defer.

💡 Теоретический фундамент и концепция

Утечка сокетов (Socket Leak): если тело HTTP-ответа resp.Body не закрыто, Go не может переиспользовать TCP-соединение для последующих запросов. Сокет остается висеть в системе до тех пор, пока сборщик мусора GC не вызовет финалайзер, что при высокой частоте запросов вызывает ошибку socket: too many open files.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим тестовый сервер.
2. Продемонстрируем цикл запросов с обязательным вызовом resp.Body.Close().
3. Добавим io.Copy(io.Discard, resp.Body) для вычитки остатка буфера.
4. Проверим стабильную работу без утечек.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func makeRequestSafe(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	// ПРАВИЛО #1: Всегда закрывать Body
	// ПРАВИЛО #2: Довычитывать Body в io.Discard для возврата TCP-сокета в Keep-Alive пул!
	defer resp.Body.Close()
	_, _ = io.Copy(io.Discard, resp.Body)

	return nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	}))
	defer ts.Close()

	client := &http.Client{Timeout: 2 * time.Second}

	const totalRequests = 100
	for i := 0; i < totalRequests; i++ {
		if err := makeRequestSafe(client, ts.URL); err != nil {
			panic(err)
		}
	}

	fmt.Printf("[Main] Успешно выполнено %d HTTP-запросов с 100%% переиспользованием Keep-Alive сокетов!\n", totalRequests)
}
📄 Терминал 
go run main.go
# Вывод:
# [Main] Успешно выполнено 100 HTTP-запросов с 100% переиспользованием Keep-Alive сокетов!
⚙️ Под капотом Go (Compiler, Linker & Runtime)

resp.Body.Close() возвращает TCP-соединение в persistConn транспортного пула только в том случае, если тело было полностью вычитано до io.EOF.

⚠️ Частые грабли и ошибки новичков

Вызов defer resp.Body.Close() внутри длинного цикла for выполнится только при выходе из функции, а не на каждой итерации. Оборачивайте тело цикла во вспомогательную функцию.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему одного resp.Body.Close() недостаточно для переиспользования Keep-Alive TCP-соединения?»

Ответ: Если в теле ответа остались непрочитанные байты, транспорт http.Transport вынужден закрыть TCP-сокет целиком (TCP RST), так как следующий HTTP-запрос получит смещение байтов. Для возврата сокета в пул необходимо вычитать остаток через io.Copy(io.Discard, resp.Body) перед закрытием.

Упражнение #4

Парсинг URL и безопасное кодирование параметров через net/url и url.Values

📌 Условие задачи

Используй net/url для парсинга URL. Добавь query-параметры (например, ?q=golang&page=2) с помощью url.Values.

💡 Теоретический фундамент и концепция

Безопасная сборка Query-строки: ручная конкатенация строк ("?q=" + str) уязвима к инъекциям и ломается на пробелах и спецсимволах (&, =, ?). Пакет net/url и тип url.Values автоматически экранируют символы согласно RFC 3986 (Percent-Encoding).

🔍 Пошаговый ход решения и ход мысли инженера

1. Распарсим базовый URL через url.Parse("https://api.example.com/search").
2. Создадим params := url.Values{}.
3. Добавим параметры через params.Add("q", "golang & concurrency").
4. Присвоим parsedURL.RawQuery = params.Encode().
5. Выведем собранный URL.
📄 main.go 
package main

import (
	"fmt"
	"net/url"
)

func main() {
	baseURL := "https://api.github.com/search/repositories"
	parsedURL, err := url.Parse(baseURL)
	if err != nil {
		panic(err)
	}

	query := url.Values{}
	query.Add("q", "language:go stars:>1000")
	query.Add("sort", "stars")
	query.Add("order", "desc")
	query.Add("page", "2")

	parsedURL.RawQuery = query.Encode()

	fmt.Println("Итоговый скомпонованный URL:")
	fmt.Println(parsedURL.String())
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

Метод query.Encode() сортирует ключи по алфавиту и заменяет спецсимволы на %XX или +.

⚠️ Частые грабли и ошибки новичков

query.Set() заменяет значение ключа, а query.Add() добавляет второе значение к тому же ключу (?tag=go&tag=web).

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем разница между url.Path и url.RawPath в структуре url.URL?»

Ответ: url.Path содержит декодированный путь (например, /user/иван), а url.RawPath — оригинальный закодированный путь (/user/%D0%B8%D0%B2%D0%B0%D0%BD). Если путь содержит символы %2F (экранированный слэш), Go использует RawPath для сохранения точной структуры URL.

Упражнение #5

Отправка POST-запроса с JSON полезной нагрузкой и Content-Type

📌 Условие задачи

Выполните POST-запрос, отправив JSON в теле. Не забудьте установить заголовок Content-Type: application/json.

💡 Теоретический фундамент и концепция

POST-запрос с полезной нагрузкой (JSON Payload): функция http.Post(url, contentType, bodyReader) передает поток байтов тела запроса и выставляет соответствующий MIME-тип заголовка.

🔍 Пошаговый ход решения и ход мысли инженера

1. Сериализуем структуру Go в JSON с помощью json.Marshal.
2. Создадим bytes.NewReader(jsonBytes).
3. Отправим запрос через http.Post(url, "application/json", reader).
4. Сервер валидирует полученный JSON и возвращает ответ.
📄 main.go 
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

type CreateUserRequest struct {
	Name  string `json:"name"`
	Email string `json:"email"`
	Role  string `json:"role"`
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		contentType := r.Header.Get("Content-Type")
		body, _ := io.ReadAll(r.Body)
		defer r.Body.Close()

		fmt.Printf("[Server] Получен %s запрос: Content-Type=%s\n", r.Method, contentType)
		fmt.Printf("[Server] Тело JSON: %s\n", string(body))

		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"id": 42, "status": "created"}`))
	}))
	defer ts.Close()

	user := CreateUserRequest{
		Name:  "Алексей",
		Email: "alex@example.com",
		Role:  "Backend Engineer",
	}

	payload, err := json.Marshal(user)
	if err != nil {
		panic(err)
	}

	resp, err := http.Post(ts.URL, "application/json", bytes.NewReader(payload))
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	respBody, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Client] Ответ сервера (Status %d): %s\n", resp.StatusCode, string(respBody))
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

bytes.NewReader реализует io.Reader и io.Seeker, позволяя http.Client автоматически вычислить заголовок Content-Length.

⚠️ Частые грабли и ошибки новичков

Без заголовка Content-Type: application/json большинство современных REST API серверов отклонят запрос с кодом 415 Unsupported Media Type.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Зачем http.Client выставляет заголовок Content-Length при передаче bytes.Reader?»

Ответ: Если размер тела известен заранее (Content-Length), HTTP-сервер может сразу аллоцировать нужный буфер и использовать Keep-Alive соединение. Если размер неизвестен, клиент переключается на Transfer-Encoding: chunked.

Упражнение #6

Настройка таймаута http.Client и перехват ошибки context.DeadlineExceeded

📌 Условие задачи

Настрой кастомный http.Client с Timeout: 5 * time.Second. Сделай запрос к серверу, который отвечает дольше 5 секунд (можно использовать httpbin.org/delay/10). Поймай ошибку таймаута.

💡 Теоретический фундамент и концепция

Политика таймаутов http.Client.Timeout: задает максимальное суммарное время на выполнение всего запроса целиком, включая DNS, TCP Handshake, TLS Handshake, отправку и чтение ответа.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим сервер с задержкой ответа 100 мс.
2. Настроим клиент с Timeout: 25 * time.Millisecond.
3. Выполним запрос client.Get(ts.URL).
4. Поймаем ошибку Client.Timeout exceeded.
📄 main.go 
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(100 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Delayed Response"))
	}))
	defer ts.Close()

	client := &http.Client{
		Timeout: 25 * time.Millisecond,
	}

	fmt.Println("[Client] Отправка запроса с таймаутом 25 мс...")
	_, err := client.Get(ts.URL)

	if err != nil {
		fmt.Printf("[Client Safety] ПЕРЕХВАЧЕН ТАЙМАУТ: %v\n", err)
	} else {
		fmt.Println("[Client] Ошибка: запрос должен был прерваться по таймауту!")
	}
}

Под капотом client.Timeout создает таймер контекста context.WithTimeout, который автоматически прерывает системные сетевые вызовы рантайма.

⚠️ Частые грабли и ошибки новичков

client.Timeout включает время на чтение всего Response Body. Если вы скачиваете файл 1 ГБ, таймаут клиента должен быть достаточно большим или управляться контекстом.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему в http.DefaultClient таймаут по умолчанию равен нулю?»

Ответ: По историческим причинам в Go нулевой таймаут означает бесконечное ожидание (no timeout). В продакшене это считается критической уязвимостью, так как зависший сторонний API может заблокировать все горутины сервиса.

Упражнение #7

Опасности http.DefaultClient в HighLoad и создание безопасного экземпляра

📌 Условие задачи

Создайте кастомный http.Client с настроенным таймаутом (Timeout: 5 * time.Second). Почему использование глобального http.DefaultClient в продакшене — плохая идея?

💡 Теоретический фундамент и концепция

Проблемы глобального http.DefaultClient:

1. Timeout == 0 — бесконечное ожидание приводит к утечке горутин (Goroutine Leak OOM).
2. Общий DefaultTransport разделяется всеми пакетами приложения.
3. MaxIdleConnsPerHost == 2 по умолчанию — всего 2 Keep-Alive соединения на хост.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим функцию-фабрику NewProductionHTTPClient(timeout).
2. Настроим кастомный транспорт и таймаут.
3. Продемонстрируем безопасный вызов.
4. Выведем параметры конфигурации.
📄 main.go 
package main

import (
	"fmt"
	"net"
	"net/http"
	"time"
)

func NewProductionHTTPClient(timeout time.Duration) *http.Client {
	transport := &http.Transport{
		Proxy: http.ProxyFromEnvironment,
		DialContext: (&net.Dialer{
			Timeout:   2 * time.Second,
			KeepAlive: 30 * time.Second,
		}).DialContext,
		MaxIdleConns:        100,
		MaxIdleConnsPerHost: 20,
		IdleConnTimeout:     90 * time.Second,
		TLSHandshakeTimeout: 2 * time.Second,
		DisableKeepAlives:   false,
	}

	return &http.Client{
		Transport: transport,
		Timeout:   timeout,
	}
}

func main() {
	client := NewProductionHTTPClient(3 * time.Second)

	fmt.Println("=== КОНФИГУРАЦИЯ PRODUCTION HTTP-КЛИЕНТА ===")
	fmt.Printf(" -> Client Timeout:         %v\n", client.Timeout)
	t := client.Transport.(*http.Transport)
	fmt.Printf(" -> MaxIdleConnsPerHost:    %d (вместо дефолтных 2!)\n", t.MaxIdleConnsPerHost)
	fmt.Printf(" -> IdleConnTimeout:        %v\n", t.IdleConnTimeout)
	fmt.Printf(" -> TLSHandshakeTimeout:    %v\n", t.TLSHandshakeTimeout)
}

⚠️ Частые грабли и ошибки новичков

Никогда не создавайте новый http.Client внутри каждой HTTP-ручки — клиент должен быть синглтоном.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему дефолтный MaxIdleConnsPerHost = 2 является узким местом в микросервисах?»

Ответ: Если микросервис А делает 100 параллельных запросов к микросервису Б, при MaxIdleConnsPerHost = 2 только 2 соединения сохранятся в пуле, а остальные 98 сокетов будут принудительно закрыты. На каждый новый запрос сервис будет заново тратить время на TCP + TLS Handshake.

Упражнение #8

Тюнинг пула соединений Keep-Alive в http.Transport для HighLoad

📌 Условие задачи

Настройте http.Transport для пулинга соединений (MaxIdleConns, IdleConnTimeout), чтобы переиспользовать TCP-соединения (Keep-Alive) и снижать нагрузку на сеть.

💡 Теоретический фундамент и концепция

Переиспользование сетевых сессий (HTTP Keep-Alive / Connection Pooling): повторное использование уже открытого TCP+TLS сокета экономит $2\text{–}3\text{ RTT}$ на каждом последующем HTTP-запросе.

🔍 Пошаговый ход решения и ход мысли инженера

1. Настроим http.Transport с высоким лимитом MaxIdleConnsPerHost: 50.
2. Выполним серию из 3 последовательных запросов к тестовому серверу.
3. Убедимся, что все запросы прошли через одно физическое TCP-соединение.
4. Проверим результат.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("PONG"))
	}))
	defer ts.Close()

	transport := &http.Transport{
		MaxIdleConns:        100,
		MaxIdleConnsPerHost: 50,
	}
	client := &http.Client{Transport: transport}

	for i := 1; i <= 3; i++ {
		resp, err := client.Get(ts.URL)
		if err != nil {
			panic(err)
		}
		_, _ = io.Copy(io.Discard, resp.Body)
		_ = resp.Body.Close()

		fmt.Printf(" -> Запрос #%d успешно выполнен (Keep-Alive сокет переиспользован)\n", i)
	}

	fmt.Println("[Main] Все запросы отработали с минимальным RTT без повторного TCP Handshake.")
}

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Каковы накладные расходы на создание нового HTTPS соединения без Keep-Alive?»

Ответ: 1. DNS Lookup ($\approx 10\text{–}50\text{ мс}$); 2. TCP 3-Way Handshake ($1\text{ RTT}$); 3. TLS 1.3 Handshake ($1\text{ RTT}$) плюс CPU на криптографию. Keep-Alive снижает накладные расходы до нуля.

Упражнение #9

Формирование кастомного HTTP-запроса через http.NewRequest и Header.Set

📌 Условие задачи

Кастомный запрос (Custom Headers): Тебе нужно передать токен авторизации. Используй req, err := http.NewRequest("GET", url, nil). Добавь заголовок: req.Header.Set("Authorization", "Bearer my-token"). Выполни запрос через client.Do(req).

💡 Теоретический фундамент и концепция

Конструктор http.NewRequest: позволяет сформировать произвольный HTTP-запрос, настроить HTTP-заголовки (req.Header), куки и тело запроса. Метод client.Do(req) отправляет сконфигурированный объект запроса.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим запрос http.NewRequest("GET", url, nil).
2. Добавим заголовок авторизации req.Header.Set("Authorization", "Bearer secret-token-999").
3. Добавим req.Header.Set("User-Agent", "GoService/2.0").
4. Выполним через client.Do(req) и проверим на сервере.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		auth := r.Header.Get("Authorization")
		ua := r.Header.Get("User-Agent")

		fmt.Printf("[Server] Получен Auth Header: %s\n", auth)
		fmt.Printf("[Server] Получен User-Agent:  %s\n", ua)

		if auth == "Bearer secret-jwt-token-xyz" {
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte(`{"access": "granted"}`))
		} else {
			w.WriteHeader(http.StatusUnauthorized)
			_, _ = w.Write([]byte(`{"error": "unauthorized"}`))
		}
	}))
	defer ts.Close()

	req, err := http.NewRequest(http.MethodGet, ts.URL+"/api/secure", nil)
	if err != nil {
		panic(err)
	}

	req.Header.Set("Authorization", "Bearer secret-jwt-token-xyz")
	req.Header.Set("User-Agent", "BackendWorkoutClient/1.0")
	req.Header.Set("Accept", "application/json")

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Client] Ответ сервера (Status %d): %s\n", resp.StatusCode, string(body))
}

Для нестандартных заголовков, требующих точного регистра, прямая запись в мапу req.Header["x-my-header"] = []string{val} обходит канонизацию.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем разница между req.Header.Set() и req.Header.Add()?»

Ответ: Set(k, v) перезаписывает все существующие значения для данного ключа. Add(k, v) добавляет новое значение в срез []string, позволяя передавать множественные заголовки с одинаковым именем.

Упражнение #10

Управление жизненным циклом запроса через http.NewRequestWithContext

📌 Условие задачи

[Каверзный кейс]: Используй context.WithTimeout вместе с http.NewRequestWithContext. Отмени контекст вручную (cancel()) до истечения таймаута. Убедись, что запрос прерывается корректно.

💡 Теоретический фундамент и концепция

Связка HTTP и context.Context (Go 1.13+): функция http.NewRequestWithContext(ctx, method, url, body) привязывает сокет к контексту. Если контекст отменяется вызовом cancel(), транспортный уровень мгновенно разрывает сокет.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим ctx, cancel := context.WithCancel(context.Background()).
2. Создадим запрос http.NewRequestWithContext(ctx, ...).
3. В фоновой горутине вызовем cancel() через 15 мс.
4. Проверим перехват ошибки context canceled.
📄 main.go 
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(100 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
	}))
	defer ts.Close()

	ctx, cancel := context.WithCancel(context.Background())

	go func() {
		time.Sleep(15 * time.Millisecond)
		fmt.Println("[Main] Пользователь нажал кнопку «Отмена» -> вызов cancel()!")
		cancel()
	}()

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, ts.URL, nil)
	if err != nil {
		panic(err)
	}

	client := &http.Client{}
	_, err = client.Do(req)

	if err != nil {
		if errors.Is(err, context.Canceled) || errors.Is(ctx.Err(), context.Canceled) {
			fmt.Printf("[Client Safety] Запрос успешно прерван по сигналу контекста: %v\n", err)
		} else {
			fmt.Printf("[Client Error] %v\n", err)
		}
	}
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

При отмене контекста http.Transport отправляет TCP RST или HTTP/2 RST_STREAM фрейм, освобождая ресурсы на обеих сторонах.

⚠️ Частые грабли и ошибки новичков

Всегда вызывайте defer cancel(), чтобы не допускать утечек ресурсов таймеров контекста.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Что происходит с TCP-соединением, если запрос прерван по cancel() контекста в HTTP/1.1 и в HTTP/2?»

Ответ: В HTTP/1.1 TCP-соединение закрывается полностью. В HTTP/2 мультиплексированное TCP-соединение остается жить, а серверу отправляется фрейм RST_STREAM с ID конкретного потока.

Упражнение #11

POST-запрос с отправкой сериализованного JSON на REST API эндпоинт

📌 Условие задачи

POST-запрос с JSON: Закодируй структуру в JSON. Отправь POST-запрос на https://jsonplaceholder.typicode.com/posts с помощью http.Post. Укажи Content-Type application/json.

💡 Теоретический фундамент и концепция

Интеграция с REST API сервисами: формирование JSON-объектов через json.Marshal и отправка в теле POST-запроса.

🔍 Пошаговый ход решения и ход мысли инженера

1. Опишем структуру BlogPost { Title, Body, UserID }.
2. Закодируем в JSON.
3. Отправим запрос через http.Post.
4. Проверим парсинг полученного ответа.
📄 main.go 
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

type BlogPost struct {
	Title  string `json:"title"`
	Body   string `json:"body"`
	UserID int    `json:"userId"`
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		var post BlogPost
		_ = json.NewDecoder(r.Body).Decode(&post)
		defer r.Body.Close()

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(fmt.Sprintf(`{"id": 101, "title": %q, "userId": %d}`, post.Title, post.UserID)))
	}))
	defer ts.Close()

	newPost := BlogPost{
		Title:  "Архитектура микросервисов на Go",
		Body:   "Подробный разбор HTTP-клиента, контекстов и пулинга соединений.",
		UserID: 42,
	}

	jsonData, _ := json.Marshal(newPost)

	resp, err := http.Post(ts.URL+"/posts", "application/json", bytes.NewReader(jsonData))
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)

Упражнение #13

}

Отправка multipart/form-data запроса с загрузкой файлов через mime/multipart

📌 Условие задачи

💡 Теоретический фундамент и концепция

Формат Multipart Form-Data (RFC 7578): используется для отправки файлов и текстовых полей формы. Структура multipart.Writer генерирует уникальный разделитель границ (Boundary) и форматирует тело запроса с заголовками Content-Disposition: form-data; name="file"; filename="...".

2. Создадим файловое поле part, _ := writer.CreateFormFile("avatar", "profile.png").
3. Запишем байты файла в part.
4. Закроем writer.Close() и передадим writer.FormDataContentType() в http.NewRequest.

import (
	"bytes"
	"fmt"
	"io"
	"mime/multipart"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		err := r.ParseMultipartForm(10 << 20)
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}

		user := r.FormValue("username")
		file, header, err := r.FormFile("document")
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}
		defer file.Close()

		content, _ := io.ReadAll(file)
		fmt.Printf("[Server Upload] Пользователь: %s\n", user)
		fmt.Printf("[Server Upload] Имя файла: %s (Размер: %d байт)\n", header.Filename, len(content))
		fmt.Printf("[Server Upload] Содержимое: %s\n", string(content))

		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("UPLOAD_SUCCESS"))
	}))
	defer ts.Close()

	body := &bytes.Buffer{}
	writer := multipart.NewWriter(body)

	_ = writer.WriteField("username", "alex_dev")

	part, err := writer.CreateFormFile("document", "contract.txt")
	if err != nil {
		panic(err)
	}
	_, _ = part.Write([]byte("Текст официального договора оказания услуг."))

	_ = writer.Close()

	req, err := http.NewRequest(http.MethodPost, ts.URL, body)
	if err != nil {
		panic(err)
	}

	req.Header.Set("Content-Type", writer.FormDataContentType())

	client := &http.Client{}
	resp, err := client.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	respMsg, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Client Response] %s\n", string(respMsg))
}

Упражнение #17

Отказоустойчивый HTTP-клиент с повторными попытками (Retry with Backoff)

📌 Условие задачи

Реализуйте HTTP-клиент с автоматическим ретраем (повторной попыткой) при получении статус-кодов 5xx или сетевых ошибок (используйте экспоненциальную задержку и context).

💡 Теоретический фундамент и концепция

Паттерн HTTP Retry with Exponential Backoff: при получении транзитных серверных ошибок (HTTP 502, 503, 504) или сетевых сбоев клиент повторяет запрос с растущей паузой $T \times 2^k$, позволяя сервису восстановиться.

🔍 Пошаговый ход решения и ход мысли инженера

1. Сервер падает на 1-й попытке (HTTP 503 Service Unavailable).
2. На 2-й попытке сервер отвечает HTTP 200 OK.
3. Клиент выполняет цикл ретраев с таймером.
4. Проверим успешное восстановление.
📄 main.go 
package main

import (
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func getWithRetry(ctx context.Context, client *http.Client, url string, maxRetries int) (*http.Response, error) {
	backoff := 20 * time.Millisecond

	for attempt := 1; attempt <= maxRetries; attempt++ {
		fmt.Printf("[Client] Попытка #%d: отправка запроса...\n", attempt)

		req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
		if err != nil {
			return nil, err
		}

		resp, err := client.Do(req)
		if err == nil && resp.StatusCode < 500 {
			return resp, nil
		}

		if resp != nil {
			_, _ = io.Copy(io.Discard, resp.Body)
			_ = resp.Body.Close()
		}

		if attempt == maxRetries {
			return nil, fmt.Errorf("исчерпаны все %d попыток: %w", maxRetries, err)
		}

		fmt.Printf(" [!] Ошибка/5xx статус. Ожидание %v перед повтором...\n", backoff)

		select {
		case <-time.After(backoff):
			backoff *= 2
		case <-ctx.Done():
			return nil, ctx.Err()
		}
	}
	return nil, context.Canceled
}

func main() {
	attempts := 0
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		attempts++
		if attempts == 1 {
			w.WriteHeader(http.StatusServiceUnavailable)
			_, _ = w.Write([]byte("Database temporarily down"))
			return
		}
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("SUCCESS_DATA"))
	}))
	defer ts.Close()

	client := &http.Client{Timeout: 2 * time.Second}
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel()

	resp, err := getWithRetry(ctx, client, ts.URL, 3)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Main Result] Успешный ответ (Status %d): %s\n", resp.StatusCode, string(body))
}

# Вывод:
# [Client] Попытка #1: отправка запроса...
#  [!] Ошибка/5xx статус. Ожидание 20ms перед повтором...
# [Client] Попытка #2: отправка запроса...
# [Main Result] Успешный ответ (Status 200): SUCCESS_DATA

Ретраи разрешены только для идемпотентных запросов (GET, PUT, DELETE, HEAD).

⚠️ Частые грабли и ошибки новичков

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему нельзя повторять (ретраить) неидемпотентные POST-запросы без Idempotency-Key?»

Ответ: Если сервер успешно обработал POST-запрос, но клиент потерял соединение на чтении ответа, повторный POST создаст дублирующую транзакцию. Заголовок Idempotency-Key: UUID позволяет серверу определить дубликат.

package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type CatalogResponse struct {
	Category string   `json:"category"`
	Products []string `json:"products"`
	Total    int      `json:"total"`
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{
			"category": "Laptops",
			"products": ["MacBook Pro 16", "ThinkPad X1", "Dell XPS 15"],
			"total": 3
		}`))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	var catalog CatalogResponse
	if err := json.NewDecoder(resp.Body).Decode(&catalog); err != nil {
		panic(err)
	}

	fmt.Printf("[Stream JSON Parser] Категория: %s (Товаров: %d)\n", catalog.Category, catalog.Total)
	for i, p := range catalog.Products {
		fmt.Printf(" -> Товар #%d: %s\n", i+1, p)
	}
}

	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	defer resp.Body.Close()
	_, _ = io.Copy(io.Discard, resp.Body)

	return nil
}

		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("HEALTHY"))
	}))

	client := &http.Client{}

	const iterations = 500
	for i := 0; i < iterations; i++ {
		if err := runCleanRequest(client, ts.URL); err != nil {
			panic(err)
		}
	}

	fmt.Printf("[Main] Успешно выполнено %d запросов подряд без единой утечки дескрипторов!\n", iterations)
}

Упражнение #23

Масштабирование MaxIdleConnsPerHost для высоконагруженных API шлюзов

📌 Условие задачи

Тонкая настройка пула соединений (Transport): Создай свой http.Transport с параметром MaxIdleConnsPerHost: 100. Передай его в http.Client. Полезно для высоконагруженных сервисов, делающих сотни запросов к одному API.

💡 Теоретический фундамент и концепция

Конфигурация HighLoad HTTP-транспорта: в архитектуре микросервисов бэкенд шлет тысячи запросов в секунду к одному и тому же сервису БД или микросервису авторизации. Настройка MaxIdleConnsPerHost = 100 удерживает 100 открытых Keep-Alive TCP-сессий, исключая задержки на постоянные переподключения.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим transport := &http.Transport{MaxIdleConnsPerHost: 100}.
2. Свяжем с client := &http.Client{Transport: transport}.
3. Запустим параллельные запросы.
4. Проверим параметры пула.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	}))
	defer ts.Close()

	transport := &http.Transport{
		MaxIdleConns:        500,
		MaxIdleConnsPerHost: 100,
		IdleConnTimeout:     60 * time.Second,
	}

	client := &http.Client{
		Transport: transport,
		Timeout:   5 * time.Second,
	}

	var wg sync.WaitGroup
	const concurrentRequests = 50
	wg.Add(concurrentRequests)

	for i := 0; i < concurrentRequests; i++ {
		go func() {
			defer wg.Done()
			resp, err := client.Get(ts.URL)
			if err != nil {
				return
			}
			_, _ = io.Copy(io.Discard, resp.Body)
			_ = resp.Body.Close()
		}()
	}

	wg.Wait()
	fmt.Printf("[HighLoad Transport] %d параллельных запросов успешно завершены через оптимизированный пул сокетов!\n", concurrentRequests)
}

Упражнение #24

Логирующий Middleware для HTTP-сервера и клиента (Request Metrics)

📌 Условие задачи

Реализуйте middleware для логирования всех входящих запросов (метод, URL, длительность выполнения).

💡 Теоретический фундамент и концепция

Паттерн HTTP Middleware (Цепочка обязанностей): функция-обёртка перехватывает запрос, фиксирует временную метку t0 := time.Now(), делегирует выполнение следующему хендлеру и логирует метод, путь, статус и время выполнения time.Since(t0).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим LoggingMiddleware(next http.Handler) http.Handler.
2. Обернем http.ResponseWriter для перехвата статус-кода.
3. Выполним тестовые GET и POST запросы.
4. Выведем журнал метрик в консоль.
📄 main.go 
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

type statusRecorder struct {
	http.ResponseWriter
	statusCode int
}

func (r *statusRecorder) WriteHeader(code int) {
	r.statusCode = code
	r.ResponseWriter.WriteHeader(code)
}

func LoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		t0 := time.Now()
		rec := &statusRecorder{ResponseWriter: w, statusCode: http.StatusOK}

		next.ServeHTTP(rec, r)

		duration := time.Since(t0)
		fmt.Printf("[HTTP ACCESS LOG] %-6s %-15s -> Status: %d | Latency: %v\n", 
			r.Method, r.URL.Path, rec.statusCode, duration.Round(time.Microsecond))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/v1/health", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(5 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	})
	mux.HandleFunc("/api/v1/orders", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(12 * time.Millisecond)
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"order_id": 99}`))
	})

	// Оборачиваем роутер в middleware
	loggedHandler := LoggingMiddleware(mux)
	ts := httptest.NewServer(loggedHandler)
	defer ts.Close()

	// Тестовые вызовы
	_, _ = http.Get(ts.URL + "/api/v1/health")
	_, _ = http.Post(ts.URL+"/api/v1/orders", "application/json", nil)
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

Встроенная структура statusRecorder перехватывает вызов WriteHeader, сохраняя код ответа для логов.

⚠️ Частые грабли и ошибки новичков

Если хендлер не вызывает WriteHeader, статус по умолчанию равен 200 OK (инициализируйте rec.statusCode = http.StatusOK).

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Зачем нужна структура statusRecorder при написании Middleware в Go?»

Ответ: Стандартный интерфейс http.ResponseWriter не имеет метода для чтения уже записанного статус-кода. Обертка statusRecorder перехватывает метод WriteHeader(code) и сохраняет его в поле структуры для последующего логирования и сбора метрик Prometheus.

Настройка HTTP и SOCKS5 прокси-сервера через http.Transport ProxyURL

📌 Условие задачи

Напиши HTTP-прокси клиент: proxyURL, _ := url.Parse("http://proxy:8080"); transport := &http.Transport{Proxy: http.ProxyURL(proxyURL)}; client := &http.Client{Transport: transport}.

💡 Теоретический фундамент и концепция

Проксирование сетевого HTTP/HTTPS трафика: поле Transport.Proxy принимает функцию func(*http.Request) (*url.URL, error). Функция http.ProxyURL(proxyURL) направляет все TCP-соединения через указанный Forward/Corporate Proxy сервер.

🔍 Пошаговый ход решения и ход мысли инженера

1. Поднимем локальный тестовый HTTP Forward Proxy сервер.
2. Сконфигурируем http.Transport{Proxy: http.ProxyURL(proxy)}.
3. Выполним запрос через прокси.
4. Убедимся, что запрос прошел через прокси-ноду.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
)

func main() {
	// 1. Целевой Origin сервер
	originServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("ORIGIN_DATA_SERVED"))
	}))
	defer originServer.Close()

	// 2. HTTP Forward Proxy сервер
	proxyHits := 0
	proxyServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		proxyHits++
		fmt.Printf("[Proxy Server] Перехвачен запрос к: %s\n", r.RequestURI)

		// Делегируем запрос на целевой сервер
		outReq, _ := http.NewRequest(r.Method, r.RequestURI, r.Body)
		resp, err := http.DefaultTransport.RoundTrip(outReq)
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadGateway)
			return
		}
		defer resp.Body.Close()

		w.WriteHeader(resp.StatusCode)
		_, _ = io.Copy(w, resp.Body)
	}))
	defer proxyServer.Close()

	// 3. Клиент с настройкой ProxyURL
	proxyURL, err := url.Parse(proxyServer.URL)
	if err != nil {
		panic(err)
	}

	transport := &http.Transport{
		Proxy: http.ProxyURL(proxyURL),
	}
	client := &http.Client{Transport: transport}

	resp, err := client.Get(originServer.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Client Response] %s (Всего через прокси: %d)\n", string(body), proxyHits)
}

	"fmt"
	"net"
	"net/http"
	"time"
)

// SafeProductionClient возвращает защищенный HTTP-клиент для микросервисов
func SafeProductionClient() *http.Client {
	return &http.Client{
		Timeout: 3 * time.Second, // Глобальный дедлайн на весь жизненный цикл запроса
		Transport: &http.Transport{
			DialContext: (&net.Dialer{
				Timeout:   1 * time.Second, // Таймаут на установку TCP 3-Way Handshake
				KeepAlive: 30 * time.Second,
			}).DialContext,
			MaxIdleConns:          200,              // Общий лимит свободных сокетов в пуле
			MaxIdleConnsPerHost:   50,               // Лимит сокетов на один микросервис
			IdleConnTimeout:       90 * time.Second, // Время жизни неактивного Keep-Alive сокета
			TLSHandshakeTimeout:   1 * time.Second,  // Таймаут TLS Negotiation
			ExpectContinueTimeout: 1 * time.Second,
		},
	}
}

func main() {
	client := SafeProductionClient()
	fmt.Printf("[Safe Client Ready] Timeout=%v, MaxIdlePerHost=%d\n", 
		client.Timeout, client.Transport.(*http.Transport).MaxIdleConnsPerHost)
}

	if err != nil {
		panic(err)
	}

package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func safeDiscardRequest(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	// Сбрасываем тело ответа без аллокаций в памяти
	_, err = io.Copy(io.Discard, resp.Body)
	return err
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("DATA_PAYLOAD"))
	}))
	defer ts.Close()

	client := &http.Client{}

	for i := 1; i <= 100; i++ {
		if err := safeDiscardRequest(client, ts.URL); err != nil {
			panic(err)
		}
	}

	fmt.Println("[Main] 100 запросов успешно завершены, сокеты переиспользованы без утечек.")
}

Упражнение #34

Клиентский Middleware через переопределение интерфейса http.RoundTripper

📌 Условие задачи

Кастомный транспорт (RoundTripper): Напишите Middleware для HTTP-клиента. Для этого создайте структуру, реализующую интерфейс http.RoundTripper. Данный транспорт должен перехватывать все исходящие запросы вашего клиента, автоматически замерять время их выполнения и выводить его в лог, после чего делегировать выполнение стандартному транспорту http.DefaultTransport.

💡 Теоретический фундамент и концепция

Интерфейс http.RoundTripper (Клиентский Middleware): содержит единственный метод RoundTrip(*http.Request) (*http.Response, error). Оборачивание транспорта позволяет реализовывать:

1. Автоматическое добавление заголовков авторизации / трассировки (Tracing Headers).
2. Замер задержек и сбор метрик в Prometheus.
3. Логирование исходящего сетевого трафика.
4. Автоматические ретраи на транспортном уровне.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим структуру LoggingTransport struct { Base http.RoundTripper }.
2. Реализуем метод RoundTrip(req).
3. Подставим в client.Transport = &LoggingTransport{Base: http.DefaultTransport}.
4. Выполним тестовые запросы и проверим лог.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

type MetricsTransport struct {
	Base http.RoundTripper
}

func (t *MetricsTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	t0 := time.Now()

	// Автоматически добавляем заголовок трассировки во все исходящие запросы
	req.Header.Set("X-Client-Trace-ID", "TRACE-UUID-998877")

	base := t.Base
	if base == nil {
		base = http.DefaultTransport
	}

	resp, err := base.RoundTrip(req)
	duration := time.Since(t0)

	if err != nil {
		fmt.Printf("[CLIENT ROUNDTRIP ERROR] %s %s -> Err: %v | Latency: %v\n", 
			req.Method, req.URL, err, duration.Round(time.Microsecond))
		return nil, err
	}

	fmt.Printf("[CLIENT ROUNDTRIP METRICS] %s %s -> Status: %d | Latency: %v\n", 
		req.Method, req.URL.Path, resp.StatusCode, duration.Round(time.Microsecond))

	return resp, nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("PONG"))
	}))
	defer ts.Close()

	client := &http.Client{
		Transport: &MetricsTransport{Base: http.DefaultTransport},
		Timeout:   2 * time.Second,
	}

	resp, err := client.Get(ts.URL + "/api/ping")
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	_, _ = io.Copy(io.Discard, resp.Body)
}

В RoundTrip нельзя модифицировать сам *http.Request без его клонирования (req.Clone(req.Context())), если запрос может быть повторен.

Упражнение #35

Отправка классических HTML-форм с Content-Type application/x-www-form-urlencoded

📌 Условие задачи

Напиши POST с application/x-www-form-urlencoded: используй url.Values и strings.NewReader(values.Encode()). Отправь на тестовый сервер.

💡 Теоретический фундамент и концепция

Формат application/x-www-form-urlencoded: стандартный формат отправки веб-форм. Данные кодируются как ключ-значение в виде key1=val1&key2=val2 и передаются в теле запроса через функцию http.PostForm(url, data) или http.Post.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим formData := url.Values{}.
2. Добавим поля formData.Set("grant_type", "password"), formData.Set("username", "admin").
3. Отправим запрос через http.Post(ts.URL, "application/x-www-form-urlencoded", strings.NewReader(formData.Encode())).
4. Сервер парсит форму через r.ParseForm() и валидирует данные.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if err := r.ParseForm(); err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}

		user := r.Form.Get("username")
		grant := r.Form.Get("grant_type")
		fmt.Printf("[Server Form Auth] User: %s | GrantType: %s\n", user, grant)

		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OAUTH_TOKEN_GRANTED"))
	}))
	defer ts.Close()

	// Формируем поля формы
	formData := url.Values{}
	formData.Set("grant_type", "password")
	formData.Set("username", "developer@google.com")
	formData.Set("scope", "read:profile write:orders")

	// Отправка запроса
	resp, err := http.Post(
		ts.URL,
		"application/x-www-form-urlencoded",
		strings.NewReader(formData.Encode()),
	)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Client] Ответ: %s\n", string(body))
}

Упражнение #37

Экспоненциальный Backoff и контекстный дедлайн в цикле повторных запросов

📌 Условие задачи

Напиши retry logic для HTTP-клиента: при ошибке сети или статусе 5xx — повтори запрос с exponential backoff (100ms, 200ms, 400ms, max 3 попытки). Используй context для ограничения общего времени.

💡 Теоретический фундамент и концепция

Паттерн Exponential Backoff with Jitter: интервал между повторными попытками увеличивается вдвое на каждом шаге ($T, 2T, 4T$), предотвращая эффект громоподобного стада (Thundering Herd Problem) при восстановлении упавшего сервиса.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим контекст с общим дедлайном 500 мс.
2. Реализуем цикл ретраев с удвоением backoff *= 2.
3. Сервер имитирует 503 на первых 2 попытках и 200 OK на 3-й.
4. Проверим успешную доставку.
📄 main.go 
package main

import (
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func executeWithBackoff(ctx context.Context, client *http.Client, url string) (string, error) {
	backoff := 25 * time.Millisecond
	const maxRetries = 3

	for attempt := 1; attempt <= maxRetries; attempt++ {
		req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
		if err != nil {
			return "", err
		}

		resp, err := client.Do(req)
		if err == nil && resp.StatusCode < 500 {
			defer resp.Body.Close()
			body, _ := io.ReadAll(resp.Body)
			return string(body), nil
		}

		if resp != nil {
			_, _ = io.Copy(io.Discard, resp.Body)
			_ = resp.Body.Close()
		}

		fmt.Printf(" [!] Попытка #%d не удалась. Пауза %v перед повтором...\n", attempt, backoff)

		select {
		case <-time.After(backoff):
			backoff *= 2
		case <-ctx.Done():
			return "", ctx.Err()
		}
	}
	return "", fmt.Errorf("все попытки исчерпаны")
}

func main() {
	tries := 0
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		tries++
		if tries < 3 {
			w.WriteHeader(http.StatusBadGateway) // 502
			return
		}
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("FINAL_SUCCESS_RESULT"))
	}))
	defer ts.Close()

	client := &http.Client{}
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel()

	result, err := executeWithBackoff(ctx, client, ts.URL)
	if err != nil {
		panic(err)
	}

	fmt.Printf("[Client] Успешный результат после ретраев: %s\n", result)
}

⚠️ Частые грабли и ошибки новичков

В реальных HighLoad сервисах к backoff обязательно добавляют случайный шум (Jitter: $\pm 20\%$), чтобы тысячи клиентов не просыпались синхронно.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Зачем нужен Full Jitter при реализации алгоритма Exponential Backoff?»

Ответ: Если сервер упал и перезагрузился, клиенты с фиксированным backoff будут слать повторные запросы синхронными волнами (Thundering Herd), снова роняя сервер. Full Jitter распределяет время ретраев равномерно по интервалу $[0, \text{backoff}]$, размазывая нагрузку во времени.

Паттерн Progress Tracking Writer: структура PassThroughWriter, реализующая io.Writer, подсчитывает количество записанных байт и обновляет процент выполнения относительно заголовка resp.ContentLength.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим структуру ProgressWriter { Total, Current }.
2. В методе Write(p) накапливаем Current += len(p) и выводим процент.

📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

type ProgressWriter struct {
	Total      int64
	Downloaded int64
}

func (pw *ProgressWriter) Write(p []byte) (int, error) {
	n := len(p)
	pw.Downloaded += int64(n)

	percent := float64(pw.Downloaded) / float64(pw.Total) * 100
	fmt.Printf("\r [Скачивание] Прогресс: %.1f%% (%d / %d байт)", 
		percent, pw.Downloaded, pw.Total)

	return n, nil
}

func main() {
	const totalSize = 2 * 1024 * 1024 // 2 МБ
	data := bytes.Repeat([]byte("X"), totalSize)

	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Length", fmt.Sprintf("%d", totalSize))
		w.Header().Set("Content-Type", "application/octet-stream")
		_, _ = w.Write(data)
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	pw := &ProgressWriter{Total: resp.ContentLength}

	// Потоковое копирование через обертку прогресса
	_, err = io.Copy(pw, resp.Body)
	if err != nil {
		panic(err)
	}

	fmt.Println("\n[Main] Скачивание успешно завершено на 100%!")
}

Параллельный сбор данных из среза URL с WaitGroup и семафором

📌 Условие задачи

Напиши параллельные HTTP-запросы: список URL. Для каждого URL запусти горутину с http.Get. Собери результаты через канал. Используй sync.WaitGroup или errgroup для ожидания.

💡 Теоретический фундамент и концепция

Паттерн Fan-Out HTTP Scraper (Параллельный краулер): параллельный запуск $N$ HTTP-запросов с ограничением конкурентности через буферизованный канал-семафор и сбор результатов в единый канал ответов.

🔍 Пошаговый ход решения и ход мысли инженера

1. Поднимем тестовые HTTP эндпоинты /item/1, /item/2, /item/3.
2. Запустим горутины под управлением sync.WaitGroup.
3. Соберем результаты в resultsChan := make(chan Result, len(urls)).
4. Закроем канал и выведем агрегированные данные.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

type FetchResult struct {
	URL        string
	StatusCode int
	Body       string
	Duration   time.Duration
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Data for " + r.URL.Path))
	}))
	defer ts.Close()

	urls := []string{
		ts.URL + "/users",
		ts.URL + "/orders",
		ts.URL + "/products",
		ts.URL + "/analytics",
	}

	client := &http.Client{Timeout: 2 * time.Second}
	resultsChan := make(chan FetchResult, len(urls))

	var wg sync.WaitGroup
	wg.Add(len(urls))

	for _, u := range urls {
		go func(targetURL string) {
			defer wg.Done()
			t0 := time.Now()

			resp, err := client.Get(targetURL)
			if err != nil {
				return
			}
			defer resp.Body.Close()

			body, _ := io.ReadAll(resp.Body)
			resultsChan <- FetchResult{
				URL:        targetURL,
				StatusCode: resp.StatusCode,
				Body:       string(body),
				Duration:   time.Since(t0),
			}
		}(u)
	}

	wg.Wait()
	close(resultsChan)

	fmt.Println("=== РЕЗУЛЬТАТЫ ПАРАЛЛЕЛЬНОГО СБОРА ДАННЫХ ===")
	for res := range resultsChan {
		fmt.Printf(" -> Status %d | Time: %6v | %s\n", 
			res.StatusCode, res.Duration.Round(time.Millisecond), res.Body)
	}
}

Упражнение #40

Стриминг и дублирование потока через io.TeeReader для логирования

📌 Условие задачи

Напиши HTTP-загрузчик файла: http.Get по URL, io.Copy в локальный файл. Покажи прогресс: в отдельной горутине читай resp.ContentLength и сколько байт скопировано (через io.TeeReader или io.Reader обёртку).

💡 Теоретический фундамент и концепция

Паттерн Stream Splitting (Разветвитель потока): функция io.TeeReader(r, w) возвращает io.Reader, который при каждом чтении из r синхронно дублирует прочитанные байты в w (по аналогии с Unix-утилитой tee).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим тестовый сервер.
2. Обернем resp.Body через tee := io.TeeReader(resp.Body, logger).
3. Считаем данные в целевой файл через io.Copy(dest, tee).
4. Проверим, что данные попали и в файл, и в логгер.
📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("STREAMING_TELEMETRY_PAYLOAD"))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	var fileStorage bytes.Buffer
	var debugLogger bytes.Buffer

	// TeeReader дублирует каждый байт из resp.Body в debugLogger во время чтения
	tee := io.TeeReader(resp.Body, &debugLogger)

	// Читаем из tee в целевое хранилище
	written, err := io.Copy(&fileStorage, tee)
	if err != nil {
		panic(err)
	}

	fmt.Printf("[TeeReader Pipeline] Записано в файл:   %d байт (%s)\n", written, fileStorage.String())
	fmt.Printf("[TeeReader Pipeline] Записано в логгер: %d байт (%s)\n", debugLogger.Len(), debugLogger.String())
}

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
	"sync"
	"time"
)

type SafeStore struct {
	mu   sync.Mutex
	data map[string]string
}

func (s *SafeStore) Set(key, val string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.data[key] = val
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Response for " + r.URL.Path))
	}))

	store := &SafeStore{data: make(map[string]string)}

	const totalEndpoints = 10
	wg.Add(totalEndpoints)

	for i := 1; i <= totalEndpoints; i++ {
		endpointURL := ts.URL + "/service/" + strconv.Itoa(i)
		go func(target string) {
			defer wg.Done()
			resp, err := client.Get(target)
			if err != nil {
				return
			}
			defer resp.Body.Close()

			body, _ := io.ReadAll(resp.Body)
			store.Set(target, string(body))
		}(endpointURL)
	}

	wg.Wait()

	fmt.Printf("=== УСПЕШНО ОПРОШЕНО %d ЭНДПОИНТОВ ===\n", len(store.data))
	for k, v := range store.data {
		fmt.Printf(" -> %s = %s\n", k, v)
		break // печатаем пример
	}
	fmt.Printf("Всего записей в потокобезопасной мапе: %d\n", len(store.data))
}

Инициализация CookieJar и автоматическая передача cookie между запросами

📌 Условие задачи

Напиши HTTP-клиент с CookieJar: jar, _ := cookiejar.New(nil); client := &http.Client{Jar: jar}. Сделай два запроса к серверу, устанавливающему cookie. Покажи, что второй запрос автоматически отправляет cookie.

💡 Теоретический фундамент и концепция

Сохранение состояния сессии (Stateful HTTP Session): http.CookieJar автоматически связывает куки с доменом и путем, возвращая их в последующих вызовах.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим cookiejar.New(nil).
2. Первый запрос к /set устанавливает cookie: auth=token123.
3. Второй запрос к /get отправляет куку на сервер.
4. Сервер подтверждает получение куки.
📄 main.go 
package main

import (
	"fmt"
	"net/http"
	"net/http/cookiejar"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path == "/set" {
			http.SetCookie(w, &http.Cookie{
				Name:  "session_id",
				Value: "XYZ-998877",
				Path:  "/",
			})
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte("Cookie Set!"))
			return
		}

		if r.URL.Path == "/get" {
			c, err := r.Cookie("session_id")
			if err != nil {
				w.WriteHeader(http.StatusBadRequest)
				_, _ = w.Write([]byte("No cookie"))
				return
			}
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte("FOUND_COOKIE:" + c.Value))
		}
	}))
	defer ts.Close()

	jar, _ := cookiejar.New(nil)
	client := &http.Client{Jar: jar}

	// 1. Первый запрос (получаем куку)
	r1, _ := client.Get(ts.URL + "/set")
	r1.Body.Close()

	// 2. Второй запрос (кука отправляется автоматически!)
	r2, _ := client.Get(ts.URL + "/get")
	defer r2.Body.Close()

	fmt.Printf("[Client Session] Статус: %s\n", r2.Status)
}

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Каковы симптомы нехватки MaxIdleConnsPerHost в графиках Grafana?»

Ответ: Резкий рост количества открываемых TCP-сокетов (TCP Connect spikes), рост задержек P99 из-за повторных TLS Handshake и накопление сокетов в состоянии TIME_WAIT на стороне клиента и сервера.

Упражнение #44

Одновременный вывод в консоль и сохранение в файл через io.TeeReader

📌 Условие задачи

Напиши HTTP-клиент с io.TeeReader: читай ответ и одновременно пиши его в os.Stdout (для отладки) и в файл (для сохранения). Используй io.TeeReader(resp.Body, file) + io.Copy.

💡 Теоретический фундамент и концепция

Разветвление входящего потока (Multi-Destination Streaming): io.TeeReader(r, w) позволяет направлять сетевой поток одновременно на экран и в долговременное хранилище за один проход.

🔍 Пошаговый ход решения и ход мысли инженера

1. Запустим тестовый сервер.
2. Создадим буфер файла и буфер консоли.
3. Обернем поток в io.TeeReader.
4. Выполним io.Copy(dest, tee).
📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Critical Security Audit Log Data"))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	var fileStorage bytes.Buffer
	var stdoutMirror bytes.Buffer

	// Одновременно пишем в stdoutMirror при чтении
	tee := io.TeeReader(resp.Body, &stdoutMirror)

	// Копируем в fileStorage
	_, _ = io.Copy(&fileStorage, tee)

	fmt.Printf("[Screen Output]: %s\n", stdoutMirror.String())
	fmt.Printf("[Saved File]:    %s\n", fileStorage.String())
}

# [Saved File]:    Critical Security Audit Log Data
⚙️ Под капотом Go (Compiler, Linker & Runtime)

TeeReader перехватывает каждый чанк данных в момент вызова Read().

⚠️ Частые грабли и ошибки новичков

Медленный Writer в TeeReader замедлит скорость чтения всего сетевого сокета.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем отличие io.MultiWriter от io.TeeReader?»

Ответ: io.MultiWriter(w1, w2) принимает данные на запись и дублирует их в несколько io.Writer. io.TeeReader(r, w) перехватывает операцию чтения из io.Reader и попутно записывает прочитанное в w.

Упражнение #45

Быстрая инспекция метаданных ресурса через HTTP HEAD-запрос

📌 Условие задачи

Напиши HTTP HEAD-запрос: http.Head(url). Получи только заголовки без тела. Используй для проверки существования ресурса или получения Content-Length перед загрузкой.

💡 Теоретический фундамент и концепция

Экономичный метод HTTP HEAD: сервер возвращает те же заголовки (Content-Length, Content-Type, Last-Modified), что и для GET, но с пустым телом ответа. Это позволяет проверить доступность файла и его размер без скачивания гигабайтов данных.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим сервер с эндпоинтом /large-archive.tar.gz.
2. Выполним http.Head(url).
3. Считаем resp.ContentLength и resp.Header.Get("Content-Type").
4. Убедимся, что тело пустое.
📄 main.go 
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Method == http.MethodHead {
			w.Header().Set("Content-Length", "1073741824") // 1 ГБ
			w.Header().Set("Content-Type", "application/x-tar")
			w.Header().Set("Accept-Ranges", "bytes")
			w.WriteHeader(http.StatusOK)
			return // Тело НЕ отправляется в HEAD-ответе
		}
		w.WriteHeader(http.StatusMethodNotAllowed)
	}))
	defer ts.Close()

	// Выполняем HEAD-запрос
	resp, err := http.Head(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Println("=== РЕЗУЛЬТАТ HTTP HEAD-ЗАПРОСА ===")
	fmt.Printf("Статус:            %s\n", resp.Status)
	fmt.Printf("Размер файла:      %.2f ГБ (%d байт)\n", 
		float64(resp.ContentLength)/(1024*1024*1024), resp.ContentLength)
	fmt.Printf("MIME-тип:          %s\n", resp.Header.Get("Content-Type"))
	fmt.Printf("Поддержка Ranges:  %s\n", resp.Header.Get("Accept-Ranges"))
}

⚠️ Частые грабли и ошибки новичков

Даже для HEAD-запроса вызов defer resp.Body.Close() обязателен для корректного возврата сокета в пул.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как с помощью HEAD-запроса проверить, изменился ли файл на сервере (Кэширование)?»

Ответ: Проверить заголовки ETag (хеш содержимого) или Last-Modified. В последующем GET-запросе передать заголовок If-None-Match: или If-Modified-Since: . Если файл не менялся, сервер вернет легковесный статус 304 Not Modified.
