Упражнение #1

Вывод переменных разных типов через fmt.Println

📌 Условие задачи

Выведите на экран несколько переменных разных типов в одной строке, используя fmt.Println и разделители.

💡 Теоретический фундамент и концепция

Функция fmt.Println из стандартного пакета fmt:

1. Принимает произвольное количество аргументов любого типа (...any или ...interface{});
2. Автоматически вставляет один пробел между операндами;
3. Добавляет символ перевода строки \n в самом конце вывода.

Под капотом fmt.Println форматирует каждый аргумент по правилам глагола по умолчанию (%v).

🔍 Пошаговый ход решения и ход мысли инженера

1. Импортируем пакет fmt.
2. Объявляем переменные базовых типов: string, int, float64, bool.
3. Передаем их в fmt.Println через запятую.
4. Для кастомного разделителя (например | ) передаем разделитель как отдельный строковый литерал.
📄 main.go 
package main

import "fmt"

func main() {
	name := "Gopher"
	age := 15
	score := 98.5
	isPro := true

	// Стандартный вывод через пробел
	fmt.Println("Имя:", name, "Возраст:", age, "Баллы:", score, "Статус:", isPro)

	// Вывод с явным разделителем
	fmt.Println(name, "|", age, "|", score, "|", isPro)
}

ℹ️ Результат выполнения
⚙️ Под капотом Go (Compiler, Linker & Runtime)

fmt.Println вызывает внутренний метод Fprintln(os.Stdout, a...). Внутри рантайма создается срез []any, память под который при выходе на интерфейс аллоцируется в куче (heap allocation), если компилятор при Escape Analysis не сможет доказать локальность объекта.

⚠️ Частые грабли и ошибки новичков
  • Если передать две строки подряд, fmt.Println("Hello,", "World!"), между ними появится пробел (Hello, World!). Но если использовать fmt.Print("Hello,", "World!"), пробела не будет (Hello,World!).
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему частый вызов fmt.Println в горячих циклах (hot path) Highload-сервиса приводит к деградации производительности GC?»

Ответ: Так как аргументы принимаются как ...any, каждое значение примитивного типа (число, bool, структура) упаковывается в интерфейс (interface boxing), что вызывает аллокации в куче и нагружает Garbage Collector. В Highload-коде используют буферизованный вывод или специализированные логгеры (uber-go/zap, rs/zerolog), работающие без аллокаций.

Упражнение #2

Базовый ввод данных через fmt.Scan

📌 Условие задачи

Считайте строку или число из консоли с помощью fmt.Scan и выведите результат обратно.

💡 Теоретический фундамент и концепция

Функция fmt.Scan считывает текст из стандартного потока ввода os.Stdin:

1. Сканирует данные, разделенные пробельными символами (пробел, табуляция, перевод строки);
2. Принимает указатели на переменные (&variable), чтобы записать в них считанные данные;
3. Возвращает количество успешно считанных элементов n и ошибку err.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем переменную для хранения числа var age int.
2. Вызываем fmt.Scan(&age).
3. Обязательно проверяем ошибку if err != nil.
4. Выводим полученное значение.
📄 main.go 
package main

import (
	"fmt"
)

func main() {
	var age int
	fmt.Print("Введите ваш возраст: ")

	// Передаем указатель &age
	_, err := fmt.Scan(&age)
	if err != nil {
		fmt.Printf("Ошибка чтения ввода: %v\n", err)
		return
	}

	fmt.Printf("Вы ввели возраст: %d лет\n", age)
}

📄 Терминал

# Вы ввели возраст: 25 лет
ℹ️ Интерактивный ввод
⚙️ Под капотом Go (Compiler, Linker & Runtime)

fmt.Scan вызывает внутренний парсер scan.doScan, который побайтово читает os.Stdin через системный вызов read(0, ...) до первого разделителя unicode.IsSpace.

⚠️ Частые грабли и ошибки новичков
  • Передача переменной по значению (fmt.Scan(age) вместо fmt.Scan(&age)). Функция не сможет изменить исходную переменную и вернет ошибку.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Что произойдет, если пользователь введет буквы 'abc' в вызов fmt.Scan(&age) для переменной типа int?»

Ответ: fmt.Scan вернет ошибку вида expected integer, значение переменной останется дефолтным (0), а непрочитанные символы останутся в буфере os.Stdin, что сломает последующие вызовы fmt.Scan.

Упражнение #3

Спецификаторы форматирования в Print, Println и Printf

📌 Условие задачи

Выведите строки, целые, вещественные числа и булевы значения через Print, Println и Printf (спецификаторы %d, %f, %s, %t, %v, %+v, %#v).

💡 Теоретический фундамент и концепция

Таблица ключевых глаголов форматирования (Verbs):

  • %d — целое число в десятичной системе (decimal);
  • %f — число с плавающей точкой (float);
  • %s — строка или срез байт (string);
  • %t — булево значение (true/false);
  • %v — значение по умолчанию;
  • %+v — значение структуры с именами полей;
  • %#v — Go-синтаксис литерала значения.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем структуру и базовые типы.
2. Выводим каждое значение через соответствующий спецификатор в fmt.Printf.
📄 main.go 
package main

import "fmt"

type Service struct {
	Name    string
	Port    int
	Healthy bool
	Rate    float64
}

func main() {
	s := Service{Name: "AuthService", Port: 8080, Healthy: true, Rate: 99.95}

	fmt.Printf("Целое: %%d -> %d\n", s.Port)
	fmt.Printf("Вещественное: %%f -> %.2f\n", s.Rate)
	fmt.Printf("Строка: %%s -> %s\n", s.Name)
	fmt.Printf("Булево: %%t -> %t\n", s.Healthy)
	fmt.Printf("Дефолт: %%v -> %v\n", s)
	fmt.Printf("С полями: %%+v -> %+v\n", s)
	fmt.Printf("Go-синтаксис: %%#v -> %#v\n", s)
}

⚠️ Частые грабли и ошибки новичков
  • Несоответствие типа и спецификатора (например, fmt.Printf("%d", "строка")). Go выдаст предупреждение на этапе go vet и выведет %!d(string=строка) в рантайме.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем отличие %+v от %#v при логировании структур данных?»

Ответ: %+v выводит структуру с именами полей ({Name:Alex Age:30}), а %#v выводит полный синтаксис Go вместе с именем пакета и типа (main.User{Name:"Alex", Age:30}). В логах дебага и тестах %#v предпочтительнее, так как исключает путаницу между похожими типами.

Упражнение #4

Побайтовое чтение потока через bufio.Reader.ReadByte

📌 Условие задачи

Прочитайте один байт (bufio.Reader.ReadByte) и определите, является ли он цифрой.

💡 Теоретический фундамент и концепция

Пакет bufio предоставляет буферизованный ввод-вывод.

Метод bufio.Reader.ReadByte():

1. Считывает ровно один байт (byte = uint8);
2. Если в буфере пусто, запрашивает блок данных из os.Stdin (обычно 4096 байт) за один системный вызов;
3. В таблице ASCII цифры от '0' до '9' имеют непрерывный диапазон кодов от 48 (0x30) до 57 (0x39).

🔍 Пошаговый ход решения и ход мысли инженера

1. Оборачиваем os.Stdin в bufio.NewReader(os.Stdin).
2. Вызываем reader.ReadByte().
3. Проверяем условие b >= '0' && b <= '9'.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Print("Введите один символ: ")

	b, err := reader.ReadByte()
	if err != nil {
		fmt.Printf("Ошибка чтения байта: %v\n", err)
		return
	}

	if b >= '0' && b <= '9' {
		fmt.Printf("Символ '%c' (код %d) — это ЦИФРА.\n", b, b)
	} else {
		fmt.Printf("Символ '%c' (код %d) — НЕ цифра.\n", b, b)
	}
}

Буферизация минимизирует количество контекст-свитчей в ядро Linux. Чтение 1000 байт по одному через небуферизованный os.Stdin.Read вызовет 1000 системных вызовов sys_read, тогда как bufio.Reader выполнит всего один вызов ядра.

⚠️ Частые грабли и ошибки новичков
  • В UTF-8 кириллические символы (например, 'Я') занимают 2 байта. Попытка прочитать русский символ через ReadByte() прочитает только первый байт UTF-8 префикса (0xD0/0xD1). Для Unicode используют ReadRune().

Вопрос с собеседования: «Как устроен буфер в bufio.NewReader и каков его размер по умолчанию?»

Ответ: По умолчанию размер внутреннего среза buf составляет 4096 байт (defaultBufSize = 4096). Если требуется другой размер (например, для чтения 64 КБ сетевых пакетов), используется bufio.NewReaderSize(rd, 65536).

Упражнение #5

Чтение полной строки с пробелами через bufio.Reader.ReadString

📌 Условие задачи

Считайте строку, содержащую пробелы, с помощью bufio.NewReader и os.Stdin.ReadString.

💡 Теоретический фундамент и концепция

Функция fmt.Scan останавливается на первом же пробеле.

Чтобы считать всю введенную строку целиком (включая пробелы) до нажатия клавиши Enter:

1. Используется метод reader.ReadString('\n');
2. Он считывает байты до символа разделителя (delimiter);
3. Символ \n (а на Windows \r\n) остается в конце строки, поэтому его удаляют через strings.TrimSpace.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем reader := bufio.NewReader(os.Stdin).
2. Читаем строку до \n: text, err := reader.ReadString('\n').
3. Очищаем от переносов строк: strings.TrimSpace(text).

package main

	"fmt"
	"os"
	"strings"
)

	}

	fmt.Printf("Получено: [%s] (длина: %d символов)\n", cleanInput, len(cleanInput))
}

ReadString динамически увеличивает внутренний буфер, если разделитель \n не встретился в первом чанке 4 КБ.

⚠️ Частые грабли и ошибки новичков

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем отличие bufio.Reader.ReadString('\n') от bufio.Scanner.Scan()?»

Ответ: ReadString возвращает строку вместе с разделителем \n и аллоцирует строку на каждый вызов. bufio.Scanner автоматически отсекает \n, переиспользует внутренний буфер байт scanner.Bytes() без лишних аллокаций памяти и безопаснее ограничивает максимальную длину строки (maxScanTokenSize = 64 * 1024).

Упражнение #7

Надежный ввод числа с валидацией и циклом повтора (strconv)

📌 Условие задачи

Реализуйте ввод числа и обработайте ошибку: если введено не число — попросите повторить (пакет strconv).

💡 Теоретический фундамент и концепция

Паттерн надежного ввода:

1. Считываем пользовательский ввод как сырую строку через bufio.Reader (это гарантирует очистку буфера os.Stdin при любых ошибках);
2. Парсим строку через strconv.Atoi(strings.TrimSpace(input));
3. Если возникла ошибка (err != nil), выводим подсказку и продолжаем цикл for;
4. При успешном парсинге выходим из цикла через break.

🔍 Пошаговый ход решения и ход мысли инженера

1. Запускаем бесконечный цикл for.
2. Считываем строку через reader.ReadString('\n').
3. Парсим через strconv.Atoi.
4. Если успешно — сохраняем и делаем break.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	var validNumber int

	for {
		fmt.Print("Введите целое положительное число: ")
		input, err := reader.ReadString('\n')
		if err != nil {
			fmt.Println("Ошибка чтения. Повторите ввод.")
			continue
		}

		clean := strings.TrimSpace(input)
		num, err := strconv.Atoi(clean)
		if err != nil || num <= 0 {
			fmt.Printf("❌ Ошибка: '%s' не является корректным числом! Попробуйте снова.\n", clean)
			continue
		}

		validNumber = num
		break
	}

	fmt.Printf("✔ Успешно введено число: %d\n", validNumber)
}

Упражнение #8

Парсинг форматированных строк через fmt.Sscanf

📌 Условие задачи

Используйте fmt.Sscanf для парсинга строки формата "Имя, возраст, рост" в соответствующие переменные.

💡 Теоретический фундамент и концепция

Функция fmt.Sscanf разбирает входную строку по заданному шаблону:

  • fmt.Sscanf(sourceStr, "%s %d %f", &name, &age, &height)
  • Она извлекает данные в переменные соответствующих типов без ручного вызова strings.Split.

	fmt.Printf("• Возраст: %d\n", age)

}

Упражнение #10

Интерактивное консольное меню с циклом и switch

📌 Условие задачи

Напишите простейшее меню: бесконечный цикл, чтение команды, switch, выход по "exit".

💡 Теоретический фундамент и концепция

Интерактивный REPL (Read-Eval-Print Loop) в консоли:

1. Бесконечный цикл for {};
2. Вывод приглашения ввода (> );
3. Считывание команды через bufio.Reader;
4. Диспетчеризация через оператор switch command;
5. Завершение работы программы при команде "exit" или "quit" через return или os.Exit(0).

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем reader := bufio.NewReader(os.Stdin).
2. Запускаем бесконечный цикл for.
3. Читаем строку, очищаем через strings.TrimSpace.
4. В switch обрабатываем команды: status, help, version, exit.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
	"time"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Println("=== Утилита управления сервером (введите 'help' для списка команд) ===")

	for {
		fmt.Print("app> ")
		input, err := reader.ReadString('\n')
		if err != nil {
			fmt.Println("Завершение по сигналу ввода.")
			break
		}

		cmd := strings.ToLower(strings.TrimSpace(input))

		switch cmd {
		case "exit", "quit":
			fmt.Println("Выключение утилиты. До свидания!")
			return
		case "help":
			fmt.Println("Доступные команды: status, time, ping, exit")
		case "status":
			fmt.Println("Статус: Сервер активен, нагрузка CPU: 12%")
		case "time":
			fmt.Printf("Текущее время: %s\n", time.Now().Format("15:04:05"))
		case "ping":
			fmt.Println("PONG!")
		case "":
			// Пользователь просто нажал Enter
			continue
		default:
			fmt.Printf("Неизвестная команда '%s'. Введите 'help'.\n", cmd)
		}
	}
}

⚠️ Частые грабли и ошибки новичков
  • Забыть привести ввод к нижнему регистру (strings.ToLower): команды Exit, EXIT и exit будут распознаваться как разные строки.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как корректно завершить REPL-цикл, если пользователь нажал Ctrl+C или Ctrl+D?»

Ответ: Нажатие Ctrl+D генерирует ошибку io.EOF в ReadString, при которой цикл корректно прерывается через break. Нажатие Ctrl+C посылает сигнал SIGINT, для перехвата которого запускают горутину с os/signal.

📌 Условие задачи

Выведите текущее время в кастомном формате с помощью fmt.Printf и пакета time.

💡 Теоретический фундамент и концепция

Уникальная особенность Go:

В отличие от языков C, Python или Java (где используются абстрактные коды %Y-%m-%d %H:%M:%S), в Go шаблон форматирования времени задается через эталонную константную дату Mon Jan 2 15:04:05 MST 2006:

  • Месяц: 01
  • День: 02
  • Час: 15 (или 03 для 12-часового формата)
  • Минута: 04
  • Секунда: 05
  • Год: 2006
  • Временная зона: -0700 или MST

🔍 Пошаговый ход решения и ход мысли инженера

1. Получаем текущее время: now := time.Now().
2. Вызываем метод now.Format("2006-01-02 15:04:05").
3. Печатаем через fmt.Printf.
📄 main.go 
package main

import (
	"fmt"
	"time"
)

func main() {

	fmt.Printf("RFC3339:   %s\n", now.Format(time.RFC3339))

	custom := now.Format("02.01.2006 15:04:05")
	fmt.Printf("Кастомный: %s\n", custom)

	// 3. Формат для логов с миллисекундами
	logFormat := now.Format("2006/01/02 15:04:05.000")
	fmt.Printf("Лог-тайм:  %s\n", logFormat)
}

Упражнение #14

Подробный вывод структур: сравнение %v, %+v и %#v

📌 Условие задачи

Подробный вывод структур: Создайте простую структуру User с полями Name и Age. Инициализируйте её. Выведите её в консоль тремя способами: через %v, %+v и %#v. Сравните результаты.

💡 Теоретический фундамент и концепция

Разница модификаторов вывода структур:

1. %v (Value): выводит только значения полей {Алексей 29};
2. %+v (Plus Value): выводит имена полей и их значения {Name:Алексей Age:29};
3. %#v (Syntax Value): выводит полное объявление типа на языке Go main.User{Name:"Алексей", Age:29}.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем структуру type User struct { Name string; Age int }.
2. Создаем экземпляр u := User{Name: "Алексей", Age: 29}.
3. Выводим через %v, %+v, %#v.
📄 main.go 
package main

import "fmt"

type User struct {
	Name string
	Age  int
}

func main() {
	user := User{Name: "Алексей", Age: 29}

	fmt.Printf("1. Базовый %%v:    %v\n", user)
	fmt.Printf("2. С полями %%+v:   %+v\n", user)
	fmt.Printf("3. Go-синтакс %%#v: %#v\n", user)
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

При %+v и %#v форматировщик обходит поля структуры через reflect.Type.Field(i).Name и считывает смещения полей в оперативной памяти.

⚠️ Частые грабли и ошибки новичков
  • Приватные (неэкспортированные со строчной буквы) поля структуры также будут выведены в %+v, поэтому не передавайте в логгер структуры с секретными полями вроде passwordHash или токенами доступа.

Ответ: Рекомендуется %#v (или diff библиотек вроде go-cmp), так как %#v явно показывает кавычки у пустых строк "", nil vs пустые срезы []int{} и точные типы полей, предотвращая ложное ощущение совпадения значений.

Упражнение #16

Консольное эхо-приложение до команды exit

📌 Условие задачи

Сделайте эхо-программу, которая читает строки до "exit" и выводит каждую с префиксом > .

💡 Теоретический фундамент и концепция

Паттерн Echo-сервера / консольного эхо:

1. Инициализация буферизованного сканера bufio.NewScanner(os.Stdin);
2. Цикл scanner.Scan(), ожидающий ввода очередной строки;
3. Проверка условия завершения (strings.EqualFold(line, "exit"));
4. Форматированный вывод строки с префиксом > .

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем scanner := bufio.NewScanner(os.Stdin).
2. В цикле for scanner.Scan() считываем строку через scanner.Text().
3. Если строка "exit" — завершаем работу.
4. Выводим fmt.Printf("> %s\n", text).
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	fmt.Println("Эхо-программа запущена (введите 'exit' для выхода):")

	for scanner.Scan() {
		line := scanner.Text()
		if strings.TrimSpace(line) == "exit" {
			fmt.Println("Завершение работы эхо-программы.")
			break
		}
		fmt.Printf("> %s\n", line)
	}

	if err := scanner.Err(); err != nil {
		fmt.Printf("Ошибка сканера: %v\n", err)
	}
}

# exit
# Завершение работы эхо-программы.
ℹ️ Пример сессии
⚙️ Под капотом Go (Compiler, Linker & Runtime)

bufio.Scanner по умолчанию использует функцию разделения bufio.ScanLines, которая ищет байты \n или \r\n и возвращает строку без этих разделителей.

⚠️ Частые грабли и ошибки новичков
  • Забыть проверить scanner.Err() после выхода из цикла: если поток ввода аварийно оборвется (например, ошибка чтения сокета/файла), цикл завершится, но ошибка не будет обработана.

Ответ: scanner.Scan() вернет false, а scanner.Err() вернет ошибку bufio.Scanner: token too long. Чтобы читать длинные строки (например, гигантские JSON логи), нужно переопределить буфер через scanner.Buffer(buf, maxCapacity).

Упражнение #17

Сложение чисел из консоли с валидацией ввода

📌 Условие задачи

Напишите программу, которая запрашивает у пользователя два числа и выводит результат их сложения, корректно обрабатывая ошибки ввода с помощью fmt.Scan.

💡 Теоретический фундамент и концепция

При считывании двух чисел fmt.Scan(&a, &b):

1. fmt.Scan ожидает ввода двух аргументов, разделенных пробелом или переводом строки;
2. Если пользователь введет нечисловые данные, функция вернет ошибку и прекратит разбор;
3. Значение n покажет, сколько именно чисел удалось успешно прочитать.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем переменные var a, b float64.
2. Вызываем fmt.Scan(&a, &b).
3. Проверяем ошибку if err != nil.
4. Выводим результат a + b.
📄 main.go 
package main

import "fmt"

func main() {
	var a, b float64
	fmt.Print("Введите два числа через пробел (например, 15.5 4.5): ")

	n, err := fmt.Scan(&a, &b)
	if err != nil {
		fmt.Printf("❌ Ошибка ввода: %v (прочитано чисел: %d)\n", err, n)
		return
	}

	sum := a + b
	fmt.Printf("✔ Результат: %.2f + %.2f = %.2f\n", a, b, sum)
}

ℹ️ Проверка сценариев
⚙️ Под капотом Go (Compiler, Linker & Runtime)

При чтении нескольких аргументов fmt.Scan последовательно вызывает метод сканирования для каждого переданного указателя. При первой же ошибке парсинг останавливается.

  • Сложение чисел с плавающей точкой (float64) может приводить к ошибкам округления (например, 0.1 + 0.2 = 0.30000000000000004). В финансовых расчетах в BigTech вместо float64 используют целочисленные копейки/центы (int64) или пакет shopspring/decimal.

Ответ: Стандарт IEEE 754 представляет дробные числа в двоичной системе, из-за чего десятичные дроби (0.1, 0.01) не могут быть представлены абсолютно точно, накапливая ошибки округления при миллионах транзакций.

📌 Условие задачи

💡 Теоретический фундамент и концепция

Спецификатор %T в fmt.Printf:

1. Выводит точное имя типа переменной на языке Go;
2. Для пользовательских типов выводит путь пакета и имя (main.User);

	fmt.Printf("ch:  значение = %v, тип = %T\n", ch, ch)

}

Для вложенных структур и коллекций:

Упражнение #27

Строгий позиционный ввод по шаблону через fmt.Scanf

📌 Условие задачи

Строгое чтение: Используй fmt.Scanf, чтобы считать данные строго в формате "Имя: [имя], Возраст: [возраст]".

💡 Теоретический фундамент и концепция

Функция fmt.Scanf:

1. Считывает данные из os.Stdin строго в соответствии со строкой формата;
2. Все литеральные символы в шаблоне (двоеточия, запятые, пробелы) обязаны точно совпасть с введенным текстом.

🔍 Пошаговый ход решения и ход мысли инженера

1. Задаем формат "Имя: %s Возраст: %d\n".
2. Считываем данные в переменные.

import "fmt"

func main() {

	var age int

	fmt.Println("Введите данные строго в формате: Имя: <имя> Возраст: <число>")
	fmt.Print("> ")

		return
	}

	fmt.Printf("✔ Успешно считано: Имя = %s, Возраст = %d\n", name, age)
}

Упражнение #28

Вывод диагностических сообщений и ошибок в Stderr через fmt.Fprintln

📌 Условие задачи

Вывод ошибок в Stderr: Напишите функцию, которая имитирует ошибку. Выведите сообщение об ошибке в поток стандартной ошибки os.Stderr с помощью fmt.Fprintln.

💡 Теоретический фундамент и концепция

В операционных системах UNIX/Linux у каждого процесса есть два основных потока вывода:

1. os.Stdout (File Descriptor 1) — стандартный вывод для полезных данных программы;
2. os.Stderr (File Descriptor 2) — поток ошибок и логов.

Функция fmt.Fprintln(os.Stderr, ...) направляет вывод напрямую в поток ошибок.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем полезный вывод в os.Stdout (через fmt.Println).
2. При возникновении ошибки выводим сообщение в os.Stderr через fmt.Fprintln(os.Stderr, ...).
3. Тестируем перенаправление потоков в терминале.
📄 main.go 
package main

import (
	"fmt"
	"os"
)

func processTask(taskID int) error {
	if taskID < 0 {
		return fmt.Errorf("недопустимый ID задачи: %d", taskID)
	}
	fmt.Printf("[STDOUT] Задача #%d успешно обработана.\n", taskID)
	return nil
}

func main() {
	// 1. Успешная задача
	if err := processTask(101); err != nil {
		fmt.Fprintln(os.Stderr, "[STDERR] Ошибка:", err)
	}

	// 2. Ошибочная задача
	if err := processTask(-5); err != nil {
		fmt.Fprintln(os.Stderr, "[STDERR] Критическая ошибка:", err)
		os.Exit(1)
	}
}

Упражнение #31

Механика разделителей и проблема пробелов в fmt.Scan

📌 Условие задачи

Проблема пробелов: Попытайся считать строку с пробелами (например, "Иван Иванов") через fmt.Scan. Изучи, почему считывается только "Иван".

💡 Теоретический фундамент и концепция

Почему fmt.Scan читает только до пробела:

Функция fmt.Scan воспринимает любые пробельные символы (пробел, табуляция, \n) как границы отдельных токенов ввода (Word Delimiters).

Когда вы вводите "Иван Иванов":

1. fmt.Scan(&name) считывает первый токен "Иван";
2. Обнаруживает пробел и завершает операцию сканирования;
3. Второй токен "Иванов" остается в системном буфере потока os.Stdin.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем var input string.
2. Запрашиваем ввод строки с пробелами через fmt.Scan(&input).
3. Показываем, что записалось в переменную, и объясняем причину.

package main

import "fmt"

func main() {
	var firstName string
	fmt.Print("Введите имя и фамилию (например, Иван Иванов): ")

	// fmt.Scan прочитает только до первого пробела
	fmt.Scan(&firstName)

	fmt.Printf("В переменную записано: [%s]\n", firstName)
	fmt.Println("Пояснение: остаток строки остался в буфере Stdin!")
}

Сканер Go использует конечный автомат, где состояние считывания строки прерывается при вызове функции unicode.IsSpace(r) == true.

1. Вызов scanner.Scan() возвращает true, пока в потоке есть данные;
2. scanner.Text() возвращает строку без завершающего \n;
3. scanner.Bytes() возвращает срез байт с нулевым выделением памяти;
4. Ошибки потока проверяются через scanner.Err().

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем scanner := bufio.NewScanner(os.Stdin).
2. В цикле for scanner.Scan() считываем текст.
3. При вводе "exit" завершаем цикл.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	fmt.Println("Введите строки (для выхода введите 'exit'):")

	lineNum := 1
	for {
		fmt.Printf("[%02d] > ", lineNum)
		if !scanner.Scan() {
			break // Достигнут EOF или ошибка потока
		}

		line := scanner.Text()
		if strings.TrimSpace(line) == "exit" {
			fmt.Println("Работа сканера завершена.")
			break
		}

		fmt.Printf("     Длина строки: %d символов\n", len(line))
		lineNum++
	}

	if err := scanner.Err(); err != nil {
		fmt.Printf("Критическая ошибка чтения: %v\n", err)
	}
}

Корректная обработка сигнала конца файла (io.EOF / Ctrl+D)

📌 Условие задачи

Обработка EOF: Сделай программу, которая читает из os.Stdin до получения сигнала конца файла (Ctrl+D / Ctrl+Z).

💡 Теоретический фундамент и концепция

Конец потока ввода (End-Of-File, EOF):

Когда программа работает в конвейере UNIX (cat data.txt | app) или пользователь нажимает в терминале:

  • Ctrl+D в Linux / macOS;
  • Ctrl+Z + Enter в Windows;

Операционная система закрывает дескриптор Stdin, и все функции чтения возвращают сигнальную ошибку io.EOF.

🔍 Пошаговый ход решения и ход мысли инженера

1. В цикле вызываем bufio.NewReader(os.Stdin).ReadString('\n').
2. Проверяем ошибку if err == io.EOF.
3. При наступлении EOF подводим итоги и корректно завершаем программу.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"io"
	"os"
	"strings"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Println("Потоковый обработчик запущен (для завершения нажмите Ctrl+D):")

	lineCount := 0
	wordCount := 0

	for {
		line, err := reader.ReadString('\n')
		if len(line) > 0 {
			lineCount++
			words := strings.Fields(line)
			wordCount += len(words)
		}

		if err != nil {
			if err == io.EOF {
				fmt.Println("\n[EOF] Достигнут конец потока данных.")
				break
			}
			fmt.Printf("Ошибка чтения: %v\n", err)
			break
		}
	}

	fmt.Printf("Итоговая статистика: строк = %d, слов = %d\n", lineCount, wordCount)
}

	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"

	// 1. Имя
	fmt.Print("Имя: ")
	nameRaw, _ := reader.ReadString('\n')
	name := strings.TrimSpace(nameRaw)
	if name == "" {
		fmt.Fprintln(os.Stderr, "❌ Ошибка: имя не может быть пустым!")
		os.Exit(1)
	}

	// 2. Возраст
	fmt.Print("Возраст: ")
	ageRaw, _ := reader.ReadString('\n')

	}

	fmt.Print("Email: ")
	emailRaw, _ := reader.ReadString('\n')
	email := strings.TrimSpace(emailRaw)
	if !strings.Contains(email, "@") || !strings.Contains(email, ".") {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: некорректный формат email '%s'!\n", email)

	fmt.Println("========================================")

	fmt.Printf("• Возраст: %d лет\n", age)

}

Упражнение #46

Посимвольное чтение рун Unicode и анализ кодовых точек

📌 Условие задачи

Чтение по одному символу: Реализуй посимвольное чтение ввода (рун) и выводи Unicode-код каждого введенного символа.

💡 Теоретический фундамент и концепция

Руны в Go (rune = int32):

В стандарте UTF-8 символы имеют переменную длину от 1 до 4 байт:

  • Английские буквы ('A', 'z') — 1 байт;
  • Кириллица ('Я', 'ж') — 2 байта;
  • Эмодзи ('🚀', '🐹') — 4 байта.

Метод bufio.Reader.ReadRune():

1. Считывает один полный Unicode-символ (кодовую точку);
2. Возвращает руну r rune, её размер в байтах size int и ошибку err.

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем reader := bufio.NewReader(os.Stdin).
2. В цикле вызываем r, size, err := reader.ReadRune().
3. Печатаем символ, его десятичный код, шестнадцатеричный Unicode (U+%04X) и размер в байтах.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Print("Введите строку с кириллицей и эмодзи: ")

	for {
		r, size, err := reader.ReadRune()
		if err != nil {
			break
		}

		if r == '\n' || r == '\r' {
			break // Конец ввода
		}

		fmt.Printf("Символ: %-3c | Unicode: U+%04X | Dec: %-5d | Байт: %d\n", r, r, r, size)
	}
}

Интерактивное меню с защитой от некорректного ввода букв

📌 Условие задачи

Интерактивное CLI-меню: Создай меню, работающее в цикле (1 - Приветствие, 2 - Показать время, 3 - Очистить экран (вывод пустых строк), 0 - Выход). Обрабатывай некорректный ввод пользователя (буквы вместо цифр).

💡 Теоретический фундамент и концепция

Надежная диспетчеризация CLI-меню:

1. Вывод пунктов меню;
2. Считывание строки целиком через bufio.Reader;
3. Преобразование строки в число choice, err := strconv.Atoi(...);
4. Обработка ошибок парсинга и невалидных пунктов без падения программы.

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем цикл for.
2. Выводим список пунктов 1, 2, 3, 0.
3. Парсим ввод и вызываем соответствующую ветку switch.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
	"time"
)

func main() {
	reader := bufio.NewReader(os.Stdin)

	for {
		fmt.Println("\n--- МЕНЮ УПРАВЛЕНИЯ ---")
		fmt.Println("1. Приветствие")
		fmt.Println("2. Текущее время сервера")
		fmt.Println("3. Очистить консоль")
		fmt.Println("0. Выход")
		fmt.Print("Выберите пункт (0-3): ")

		input, err := reader.ReadString('\n')
		if err != nil {
			break
		}

		choice, err := strconv.Atoi(strings.TrimSpace(input))
		if err != nil {
			fmt.Println("❌ Ошибка: введите цифру от 0 до 3, а не текст!")
			continue
		}

		switch choice {
		case 1:
			fmt.Println("👋 Привет, разработчик! Отличного дня.")
		case 2:
			fmt.Printf("⏰ Время на сервере: %s\n", time.Now().Format("15:04:05 (MST)"))
		case 3:
			fmt.Print("\033[H\033[2J") // ANSI код очистки экрана
			fmt.Println("✔ Экран очищен.")
		case 0:
			fmt.Println("🛑 Завершение работы. До свидания!")
			return
		default:
			fmt.Printf("⚠️ Пункт %d отсутствует. Выберите от 0 до 3.\n", choice)
		}
	}
}

Реализация интерфейса fmt.Stringer для доменных структур

📌 Условие задачи

Реализуй Stringer интерфейс для структуры Book (Title, Author, Year). Переопредели метод String() string. Проверь, что fmt.Println(book) использует твой метод.

💡 Теоретический фундамент и концепция

Интерфейс fmt.Stringer:

Один из важнейших интерфейсов стандартной библиотеки:

`go

type Stringer interface {

String() string

}

`

Если структура реализует метод String() string, функции fmt.Println, fmt.Printf("%v") и fmt.Sprintf вызывают именно этот метод вместо стандартного рефлексивного вывода полей!

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем структуру Book с полями Title, Author, Year.
2. Реализуем метод func (b Book) String() string.
3. Передаем структуру в fmt.Println(book).
📄 main.go 
package main

import "fmt"

type Book struct {
	Title  string
	Author string
	Year   int
}

// Реализация интерфейса fmt.Stringer
func (b Book) String() string {
	return fmt.Sprintf("📖 «%s» — %s (%d г.)", b.Title, b.Author, b.Year)
}

func main() {
	book := Book{
		Title:  "Язык программирования Go",
		Author: "Алан Донован, Брайан Керниган",
		Year:   2016,
	}

	// fmt.Println автоматически вызывает метод String()
	fmt.Println(book)

	// fmt.Sprintf также использует String()
	info := fmt.Sprintf("Книга в каталоге: %s", book)
	fmt.Println(info)
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

При форматировании рантайм Go выполняет проверку утверждения типа (Type Assertion): if s, ok := p.(Stringer); ok { s.String() }.

⚠️ Частые грабли и ошибки новичков
  • Бесконечная рекурсия: если внутри метода String() вызвать fmt.Sprintf("%v", b) (передав ту же структуру b), функция вызовет сама себя и упадет с паникой runtime: goroutine stack exceeds limit.

Вопрос с собеседования: «Почему метод String() рекомендуется реализовывать на value-ресивере (b Book), а не на pointer-ресивере (b *Book)?»

Ответ: Если метод объявлен на pointer-ресивере (b *Book) String(), он сработает только при передаче указателя fmt.Println(&book). Упражнение #53

Интерфейс fmt.GoStringer и спецификатор %#v

📌 Условие задачи

Реализуй GoStringer интерфейс (GoString() string) для той же структуры. Проверь разницу между %v и %#v.

💡 Теоретический фундамент и концепция

Интерфейс fmt.GoStringer:

`go

type GoStringer interface {

GoString() string

}

`

  • Метод String() string вызывается при %v, %s и fmt.Println;
  • Метод GoString() string вызывается строго при спецификаторе %#v;
  • Позволяет генерировать точный Go-код для сериализации объектов или отладки.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем структуру Money (сумма и валюта).
2. Реализуем String() string (для пользователей) и GoString() string (для разработчиков).
3. Сравниваем вывод %v и %#v.
📄 main.go 
package main

import "fmt"

type Money struct {
	AmountCents int64
	Currency    string
}

// Для пользовательского интерфейса (%v, Println)
func (m Money) String() string {
	return fmt.Sprintf("%.2f %s", float64(m.AmountCents)/100.0, m.Currency)
}

// Для отладки и Go-кода (%#v)
func (m Money) GoString() string {
	return fmt.Sprintf("finance.Money{AmountCents: %d, Currency: %q}", m.AmountCents, m.Currency)
}

func main() {
	price := Money{AmountCents: 154990, Currency: "RUB"}

	fmt.Printf("Пользовательский вид (%%v):  %v\n", price)
	fmt.Printf("Отладочный вид (%%#v):         %#v\n", price)
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

При обработке флага # форматировщик сначала проверяет интерфейс fmt.GoStringer. Если он реализован, рефлексивный парсер не запускается.

⚠️ Частые грабли и ошибки новичков
  • Путаница между String() и GoString(): не помещайте в String() внутренние технические детали, а в GoString() — пользовательские тексты.

Вопрос с собеседования: «Зачем нужен fmt.GoStringer, если есть стандартный %#v?»

Ответ: Стандартный %#v выводит все приватные поля структуры как есть. GoString() позволяет скрыть чувствительные данные (хэши, пароли) или преобразовать внутреннее представление (например, миллисекунды в читаемый time.Duration) в валидный Go-синтаксис.

Срез os.Args []string:

1. os.Args[0] — путь или имя исполняемого файла;
2. os.Args[1:] — срез параметров командной строки, переданных пользователем;

Итоговое сопоставление семейства функций fmt.Scan*:

1. fmt.Scan: игнорирует переносы строк, читает токены до первого пробельного разделителя, ждет ввода недостающих аргументов на следующих строках;
2. fmt.Scanln: читает аргументы только с текущей строки, строго завершается по \n;
3. fmt.Scanf: сопоставляет вход строго с шаблоном форматирования, включая литеральные разделители.

	var score float64

}

Потоковый Unicode-сканер через bufio.Reader.ReadRune

📌 Условие задачи

💡 Теоретический фундамент и концепция

Метод ReadRune():

  • Автоматически декодирует UTF-8 поток;
  • При ошибке декодирования (битый байт) возвращает руну utf8.RuneError (\uFFFD) и размер 1 байт.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем ридер над os.Stdin.
2. В цикле считываем руны до переноса строки.

📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"unicode/utf8"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Print("Введите текст: ")

	for {
		r, size, err := reader.ReadRune()
		if err != nil {
			break
		}
		if r == '\n' {
			break
		}

		if r == utf8.RuneError && size == 1 {
			fmt.Println("⚠️ Обнаружен поврежденный байт UTF-8!")
			continue
		}

		fmt.Printf("Руна: %c (код: %d)\n", r, r)
	}
}

Парсинг математического выражения:

3. Валидация поддерживаемых операторов.

🔍 Пошаговый ход решения и ход мысли инженера

1. Запрашиваем выражение.

package main

func main() {
	var (
		a, b float64
		op   string
	)

	fmt.Print("Введите математическое выражение (например, 10.5 * 2): ")
	n, err := fmt.Scanf("%f %s %f\n", &a, &op, &b)

	if err != nil || n != 3 {
		fmt.Printf("❌ Ошибка разбора выражения: %v\n", err)
		return
	}

	var result float64

	switch op {
	case "+":
		result = a + b
	case "-":
		result = a - b
	case "*":
		result = a * b
	case "/":
		if b == 0 {
			fmt.Println("❌ Ошибка: деление на ноль невозможно!")
			return
		}
		result = a / b
	default:
		fmt.Printf("❌ Неизвестный оператор '%s'. Поддерживаются: +, -, *, /\n", op)
		return
	}

	fmt.Printf("✔ Результат: %.2f %s %.2f = %.2f\n", a, op, b, result)
}

Архитектура консольного REPL:

1. Лексер: считывание строки через bufio.Reader и разделение на команду и аргументы (strings.SplitN);
2. Роутер команд: мапа или switch обработчиков;

package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	store := make(map[string]string)

	fmt.Println("🚀 Go REPL Shell v1.0 (введите 'help' для справки)")

	for {
		fmt.Print("repl> ")
		line, err := reader.ReadString('\n')
		if err != nil {
			break
		}

		input := strings.TrimSpace(line)
		if input == "" {
			continue
		}

		parts := strings.SplitN(input, " ", 3)
		command := strings.ToLower(parts[0])

		switch command {
		case "exit", "quit":
			fmt.Println("👋 Завершение сессии REPL.")
			return
		case "help":
			fmt.Println("Доступные команды:")
			fmt.Println("  set <ключ> <значение> - сохранить значение")
			fmt.Println("  get <ключ>            - получить значение")
			fmt.Println("  print <текст>         - напечатать строку")
			fmt.Println("  keys                  - список всех ключей")
			fmt.Println("  exit                  - выйти")
		case "set":
			if len(parts) < 3 {
				fmt.Println("❌ Ошибка синтаксиса: используйте 'set <ключ> <значение>'")
				continue
			}
			store[parts[1]] = parts[2]
			fmt.Printf("✔ Ключ '%s' успешно сохранен.\n", parts[1])
		case "get":
			if len(parts) < 2 {
				fmt.Println("❌ Ошибка: укажите ключ 'get <ключ>'")
				continue
			}
			if val, ok := store[parts[1]]; ok {
				fmt.Printf("=> %s\n", val)
			} else {
				fmt.Printf("⚠️ Ключ '%s' не найден.\n", parts[1])
			}
		case "print":
			if len(parts) < 2 {
				fmt.Println()
				continue
			}
			text := strings.TrimPrefix(input, parts[0]+" ")
			fmt.Println(text)
		case "keys":
			fmt.Printf("Всего ключей в памяти: %d\n", len(store))
			for k, v := range store {
				fmt.Printf("  • %s = %s\n", k, v)
			}
		default:
			fmt.Printf("❌ Неизвестная команда '%s'. Введите 'help'.\n", command)
		}
	}
}

Упражнение #62

Потоковое суммирование чисел из Stdin до EOF через ScanWords

📌 Условие задачи

Напиши программу, которая читает числа из stdin до EOF (Ctrl+D / Ctrl+Z). Суммируй все числа и выведи результат. Используй bufio.Scanner с разбиением по словам.

💡 Теоретический фундамент и концепция

Кастомный сплиттер scanner.Split(bufio.ScanWords):

По умолчанию bufio.Scanner читает строки (ScanLines).

Если переключить сплиттер на bufio.ScanWords:

1. Сканер будет возвращать слова/числа, разделенные любыми пробелами или переводами строк;
2. Это позволяет читать поток из тысяч чисел независимо от того, как они отформатированы.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем scanner := bufio.NewScanner(os.Stdin).
2. Устанавливаем scanner.Split(bufio.ScanWords).
3. В цикле суммируем числа через strconv.ParseFloat.
4. При EOF выводим сумму, количество и среднее.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
)

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	// Переключаем сканер в режим чтения слов
	scanner.Split(bufio.ScanWords)

	fmt.Println("Введите поток чисел через пробел или Enter (завершение — Ctrl+D):")

	var total float64
	count := 0

	for scanner.Scan() {
		token := scanner.Text()
		val, err := strconv.ParseFloat(token, 64)
		if err != nil {
			fmt.Printf("⚠️ Пропуск нечислового токена: '%s'\n", token)
			continue
		}

		total += val
		count++
	}

	if err := scanner.Err(); err != nil {
		fmt.Printf("Ошибка сканера: %v\n", err)
		return
	}

	fmt.Println("\n========================================")
	fmt.Printf("Обработано чисел: %d\n", count)
	fmt.Printf("Сумма:            %.2f\n", total)
	if count > 0 {
		fmt.Printf("Среднее:          %.2f\n", total/float64(count))
	}
	fmt.Println("========================================")
}

  • Внешний цикл по строкам от 1 до 10;
  • Внутренний цикл по столбцам от 1 до 10;

	}

Динамический консольный прогресс-бар через возврат каретки (\r)

📌 Условие задачи

💡 Теоретический фундамент и концепция

Механика динамического Progress Bar:

1. Символ \r (Carriage Return) возвращает курсор в начало строки;
2. Общая длина шкалы фиксирована (например, 20 символов);
3. Количество заполненных символов # пропорционально проценту выполнения;
4. Оставшиеся ячейки заполняются дефисами -.

🔍 Пошаговый ход решения и ход мысли инженера

1. В цикле от 0 до 100% рассчитываем доли заполнения.
2. Формируем строку [#####-----] 50%.
3. Печатаем через fmt.Printf("\r...") с задержкой time.Sleep.
4. В конце выводим fmt.Println().
📄 main.go 
package main

import (
	"fmt"
	"strings"
	"time"
)

func renderProgressBar(percent int, width int) {
	filled := (percent * width) / 100
	empty := width - filled

	bar := strings.Repeat("█", filled) + strings.Repeat("░", empty)
	fmt.Printf("\r🚀 Загрузка: [%s] %3d%%", bar, percent)
}

func main() {
	totalSteps := 100
	barWidth := 25

	fmt.Println("Старт процесса деплоя артефакта...")

	for i := 0; i <= totalSteps; i++ {
		renderProgressBar(i, barWidth)
		time.Sleep(30 * time.Millisecond)
	}

	fmt.Println("\n✔ Деплой успешно завершен на 100%!")
}

Упражнение #65

Цветной и стилизованный консольный вывод через ANSI Escape Codes

📌 Условие задачи

Создай цветной вывод в консоль без внешних пакетов, используя ANSI escape-коды (\033[31m — красный, \033[0m — сброс). Напиши функции Red(), Green(), Yellow() для обёртки строк.

💡 Теоретический фундамент и концепция

ANSI Escape Sequences (Управляющие коды терминала):

Формат: \033[<КОД>m (где \033 или \x1b — символ ESC):

  • \033[0m — полный сброс стилей (Reset);
  • \033[1m — жирный шрифт (Bold);
  • \033[31m — красный текст (Red);
  • \033[32m — зеленый текст (Green);
  • \033[33m — желтый текст (Yellow);
  • \033[36m — цвет Go Cyan;
  • \033[41m — красный фон (Background).

🔍 Пошаговый ход решения и ход мысли инженера

1. Задаем константы ANSI-кодов.
2. Создаем хелперы Red(s), Green(s), Yellow(s), Cyan(s).
3. Выводим цветные структурированные логи.
📄 main.go 
package main

import "fmt"

const (
	ColorReset  = "\033[0m"
	ColorRed    = "\033[31m"
	ColorGreen  = "\033[32m"
	ColorYellow = "\033[33m"
	ColorCyan   = "\033[36m"
	ColorBold   = "\033[1m"
)

func Red(s string) string    { return ColorRed + s + ColorReset }
func Green(s string) string  { return ColorGreen + s + ColorReset }
func Yellow(s string) string { return ColorYellow + s + ColorReset }
func Cyan(s string) string   { return ColorCyan + s + ColorReset }
func Bold(s string) string   { return ColorBold + s + ColorReset }

func main() {
	fmt.Println(Bold("=== СИСТЕМА МОНИТОРИНГА KUBERNETES ==="))

	fmt.Printf("[%s] %s: Все поды запущены (%s)\n", Green("SUCCESS"), Cyan("auth-service"), Green("Ready: 3/3"))
	fmt.Printf("[%s] %s: Превышен порог памяти (%s)\n", Yellow("WARNING"), Cyan("payment-gate"), Yellow("88% RAM"))
	fmt.Printf("[%s] %s: База данных недоступна! (%s)\n", Red("CRITICAL"), Cyan("billing-api"), Red("Connection Refused"))
}
