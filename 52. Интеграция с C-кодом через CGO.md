# Интеграция с C-кодом через CGO

В этом файле собраны уникальные упражнения по теме **"Интеграция с C-кодом через CGO"**, отсортированные по возрастанию сложности.

---

1. **Первый вызов C-функции.**: Напишите простую C-функцию в комментарии `import "C"` (например, `int add(int a, int b)`), вызовите её из Go. Скомпилируйте и запустите.

2. **Передача и возврат сложных типов.**: Объявите C-структуру `Point { double x; double y; }`, создайте её в Go, передайте в C-функцию, которая вычисляет расстояние от начала координат, и верните результат.

3. **Передача строк и работа с памятью.**: Передайте Go-строку в C-функцию, ожидающую `const char*`. Используйте `C.CString`, не забудьте освободить память через `C.free`. Покажите утечку, если забыть освободить.

4. **Первый CGO**: Напиши в файле комментарий `/* #include <stdlib.h> */` строго перед строкой `import "C"`. Вызови функцию `C.random()` (или `C.rand()`). Убедись, что программа компилируется и работает.

5. Напиши простейшую CGO-программу. В импорте `/* #include <stdio.h> */ import "C"` вызови `C.puts(C.CString("Hello from C"))`. Собери и запусти.

6. Напишите минимальную программу с `cgo`: вызовите `C.printf` из Go. Объясните магию комментария `// #cgo` и `// #include`. Покажите сгенерированный `_cgo_.go` через `go tool cgo` и найдите функцию-прокси.

7. **Простейший inline C-вызов**: Напишите программу, которая использует механизм CGO. Внедрите простую C-функцию `sum` прямо в псевдо-комментарий перед ключевой строкой `import "C"`:
    ```c
    // int sum(int a, int b) { return a + b; }
    import "C"
    ```
    Вызовите эту функцию из вашего Go-кода как `C.sum(5, 10)` и выведите результат.

8. **Обратный вызов: передача Go-функции в C.**: Экспортируйте Go-функцию с сигнатурой `//export GoCallback`, передайте её в C как callback (через `unsafe.Pointer` или `C.function_pointer`), вызовите из C обратно в Go. Обратите внимание на ограничения (нельзя блокировать горутину надолго).

9. **[Накладные расходы (Overhead)]**: Напиши бенчмарк: вызов пустой Go-функции в цикле vs вызов пустой C-функции в цикле. Оцени разницу во времени (CGO требует переключения стека и планировщика, ~50-100 наносекунд на вызов).

10. Напишите C-функцию, которая принимает `int`, `double`, `char*` и возвращает `int`. Создайте Go-обёртки для каждого типа. Объясните правила конвертации: `C.int` vs `int`, `C.CString` и необходимость `C.free` для избежания утечек.

11. **Hello CGO**: Напишите простейшую программу с `import "C"` и вызовом `C.puts()`. Соберите через `go build`.

12. **Go String -> C String (Утечки памяти!)**: Тебе нужно передать Go-строку в C-функцию `puts`. Передай её через `C.CString(goStr)`. Пойми, что `C.CString` выделяет память через `malloc` в куче C, которую Go GC не видит! Обязательно добавь `defer C.free(unsafe.Pointer(cStr))` (потребуется импорт `stdlib.h`).

13. **C preamble**: Используйте C-комментарий перед `import "C"` для включения C-кода: `// #include <stdio.h>\nimport "C"`.

14. Реализуйте «калькулятор» на C с простыми операциями. Соберите как **static library** (`.a`) и слинкуйте через `#cgo LDFLAGS`. Объясните разницу между static и dynamic linking в контексте самодостаточного Go-бинарника.

15. **C String -> Go String**: Напиши в C-комментарии функцию, возвращающую строку `char*` (например, `"Hello from C"`). В Go вызови её и конвертируй результат в нормальную Go-строку с помощью `C.GoString()`. (Эта операция физически копирует байты из C-памяти в Go-память).

16. **Примитивные типы**: Передайте `int`, `float64` в C-функцию и получите результат обратно. Изучите маппинг типов (Go `int` ≠ C `int`).

17. **Накладные расходы cgo.**: Напишите бенчмарк, сравнивающий вызов C-функции с пустой Go-функцией. Измерьте накладные расходы на переход между мирами. Сравните с чисто C-программой.

18. **Управление памятью в CGO**: Напишите вызов стандартной функции `strlen` из библиотеки `string.h` Си.
    * Передайте строку Go в Си-код с помощью вспомогательной функции `C.CString(str)`.
    * Объясните в комментариях, почему эта функция выделяет память под строку в неуправляемой куче Си (вне видимости сборщика мусора Go).
    * Обязательно освободите выделенную память сразу после использования функции с помощью `C.free(unsafe.Pointer(cStr))`, подключив библиотеку `<stdlib.h>`.

19. **Строки**: Преобразуйте Go `string` в C `*C.char` через `C.CString()`. **Важно:** освободите память через `C.free()` (используйте `defer`).

20. Напишите микробенчмарк на накладные расходы `cgo`: вызов пустой C-функции в цикле 1 млн раз. Сравните с вызовом пустой Go-функции. Объясните, откуда берутся ~100–200 ns (переключение стеков, `runtime·entersyscall`, `pthread` locks, проверки `cgocheck`).

21. **Слайсы и массивы**: Передайте Go `[]int` в C-функцию, которая модифицирует массив. Используйте `&slice[0]` для получения указателя.

22. **Передача Go-указателя в Си**: В Go создай структуру `Data`. Передай указатель на неё в C-функцию. *Важно:* CGO запрещает C-коду сохранять указатели на память Go после завершения функции (потому что Go GC может их переместить). Нарушь это правило и получи панику от `cgo pointer checking`.

23. **[Передача слайсов]**: Передай слайс `[]int` в C-функцию, которая меняет его значения. Используй `(*C.int)(unsafe.Pointer(&slice[0]))` и длину. Убедись, что изменения видны в Go (zero-copy).

24. **Структуры**: Создайте C-структуру в preamble, используйте её из Go. Изучите alignment и padding differences.

25. **Многопоточность и CGO.**: Запустите несколько горутин, вызывающих C-функцию. Используйте `runtime.LockOSThread()` для привязки горутины к потоку, если это необходимо. Обсудите проблему планировщика Go и потоков ОС при cgo-вызовах.

26. **Callback функции**: Передайте Go-функцию как callback в C (через `//export`). Изучите ограничения (нельзя захватывать переменные из окружения).

27. Создайте C-структуру с вложенными массивами и указателями. Передайте её в Go через `cgo`. Объясните, как Go видит C-структуры (padding, alignment) и почему `unsafe` для доступа к полям не нужен, но `reflect` может понадобиться для сложных layout.

28. **Cgo types**: Изучите специальные типы: `C.int`, `C.char`, `C.void`, `C.size_t`. Почему они нужны?

29. **Ограничения на передачу указателей (Pointer Rules)**: Напишите в комментариях правила передачи Go-указателей в Си-код. Объясните, почему падает программа, если вы пытаетесь передать в Си-код указатель на Go-память, которая внутри себя содержит другие указатели на Go-память (механизм CGO pointer check на лету отслеживает такие ситуации для предотвращения багов при работе сборщика мусора).

30. **CGO.Handle (Безопасная передача)**: Реши проблему из 659 с помощью пакета `runtime/cgo`. Создай `handle := cgo.NewHandle(myGoStruct)`. Передай этот `handle` (он является `uintptr`) в C. Внутри C вызови Go-функцию, передав ей handle обратно, и восстанови структуру через `handle.Value()`. Не забудь `handle.Delete()`.

31. **[Go вызывается из C (Callbacks)]**: Напиши C-функцию `void do_work(void (*cb)(int))`. В Go создай функцию `export MyCallback`. Передай её в C-функцию. (Это требует экспорта Go-функции в C через `//export`).

32. **Error handling**: Обработайте ошибки из C-кода через `errno`. Используйте `C.ferror()`, `C.strerror()`.

33. Напишите функцию на C, которая аллоцирует память (`malloc`) и возвращает указатель. Go-код должен использовать эту память, затем явно освободить через `C.free`. Объясните, почему Go GC не управляет C-памятью, и как `C.CBytes`/`C.CString` создают копии, чтобы избежать проблем.

34. **Memory management**: Создайте C-функцию, которая аллоцирует память через `malloc`. Освободите её из Go через `C.free()`.

35. **Безопасность данных при передаче указателей.**: Покажите ошибку: передайте указатель на Go-переменную в C, сохраните его там глобально, а в Go освободите память (например, выйдите из функции). Позже C попытается обратиться по висячему указателю. Обсудите правила `cgo` о передаче указателей в C.

36. **Global variables**: Доступ к C global variables из Go через `C.variable_name`.

37. Реализуйте передачу Go-слайса в C **без копирования**: используйте `&slice[0]` и C-функцию, принимающую `*C.int` и `len`. Объясните, почему нужно держать слайс **pinned** (не давать GC переместить underlying array) и как `runtime.KeepAlive` помогает.

38. **Calling external C library**: Подключите внешнюю C-библиотеку (например, `libcurl` или `openssl`) через `#cgo LDFLAGS: -lcurl`.

39. **[Каверзный кейс — Блокировка горутин]**: Вызови долгую C-функцию (например, `sleep(5)`). Во время её выполнения запусти другую горутину в Go. Убедись, что поток ОС (M) заблокирован в C-коде. Посмотри через `runtime.NumGoroutine()` и `GOMAXPROCS`, как планировщик создает новый поток, чтобы не остановить работу Go-программы.

40. **Экспорт Go-функций в Си**: Напиши функцию на Go `func MyGoLogger(msg *C.char)`. Напиши над ней комментарий `//export MyGoLogger`. Теперь эта функция доступна для вызова прямо из C-кода! Вызови её из Сишного комментария.

41. **Накладные расходы CGO (Benchmarks)**: Напишите тест производительности (benchmark), замеряющий:
    * Скорость вызова пустой функции, написанной на Go.
    * Скорость вызова пустой функции, написанной на C через CGO.
    Проанализируйте результаты. Объясните причину накладных расходов CGO (смена контекста планировщика, сохранение регистров, переход стека g-to-m, отключение инлайнинга).

42. **Custom CFLAGS**: Настройте compiler flags через `#cgo CFLAGS: -O3 -Wall`.

43. Создайте Go-структуру с полем `*C.char`, указывающим на C-строку. Напишите функцию, которая корректно копирует данные в `string` через `C.GoString` и освобождает C-память. Объясните разницу между `C.GoString` (копирует) и прямым использованием C-указателя (zero-copy, но опасно).

44. **pkg-config**: Используйте `#cgo pkg-config: libname` для автоматического получения флагов компиляции.

45. **Static linking**: Соберите статически линкованный бинарник через `CGO_LDFLAGS="-static"`.

46. **Накладные расходы CGO (Бенчмарк)**: Напиши пустую функцию на Go и пустую функцию на C. Напиши бенчмарк для обеих. Убедись, что вызов C-функции (Context Switch, настройка стеков) занимает ~50-100 наносекунд, что в десятки раз медленнее вызова обычной Go-функции. Вывод: *не вызывай CGO в горячих циклах!*

47. **[C-структуры в Go]**: Опиши C-структуру в заголовочном файле. Создай её в Go, заполни поля и передай в C-функцию. Обрати внимание на правила CGO: нельзя передавать указатели на Go-память, содержащие другие указатели на Go-память, в C-код, если C-код их сохраняет.

48. **Cross-compilation с CGO**: Попробуйте cross-compile CGO код (это сложно!). Используйте Docker или cross-compiler toolchains.

49. Напишите программу с `cgo`, которая создаёт C-thread (`pthread_create`) из Go. Объясните, почему это опасно: C-thread не знает о Go-scheduler, а Go-signal handler может конфликтовать. Покажите использование `runtime.LockOSThread` для goroutine, работающей с C-thread.

50. **C++ interop**: Вызовите C++ код из Go через `extern "C"` wrapper функции.

51. **Использование директив `#cgo`**: Напишите программу, которая линкуется с системной библиотекой (например, математической библиотекой `libm` в Unix). Используйте директивы компилятора в псевдо-комментариях для настройки флагов компиляции и линковки:
    ```go
    // #cgo LDFLAGS: -lm
    // #include <math.h>
    import "C"
    ```
    Вызовите функцию `C.sqrt(...)` из вашего Go-кода.

52. **Go callbacks в C**: Создайте C-библиотеку, которая вызывает Go-функции для event handling. Используйте `//export` и `CgoHandle` для передачи контекста.

53. **C-структуры и Union в Go**: Опиши в C `union Data { int i; float f; }`. Импортируй её в Go. Go не поддерживает юнионы, поэтому он представит её как массив байт `[4]byte`. Используй `encoding/binary` или `unsafe` для записи и чтения нужного поля.

54. **[Статическая линковка C-библиотеки]**: Скомпилируй простую C-библиотеку в `.a` файл. Напиши CGO-код, который линкует её локально (через `#cgo LDFLAGS: -L./lib -lmylib`). Собери Go-бинарник.

55. Реализуйте **callback** (обратный вызов): C-функция принимает function pointer, Go передаёт `cgo`-экспортированную функцию (`//export`). Объясните механизм: Go создаёт C-функцию-обёртку (`crosscall2`), переключение стеков, и почему callback — самый дорогой путь в `cgo`.

56. **Thread safety**: Изучите, как CGO взаимодействует с горутинами. Каждый CGO вызов может блокировать OS thread. Используйте `runtime.LockOSThread()` при необходимости.

57. **Cgo overhead**: Напишите бенчмарк, сравнивающий pure Go функцию vs CGO wrapper. Измерьте overhead (~100-1000ns на вызов).

58. Создайте программу, демонстрирующую `CgoCheck`: попытайтесь передать Go-указатель, содержащий внутри себя указатели, в C-функцию. Объясните, почему рантайм паникует (C не может следить за moving GC), и как обойти через `C.CBytes` (глубокое копирование в unmanaged память).

59. **Batching CGO calls**: Вместо 1000 мелких CGO вызовов, сделайте один вызов, который обрабатывает batch данных.

60. **Ручное управление памятью в Go**: Откажись от Garbage Collector'а. Вызови `ptr := C.malloc(1024 * 1024)` (1 МБ). Оберни его в слайс `unsafe.Slice((*byte)(ptr), 1024*1024)`. Работай с ним как с обычным срезом. В конце не забудь `C.free(ptr)`. Это супер-трюк для кэшей, которые не должны напрягать Go GC.

61. **Avoiding string copies**: Используйте `C.CBytes()` для передачи `[]byte` без конверсии в string.

62. **Обратные вызовы (Callbacks) из C в Go**: Напишите программу, в которой Си-функция принимает указатель на функцию в качестве аргумента (коллбэк). Экспортируйте вашу Go-функцию в пространство имен Си, добавив специальный комментарий `//export MyGoCallback` над её объявлением. Передайте адрес этой экспортированной функции в Си-код.

63. **Custom allocators в C**: Реализуйте C-функцию с custom allocator, вызывайте её из Go для снижения GC pressure.

64. Напишите wrapper для небольшой C++ библиотеки (простой класс) через `extern "C"` интерфейс. Соберите с помощью `g++` и `#cgo LDFLAGS`. Объясните, почему `cgo` напрямую не поддерживает C++ (name mangling, exceptions, ABI).

В Go-коде используй директивы `#cgo CFLAGS: -I.` и `#cgo LDFLAGS: -L. -lmath`, чтобы слинковать свою кастомную C-библиотеку прямо в Go-бинарник.
