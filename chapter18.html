Упражнение #1

Чтение файла целиком в память через os.ReadFile

📌 Условие задачи

Прочитайте файл целиком в строку через os.ReadFile (1.16+).

💡 Теоретический фундамент и концепция

Функция os.ReadFile(filename) (Go 1.16+) — стандартный и наиболее эффективный способ прочитать файл небольшого или среднего размера за один системный вызов. Она самостоятельно открывает файл, читает его содержимое в слайс байт []byte и гарантированно закрывает файловый дескриптор даже при возникновении ошибок.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим тестовый файл example.txt с помощью os.WriteFile.
2. Вызовем data, err := os.ReadFile("example.txt").
3. Преобразуем []byte в строку string(data) и выведем в терминал.
4. В main убедимся в корректной обработке ошибок err != nil.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	// Подготовка тестового файла
	filename := "example.txt"
	content := "Go 1.22 File I/O Engine\nHighLoad Architecture"
	if err := os.WriteFile(filename, []byte(content), 0644); err != nil {
		log.Fatalf("Ошибка создания файла: %v", err)
	}

	// Чтение файла целиком
	data, err := os.ReadFile(filename)
	if err != nil {
		log.Fatalf("Ошибка чтения файла: %v", err)
	}

	fmt.Println("--- Содержимое файла ---")
	fmt.Println(string(data))
}
📄 Терминал 
go run main.go
# Вывод:
# --- Содержимое файла ---
# Go 1.22 File I/O Engine
# HighLoad Architecture
⚙️ Под капотом Go (Compiler, Linker & Runtime)

os.ReadFile сначала запрашивает размер файла через stat системный вызов, предвыделяет буфер make([]byte, 0, size+1) и читает данные через syscall read, избегая многократных реаллокаций памяти.

⚠️ Частые грабли и ошибки новичков

Не используйте os.ReadFile для гигантских файлов (логи на 10GB, дампы БД) — это приведет к исчерпанию памяти (OOM Kill). Для больших файлов применяйте потоковое чтение bufio.Reader или io.Copy.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему ioutil.ReadFile объявлен deprecated в Go 1.16+?»

Ответ: Пакет io/ioutil был признан избыточным и плохо структурированным. Все его функции были перенесены в целевые пакеты: os.ReadFile, os.WriteFile, os.CreateTemp в пакет os, а io.ReadAll, io.Discard — в пакет io.

Упражнение #2

Дозапись данных в файл через os.OpenFile и флаги O_APPEND|O_CREATE|O_WRONLY

📌 Условие задачи

Откройте файл на дозапись с помощью os.OpenFile и флагов O_APPEND|O_CREATE|O_WRONLY, допишите несколько строк.

💡 Теоретический фундамент и концепция

Функция os.OpenFile(name, flag, perm) предоставляет полный контроль над режимами открытия файла через побитовое объединение флагов POSIX:

  • os.O_WRONLY: открытие только для записи.
  • os.O_CREATE: создание файла, если он не существует.
  • os.O_APPEND: автоматическое перемещение указателя записи в самый конец файла перед каждой операцией записи.

🔍 Пошаговый ход решения и ход мысли инженера

1. Откроем файл app.log с флагами os.O_APPEND|os.O_CREATE|os.O_WRONLY и правами 0644.
2. Обязательно добавим defer file.Close().
3. Запишем строку с таймстемпом через file.WriteString.
4. В main проверим, что повторный запуск дописывает строки в конец.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
	"time"
)

func appendLog(filename, message string) error {
	file, err := os.OpenFile(filename, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
	if err != nil {
		return fmt.Errorf("ошибка открытия файла: %w", err)
	}
	defer file.Close()

	logLine := fmt.Sprintf("[%s] %s\n", time.Now().Format("2006-01-02 15:04:05"), message)
	if _, err := file.WriteString(logLine); err != nil {
		return fmt.Errorf("ошибка записи в лог: %w", err)
	}
	return nil
}

func main() {
	logFile := "audit.log"
	_ = appendLog(logFile, "Service started: port 8080")
	_ = appendLog(logFile, "Database connected successfully")

	data, err := os.ReadFile(logFile)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("--- Audit Log ---")
	fmt.Print(string(data))
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

Флаг O_APPEND на уровне ядра ОС (Linux/Unix) гарантирует атомарность перемещения курсора в конец файла перед системным вызовом write, что защищает от перезаписи логов при параллельной записи несколькими процессами.

⚠️ Частые грабли и ошибки новичков

Если забыть флаг os.O_CREATE, при отсутствии файла os.OpenFile вернет ошибку no such file or directory.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Безопасен ли O_APPEND при одновременной записи в файл из нескольких процессов?»

Ответ: В POSIX-совместимых ОС системный вызов write с флагом O_APPEND является атомарным для блоков данных до PIPE_BUF (обычно 4096 байт). Ядро ОС гарантирует, что курсор сместится в конец и данные запишутся без перезаписи соседних строк.

Упражнение #3

Построчное чтение файла через bufio.Scanner и defer file.Close

📌 Условие задачи

Откройте файл с помощью os.Open, прочитайте его построчно, используя bufio.Scanner, и обязательно закройте файл через defer.

💡 Теоретический фундамент и концепция

bufio.Scanner читает поток данных небольшими порциями в кольцевой буфер фиксированного размера (по умолчанию 64KB), разделяя данные по символу перевода строки \n. Это позволяет обрабатывать терабайтные файлы с константным потреблением оперативной памяти $O(1)$.

🔍 Пошаговый ход решения и ход мысли инженера

1. Откроем файл os.Open("data.txt").
2. Проверим ошибку открытия if err != nil.
3. Установим defer file.Close().
4. Инициализируем scanner := bufio.NewScanner(file).
5. В цикле for scanner.Scan() прочитаем строки и выведем их с номерами.
6. Проверим ошибку сканера if err := scanner.Err(); err != nil.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"log"

Упражнение #4

Запись и чтение бинарных последовательностей int32

📌 Условие задачи

Сформируйте бинарный файл из последовательности int32 и прочитайте их обратно в слайс.

💡 Теоретический фундамент и концепция

Бинарный формат сохраняет числа в памяти точно в их машинном представлении (по 4 байта на каждое int32), исключая текстовое форматирование и парсинг, что ускоряет чтение и запись в 10–50 раз.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим срез numbers := []int32{100, 2500, -42, 999999}.
2. Запишем их в бинарный файл numbers.bin через encoding/binary.Write с порядком binary.LittleEndian.
3. Откроем файл и прочитаем данные обратно в срез readNumbers через binary.Read.
4. В main убедимся в полном совпадении данных.
📄 main.go 
package main

import (
	"encoding/binary"
	"fmt"
	"log"
	"os"
)

func main() {
	filename := "numbers.bin"
	original := []int32{100, 2500, -42, 999999}

	// 1. Бинарная запись
	file, err := os.Create(filename)
	if err != nil {
		log.Fatal(err)
	}
	if err := binary.Write(file, binary.LittleEndian, original); err != nil {
		file.Close()
		log.Fatal(err)
	}
	file.Close()

	// 2. Бинарное чтение
	readFile, err := os.Open(filename)
	if err != nil {
		log.Fatal(err)
	}
	defer readFile.Close()

	restored := make([]int32, len(original))
	if err := binary.Read(readFile, binary.LittleEndian, &restored); err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Исходный срез:      %v\n", original)
	fmt.Printf("Восстановленный:    %v\n", restored)
	fmt.Printf("Размер на диске:    %d байт (4 числа * 4 байта)\n", len(original)*4)
}

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем разница между LittleEndian и BigEndian? Какой порядок принят в сети?»

Ответ: LittleEndian хранит младшие байты первыми (стандарт процессоров x86 и ARM). BigEndian хранит старшие байты первыми (стандарт сетевых протоколов TCP/IP, так называемый Network Byte Order).

Упражнение #5

Рекурсивный обход директории filepath.Walk и фильтрация .go файлов

📌 Условие задачи

Рекурсивно обойдите директорию (filepath.Walk), выведите только файлы с расширением .go.

💡 Теоретический фундамент и концепция

Функция filepath.Walk(root, walkFn) рекурсивно обходит файловое дерево, вызывая коллбэк WalkFunc для каждого найденного файла и каталога.

🔍 Пошаговый ход решения и ход мысли инженера

1. Зададим корневую директорию для поиска.
2. Вызовем filepath.Walk.
3. Внутри функции обратного вызова отфильтруем каталоги if info.IsDir().
4. Проверим расширение через filepath.Ext(path) == ".go".
5. Выведем путь к каждому найденному .go файлу.
📄 main.go 
package main

import (
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
)

func main() {
	// Создаем структуру для демонстрации
	_ = os.MkdirAll("demo/pkg/sub", 0755)
	_ = os.WriteFile("demo/main.go", []byte("package main"), 0644)
	_ = os.WriteFile("demo/pkg/util.go", []byte("package pkg"), 0644)
	_ = os.WriteFile("demo/pkg/sub/sub.go", []byte("package sub"), 0644)
	_ = os.WriteFile("demo/readme.md", []byte("# Docs"), 0644)

	defer os.RemoveAll("demo")

	fmt.Println("Найденные .go файлы:")
	err := filepath.Walk("demo", func(path string, info fs.FileInfo, err error) error {
		if err != nil {
			return err
		}
		// Пропускаем директории
		if info.IsDir() {
			return nil
		}
		// Проверяем расширение
		if filepath.Ext(path) == ".go" {
			fmt.Printf(" -> %s (%d байт)\n", path, info.Size())
		}
		return nil
	})

	if err != nil {
		fmt.Printf("Ошибка обхода: %v\n", err)
	}
}

#  -> demo/pkg/sub/sub.go (11 байт)

⚙️ Под капотом Go (Compiler, Linker & Runtime)

filepath.Walk вызывает os.Lstat для каждого файла в дереве каталогов. Начиная с Go 1.16 доступна более быстрая функция filepath.WalkDir, которая использует fs.DirEntry и избегает лишних вызовов stat.

⚠️ Частые грабли и ошибки новичков

Если внутри коллбэка вернуть filepath.SkipDir для директории, обходчик пропустит все файлы внутри этой папки.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему filepath.WalkDir быстрее filepath.Walk в Go 1.16+?»

Ответ: filepath.Walk на каждом шаге выполняет системный вызов os.Lstat, что на дисках с миллионами файлов создает миллионы IOPS. filepath.WalkDir берет тип файла напрямую из системного вызова getdents64 (структура DirEntry), вызывая Info() только при явном запросе.

Упражнение #6

Бинарная сериализация структур фиксированного размера

📌 Условие задачи

Запишите в файл структуру фиксированного размера через encoding/binary.Write и прочитайте обратно binary.Read.

💡 Теоретический фундамент и концепция

Для сериализации структуры через encoding/binary она обязана состоять только из типов фиксированного размера (числа, булевы флаги, массивы фиксированной длины [N]byte). Срезы []byte и строки string запрещены, так как их размер в памяти динамический.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявим структуру Header struct { Magic [4]byte; Version uint16; Checksum uint32 }.
2. Запишем экземпляр в файл через binary.Write.
3. Откроем файл и восстановим структуру через binary.Read.
4. В main распечатаем поля структуры.
📄 main.go 
package main

import (
	"encoding/binary"
	"fmt"
	"log"
	"os"
)

type Header struct {
	Magic    [4]byte // Сигнатура файла "GOPR"
	Version  uint16  // Версия формата
	Checksum uint32  // Контрольная сумма CRC32
}

func main() {
	filename := "packet.bin"

	hdr := Header{
		Magic:    [4]byte{'G', 'O', 'P', 'R'},
		Version:  2,
		Checksum: 0xDEADBEEF,
	}

	// 1. Запись
	fWrite, err := os.Create(filename)
	if err != nil {
		log.Fatal(err)
	}
	if err := binary.Write(fWrite, binary.BigEndian, hdr); err != nil {
		fWrite.Close()
		log.Fatal(err)
	}
	fWrite.Close()

	// 2. Чтение
	fRead, err := os.Open(filename)
	if err != nil {
		log.Fatal(err)
	}
	defer fRead.Close()

	var readHdr Header
	if err := binary.Read(fRead, binary.BigEndian, &readHdr); err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Восстановленный заголовок:\n")
	fmt.Printf(" -> Magic:    %s\n", string(readHdr.Magic[:]))
	fmt.Printf(" -> Version:  %d\n", readHdr.Version)
	fmt.Printf(" -> Checksum: 0x%X\n", readHdr.Checksum)
}
📄 Терминал 
go run main.go
# Вывод:
# Восстановленный заголовок:
#  -> Magic:    GOPR
#  -> Version:  2
#  -> Checksum: 0xDEADBEEF
⚙️ Под капотом Go (Compiler, Linker & Runtime)

Размер структуры в файле составляет ровно $4 + 2 + 4 = 10$ байт. Пакет encoding/binary упаковывает поля без внутреннего паддинга структуры Go в оперативной памяти.

⚠️ Частые грабли и ошибки новичков

Использование типа int (платформозависимый размер 4 или 8 байт) вызовет панику binary.Write: invalid type int. Всегда используйте строго типизированные int32, int64, uint16.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему binary.Write не поддерживает структуры с полями типа string или slice?»

Ответ: Потому что string и slice представлены в рантайме Go как структуры заголовков (StringHeader/SliceHeader), содержащие указатели на кучу. Запись указателя на диск бессмысленна, так как при следующем запуске адрес памяти будет невалиден.

Упражнение #8

Управление правами доступа к файлам через os.Chmod

📌 Условие задачи

Измените права доступа к файлу с помощью os.Chmod (например, сделать только чтение).

💡 Теоретический фундамент и концепция

Права доступа в Unix задаются в восьмеричной системе счисления (0400 — только чтение владельцем, 0644 — чтение/запись владельцем и чтение остальными, 0755 — исполняемый файл). Функция os.Chmod(name, mode) изменяет биты прав fs.FileMode.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл с правами 0644.
2. Изменим права на 0400 (Read-Only) через os.Chmod.
3. Запросим метаданные через os.Stat и выведем info.Mode().Perm().
4. Попробуем открыть на запись и убедимся в получении permission denied.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	filename := "readonly.txt"
	_ = os.WriteFile(filename, []byte("секретные константные данные"), 0644)

	// Делаем файл доступным только для чтения владельцем (0400)
	if err := os.Chmod(filename, 0400); err != nil {
		log.Fatalf("Ошибка chmod: %v", err)
	}

	info, err := os.Stat(filename)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Текущие права файла %s: %v (%04o)\n", filename, info.Mode().Perm(), info.Mode().Perm())

	// Попытка открыть файл на запись вызовет ошибку доступа
	_, errWrite := os.OpenFile(filename, os.O_WRONLY, 0)
	if errWrite != nil {
		fmt.Printf("Ожидаемый отказ записи: %v\n", errWrite)
	}
}

Упражнение #9

Идиоматичное закрытие файлов: defer file.Close() сразу после проверки err

📌 Условие задачи

Обязательно добавь defer file.Close() сразу после создания.

💡 Теоретический фундамент и концепция

Файловые дескрипторы — ограниченный ресурс операционной системы (лимит ulimit -n). Не закрытые вовремя дескрипторы приводят к утечке ресурсов (File Descriptor Leak) и падению сервиса с ошибкой too many open files.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл f, err := os.Create("temp.txt").
2. Сначала проверим if err != nil.
3. Только после успешной проверки напишем defer f.Close().
4. Запишем данные в файл.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
)

func writeSafeFile(name, payload string) error {
	file, err := os.Create(name)
	if err != nil {
		return fmt.Errorf("сбой создания файла: %w", err)
	}
	// Идиоматичный defer сразу после проверки err:
	defer file.Close()

	if _, err := file.WriteString(payload); err != nil {
		return fmt.Errorf("сбой записи: %w", err)
	}

	fmt.Printf("Файл %s успешно записан\n", name)
	return nil
}

func main() {
	if err := writeSafeFile("output.txt", "Highload Go Architecture"); err != nil {
		log.Fatal(err)
	}
}
📄 Терминал 
go run main.go
# Вывод:
# Файл output.txt успешно записан
⚙️ Под капотом Go (Compiler, Linker & Runtime)

defer гарантирует вызов file.Close() при любом исходе: успешном возврате, ошибке на промежуточном шаге или даже панике внутри функции.

⚠️ Частые грабли и ошибки новичков

Никогда не ставьте defer file.Close() ДО проверки if err != nil. Если открытие завершилось ошибкой, переменная file будет равна nil, и file.Close() запаникует с Nil Pointer Dereference.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему в цикле обработки 100 000 файлов нельзя ставить defer file.Close()?»

Ответ: defer выполняется только при выходе из окружающей функции, а не при завершении итерации цикла. В результате все 100 000 дескрипторов останутся открытыми одновременно, исчерпав лимит ОС too many open files. Решение: выносить тело цикла в отдельную функцию или закрывать файлы явно file.Close().

Упражнение #12

Потоковое копирование файлов через io.Copy и zero-copy оптимизации

📌 Условие задачи

Скопируйте содержимое одного файла в другой с использованием io.Copy.

💡 Теоретический фундамент и концепция

io.Copy(dst, src) перекачивает данные из любого io.Reader в io.Writer с фиксированным буфером (32KB). В Linux для файловых дескрипторов io.Copy может использовать системный вызов copy_file_range (Zero-Copy), передавая данные напрямую в ядре без копирования в пространство пользователя.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим исходный файл source.dat.
2. Откроем source.dat на чтение через os.Open.
3. Создадим destination.dat через os.Create.
4. Вызовем bytesCopied, err := io.Copy(destFile, srcFile).
5. В main проверим количество скопированных байт.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func copyFile(srcName, dstName string) (int64, error) {
	src, err := os.Open(srcName)
	if err != nil {
		return 0, fmt.Errorf("ошибка открытия источника: %w", err)
	}
	defer src.Close()

	dst, err := os.Create(dstName)
	if err != nil {
		return 0, fmt.Errorf("ошибка создания приемника: %w", err)
	}
	defer dst.Close()

	n, err := io.Copy(dst, src)
	if err != nil {
		return n, fmt.Errorf("сбой копирования io.Copy: %w", err)
	}

	return n, nil
}

func main() {
	_ = os.WriteFile("source.dat", []byte("High Performance Golang I/O Pipeline"), 0644)

	copied, err := copyFile("source.dat", "destination.dat")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Скопировано: %d байт\n", copied)
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

Если оба дескриптора — файлы ОС в Linux, io.Copy вызывает os.File.ReadFrom, который делегирует работу системному вызову copy_file_range(2) ядра Linux, копируя блоки на уровне файловой системы.

Не забывайте закрывать оба файла через defer.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Почему io.Copy эффективнее ручного цикла с чтением в срез make([]byte, 1024)?»

Ответ: 1) io.Copy переиспользует единый 32KB буфер из внутреннего пула памяти. 2) Он проверяет интерфейсы оптимизации io.WriterTo и io.ReaderFrom, активируя системный вызов ядра Zero-Copy (sendfile/copy_file_range).

Упражнение #16

Блочное копирование файлов через фиксированный буфер

📌 Условие задачи

Создайте программу, которая копирует содержимое одного текстового файла в другой, читая и записывая данные небольшими блоками (буферами).

💡 Теоретический фундамент и концепция

Чтение фиксированными блоками (buf := make([]byte, 1024)) позволяет копировать файлы произвольного объема с постоянным потреблением оперативной памяти.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим исходный файл source.txt.
2. Откроем файл-источник os.Open и создадим файл-приемник os.Create.
3. В цикле вызовем src.Read(buf) до получения io.EOF.
4. Запишем вычитанный кусок dst.Write(buf[:n]).
5. В main убедимся в корректности копии.
📄 main.go 
package main

import (
	"errors"
	"fmt"
	"io"
	"log"
	"os"
)

func copyBuffered(srcPath, dstPath string, chunkSize int) error {
	src, err := os.Open(srcPath)
	if err != nil {
		return err
	}
	defer src.Close()

	dst, err := os.Create(dstPath)
	if err != nil {
		return err
	}
	defer dst.Close()

	buf := make([]byte, chunkSize)
	totalBytes := 0

	for {
		n, err := src.Read(buf)
		if n > 0 {
			if _, writeErr := dst.Write(buf[:n]); writeErr != nil {
				return writeErr
			}
			totalBytes += n
		}
		if err != nil {
			if errors.Is(err, io.EOF) {
				break // Достигнут конец файла
			}
			return err
		}
	}

	fmt.Printf("Скопировано блоков порциями по %d байт. Всего: %d байт\n", chunkSize, totalBytes)
	return nil
}

func main() {
	_ = os.WriteFile("source.txt", []byte("HighLoad Architecture Block Copy"), 0644)
	if err := copyBuffered("source.txt", "dest.txt", 8); err != nil {
		log.Fatal(err)
	}
}
📄 Терминал 
go run main.go
# Вывод:
# Скопировано блоков порциями по 8 байт. Всего: 32 байт
⚙️ Под капотом Go (Compiler, Linker & Runtime)

src.Read(buf) возвращает $n > 0$ и io.EOF на последнем шаге. Важно сначала записать buf[:n], а уже затем проверять err == io.EOF.

⚠️ Частые грабли и ошибки новичков

Ошибка новичков: проверить if err == io.EOF до записи buf[:n], из-за чего последний блок данных теряется.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Может ли метод Read вернуть n > 0 и одновременно err == io.EOF?»

Ответ: Да! По контракту интерфейса io.Reader, при чтении последних байтов метод может вернуть ненулевое количество байт $n > 0$ и одновременно ошибку io.EOF. Вызывающий код обязан сначала обработать первые $n$ байт.

Конкатенация двух текстовых файлов в третий через io.Copy

Слияние файлов (Concatenation) выполняется последовательным вызовом io.Copy(merged, file1) и io.Copy(merged, file2) без загрузки обоих файлов целиком в RAM.

🔍 Пошаговый ход решения и ход мысли инженера

4. Скопируем второй файл через io.Copy.

📄 main.go 
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func mergeFiles(dst string, sources ...string) error {
	out, err := os.Create(dst)
	if err != nil {
		return err
	}
	defer out.Close()

	for _, srcPath := range sources {
		in, err := os.Open(srcPath)
		if err != nil {
			return err
		}
		_, copyErr := io.Copy(out, in)
		in.Close()
		if copyErr != nil {
			return copyErr
		}
	}
	return nil
}

func main() {
	_ = os.WriteFile("part1.txt", []byte("Section 1: Overview\n"), 0644)
	_ = os.WriteFile("part2.txt", []byte("Section 2: Architecture\n"), 0644)

	if err := mergeFiles("merged.txt", "part1.txt", "part2.txt"); err != nil {
		log.Fatal(err)
	}

	result, _ := os.ReadFile("merged.txt")
	fmt.Println("--- Merged Result ---")
	fmt.Print(string(result))
}

package main

import (
	"errors"
	"fmt"
	"os"
)

func fileExists(path string) (bool, error) {
	_, err := os.Stat(path)
	if err == nil {
		return true, nil // Файл существует
	}
	if errors.Is(err, os.ErrNotExist) || os.IsNotExist(err) {
		return false, nil // Файл гарантированно не существует
	}
	return false, err // Другая ошибка (например, нет прав доступа на родительскую папку)
}

func main() {
	_ = os.WriteFile("config.yaml", []byte("version: 1"), 0644)

	for _, name := range []string{"config.yaml", "missing.json"} {
		exists, err := fileExists(name)
		if err != nil {
			fmt.Printf("Ошибка проверки %s: %v\n", name, err)
		} else {
			fmt.Printf("Файл %-12s существует: %v\n", name, exists)
		}
	}
}

Упражнение #24

Рекурсивное копирование дерева директорий

📌 Условие задачи

Реализуйте копирование директории со всеми поддиректориями и файлами (рекурсивное создание папок и копирование содержимого).

💡 Теоретический фундамент и концепция

Рекурсивное копирование обходит дерево исходной папки с помощью filepath.WalkDir, создает зеркальную структуру каталогов через os.MkdirAll и копирует файлы через io.Copy.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим структуру src_dir/a/b/file.txt.
2. Реализуем функцию CopyDir(src, dst string) error.
3. Для каждой записи определим относительный путь через filepath.Rel(src, path).
4. Если это папка — вызываем os.MkdirAll, если файл — копируем данные.
5. В main убедимся в точном клонировании дерева.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"io/fs"
	"log"
	"os"
	"path/filepath"
)

func CopyFile(src, dst string) error {
	in, err := os.Open(src)
	if err != nil {
		return err
	}
	defer in.Close()

	out, err := os.Create(dst)
	if err != nil {
		return err
	}
	defer out.Close()

	_, err = io.Copy(out, in)
	return err
}

func CopyDir(src, dst string) error {
	return filepath.WalkDir(src, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		relPath, err := filepath.Rel(src, path)
		if err != nil {
			return err
		}
		targetPath := filepath.Join(dst, relPath)

		if d.IsDir() {
			return os.MkdirAll(targetPath, 0755)
		}
		return CopyFile(path, targetPath)
	})
}

func main() {
	_ = os.MkdirAll("source_tree/docs/sub", 0755)
	_ = os.WriteFile("source_tree/main.txt", []byte("Root file"), 0644)
	_ = os.WriteFile("source_tree/docs/sub/readme.txt", []byte("Nested doc"), 0644)

	defer os.RemoveAll("source_tree")
	defer os.RemoveAll("backup_tree")

	if err := CopyDir("source_tree", "backup_tree"); err != nil {
		log.Fatal(err)
	}

	data, _ := os.ReadFile("backup_tree/docs/sub/readme.txt")
	fmt.Printf("Успешно скопировано в бэкап: %s\n", string(data))
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

filepath.Rel вычисляет относительный путь от корня, гарантируя сохранение иерархии в целевой папке.

⚠️ Частые грабли и ошибки новичков

При копировании симлинков os.Open будет следовать по ссылке, а не копировать сам симлинк. Для копирования симлинков используют os.Readlink и os.Symlink.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как предотвратить бесконечную рекурсию при копировании директорий с циклическими симлинками?»

Ответ: Отслеживать ino (inode) каждого каталога в map[uint64]bool или использовать filepath.WalkDir с проверкой d.Type()&fs.ModeSymlink != 0 без автоматического перехода по ссылкам.

Универсальная функция ReadLines с корректной обработкой переносов строк

💡 Теоретический фундамент и концепция

bufio.ScanLines — стандартная функция разбиения для bufio.Scanner. Она автоматически корректно обрабатывает файлы, в конце которых нет завершающего символа переноса строки \n.

🔍 Пошаговый ход решения и ход мысли инженера

1. Реализуем функцию ReadLines(filename string) ([]string, error).
2. Откроем файл, установим defer f.Close().
3. Создадим сканер scanner := bufio.NewScanner(f).

📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"log"
	"os"
)

func ReadLines(filename string) ([]string, error) {
	file, err := os.Open(filename)
	if err != nil {
		return nil, fmt.Errorf("ReadLines open: %w", err)
	}
	defer file.Close()

	var lines []string
	scanner := bufio.NewScanner(file)
	scanner.Split(bufio.ScanLines)

	for scanner.Scan() {
		lines = append(lines, scanner.Text())
	}

	if err := scanner.Err(); err != nil {
		return nil, fmt.Errorf("ReadLines scan: %w", err)
	}

	return lines, nil
}

func main() {
	// Файл без \n на последней строке:
	_ = os.WriteFile("test_lines.txt", []byte("Alpha\n\nBeta\nGamma"), 0644)

	lines, err := ReadLines("test_lines.txt")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Всего строк вычитано: %d\n", len(lines))
	for i, l := range lines {
		fmt.Printf("line[%d] = %q\n", i, l)
	}
}

Упражнение #29

Высокоскоростная буферизованная запись через bufio.Writer и Flush()

📌 Условие задачи

Буферизированная запись: Для быстрой записи большого количества строк используй bufio.NewWriter. Напиши 1000 строк в файл через него и обязательно вызови Flush() в конце, чтобы сбросить буфер на диск.

💡 Теоретический фундамент и концепция

Каждый прямой системный вызов write требует дорогостоящего переключения контекста User Space $\leftrightarrow$ Kernel Space. bufio.Writer накапливает данные во внутреннем буфере (4096 байт) и выполняет один системный вызов на сотни операций записи, ускоряя запись в 50–100 раз.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл bulk.log.
2. Обернем его в writer := bufio.NewWriter(file).
3. В цикле запишем 1000 строк через writer.WriteString.
4. В конце обязательно вызовем writer.Flush().
5. Проверим размер полученного файла.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"log"
	"os"
)

func main() {
	path := "bulk.log"
	file, err := os.Create(path)
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	// Инициализация буферизованного писателя (дефолтный буфер 4KB)
	writer := bufio.NewWriter(file)

	for i := 1; i <= 1000; i++ {
		line := fmt.Sprintf("Log entry #%04d: status=OK latency_ms=1.2\n", i)
		if _, err := writer.WriteString(line); err != nil {
			log.Fatal(err)
		}
	}

	// КРИТИЧЕСКИ ВАЖНО: сброс остатка буфера в файл перед закрытием!
	if err := writer.Flush(); err != nil {
		log.Fatalf("Ошибка Flush: %v", err)
	}

	info, _ := file.Stat()
	fmt.Printf("Успешно записано 1000 строк. Итоговый размер файла: %d байт\n", info.Size())
}

bufio.Writer автоматически сбрасывает данные на диск, когда накопленный объем превышает размер буфера (4096 байт). Последняя неполная порция остается в памяти до вызова Flush().

Ответ: Потому что file.WriteString совершает 10 000 системных вызовов write(2) с переключением колец защиты CPU (Ring 3 -> Ring 0 -> Ring 3). bufio.Writer группирует строки в буфер и делает всего 10 системных вызовов по 4KB.

Потоковое вычисление хэша SHA256 блоками по 1 КБ

📌 Условие задачи

Читайте большой файл блоками по 1 КБ, вычисляя SHA256-хэш всего файла.

💡 Теоретический фундамент и концепция

Криптографический хэш crypto/sha256 реализует интерфейс io.Writer. Функция io.Copy(hash, file) или блочное чтение позволяет вычислить контрольную сумму файла любого объема без загрузки в память.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл data.bin.
2. Инициализируем h := sha256.New().
3. В цикле вычитаем файл порциями по 1024 байта и запишем в h.Write(buf[:n]).
4. Получим финальный хэш h.Sum(nil) и выведем в виде hex-строки.
📄 main.go 
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"errors"
	"fmt"
	"io"
	"log"
	"os"
)

func computeSHA256Chunks(path string) (string, error) {
	file, err := os.Open(path)
	if err != nil {
		return "", err
	}
	defer file.Close()

	hasher := sha256.New()
	buf := make([]byte, 1024) // Блок 1 КБ

	for {
		n, err := file.Read(buf)
		if n > 0 {
			hasher.Write(buf[:n])
		}
		if err != nil {
			if errors.Is(err, io.EOF) {
				break
			}
			return "", err
		}
	}

	hashBytes := hasher.Sum(nil)
	return hex.EncodeToString(hashBytes), nil
}

func main() {
	path := "checksum_test.txt"
	_ = os.WriteFile(path, []byte("Cryptographic hash verification pipeline in Go 1.22"), 0644)

	hash, err := computeSHA256Chunks(path)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("SHA256 (%s) = %s\n", path, hash)
}

	"os"
)

	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			return fmt.Errorf("файл %s не найден на диске: %w", path, err)
		}
		return fmt.Errorf("ошибка доступа к файлу %s: %w", path, err)

		if closeErr != nil && retErr == nil {
			retErr = fmt.Errorf("ошибка закрытия файла: %w", closeErr)
		}
	}()

	fmt.Println("Файл успешно прочитан")
	return nil
}

📌 Условие задачи

💡 Теоретический фундамент и концепция

bufio.Scanner настраивается с помощью функции разделения scanner.Split(fn):

  • bufio.ScanLines — построчное чтение.
  • bufio.ScanWords — разделение по пробельным символам (слова).
  • bufio.ScanRunes / bufio.ScanBytes — подсчет символов/байт.

🔍 Пошаговый ход решения и ход мысли инженера

2. Реализуем функцию подсчета строк countTokens(path, bufio.ScanLines).

📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"log"
	"os"
)

func countTokens(path string, splitFn bufio.SplitFunc) (int, error) {
	file, err := os.Open(path)
	if err != nil {
		return 0, err
	}
	defer file.Close()

	scanner := bufio.NewScanner(file)
	scanner.Split(splitFn)

	count := 0
	for scanner.Scan() {
		count++
	}
	return count, scanner.Err()
}

func main() {
	path := "document.txt"
	_ = os.WriteFile(path, []byte("Go is an open source programming language\nthat makes it easy to build simple, reliable, and efficient software."), 0644)

	lines, err := countTokens(path, bufio.ScanLines)
	if err != nil {
		log.Fatal(err)
	}

	words, _ := countTokens(path, bufio.ScanWords)
	runes, _ := countTokens(path, bufio.ScanRunes)

	fmt.Printf("Файл: %s\n", path)
	fmt.Printf(" -> Строк:    %d\n", lines)
	fmt.Printf(" -> Слов:     %d\n", words)
	fmt.Printf(" -> Символов: %d\n", runes)
}

Упражнение #42

Сравнение флагов открытия os.O_RDONLY, os.O_RDWR, os.O_TRUNC

📌 Условие задачи

Покажите разницу режимов открытия: os.O_RDONLY, os.O_RDWR, os.O_TRUNC и т.д., проверьте ошибки при записи в файл, открытый только на чтение.

💡 Теоретический фундамент и концепция

Режимы доступа к файлам в Go задаются константами пакета os:

  • os.O_RDONLY: только чтение (попытка записи вызывает ошибку ядра EBADF).
  • os.O_WRONLY: только запись.
  • os.O_RDWR: чтение и запись одновременно.
  • os.O_TRUNC: усечение файла до нулевой длины при открытии.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл test_modes.txt с текстом.
2. Откроем в режиме os.O_RDONLY и попытаемся записать данные.
3. Откроем в режиме os.O_RDWR и убедимся в успешной записи.
4. Откроем в режиме os.O_TRUNC и проверим обнуление размера.
📄 main.go 
package main

import (
	"fmt"
	"os"
)

func main() {
	path := "test_modes.txt"
	_ = os.WriteFile(path, []byte("Original Content 12345"), 0644)

	// 1. Попытка записи в файл O_RDONLY:
	fReadOnly, _ := os.OpenFile(path, os.O_RDONLY, 0)
	_, errWrite := fReadOnly.WriteString("New data")
	fReadOnly.Close()
	fmt.Printf("[O_RDONLY] Попытка записи завершилась: %v\n", errWrite)

	// 2. Открытие O_RDWR (чтение и запись):
	fReadWrite, _ := os.OpenFile(path, os.O_RDWR, 0)
	_, _ = fReadWrite.WriteString("Modified")
	fReadWrite.Close()
	data1, _ := os.ReadFile(path)
	fmt.Printf("[O_RDWR] После перезаписи начала: %s\n", string(data1))

	// 3. Открытие с O_TRUNC (сброс длины в 0):
	fTrunc, _ := os.OpenFile(path, os.O_WRONLY|os.O_TRUNC, 0)
	_, _ = fTrunc.WriteString("Fresh")
	fTrunc.Close()
	data2, _ := os.ReadFile(path)
	fmt.Printf("[O_TRUNC] После усечения:        %s\n", string(data2))
}

Флаги доступа O_RDONLY, O_WRONLY, O_RDWR являются взаимоисключающими, их нельзя комбинировать через битовое ИЛИ | между собой.

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Что будет, если скомбинировать os.O_RDONLY | os.O_WRONLY?»

Ответ: В Unix O_RDONLY равен 0, а O_WRONLY равен 1. Выражение 0 | 1 = 1, поэтому файл откроется только на запись (O_WRONLY). Для одновременного чтения и записи необходимо использовать os.O_RDWR (равный 2).

Упражнение #44

Ручной рекурсивный обход дерева каталогов через os.ReadDir

📌 Условие задачи

[Высокая сложность]: Напиши рекурсивную функцию, которая обходит все файлы и папки в указанной директории (дерево) и выводит их пути.

💡 Теоретический фундамент и концепция

Ручной рекурсивный обход каталогов реализуется через функцию, которая считывает os.ReadDir(dir), выводит текущий элемент и рекурсивно вызывает сама себя для каждого подкаталога entry.IsDir().

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим дерево вложенных папок и файлов.
2. Реализуем функцию WalkTree(dir string, level int) error.
3. Сформируем визуальный отступ strings.Repeat(" ", level).
4. В main распечатаем красивое иерархическое дерево каталогов.
📄 main.go 
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strings"
)

func WalkTree(dir string, level int) error {
	entries, err := os.ReadDir(dir)
	if err != nil {
		return err
	}

	indent := strings.Repeat("  ", level)
	for _, entry := range entries {
		fullPath := filepath.Join(dir, entry.Name())
		if entry.IsDir() {
			fmt.Printf("%s📁 %s/\n", indent, entry.Name())
			if err := WalkTree(fullPath, level+1); err != nil {
				return err
			}
		} else {
			info, _ := entry.Info()
			size := int64(0)
			if info != nil {
				size = info.Size()
			}
			fmt.Printf("%s📄 %s (%d B)\n", indent, entry.Name(), size)
		}
	}
	return nil
}

func main() {
	root := "project_tree"
	_ = os.MkdirAll(root+"/cmd/server", 0755)
	_ = os.MkdirAll(root+"/internal/config", 0755)
	_ = os.WriteFile(root+"/cmd/server/main.go", []byte("package main"), 0644)
	_ = os.WriteFile(root+"/internal/config/config.go", []byte("package config"), 0644)
	_ = os.WriteFile(root+"/go.mod", []byte("module myapp\n\ngo 1.22"), 0644)

	defer os.RemoveAll(root)

	fmt.Printf("Иерархическое дерево папки %s/:\n", root)
	_ = WalkTree(root, 0)
}

⚠️ Частые грабли и ошибки новичков

🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем отличие Depth-First Search (DFS) и Breadth-First Search (BFS) обхода директорий?»

Ответ: Рекурсивный WalkTree реализует DFS (сначала погружается вглубь до крайних файлов). BFS использует очередь container/list или слайс и обходит сначала все файлы текущего уровня, что удобнее для поиска ближайших файлов.

Упражнение #47

Десериализация бинарных данных через encoding/gob

📌 Условие задачи

Прочитайте созданный gob-файл обратно в память и выведите данные на экран.

💡 Теоретический фундамент и концепция

Формат encoding/gob — нативный высокоскоростной бинарный формат сериализации Go. Он сохраняет информацию о типах и структурах данных, позволяя надежно восстанавливать сложные графы объектов.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявим структуру UserSession struct { UserID int; Username string; Scopes []string }.
2. Запишем экземпляр в файл через gob.NewEncoder(f).Encode(...).
3. Откроем файл и прочитаем через gob.NewDecoder(f).Decode(...).
4. В main проверим точное восстановление срезов и полей.
📄 main.go 
package main

import (
	"encoding/gob"
	"fmt"
	"log"
	"os"
)

type UserSession struct {
	UserID   int
	Username string
	Scopes   []string
}

func main() {
	path := "session.gob"

	original := UserSession{
		UserID:   1001,
		Username: "cloud_admin",
		Scopes:   []string{"read:users", "write:billing", "admin:all"},
	}

	// 1. Запись gob
	outFile, err := os.Create(path)
	if err != nil {
		log.Fatal(err)
	}
	if err := gob.NewEncoder(outFile).Encode(original); err != nil {
		outFile.Close()
		log.Fatal(err)
	}
	outFile.Close()

	// 2. Чтение gob
	inFile, err := os.Open(path)
	if err != nil {
		log.Fatal(err)
	}
	defer inFile.Close()

	var restored UserSession
	if err := gob.NewDecoder(inFile).Decode(&restored); err != nil {
		log.Fatal(err)
	}

Упражнение #50

Безопасная замена в файле (in-place replacement) требует создания резервной копии (filename.bak) перед модификацией. Это защищает от потери данных при сбое питания в процессе записи.

4. Перезапишем оригинальный файл.
5. В main убедимся в наличии бэкапа и обновленного файла.
📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"log"
	"os"
)

func SedReplace(path, oldText, newText string) error {
	// 1. Читаем оригинал
	data, err := os.ReadFile(path)
	if err != nil {
		return fmt.Errorf("read: %w", err)
	}

	// 2. Создаем резервную копию .bak
	bakPath := path + ".bak"
	if err := os.WriteFile(bakPath, data, 0644); err != nil {
		return fmt.Errorf("backup failed: %w", err)
	}

	// 3. Заменяем вхождения
	updated := bytes.ReplaceAll(data, []byte(oldText), []byte(newText))

	// 4. Перезаписываем исходный файл
	if err := os.WriteFile(path, updated, 0644); err != nil {
		return fmt.Errorf("write updated: %w", err)
	}

	fmt.Printf("Файл %s успешно обновлен. Бэкап сохранен в %s\n", path, bakPath)
	return nil
}

func main() {
	path := "settings.env"
	_ = os.WriteFile(path, []byte("ENV=staging\nDB_HOST=staging.db.corp\nPORT=8080"), 0644)

	if err := SedReplace(path, "staging", "production"); err != nil {
		log.Fatal(err)
	}

	res, _ := os.ReadFile(path)
	fmt.Println("--- Обновленный файл ---")
	fmt.Println(string(res))
}

Упражнение #51

Определение MIME-типа и формата по магическому числу (Magic Bytes)

📌 Условие задачи

Откройте бинарный файл с помощью os.Open и прочитайте первые 16 байт, чтобы определить "магическое число" (сигнатуру) файла.

💡 Теоретический фундамент и концепция

Магические числа (Magic Numbers / File Signatures) — первые фиксированные байты файла, идентифицирующие его формат (например, GIF89a, \x89PNG, \xFF\xD8\xFF для JPEG, PK\x03\x04 для ZIP). Пакет http.DetectContentType использует первые 512 байт файла для определения MIME-типа.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файлы с сигнатурами PNG и ZIP.
2. Напишем функцию DetectMagic(path string).
3. Вычитаем первые 16 байт через io.ReadFull.
4. Сравним сигнатуру и выведем определенный формат.
📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"log"
	"os"
)

var (
	pngMagic = []byte{0x89, 'P', 'N', 'G', 0x0D, 0x0A, 0x1A, 0x0A}
	zipMagic = []byte{'P', 'K', 0x03, 0x04}
	pdfMagic = []byte{'%', 'P', 'D', 'F'}
)

func detectFormat(path string) (string, error) {
	f, err := os.Open(path)
	if err != nil {
		return "", err
	}
	defer f.Close()

	header := make([]byte, 16)
	n, err := io.ReadFull(f, header)
	if err != nil && err != io.ErrUnexpectedEOF && err != io.EOF {
		return "", err
	}

	header = header[:n]
	switch {
	case bytes.HasPrefix(header, pngMagic):
		return "Image (PNG)", nil
	case bytes.HasPrefix(header, zipMagic):
		return "Archive (ZIP / JAR / DOCX)", nil
	case bytes.HasPrefix(header, pdfMagic):
		return "Document (PDF)", nil
	default:
		return "Unknown Binary Format", nil
	}
}

func main() {
	// Создаем тестовый заголовок PNG
	_ = os.WriteFile("sample.png", append(pngMagic, []byte("DATA_PAYLOAD")...), 0644)

	format, err := detectFormat("sample.png")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Формат файла sample.png определен как: %s\n", format)
}

Упражнение #53

Копирование через io.CopyBuffer и сверка SHA256-хэшей оригинала и копии

📌 Условие задачи

Напиши программу, которая копирует бинарный файл (изображение или архив). Используй io.CopyBuffer с буфером 4KB для эффективности. Сравни хеши оригинала и копии (crypto/sha256).

💡 Теоретический фундамент и концепция

io.CopyBuffer(dst, src, buf) позволяет разработчику контролировать размер буфера передачи данных (например, выделять его в пуле sync.Pool), что исключает лишние аллокации при миллионах операций копирования.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим исходный бинарный файл source.bin.
2. Скопируем его в copy.bin через io.CopyBuffer с буфером 4096 байт.
3. Вычислим SHA256 обоих файлов.
4. Сверим хэши и убедимся в побайтовой идентичности.
📄 main.go 
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"log"
	"os"
)

func hashFile(path string) (string, error) {
	f, err := os.Open(path)
	if err != nil {
		return "", err
	}
	defer f.Close()

	h := sha256.New()
	if _, err := io.Copy(h, f); err != nil {
		return "", err
	}
	return hex.EncodeToString(h.Sum(nil)), nil
}

func copyWithBuffer(srcPath, dstPath string) error {
	src, err := os.Open(srcPath)
	if err != nil {
		return err
	}
	defer src.Close()

	dst, err := os.Create(dstPath)
	if err != nil {
		return err
	}
	defer dst.Close()

	// Выделение управляемого буфера 4KB
	customBuf := make([]byte, 4096)
	if _, err := io.CopyBuffer(dst, src, customBuf); err != nil {
		return err
	}
	return nil
}

func main() {
	_ = os.WriteFile("source.bin", []byte("HighLoad Binary Payload 1234567890"), 0644)

	if err := copyWithBuffer("source.bin", "copy.bin"); err != nil {
		log.Fatal(err)
	}

	h1, _ := hashFile("source.bin")
	h2, _ := hashFile("copy.bin")

	fmt.Printf("Хэш оригинала: %s\n", h1)
	fmt.Printf("Хэш копии:     %s\n", h2)
	fmt.Printf("Целостность подтверждена: %v\n", h1 == h2)
}

		}
		return
	}
	defer file.Close()

	fmt.Printf("[200] Файл %s успешно открыт для чтения (fd=%d)\n", path, file.Fd())
}

Метод file.Seek(offset, io.SeekStart) сдвигает указатель на заданное количество байт. Считывание io.ReadFull(file, buf) гарантирует вычитку ровно 4 байт из выбранной позиции.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл из 16 байт: 0x00, 0x01, ..., 0x0F.
2. Вызовем file.Seek(8, io.SeekStart) (середина файла).
3. Прочитаем 4 байта в буфер buf := make([]byte, 4).
4. В main выведем вычитанные байты.

	"fmt"
	"io"
	"log"
	"os"
)

	path := "binary_payload.bin"

	_ = os.WriteFile(path, payload, 0644)

	}
	defer file.Close()

	// Сдвигаем курсор на середину (8-й байт)
	midOffset := int64(len(payload) / 2)

		log.Fatal(err)
	}

	fmt.Printf("Позиция курсора: %d\n", pos)
	fmt.Printf("Прочитано 4 байта из середины: %v\n", buf)

Упражнение #59

Симметричное XOR-шифрование файлов с сохранением в бинарный формат

📌 Условие задачи

Создайте программу, которая шифрует текстовый файл простым XOR-шифром, сохраняя результат в бинарный файл, а затем расшифровывает его обратно.

💡 Теоретический фундамент и концепция

Операция XOR ($\oplus$) обладает свойством инволюции: $(A \oplus K) \oplus K = A$. Это позволяет использовать один и тот же алгоритм для шифрования и дешифрования потока байт ключом key.

🔍 Пошаговый ход решения и ход мысли инженера

1. Напишем функцию xorCipher(src, dst string, key byte) error.
2. Зашифруем исходный текст secret.txt в бинарный encrypted.bin.
3. Расшифруем encrypted.bin в decrypted.txt.
4. В main убедимся в совпадении текста с оригиналом.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
)

func xorCipher(srcPath, dstPath string, key byte) error {
	data, err := os.ReadFile(srcPath)
	if err != nil {
		return err
	}

	result := make([]byte, len(data))
	for i, b := range data {
		result[i] = b ^ key // Побайтовый XOR
	}

	return os.WriteFile(dstPath, result, 0644)
}

func main() {
	originalText := "TOP_SECRET_PRODUCTION_CREDENTIALS"
	_ = os.WriteFile("plain.txt", []byte(originalText), 0644)

	var key byte = 0xAA // Секретный ключ 10101010

	// 1. Шифрование
	if err := xorCipher("plain.txt", "cipher.bin", key); err != nil {
		log.Fatal(err)
	}

	encData, _ := os.ReadFile("cipher.bin")
	fmt.Printf("Зашифрованные байты (hex): % X\n", encData)

	// 2. Дешифрование тем же ключом
	if err := xorCipher("cipher.bin", "decrypted.txt", key); err != nil {
		log.Fatal(err)
	}

	decData, _ := os.ReadFile("decrypted.txt")
	fmt.Printf("Расшифрованный текст:      %s\n", string(decData))
}

Упражнение #60

Чтение файла порциями строго по 16 байт через file.Read до io.EOF

📌 Условие задачи

Чтение по кускам (Chunks): Открой файл и читай его порциями ровно по 16 байт в цикле, используя метод file.Read(buf) до достижения io.EOF.

💡 Теоретический фундамент и концепция

Чтение строго фиксированными порциями (file.Read(buf)) — фундаментальный паттерн для парсеров бинарных пакетов, видеопотоков и баз данных (чтение страниц размером 4KB/8KB).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл stream.dat длиной 45 байт.
2. Откроем файл через os.Open.
3. В цикле вычитаем по 16 байт в буфер buf := make([]byte, 16).
4. Для каждого куска выведем размер и шестнадцатеричный дамп.
📄 main.go 
package main

import (
	"errors"
	"fmt"
	"io"
	"log"
	"os"
)

func main() {
	path := "stream.dat"
	_ = os.WriteFile(path, []byte("0123456789ABCDEFabcdefghij0123456789FinalChunk"), 0644)

	file, err := os.Open(path)
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	buf := make([]byte, 16)
	chunkIndex := 1

	for {
		n, err := file.Read(buf)
		if n > 0 {
			fmt.Printf("Chunk #%d (размер %2d байт): %q\n", chunkIndex, n, string(buf[:n]))
			chunkIndex++
		}
		if err != nil {
			if errors.Is(err, io.EOF) {
				fmt.Println("Поток успешно вычитан до конца (io.EOF)")
				break
			}
			log.Fatalf("Ошибка чтения: %v", err)
		}
	}
}

package main

import (
	"fmt"
	"io/fs"
	"log"
	"os"
	"path/filepath"
)

func findTxtFiles(root string) ([]string, error) {
	var txtPaths []string

	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if !d.IsDir() && filepath.Ext(path) == ".txt" {
			txtPaths = append(txtPaths, path)
		}
		return nil
	})

	return txtPaths, err
}

Спецификация W3C PNG определяет строгую 8-байтную сигнатуру: \x89 P N G \r \n \x1a \n (0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A). Чтение ровно 8 байт через io.ReadFull позволяет валидировать формат файла.

📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"log"
	"os"
)

var pngHeader = []byte{0x89, 'P', 'N', 'G', 0x0D, 0x0A, 0x1A, 0x0A}

func isPNG(path string) (bool, error) {
	file, err := os.Open(path)
	if err != nil {
		return false, err
	}
	defer file.Close()

	buf := make([]byte, 8)
	if _, err := io.ReadFull(file, buf); err != nil {
		return false, err
	}

	return bytes.Equal(buf, pngHeader), nil
}

func main() {
	path := "image_test.png"
	_ = os.WriteFile(path, append(pngHeader, []byte("IHDR_CHUNK_DATA")...), 0644)

	valid, err := isPNG(path)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Файл %s является валидным PNG: %v\n", path, valid)
}

Разбиение большого бинарного файла на чанки (Split) и сборка обратно (Merge)

Напиши программу, которая разбивает большой бинарный файл на части (chunk'и) заданного размера (например, 1MB каждый). Затем напиши программу-сборщик, которая объединяет chunk'и обратно.

💡 Теоретический фундамент и концепция

Паттерн Chunking (нарезка на части) применяется в протоколах BitTorrent, S3 Multipart Upload и Telegram Bot API для надежной передачи больших файлов по нестабильной сети.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим тестовый файл large_payload.dat.
2. Реализуем функцию SplitFile(path string, chunkSize int64) ([]string, error).
3. Реализуем функцию MergeChunks(chunks []string, dst string) error.
4. В main сверим размер и содержимое оригинала и собранного файла.
📄 main.go 
package main

import (
	"bytes"
	"fmt"
	"io"
	"log"
	"os"
)

func SplitFile(srcPath string, chunkSize int64) ([]string, error) {
	src, err := os.Open(srcPath)
	if err != nil {
		return nil, err
	}
	defer src.Close()

	var chunkFiles []string
	part := 1

	for {
		chunkName := fmt.Sprintf("%s.part%03d", srcPath, part)
		dst, err := os.Create(chunkName)
		if err != nil {
			return nil, err
		}

		// Копируем ровно chunkSize байт
		n, err := io.CopyN(dst, src, chunkSize)
		dst.Close()

		if n > 0 {
			chunkFiles = append(chunkFiles, chunkName)
			part++
		}
		if err == io.EOF {
			break
		}
		if err != nil {
			return nil, err
		}
	}
	return chunkFiles, nil
}

func MergeChunks(chunks []string, dstPath string) error {
	dst, err := os.Create(dstPath)
	if err != nil {
		return err
	}
	defer dst.Close()

	for _, chunk := range chunks {
		in, err := os.Open(chunk)
		if err != nil {
			return err
		}
		_, err = io.Copy(dst, in)
		in.Close()
		if err != nil {
			return err
		}
	}
	return nil
}

func main() {
	originalData := []byte("0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ_PAYLOAD_DATA")
	_ = os.WriteFile("source.dat", originalData, 0644)

	// Нарезка чанками по 16 байт
	chunks, err := SplitFile("source.dat", 16)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Файл нарезан на %d чанков: %v\n", len(chunks), chunks)

	// Сборка обратно
	if err := MergeChunks(chunks, "restored.dat"); err != nil {
		log.Fatal(err)
	}

	restoredData, _ := os.ReadFile("restored.dat")
	fmt.Printf("Целостность сборки: %v\n", bytes.Equal(originalData, restoredData))

	// Очистка
	_ = os.Remove("source.dat")
	_ = os.Remove("restored.dat")
	for _, c := range chunks {
		_ = os.Remove(c)
	}
}

📌 Условие задачи

Напиши программу, которая реализует простую базу данных в файле: запись структур Record { ID int; Name string; Score float64 } с фиксированным размером записи. Реализуй CRUD: Create, Read, Update, Delete (soft delete).

💡 Теоретический фундамент и концепция

Файловые СУБД с фиксированным размером слота (Slot Size) позволяют вычислять точное смещение любой записи по формуле: $\text{offset} = \text{slotID} \times \text{recordSize}$. Чтение и перезапись выполняются за $O(1)$ через file.Seek.

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявим структуру Record struct { ID int32; Name [24]byte; Score float64; IsDeleted bool }.
2. Реализуем WriteRecord(slot int, r Record) через file.Seek.
3. Реализуем ReadRecord(slot int) через file.Seek.
4. Реализуем SoftDelete(slot int) через обновление флага IsDeleted.
5. В main покажем работу CRUD-операций.
📄 main.go 
package main

import (
	"bytes"
	"encoding/binary"
	"fmt"
	"log"
	"os"
)

type Record struct {
	ID        int32
	Name      [24]byte
	Score     float64
	IsDeleted bool
}

const recordSize = 37 // 4 + 24 + 8 + 1 байт

type DatabaseEngine struct {
	file *os.File
}

func NewDB(path string) (*DatabaseEngine, error) {
	f, err := os.OpenFile(path, os.O_RDWR|os.O_CREATE, 0644)
	if err != nil {
		return nil, err
	}
	return &DatabaseEngine{file: f}, nil
}

func (db *DatabaseEngine) Close() error {
	return db.file.Close()
}

func (db *DatabaseEngine) Write(slot int64, rec Record) error {
	offset := slot * recordSize
	if _, err := db.file.Seek(offset, ioSeekStart()); err != nil {
		return err
	}
	return binary.Write(db.file, binary.LittleEndian, rec)
}

func (db *DatabaseEngine) Read(slot int64) (Record, error) {
	offset := slot * recordSize
	var rec Record
	if _, err := db.file.Seek(offset, ioSeekStart()); err != nil {
		return rec, err
	}
	err := binary.Read(db.file, binary.LittleEndian, &rec)
	return rec, err
}

func ioSeekStart() int { return 0 }

func main() {
	dbPath := "mini_engine.db"
	db, err := NewDB(dbPath)
	if err != nil {
		log.Fatal(err)
	}
	defer func() {
		db.Close()
		_ = os.Remove(dbPath)
	}()

	// 1. Create: пишем в слот 0 и 1
	var name1 [24]byte
	copy(name1[:], "Alice")
	_ = db.Write(0, Record{ID: 101, Name: name1, Score: 98.5, IsDeleted: false})

	var name2 [24]byte
	copy(name2[:], "Bob")
	_ = db.Write(1, Record{ID: 102, Name: name2, Score: 85.0, IsDeleted: false})

	// 2. Read: прямое чтение слота 1 за O(1)
	rec, _ := db.Read(1)
	cleanName := string(bytes.TrimRight(rec.Name[:], "\x00"))
	fmt.Printf("[Read Slot 1] ID=%d, Name=%s, Score=%.1f\n", rec.ID, cleanName, rec.Score)

	// 3. Delete (Soft delete) слота 0:
	rec0, _ := db.Read(0)
	rec0.IsDeleted = true
	_ = db.Write(0, rec0)

	rec0Updated, _ := db.Read(0)
	fmt.Printf("[Read Slot 0] Deleted: %v\n", rec0Updated.IsDeleted)
}

📌 Условие задачи

Напиши программу, которая читает файл с произвольной позиции (os.File.Seek). Реализуй "tail" — чтение последних N байт файла без загрузки всего файла в память.

💡 Теоретический фундамент и концепция

Утилита tail считывает последние байты лог-файла. Перемещение file.Seek(-N, io.SeekEnd) мгновенно ставит указатель чтения в конец файла за время $O(1)$ без чтения предыдущих терабайт.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим большой файл лога.
2. Реализуем функцию TailBytes(path string, n int64) ([]byte, error).
3. Запросим размер файла через file.Stat().
4. Сместимся на -n от io.SeekEnd.
5. Вычитаем остаток файла и распечатаем.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func TailBytes(path string, n int64) ([]byte, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer file.Close()

	info, err := file.Stat()
	if err != nil {
		return nil, err
	}

	size := info.Size()
	offset := int64(0)
	if size > n {
		offset = -n
	} else {
		offset = -size
	}

	// Смещение назад от конца файла
	if _, err := file.Seek(offset, io.SeekEnd); err != nil {
		return nil, err
	}

	return io.ReadAll(file)
}

	"fmt"

	"log"
	"os"

func directCopy(srcName, dstName string) (int64, error) {

Мониторинг изменений файла по размеру и времени модификации (Polling)

Опрос метаданных (Polling File Watcher) через os.Stat — простейший кроссплатформенный способ отслеживания изменений файлов. Он сравнивает info.ModTime() и info.Size() между интервалами опроса.

2. Запросим начальные метаданные lastMod := info.ModTime().

📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
	"time"
)

func main() {
	path := "config.live"
	_ = os.WriteFile(path, []byte("v1"), 0644)

	info, err := os.Stat(path)
	if err != nil {
		log.Fatal(err)
	}

	lastMod := info.ModTime()
	lastSize := info.Size()

	fmt.Printf("Мониторинг файла %s запущен...\n", path)

	// Имитация фонового изменения файла
	go func() {
		time.Sleep(20 * time.Millisecond)
		_ = os.WriteFile(path, []byte("v2_updated_configuration_payload"), 0644)
	}()

	for i := 0; i < 4; i++ {
		time.Sleep(10 * time.Millisecond)
		currentInfo, err := os.Stat(path)
		if err != nil {
			continue
		}

			fmt.Printf("[EVENT] Файл %s изменен! Новый размер: %d B, Время: %s\n",
				path, currentInfo.Size(), currentInfo.ModTime().Format("15:04:05.000"))
			lastMod = currentInfo.ModTime()
			lastSize = currentInfo.Size()
		}
	}

	_ = os.Remove(path)
}

📄 main.go 
package main

import (
	"fmt"
	"io/fs"
	"log"
	"os"
	"path/filepath"
)

func CalculateDirSize(root string) (totalSize int64, fileCount int, err error) {
	err = filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if !d.IsDir() {
			info, err := d.Info()
			if err != nil {
				return err
			}
			totalSize += info.Size()
			fileCount++
		}
		return nil
	})
	return totalSize, fileCount, err
}

func main() {
	root := "metrics_storage"
	_ = os.MkdirAll(root+"/node1/logs", 0755)
	_ = os.WriteFile(root+"/node1/logs/app.log", make([]byte, 1024), 0644) // 1024 B
	_ = os.WriteFile(root+"/summary.json", make([]byte, 512), 0644)        // 512 B

	size, count, err := CalculateDirSize(root)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Директория:       %s\n", root)
	fmt.Printf("Всего файлов:     %d\n", count)
	fmt.Printf("Суммарный размер: %d байт (%.2f KB)\n", size, float64(size)/1024)

	_ = os.RemoveAll(root)
}

	"encoding/gob"
	"fmt"
	"log"
	"os"
)

type TaskRecord struct {
	ID        int
	TaskTitle string
	IsDone    bool
}

func main() {
	path := "tasks.gob"
	original := []TaskRecord{
		{ID: 1, TaskTitle: "Design Database Schema", IsDone: true},
		{ID: 2, TaskTitle: "Implement JWT Middleware", IsDone: true},
		{ID: 3, TaskTitle: "Setup Kubernetes Cluster", IsDone: false},

	inFile, err := os.Open(path)
	if err != nil {
		log.Fatal(err)

	if err := gob.NewDecoder(inFile).Decode(&restored); err != nil {
		log.Fatal(err)
	}

	fmt.Println("Восстановленный список задач из gob:")
	for _, t := range restored {
		fmt.Printf(" -> [%02d] (Done: %-5v) %s\n", t.ID, t.IsDone, t.TaskTitle)
	}

	_ = os.Remove(path)
}

Буферизованная запись 10 000 строк и обязательность Flush()

📌 Условие задачи

Буферизованная запись (Writer): Напишите программу, которая записывает 10 000 строк в файл. Используйте bufio.NewWriter. Не забудьте вызвать метод Flush() в конце (объясните в комментариях, почему без Flush часть данных может не записаться).

💡 Теоретический фундамент и концепция

bufio.NewWriter накапливает строки во внутреннем буфере в RAM. Если функция завершится без вызова writer.Flush(), последняя накопленная порция данных (до 4096 байт) будет утеряна при закрытии дескриптора.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создадим файл benchmark.log.
2. Обернем его в bufio.NewWriter.
3. В цикле запишем 10 000 строк.
4. Вызовем writer.Flush().
5. Проверим количество строк в полученном файле.
📄 main.go 
package main

import (
	"bufio"
	"fmt"
	"log"
	"os"
)

func main() {
	path := "benchmark.log"
	file, err := os.Create(path)
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	writer := bufio.NewWriter(file)

	const totalLines = 10000
	for i := 1; i <= totalLines; i++ {
		line := fmt.Sprintf("EventID=%05d Status=SUCCESS Latency=0.45ms\n", i)
		if _, err := writer.WriteString(line); err != nil {
			log.Fatal(err)
		}
	}

	// ОБЯЗАТЕЛЬНО: сброс остатка внутреннего буфера в дескриптор файла
	// Без Flush() хвост буфера (до 4KB) останется в памяти и не попадет на диск.
	if err := writer.Flush(); err != nil {
		log.Fatalf("Ошибка Flush: %v", err)
	}

	info, _ := file.Stat()
	fmt.Printf("Успешно записано %d строк через bufio.Writer. Размер: %d байт\n", totalLines, info.Size())

	_ = os.Remove(path)
}

📌 Условие задачи

💡 Теоретический фундамент и концепция

Ротация логов предотвращает переполнение диска. При превышении лимита размера текущий файл атомарно переименовывается (os.Rename), а для записи открывается новый чистый дескриптор.

🔍 Пошаговый ход решения и ход мысли инженера

1. Реализуем структуру RotatingLogger.
2. В методе Write(msg string) проверяем текущий размер через file.Stat().
3. Если size >= maxSize — вызываем rotate().
4. В main запишем данные и проверим ротацию.
📄 main.go 
package main

import (
	"fmt"
	"log"
	"os"
)

type RotatingLogger struct {
	basePath string
	maxBytes int64
	file     *os.File
	count    int
}

func NewRotatingLogger(basePath string, maxBytes int64) (*RotatingLogger, error) {
	f, err := os.OpenFile(basePath, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		return nil, err
	}
	return &RotatingLogger{basePath: basePath, maxBytes: maxBytes, file: f}, nil
}

func (l *RotatingLogger) rotate() error {
	l.file.Close()
	l.count++
	backupPath := fmt.Sprintf("%s.%d", l.basePath, l.count)

	if err := os.Rename(l.basePath, backupPath); err != nil {
		return err
	}

	fmt.Printf("[ROTATION] Файл ротирован в %s\n", backupPath)

	f, err := os.OpenFile(l.basePath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, 0644)
	if err != nil {
		return err
	}
	l.file = f
	return nil
}

func (l *RotatingLogger) Log(msg string) error {
	info, err := l.file.Stat()
	if err != nil {
		return err
	}
	if info.Size() >= l.maxBytes {
		if err := l.rotate(); err != nil {
			return err
		}
	}
	_, err = l.file.WriteString(msg + "\n")
	return err
}

func (l *RotatingLogger) Close() error {
	return l.file.Close()
}

func main() {
	base := "app_rot.log"
	// Лимит 40 байт для демонстрации
	logger, err := NewRotatingLogger(base, 40)
	if err != nil {
		log.Fatal(err)
	}
	defer logger.Close()

	_ = logger.Log("Line 1: Server initialized")
	_ = logger.Log("Line 2: Heavy database query completed")
	_ = logger.Log("Line 3: Cache cleared")

	// Очистка
	_ = os.Remove(base)
	_ = os.Remove(base + ".1")
}

💡 Теоретический фундамент и концепция

package main

import (
	"fmt"
	"io/fs"
	"log"
	"os"
	"path/filepath"
	"strings"
)

func PrintTree(root string) error {
	return filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if path == root {
			fmt.Printf("📦 %s/\n", root)
			return nil
		}

		rel, _ := filepath.Rel(root, path)
		depth := strings.Count(rel, string(filepath.Separator))
		indent := strings.Repeat("  ", depth)

		if d.IsDir() {
			fmt.Printf("%s📁 %s/\n", indent, d.Name())
		} else {
			fmt.Printf("%s📄 %s\n", indent, d.Name())
		}
		return nil
	})
}

func main() {
	root := "sample_app"
	_ = os.MkdirAll(root+"/api/v1", 0755)
	_ = os.MkdirAll(root+"/configs", 0755)
	_ = os.WriteFile(root+"/main.go", []byte("package main"), 0644)
	_ = os.WriteFile(root+"/api/v1/router.go", []byte("package v1"), 0644)
	_ = os.WriteFile(root+"/configs/app.yaml", []byte("env: prod"), 0644)

	defer os.RemoveAll(root)

	if err := PrintTree(root); err != nil {
		log.Fatal(err)
	}
}

Напиши программу, которая находит все файлы с определённым расширением в директории и поддиректориях. Подсчитай их общий размер.

💡 Теоретический фундамент и концепция

Фильтрация по расширению filepath.Ext(path) == targetExt в сочетании с d.Info() позволяет агрегировать статистику файлов заданного типа (например, размер всех .log файлов).

🔍 Пошаговый ход решения и ход мысли инженера

2. Реализуем функцию FindAndSumBySize(root, ext string) (int64, []string, error).

📄 main.go 
package main

import (
	"fmt"
	"io/fs"
	"log"
	"os"
	"path/filepath"
)

func FindAndSumBySize(root, ext string) (int64, []string, error) {
	var totalSize int64
	var matches []string

	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if !d.IsDir() && filepath.Ext(path) == ext {
			info, err := d.Info()
			if err != nil {
				return err
			}
			totalSize += info.Size()
			matches = append(matches, path)
		}
		return nil
	})

	return totalSize, matches, err
}

func main() {
	root := "log_archive"
	_ = os.MkdirAll(root+"/server1", 0755)
	_ = os.WriteFile(root+"/system.log", make([]byte, 2048), 0644)
	_ = os.WriteFile(root+"/server1/app.log", make([]byte, 4096), 0644)
	_ = os.WriteFile(root+"/server1/readme.md", []byte("docs"), 0644)

	defer os.RemoveAll(root)

	size, files, err := FindAndSumBySize(root, ".log")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Найдено .log файлов: %d\n", len(files))
	for _, f := range files {
		fmt.Printf(" -> %s\n", f)
	}
	fmt.Printf("Суммарный объем: %d байт (%.2f KB)\n", size, float64(size)/1024)
}

	"log"

package main

import (
	"bufio"
	"fmt"
	"log"
	"os"
	"strings"
)

func CountErrorLines(path string) (int, error) {
	file, err := os.Open(path)
	if err != nil {
		return 0, err
	}
	defer file.Close()

	scanner := bufio.NewScanner(file)
	count := 0

	for scanner.Scan() {
		if strings.Contains(scanner.Text(), "ERROR") {
			count++
		}
	}

	return count, scanner.Err()
}

func main() {
	path := "app_events.log"
	payload := "INFO: app started\nERROR: db timeout\nWARN: high cpu\nERROR: disk full\nINFO: healthy"
	_ = os.WriteFile(path, []byte(payload), 0644)

	errCount, err := CountErrorLines(path)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Обнаружено строк с ошибками [ERROR]: %d\n", errCount)
	_ = os.Remove(path)
}

📌 Условие задачи

Программа должна прочитать input, преобразовать весь текст в ВЕРХНИЙ РЕГИСТР, посчитать количество слов, и записать в output файл результат в формате: "WORDS: \nUPPERCASE TEXT: ...". Обработать все ошибки (нет файла, нет прав и т.д.) через log.Fatalf.

💡 Теоретический фундамент и концепция

Полноценная CLI-утилита использует пакет flag для парсинга аргументов командной строки, валидирует наличие файлов и прав доступа, выполняет преобразования и форматирует результат.

🔍 Пошаговый ход решения и ход мысли инженера

2. Вызовем flag.Parse().
3. Прочитаем входной файл и посчитаем слова.
4. Преобразуем текст в strings.ToUpper(text).
5. Запишем форматированный отчет в выходной файл.
6. В main протестируем работу CLI-конвейера.
📄 main.go 
package main

import (
	"bufio"
	"flag"
	"fmt"
	"log"
	"os"
	"strings"
)

func runCLI(inputPath, outputPath string) {
	if inputPath == "" || outputPath == "" {
		log.Fatalf("Ошибка: обязательны оба флага -input и -output")
	}

	// 1. Читаем исходный файл
	data, err := os.ReadFile(inputPath)
	if err != nil {
		log.Fatalf("Критическая ошибка чтения input файла %s: %v", inputPath, err)
	}

	content := string(data)

	// 2. Подсчет слов
	scanner := bufio.NewScanner(strings.NewReader(content))
	scanner.Split(bufio.ScanWords)
	wordCount := 0
	for scanner.Scan() {
		wordCount++
	}

	// 3. Преобразование в верхний регистр
	upperContent := strings.ToUpper(content)

	// 4. Формирование вывода
	result := fmt.Sprintf("WORDS: %d\nUPPERCASE TEXT:\n%s\n", wordCount, upperContent)

	// 5. Запись в output файл
	if err := os.WriteFile(outputPath, []byte(result), 0644); err != nil {
		log.Fatalf("Критическая ошибка записи в output файл %s: %v", outputPath, err)
	}

	fmt.Printf("Обработка завершена: %d слов записано в %s\n", wordCount, outputPath)
}

func main() {
	inputFlag := flag.String("input", "input.txt", "Путь к исходному текстовому файлу")
	outputFlag := flag.String("output", "output.txt", "Путь к результирующему файлу")
	flag.Parse()

	// Демонстрационная подготовка тестового файла
	_ = os.WriteFile(*inputFlag, []byte("Go highload architecture and file processing engine"), 0644)

	runCLI(*inputFlag, *outputFlag)

	res, _ := os.ReadFile(*outputFlag)
	fmt.Println("--- Результат работы CLI ---")
	fmt.Print(string(res))

	_ = os.Remove(*inputFlag)
	_ = os.Remove(*outputFlag)
}

	"fmt"
	"log"
	"os"
)

func main() {

	if err != nil {
		log.Fatalf("Ошибка создания временного файла: %v", err)

	fmt.Println("Выход из main: файл будет автоматически удален через defer os.Remove")
}

Упражнение #100

Реализация интерфейсов io.Reader и io.Writer для собственного типа MemoryBuffer

📌 Условие задачи

Напиши программу, которая реализует io.Reader и io.Writer для кастомного типа (например, type MemoryBuffer struct { data []byte }). Реализуй методы Read и Write по интерфейсам.

💡 Теоретический фундамент и концепция

Реализация стандартных интерфейсов io.Reader и io.Writer делает кастомный тип совместимым со всей стандартной библиотекой Go (io.Copy, bufio, json.NewDecoder, http.Post, crypto/sha256).

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявим type MemoryBuffer struct { buf []byte; offset int }.
2. Реализуем метод Write(p []byte) (n int, err error).
3. Реализуем метод Read(p []byte) (n int, err error).
4. В main проверим совместимость с io.Copy и fmt.Fprintf.
📄 main.go 
package main

import (
	"fmt"
	"io"
	"log"
)

type MemoryBuffer struct {
	buf    []byte
	offset int
}

func NewMemoryBuffer() *MemoryBuffer {
	return &MemoryBuffer{buf: make([]byte, 0, 128)}
}

// Реализация io.Writer: дописывает данные в конец буфера
func (m *MemoryBuffer) Write(p []byte) (n int, err error) {
	m.buf = append(m.buf, p...)
	return len(p), nil
}

// Реализация io.Reader: читает данные с текущей позиции offset до io.EOF
func (m *MemoryBuffer) Read(p []byte) (n int, err error) {
	if m.offset >= len(m.buf) {
		return 0, io.EOF
	}
	n = copy(p, m.buf[m.offset:])
	m.offset += n
	return n, nil
}

func main() {
	mem := NewMemoryBuffer()

	// 1. Запись через fmt.Fprintf (интерфейс io.Writer)
	fmt.Fprintf(mem, "Item #%d: %s\n", 1, "HighLoad Architecture")
	fmt.Fprintf(mem, "Item #%d: %s\n", 2, "Custom io.ReadWriter Implementation")

	// 2. Чтение через io.ReadAll (интерфейс io.Reader)
	result, err := io.ReadAll(mem)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Println("--- Данные из кастомного MemoryBuffer ---")
	fmt.Print(string(result))
}

Интерфейсы в Go удовлетворяются неявно (duck typing). Наличие методов Read и Write автоматически делает *MemoryBuffer реализацией интерфейса io.ReadWriter.

⚠️ Частые грабли и ошибки новичков

Обязательно возвращайте io.EOF, когда m.offset >= len(m.buf), иначе io.ReadAll зависнет в бесконечном цикле!
