# Системные вызовы и взаимодействие с ОС

В этом файле собраны уникальные упражнения по теме **"Системные вызовы и взаимодействие с ОС"**, отсортированные по возрастанию сложности.

---

1. **Прямой системный вызов `write`.**: Используя пакет `syscall` (или `golang.org/x/sys/unix`), сделайте системный вызов `SYS_WRITE` напрямую для вывода строки в stdout (fd=1). Сравните с `fmt.Print`.

2. **Работа с `mmap`.**: Реализуйте чтение файла через отображение в память (`syscall.Mmap`). Прочитайте содержимое файла, измените байты в слайсе, синхронизируйте (`syscall.Msync`) и убедитесь, что изменения записаны на диск.

3. **Создание анонимного mmap.**: Выделите область памяти через `mmap` с флагами `MAP_ANON|MAP_PRIVATE`, используйте её как слайс байт в Go. Сравните производительность выделения больших блоков с `make([]byte, ...)`.

4. **[Прямая работа с файлами]**: Открой файл через `unix.Open(path, unix.O_RDWR|unix.O_CREAT, 0666)`. Запиши в него байты через `unix.Write(fd, data)`. Прочитай через `unix.Read(fd, buf)`. Закрой через `unix.Close(fd)`.

5. **Использование `epoll` для асинхронного ввода-вывода.**: Напишите TCP-сервер с использованием `epoll` напрямую (через `unix.EpollCreate`, `unix.EpollCtl`, `unix.EpollWait`). Реализуйте неблокирующий accept и чтение. Сравните с обычным `net` пакетом по задержке.

6. Напишите программу, которая использует `syscall.Syscall6` для вызова `getpid` (или `getuid`) на Linux. Сравните с `os.Getpid()`. Объясните, почему в Go предпочтительнее пакеты `syscall`/`golang.org/x/sys/unix` вместо прямого inline-asm.

7. **Первый syscall**: Вызовите `syscall.Write(1, []byte("Hello\n"))` для вывода в stdout без использования `fmt`.

8. **File operations**: Откройте файл через `syscall.Open()`, прочитайте через `syscall.Read()`, закройте через `syscall.Close()`.

9. **[mmap — Memory Mapped Files]**: Открой файл. Используй `unix.Mmap(fd, 0, length, unix.PROT_READ|unix.PROT_WRITE, unix.MAP_SHARED)`. Измени байты прямо в возвращенном слайсе `[]byte`. Вызови `unix.Munmap(b)`. Открой файл в редакторе — изменения должны быть сохранены на диск без вызова `Write`.

10. **Сырой Write (Без пакета `fmt`)**: Напиши "Hello, OS!" в консоль, используя только функцию `unix.Write(unix.Stdout, []byte("..."))`. Ты обращаешься напрямую к файловому дескриптору `1` (STDOUT).

11. **Process creation**: Создайте дочерний процесс через `syscall.ForkExec()` (или `syscall.Clone()` на Linux).

12. **Signals**: Отправьте сигнал процессу через `syscall.Kill(pid, syscall.SIGTERM)`.

13. **Работа с сигналами через `syscall`.**: Установите обработчик сигналов (SIGINT, SIGTERM) с помощью `syscall.Signal` или `unix.Sigaction`. Перехватите сигнал и выполните корректный shutdown, не используя `signal.Notify` (только системные вызовы).

14. **Environment variables**: Получите переменные окружения через `syscall.Getenv()` (не путать с `os.Getenv()`).

15. **Получение системной информации**: Используй `unix.Getpid()`, `unix.Getuid()`, `unix.Getpagesize()` (размер страницы памяти в твоей ОС) и `unix.Uname()` для получения версии ядра Linux/Darwin. Распечатай результаты.

Выполните сисколл получения ID текущего процесса (например, `syscall.SYS_GETPID` в Linux/macOS) и выведите возвращаемое значение.

    Создайте HTTP сервер без использования стандартной библиотеки `net/http`:
    
    **Requirements:**
    * Raw socket programming через syscalls.

    * Zero-copy response через mmap для статических файлов.
    * Graceful shutdown с ожиданием активных соединений.
    
    **Architecture:**
    * Main goroutine: accept loop + epoll wait.
    * Worker goroutines: обработка HTTP запросов.
    * Epoll instance: мониторинг всех клиентских сокетов.
    * Signal handling: SIGTERM для graceful shutdown.
    
    **Performance targets:**
    * 100k+ concurrent connections.
    * < 1ms latency для простых запросов.
    * Минимальное количество аллокаций (используйте buffer pools).
    * Сравните производительность с `net/http` и `fasthttp`.
    
    **Advanced features:**
    * HTTP/1.1 keep-alive.
    * Chunked transfer encoding.
    * Static file serving через mmap + sendfile() syscall.
    * Rate limiting через token bucket в памяти.
    * Metrics: connections, requests/sec, latency percentiles.
    
    **Optimization techniques:**
    * `runtime.LockOSThread()` для epoll thread.
    * `GOMAXPROCS` tuning для worker threads.
    * Buffer pooling через `sync.Pool`.
    * Zero-copy string conversions через unsafe.
    * Batch processing epoll events.
    
    **Testing:**
    * Load testing через `wrk` или `vegeta`.
    * Сравнение с nginx, net/http, fasthttp.
    * Memory profiling через pprof.
    * Goroutine leak detection.
