Упражнение #1

Три способа инициализации массива: Zero values, явный литерал и эллипсис [...]

📌 Условие задачи

Инициализация массива: Объявите массив из 5 элементов типа int. Инициализируйте его тремя способами: по умолчанию (zero values), явным списком значений в литерале, и с помощью синтаксиса многоточия [...]int{...}.

💡 Теоретический фундамент и концепция

Массивы (Arrays) в Go:

1. Массив — это структура данных фиксированной длины, непрерывно расположенная в памяти;
2. Длина массива является неотъемлемой частью его типа ([5]int и [10]int — два абсолютно разных, несовместимых типа!);
3. Способы инициализации:
  • var a [5]int — все элементы инициализируются нулями (Zero Values);
  • b := [5]int{10, 20, 30, 40, 50} — явное перечисление;
  • c := [...]int{1, 2, 3, 4, 5} — компилятор сам подсчитывает количество элементов (длина равна 5).

🔍 Пошаговый ход решения и ход мысли инженера

1. Объявляем var a [5]int.
2. Объявляем b := [5]int{10, 20, 30, 40, 50}.
3. Объявляем c := [...]int{1, 2, 3, 4, 5}.
4. Выводим значения и типы всех трех массивов.
📄 main.go 
package main

import "fmt"

func main() {
	// 1. По умолчанию (zero values)
	var arr1 [5]int

	// 2. Явный литерал со всеми элементами
	arr2 := [5]int{10, 20, 30, 40, 50}

	// 3. Синтаксис многоточия (размер определяет компилятор)
	arr3 := [...]int{100, 200, 300, 400, 500}

	fmt.Printf("1. Zero values: %v (тип: %T)\n", arr1, arr1)
	fmt.Printf("2. Явный:       %v (тип: %T)\n", arr2, arr2)
	fmt.Printf("3. Эллипсис:    %v (тип: %T)\n", arr3, arr3)
}

Массив выделяется единым непрерывным блоком на стеке. [5]int занимает ровно $5 imes 8 = 40$ байт без служебных заголовков.

⚠️ Частые грабли и ошибки новичков
  • Использование [...]int в качестве типа параметра функции func f(a [...]int): синтаксис [...] разрешен только в литералах объявления, но запрещен в сигнатурах типов!
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «В чем отличие [...]int{1, 2} от []int{1, 2}?»

Ответ: [...]int{1, 2} создает статический массив [2]int на стеке (память $O(1)$ без аллокаций в куче). []int{1, 2} создает срез — 24-байтную структуру-дескриптор SliceHeader, указывающую на базовый массив.

Упражнение #2

Прямой доступ к элементам массива по индексу и вычисление длины len()

📌 Условие задачи

Объяви массив [5]int, заполни его значениями {10, 20, 30, 40, 50}. Выведи длину через len и каждый элемент по индексу.

💡 Теоретический фундамент и концепция

Индексация массивов:

  • Индексы в Go начинаются с $0$ и заканчиваются $ ext{len}(arr) - 1$;
  • Доступ arr[i] имеет сложность $O(1)$ по времени;
  • Функция len(arr) для массивов вычисляется на этапе компиляции (Compile-Time Constant) и не требует инструкций в рантайме.

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем массив [5]int{10, 20, 30, 40, 50}.
2. Печатаем длину len(arr).
3. В цикле выводим элементы по прямому индексу arr[i].
📄 main.go 
package main

import "fmt"

func main() {
	numbers := [5]int{10, 20, 30, 40, 50}

	fmt.Printf("Массив: %v | Длина массива: %d\n\n", numbers, len(numbers))

	for i := 0; i < len(numbers); i++ {
		fmt.Printf("numbers[%d] = %d (адрес: %p)\n", i, numbers[i], &numbers[i])
	}
}

⚠️ Частые грабли и ошибки новичков
  • Обращение к отрицательному индексу arr[-1]: в Go отрицательная индексация запрещена и вызывает ошибку компиляции invalid array index -1.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Является ли вызов len(arr) для массива [100]int функцией рантайма?»

Ответ: Нет! Для массивов len(arr) и cap(arr) являются константами времени компиляции (Compile-time Constants). Компилятор сразу подставляет число 100 в машинный код.

Упражнение #3

Гарантия инициализации Zero Values для неинициализированного массива

📌 Условие задачи

Объявите массив из 5 целых чисел, не инициализируя его. Выведите значения по умолчанию (zero values).

💡 Теоретический фундамент и концепция

Безопасность памяти в Go (Zero Initialization):

  • В Go нет концепции «мусора в памяти» (Uninitialized Memory), как в C/C++;

package main

import "fmt"

	for idx, val := range data {
		fmt.Printf("  data[%d] = %d\n", idx, val)
	}
}

Упражнение #5

Вычисление суммы и произведения элементов массива [7]int за один проход

📌 Условие задачи

Создайте массив из 7 чисел, найдите сумму и произведение всех элементов.

💡 Теоретический фундамент и концепция

Алгоритмический проход по массиву с накоплением суммы (нейтральный элемент 0) и произведения (нейтральный элемент 1).

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем массив [7]int{2, 3, 5, 7, 11, 13, 17}.
2. Инициализируем sum = 0 и product = 1.
3. В одном цикле аккумулируем оба значения.
📄 main.go 
package main

import "fmt"

func main() {
	primes := [7]int{2, 3, 5, 7, 11, 13, 17}

	sum := 0
	product := 1

	for _, n := range primes {
		sum += n
		product *= n
	}

	fmt.Printf("Массив:       %v\n", primes)
	fmt.Printf("Сумма:        %d\n", sum)
	fmt.Printf("Произведение: %d\n", product)
}

⚠️ Частые грабли и ошибки новичков
  • Инициализация product = 0: любое умножение на 0 оставит произведение нулевым.

📌 Условие задачи

Значимая семантика массива: Создай a := [3]int{1, 2, 3}. Присвой b := a. Измени b[0]. Выведи оба массива и убедись, что массивы в Go копируются целиком.

💡 Теоретический фундамент и концепция

Value Semantics (Семантика значений):

1. В Go массивы являются типами-значениями (Value Types), а НЕ ссылочными типами (в отличие от Java, C#, JS или Python);
2. Операция присваивания b := a создает абсолютно независимую копию всех элементов в новом блоке памяти;
3. Модификация b[0] = 999 никак не влияет на массив a.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем a := [3]int{1, 2, 3}.
2. Присваиваем b := a.
3. Мутируем b[0] = 999.
4. Сравниваем адреса памяти и значения a и b.
📄 main.go 
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := a // Полное глубокое копирование массива a в b!

	// Изменяем копию b:
	b[0] = 999

	fmt.Printf("Массив a: %v (адрес: %p)\n", a, &a)
	fmt.Printf("Массив b: %v (адрес: %p)\n", b, &b)
}

  • Ожидание, что массивы ведут себя как срезы (slices): срез скопировал бы заголовок и мутировал общую память, а массив копирует данные целиком!

Вопрос с собеседования: «Почему в Go для передачи коллекций данных в функции практически всегда используют срезы []T, а не массивы [N]T?»

🔍 Пошаговый ход решения и ход мысли инженера

package main

import "fmt"

func IsArrayPalindrome(arr [6]int) bool {
	i, j := 0, len(arr)-1
	for i < j {
		if arr[i] != arr[j] {
			return false
		}
		i++
		j--
	}
	return true
}

func main() {
	arr1 := [6]int{1, 2, 3, 3, 2, 1}
	arr2 := [6]int{1, 2, 3, 4, 2, 1}

	fmt.Printf("Массив %v -> Палиндром: %t\n", arr1, IsArrayPalindrome(arr1))
	fmt.Printf("Массив %v -> Палиндром: %t\n", arr2, IsArrayPalindrome(arr2))
}

💡 Теоретический фундамент и концепция

Алгоритм Bubble Sort для массивов строк:

  • Внешний цикл $N-1$ проходов;
  • Внутренний цикл сравнивает длины len(arr[j]) > len(arr[j+1]);
  • Атомарный обмен элементов на месте arr[j], arr[j+1] = arr[j+1], arr[j].

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем массив [5]string{"Go", "Kubernetes", "C", "Python", "Rust"}.

3. Выводим отсортированный массив.
📄 main.go 
package main

import "fmt"

func BubbleSortByLength(arr *[5]string) {
	n := len(arr)
	for i := 0; i < n-1; i++ {
		for j := 0; j < n-i-1; j++ {
			if len(arr[j]) > len(arr[j+1]) {
				arr[j], arr[j+1] = arr[j+1], arr[j]
			}
		}
	}
}

func main() {
	words := [5]string{"Kubernetes", "Go", "TypeScript", "C", "Rust"}

	fmt.Printf("До сортировки:    %v\n", words)
	BubbleSortByLength(&words)
	fmt.Printf("После сортировки: %v\n", words)
}

Выход за границы: Создайте массив arr [3]int. Попробуйте обратиться к arr[5] напрямую. Посмотрите на ошибку компиляции. Теперь создайте переменную index := 5 и попробуйте обратиться к arr[index]. 💡 Теоретический фундамент и концепция

Механика защиты границ (Bounds Checking) в Go:

1. Константный индекс arr[5]: Компилятор статически знает, что len(arr) == 3. Так как $5 \ge 3$, компилятор выдает ошибку на этапе сборки: invalid array index 5 (out of bounds for 3-element array);
2. Динамический индекс arr[index]: Значение переменной index может зависеть от ввода пользователя или рантайм-логики. Компилятор вставляет инструкцию проверки границ:

if uint(index) >= uint(len(arr)) { runtime.panicIndex() };

3. В рантайме программа падает с контролируемой паникой panic: runtime error: index out of range [5] with length 3, предотвращая уязвимость переполнения буфера (Buffer Overflow).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем массив arr := [3]int{10, 20, 30}.
2. Объясняем статическую ошибку arr[5].
3. Создаем переменную index := 5 и перехватываем runtime panic через recover().
📄 main.go 
package main

import "fmt"

func SafeAccess(arr [3]int, idx int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("⚠️ Перехвачена паника: %v\n", r)
		}
	}()

	fmt.Printf("Попытка доступа к arr[%d]...\n", idx)
	val := arr[idx] // Вызовет runtime panic при idx >= 3!
	fmt.Printf("Значение: %d\n", val)
}

func main() {
	arr := [3]int{10, 20, 30}

	// 1. Статический выход за границы:
	// _ = arr[5] // ОШИБКА КОМПИЛЯЦИИ: invalid array index 5 (out of bounds for 3-element array)

	// 2. Динамический выход за границы (Runtime Panic):
	SafeAccess(arr, 1) // Корректный индекс
	SafeAccess(arr, 5) // Невалидный индекс -> Panic
}

⚙️ Под капотом Go (Compiler, Linker & Runtime)

Компилятор использует оптимизацию CMPQ idx, $3; JAE panicIndex (беззнаковое сравнение отлавливает и отрицательные индексы, и выход за верхнюю границу одной инструкцией).

  • Игнорирование проверки индексов перед обращением к массиву в сетевых парсерах.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Как проверка границ (Bounds Checking) защищает Go-сервисы от атак типа Heartbleed?»

Ответ: Heartbleed в OpenSSL произошел из-за отсутствия проверки длины буфера в C, что позволило злоумышленникам вычитать приватные ключи из чужой памяти. В Go любой выход за границы гарантированно прерывается рантайм-паникой, исключая утечку произвольной памяти.
