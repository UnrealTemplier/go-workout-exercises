# Ассемблер Go (Plan 9 Assembly) и SIMD

В этом файле собраны уникальные упражнения по теме **"Ассемблер Go (Plan 9 Assembly) и SIMD"**, отсортированные по возрастанию сложности.

---

1. **Objdump и hot path.**: Напишите функцию `SumSlice([]int64) int64`. Соберите через `go build -gcflags="-S"` или `go tool objdump -s SumSlice`. Найдите цикл, инструкции `MOVQ`, `ADDQ`, bounds check (`CMPQ`, `JAE`). Объясните, как компилятор Go (SSA backend) генерирует код.

2. **Calling Convention Go.**: Изучите `src/runtime/sys_amd64.s` или документацию. Объясните: параметры передаются в `AX`, `BX`, `CX`, `DX`, `DI`, `SI`, стек; возврат в `AX` (для int/pointer). Напишите функцию `func Add(a, b int64) int64` на Plan 9 assembly (`TEXT ·Add(SB), NOSPLIT, $0-24; MOVQ a+0(FP), AX; ADDQ b+8(FP), AX; MOVQ AX, ret+16(FP); RET`). Объясните синтаксис `a+0(FP)`.

3. **Bounds Check Elimination.**: Напишите функцию, которая суммирует слайс с `for i := 0; i < len(s); i++`. Затем оптимизированную версию: `n := len(s); for i := 0; i < n; i++`. Сравните ассемблерный вывод. Объясните, почему compiler иногда убирает bounds check, а иногда нет (зависит от proof в SSA).

4. **Первая функция на ассемблере Go.**: Напишите ассемблерный файл `.s` с функцией `Add(x, y int) int`, использующей инструкции `ADDQ`. Свяжите с Go-функцией, объявленной как `func Add(x, y int) int` без тела.

5. **Простая функция на asm.**: Напишите на Plan 9 assembly функцию `Max(a, b int64) int64`, которая возвращает максимум. Соберите через `go test`. Объясните директиву `//go:linkname` и `//go:noescape` (если используете unsafe).

6. **[Базовый ассемблер]**: Создай файл `add.s`. Напиши функцию на Go Plan 9 Assembly, которая складывает два `int64` и возвращает результат (`ADDQ R8, R9, AX` / `RET`). Вызови её из Go.

7. **Assembly + unsafe: memcpy.**: Напишите функцию `FastCopy(dst, src []byte) int` на assembly, копирующую байты через `MOVQ` (8 байт за раз) и `MOVB` для остатка. Сравните с `copy(builtin)`. Объясните, почему builtin `copy` может использовать `REP MOVSB` или `AVX` и обычно быстрее ручного кода.

8. **Ассемблерная оптимизация хот-спота.**: Найдите узкое место в Go-коде (например, вычисление хэша), перепишите критический цикл на asm с использованием регистров. Сравните бенчмарком.

9. **SIMD через cgo.**: Напишите C-функцию с AVX2 intrinsics (`_mm256_add_epi32` или `_mm256_loadu_si256`), скомпилируйте через cgo. Вызовите из Go для суммирования двух массивов `[]int32`. Сравните с pure Go. Объясните оверхед cgo (~100 ns) и когда он амортизируется (большие массивы).

10. **[SIMD: AVX2 (Addition)]**: Напиши ассемблерную функцию `AddFloatsAVX2(a, b []float32, res []float32)`. Используй инструкции `VMOVDQU` (загрузка 256-бит / 8 float32), `VADDPS` (сложение 8 чисел за один такт), `VMOVDQU` (выгрузка). Сравни скорость с обычным Go-циклом.

11. **SIMD через Go Assembly (AVX2).**: Напишите функцию `SumFloat32AVX2(f []float32) float32` на Plan 9 assembly с использованием AVX2 инструкций: `VMOVUPS`, `VADDPS`, `VEXTRACTF128`. Объясните, что Go assembler поддерживает AVX/AVX2 через префиксы `V` и операнды `Y0`-`Y15`. Сравните с scalar loop.

12. **Использование SIMD для пакетной обработки.**: Реализуйте функцию суммирования слайса `[]int32` с помощью AVX2 инструкций через план9 asm (или cgo + интринсики). Сравните скорость с обычным циклом на больших массивах.

13. **Unrolled loop.**: Напишите суммирование массива `[]int64` с разворотом цикла (4 итерации за проход). Объясните, почему unrolling уменьшает branch misprediction и позволяет ILP (Instruction Level Parallelism). Сравните с ассемблерным выводом компилятора (Go compiler делает unrolling автоматически при `-gcflags="-B"`? Нет, Go compiler редко unroll, покажите ручное).

14. **[Каверзный кейс — Assembly BYTE Directives]**: Plan 9 ассемблер не поддерживает новейшие инструкции AVX-512. Напиши функцию, использующую `BYTE` директивы (прямая запись опкодов процессора) для вызова инструкции, которой нет в Go ASM.

15. **Первый Assembly файл**: Создай `math.go` с пустой функцией `func Add(a, b int64) int64`. Рядом создай `math_amd64.s`. Напиши на языке Plan 9 Assembly (диалект ассемблера в Go) функцию: прочитай `a` и `b` из стека, сложи (инструкция `ADDQ`) и положи в результат. Вызови из `main`.

16. **Branchless code.**: Реализуйте `Abs(x int64) int64` через `mask := x >> 63; return (x ^ mask) - mask` (без `if`). Покажите в objdump отсутствие `JMP`. Объясните, почему branchless предпочтителен в hot loops (нет branch prediction misses).

17. **Работа с флагами процессора.**: Определите поддержку AVX2/SSE4.2 через `runtime` или `golang.org/x/sys/cpu`. Используйте условный вызов asm-функции при наличии SIMD, иначе – fallback на Go.

18. **Профилирование + оптимизация.**: Используйте `perf` (Linux) или `go test -cpuprofile`: найдите функцию, которая занимает >30% CPU. Перепишите её критический участок на assembly или измените структуру данных (SoA). Покажите до/после в `go tool pprof`.

19. **[Строки и SIMD]**: Реализуй `IndexByte` (поиск байта в слайсе) на ассемблере с использованием `PCMPEQB` (сравнение 16 байт одновременно). Сравни со стандартным `bytes.IndexByte`.

20. **Дизассемблирование**: Напиши простую функцию на Go и скомпилируй её командой `go tool compile -S math.go`. Изучи сгенерированный ассемблерный код. Найди, как компилятор настраивает стек-фреймы и как передает регистры (в современном Go используется register-based calling convention).

21. **Умножение матриц через SIMD.**: Реализуйте умножение двух матриц 4x4 float32 с помощью SSE/NEON инструкций на ассемблере. Сравните производительность с наивной реализацией на Go.

22. **Векторизация (SIMD)**: Изучи, что такое SIMD (Single Instruction, Multiple Data). Обычный процессор складывает два массива в цикле по 1 элементу за раз. SIMD инструкции (например, AVX2) могут сложить по 4 или 8 чисел (`float64`) за ОДИН такт процессора!

23. **[Avo / PeachPy]**: Изучи кодогенераторы ассемблера для Go (например, `github.com/mmcloughlin/avo`). Напиши генератор, который создает AVX2 код для умножения матриц, чтобы не писать опкоды вручную.

24. **Инлайн-ассемблер через `unsafe` (функционально).**: Продемонстрируйте вставку машинных инструкций в срез байт, изменение разрешения памяти на исполнение (через `syscall.Mmap` с `PROT_EXEC`) и вызов. Обсудите риски.

25. **Ваша первая ассемблерная функция (Plan 9)**: Объявите в Go-файле функцию `AddASM(a, b int64) int64` без тела. В этой же директории создайте файл `add_amd64.s` (или под вашу архитектуру) с синтаксисом Plan 9 Assembly. Напишите ассемблерную реализацию функции:
    * Считайте аргументы из стека/регистров (учитывая соглашение о вызовах Go Calling Convention — регистровое в Go 1.17+).
    * Сложите значения.
    * Верните результат.
    Протестируйте вызов этой функции из Go.

26. **Использование `avo`**: Писать ассемблер руками больно и опасно. Установи `github.com/mmcloughlin/avo` — библиотеку, которая генерирует Go Assembly с помощью обычного Go-кода. Напиши скрипт-генератор, который создает `.s` файл для быстрого попарного сложения двух слайсов на базе AVX-инструкций.

27. **[Memory Fences]**: Используй `runtime.StoreLoadFence()` или `MFENCE` в ассемблере. Объясни, почему на слабых архитектурах памяти (ARM) переупорядочивание инструкций процессором может сломать Lock-Free алгоритмы, написанные для x86 (где модель памяти строгая — Total Store Order).

28. **Профилирование на уровне инструкций с `perf` и `objdump`.**: Скомпилируйте Go-бинарник с `-gcflags="-S"` для вывода asm, найдите неэффективные участки с помощью `perf record`, `perf annotate`. Оптимизируйте на основе анализа.

29. **Оптимизация строк (IndexByte)**: Напиши бенчмарк, который ищет символ в строке на 10 МБ с помощью цикла `for` и с помощью `strings.IndexByte`. Посмотри исходники `IndexByte` — ты увидишь, что "под капотом" она реализована на чистом Assembly с использованием SIMD, поэтому работает в десятки раз быстрее.

30. **Векторные вычисления SIMD (AVX2 / SSE / NEON)**: Напишите ресурсоемкую математическую задачу: покомпонентное сложение двух огромных векторов (слайсов) `[]float32` (размером 10 000 000 элементов).
    * Реализуйте базовый вариант на чистом Go (в цикле).
    * Напишите оптимизированную версию на ассемблере Plan 9, используя векторные SIMD-инструкции процессора (например, `VADDPS` для параллельного сложения 8 вещественных чисел за одну инструкцию на x86 AVX2).
    Запустите бенчмарк сравнения обеих функций и проанализируйте разницу в скорости.

31. **SIMD JSON (Парсинг будущего)**: Установи `github.com/minio/simdjson-go` (порт сверхбыстрого C++ парсера JSON). Сравни его скорость со стандартным `encoding/json`. Пойми, что для парсинга гигабайтов JSON в реальном времени стандартная рефлексия не годится — нужен SIMD-парсер, который ищет кавычки и скобки по 32 байта за раз.

32. **Директива `go:noescape` и `go:nosplit`**: При объявлении ассемблерных функций добавь над ними эти прагмы. Узнай, что `go:noescape` говорит компилятору не делать Escape Analysis для аргументов функции (ускоряет работу памяти), а `go:nosplit` запрещает рантайму проверять размер стека горутины (экономит такты, но может вызвать панику, если стек переполнится).

33. **Struct of Arrays > Array of Structs для SIMD.**: Если вы обрабатываете одно поле множества объектов (например, все X координаты), SoA позволяет SIMD обрабатывать 8 значений одновременно.

34. **Huge pages для memory-intensive workloads.**: TLB misses expensive. Huge pages (2MB/1GB) снижают TLB misses в 512x/262144x. Используйте для больших data structures.
