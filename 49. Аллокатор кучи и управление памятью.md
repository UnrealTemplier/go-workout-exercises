# Аллокатор кучи и управление памятью

В этом файле собраны уникальные упражнения по теме **"Аллокатор кучи и управление памятью"**, отсортированные по возрастанию сложности.

1. **Архитектура аллокатора (TCMalloc)**: Опишите трехуровневую иерархию аллокатора кучи Go в комментариях к коду [483]:
    * `mcache` — персональный локальный кэш каждого процессора `P` для сверхбыстрой аллокации мелких объектов без блокировок [483].
    * `mcentral` — центральный пул свободных спанов, сгруппированных по классам размеров (size classes), защищенный мьютексом [483].
    * `mheap` — глобальная куча, запрашивающая страницы памяти напрямую у операционной системы [483].

3. **Понимание спанов (`mspan`) и фрагментации**: Память в Go нарезается на страницы (pages) размером 8 КБ, которые объединяются в структуры `mspan`. Каждый спан нарезается на ячейки фиксированного размера (size classes, всего около 67 классов). Объясните в комментариях концепцию внутренней фрагментации памяти: почему при аллокации структуры размером 33 байта рантайм выделит под неё ячейку из класса 48 байт, и куда деваются "лишние" 15 байт.

4. **Динамический рост стека**: Стек горутины в Go начинается всего с 2 КБ. Напишите рекурсивную функцию глубокой вложенности (например, вычисление факториала без оптимизации хвостовой рекурсии). Объясните в комментариях, как Go расширяет стек: при достижении лимита рантайм выделяет новый сегмент памяти в куче (в 2 раза больше предыдущего), полностью копирует туда текущий стек и автоматически корректирует все указатели (stack split/growth).

6. **Tiny, Small, Large allocations:**
    * Tiny: < 16 bytes (special handling, может объединять несколько аллокаций)
    * Small: 16 bytes - 32 KB (через mspan)
    * Large: > 32 KB (напрямую из mheap)

8. **mcache**: Каждый P имеет свой `mcache` — локальный кэш `mspan`'ов для разных size classes. Это позволяет аллоцировать без блокировок.

9. **mcentral**: Когда `mcache` истощается, он запрашивает новые `mspan`'ы из `mcentral` (глобальный для каждого size class, с блокировкой).

10. **[Tiny Allocator (< 16 bytes)]**: Напиши структуру из двух полей `bool` и `int8` (занимает 2 байта). Создай миллион таких структур. Объясни, как Tiny Allocator объединяет маленькие объекты (< 16B) в один блок 16B, чтобы уменьшить фрагментацию памяти.

11. **mheap**: Глобальный heap, управляющий всей памятью процесса. Содержит все `mspan`'ы, организованные в radix tree для быстрого поиска.

12. **Иерархия: mcache → mcentral → mheap.**: Напишите программу, интенсивно выделяющую объекты разного размера (маленькие <32KB, большие). Соберите профиль памяти (`pprof`), определите, из каких классов размеров (size classes) выделялась память, и в каких компонентах аллокатора.

13. **mspan**: Непрерывный блок памяти, состоящий из нескольких страниц (8KB каждая). Содержит объекты одного size class.

14. **Page allocation**: Изучите, как runtime запрашивает страницы у ОС через `mmap`/`VirtualAlloc` и возвращает через `munmap`/`VirtualFree`.
