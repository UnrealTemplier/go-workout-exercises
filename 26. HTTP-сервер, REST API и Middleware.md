# HTTP-сервер, REST API и Middleware

В этом файле собраны уникальные упражнения по теме **"HTTP-сервер, REST API и Middleware"**, отсортированные по возрастанию сложности.

---

1. Создай обработчик `/time`, который возвращает текущее время в формате `time.Now().Format(time.RFC3339)`.

2. Запустите HTTP-сервер с одним обработчиком `/`, возвращающим «Hello, World!».

3. Реализуй интерфейс `http.Handler` на своей структуре (метод `ServeHTTP(w, r)`). Передай эту структуру в `http.ListenAndServe`.

4. Добавьте маршруты `/hello`, `/time`, `/json` с разными ответами (текст, текущее время, JSON-структура).

6. Используй `http.HandlerFunc` для привязки обычной функции к маршруту.

7. Зарегистрируйте несколько хендлеров с помощью `http.HandleFunc` для разных путей (`/home`, `/about`).

8. Напиши **handler с path-параметрами** без фреймворков: `GET /users/123/profile`. Используй `strings.TrimPrefix(r.URL.Path, "/users/")` + `strings.Split` для извлечения `id`. Верни `"user_id": 123`.

9. Используйте `http.ServeMux` (созданный явно через `http.NewServeMux()`, а не глобальный `http.DefaultServeMux`) для изоляции роутинга.

10. Извлеки query-параметры из входящего запроса: `r.URL.Query().Get("name")`. Выведи приветствие с этим именем.

11. Реализуйте HTTP-клиент, делающий GET-запрос к публичному API (например, `https://api.github.com`) и выводящий статус ответа.

12. Напиши **REST API** с полным CRUD (in-memory `map[int]User` + `sync.RWMutex`):
- `GET /users` — список
- `GET /users/{id}` — один пользователь
- `POST /users` — создать
- `PUT /users/{id}` — обновить
- `DELETE /users/{id}` — удалить

13. Извлеките значение переменной пути (`id` через `r.PathValue("id")`) и query-параметры (`?page=2&sort=desc` через `r.URL.Query()`).

14. **[Сложный роутинг (Go 1.22+)]**: Используй новый синтаксис роутинга: `mux.HandleFunc("GET /users/{id}", ...)`. Извлеки `id` из `r.PathValue("id")`.

15. Напиши **JSON API handler**: `POST /api/users`. Прочитай тело `r.Body` (`json.NewDecoder(r.Body).Decode(&user)`), валидируй (имя не пустое, возраст > 0), верни `201 Created` с созданным JSON. Не забудь `defer r.Body.Close()`.

16. Отправьте POST-запрос с JSON-телом на свой сервер. Сервер должен распарсить тело в структуру и вернуть её обратно с подтверждением.

17. Напишите хендлер, который принимает JSON в теле запроса, десериализует его в структуру (используйте `json.Decoder` и `DisallowUnknownFields`) и возвращает JSON-ответ.

18. Напиши **middleware chain**: `LoggingMiddleware → AuthMiddleware → RateLimitMiddleware → Handler`. Покажи композицию: `chain := Logging(RateLimit(Auth(handler)))`.

19. Напиши **Auth middleware**: проверяй заголовок `Authorization: Bearer <token>`. Если токен неверен — верни `401 Unauthorized`. Если верен — добавь `user_id` в `context.Context` через `context.WithValue` и передай дальше.

20. Правильно устанавливайте HTTP статус-коды с помощью `http.Error` или `w.WriteHeader()`. Поймите, почему `WriteHeader` нужно вызывать **строго до** первой записи в `w`.

21. Напиши **Request ID middleware**: генерируй UUID (или `rand`) для каждого запроса, добавь в контекст. Все логи внутри handler'а должны включать этот ID. Добавь заголовок `X-Request-ID` в ответ.
