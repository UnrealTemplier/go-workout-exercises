1. **Простейший TCP Echo-сервер**: Напишите программу, которая слушает порт `8080` по протоколу TCP с помощью `net.Listen`. При подключении клиента сервер должен войти в бесконечный цикл, считывать входящие данные и отправлять их обратно клиенту (эхо). Закройте соединение, когда клиент отключится.

2. **TCP-сервер (Echo)**: Используй `net.Listen("tcp", ":8080")`. Напиши цикл, который принимает подключения (`Accept()`). При подключении читай данные из соединения и отправляй их обратно клиенту (эхо). (Для теста используй утилиту `telnet` или `nc` в консоли).

3. Напиши **TCP-эхо-сервер**: `net.Listen("tcp", ":8080")`, принимай соединение `Accept()`, читай строку через `bufio.Reader`, пиши её обратно с префиксом `"Echo: "`. Закрой соединение после одного ответа.

4. Напишите TCP-клиент, который подключается к `google.com:80`, отправляет сырой HTTP GET-запрос (просто строку) и читает ответ.

5. Создайте TCP-сервер на `localhost:8080`, который принимает соединения и отправляет «Hello, client!» каждому подключившемуся.

6. Модифицируй сервер из 15.1: обрабатывай каждое соединение в **отдельной горутине**. Сервер должен принимать множество клиентов одновременно без блокировки.

7. Напиши **line-delimited protocol**: сервер читает строки (`ReadString('\n')`), парсит команду (`"ADD 5 3"` → `8`, `"MUL 4 2"` → `8`), отправляет результат. Клиент отправляет команды интерактивно (чтение из `os.Stdin`).

8. Реализуйте TCP-клиент, который подключается к вашему серверу, читает сообщение и выводит его.

9. **Простейший TCP-клиент**: Напишите клиентское приложение, которое подключается к вашему Echo-серверу с помощью `net.Dial("tcp", "localhost:8080")`. Клиент должен считать строку из консоли (`os.Stdin`), отправить её на сервер, дождаться ответа от сервера, вывести его на экран и завершить работу.

10. Создайте простой TCP-сервер (`net.Listen`), который принимает подключение, читает сообщение от клиента и отправляет его обратно (эхо-сервер).

11. Изучите проблему "Read deadlocks" в TCP: что будет, если клиент подключится, но не отправит данные, а сервер будет вечно ждать в `conn.Read()`? Добавьте `SetReadDeadline`, чтобы решить это.

12. Напиши **length-prefixed protocol**: перед отправкой данных пиши 4 байта (uint32, big-endian) с длиной, затем payload. Сервер читает сначала 4 байта, затем ровно `length` байт. Это надёжнее, чем `\n`.

13. **Конкурентный сервер**: В сервере из 326 вызов `Accept()` блокирует цикл. Оберни обработку каждого соединения в отдельную горутину `go handleConnection(conn)`. Запусти два клиента одновременно и убедись, что сервер работает с обоими параллельно.

14. Реализуйте обмен данными по TCP с использованием "Length-Prefixed" протокола (сначала отправляем 4 байта длины сообщения, затем само сообщение). Это решает классическую проблему "TCP stream framing" (склеивание и разрыв пакетов).

15. Напиши **TCP-чат-сервер**: храни `map[net.Conn]bool` (активные клиенты) с `sync.Mutex`. При получении сообщения от одного клиента — broadcast'ь его всем остальным. Напиши клиент, который читает сообщения в одной горутине и пишет в другой.

16. **Многопоточный TCP-сервер**: Перепишите задачу с TCP-сервером так, чтобы сервер мог обрабатывать множество клиентов одновременно. Каждое новое соединение, возвращаемое методом `listener.Accept()`, должно передаваться в отдельную горутину `go handleConnection(conn net.Conn)`. Проверьте работу сервера, подключившись к нему из нескольких терминалов одновременно (например, с помощью утилиты `nc localhost 8080` или `telnet`).

17. **TCP-Чат (Broadcasting)**: Усложни сервер. Сохраняй все активные `net.Conn` в мапу. Если один клиент присылает сообщение, сервер должен рассылать его всем остальным клиентам из мапы (используй `sync.Mutex` для защиты мапы!).

18. Напиши **TCP-прокси**: сервер слушает `:8080`, при соединении устанавливает второе соединение к `target:9090` и копирует данные в обе стороны (`io.Copy` в двух горутинах). Закрой оба соединения при разрыве любого.

19. Сравните поведение TCP и UDP: что произойдет, если UDP-сервер выключен, а клиент отправит пакет? (Спойлер: клиент не узнает об ошибке, в отличие от TCP).

20. Напиши **TCP-клиент с reconnect**: если соединение разорвано, жди 100ms, 200ms, 400ms... (экспоненциальный backoff) до 5 попыток, затем верни ошибку. Используй `context` для отмены ожидания.

21. Напиши **TCP heartbeat**: клиент каждые 3 секунды отправляет `"PING"`, сервер отвечает `"PONG"`. Если сервер не получил PING за 10 секунд — закрой соединение. Если клиент не получил PONG — переподключись.

23. **UDP-сервер**: UDP работает без установки соединения. Используй `net.ListenUDP`. Читай данные через `ReadFromUDP` (получишь байты и адрес отправителя) и отправляй ответ через `WriteToUDP`.

24. Добавьте обработку множества одновременных клиентов на сервере с помощью горутин. Каждый клиент получает уникальный ID.

25. **Таймауты сокетов**: В TCP-клиенте используй метод `conn.SetDeadline(time.Now().Add(2 * time.Second))`. Убедись, что если сервер долго не отвечает, клиент завершается с ошибкой `i/o timeout`.
