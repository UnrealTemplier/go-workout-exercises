Ниже представлен новый глубокий блок практических упражнений, посвященных **продвинутой работе с данными в Go** (задачи 556–575). 

Этот раздел охватывает распределенные транзакции в документоориентированных базах (MongoDB), высокопроизводительную пакетную вставку в аналитические системы (ClickHouse) через бинарный протокол, поисковую оптимизацию в Elasticsearch/OpenSearch и проектирование Change Data Capture (CDC) систем с низкоуровневым разбором протокола логической репликации PostgreSQL.

### Раздел 44: Продвинутая работа с данными (MongoDB, ClickHouse, Elasticsearch, CDC) (Задачи 556–575)

#### Подраздел 44.1: MongoDB — Транзакции и сессии (Задачи 556–561)

*Работа с MongoDB требует понимания драйвера, управления контекстом через сессии и реализации ACID-транзакций в распределенных реплика-сетах.*

556. **Инициализация подключения и пулинг**: Подключите официальный драйвер MongoDB: `go.mongodb.org/mongo-driver/mongo`. Напишите код инициализации клиента `mongo.Connect`. Настройте параметры пула соединений (`SetMaxPoolSize`, `SetMinPoolSize`, `SetMaxConnIdleTime`). Выполните проверку связи с помощью `client.Ping`.
557. **CRUD на сырых BSON-документах**: Напишите функции для вставки, поиска и обновления документов в коллекции `inventory`. Продемонстрируйте использование различных BSON-типов данных Go:
    * `bson.D` — упорядоченный массив пар "ключ-значение" (используется для запросов фильтрации и обновлений).
    * `bson.M` — неупорядоченная мапа (удобна для простых выборок).
    * `bson.A` — массив BSON-элементов.
558. **Изоляция операций через сессии (Sessions)**: Создайте сессию с помощью метода `client.StartSession()`. Напишите код, который выполняет несколько последовательных операций в рамках одной сессии, передавая `mongo.SessionContext` во все вызовы методов коллекции, чтобы гарантировать логическую связь запросов и контролировать общий таймаут выполнения.
559. **Распределенные транзакции (Multi-document Transactions)**: Представьте, что вам нужно списать средства со счета одного пользователя и начислить их другому внутри MongoDB (в рамках Replica Set). Реализуйте распределенную ACID-транзакцию:
    * Начните сессию.
    * Вызовите метод `session.WithTransaction(ctx, func(sessCtx mongo.SessionContext) (interface{}, error) { ... })`.
    * Внутри функции выполните два обновления документов.
    * Верните ошибку при нехватке средств для автоматического отката (abort) транзакции.
560. **Оптимистическая блокировка (Optimistic Locking)**: Распределенные транзакции в MongoDB создают нагрузку на кластер. Реализуйте паттерн оптимистической блокировки для обновления документов. Добавьте в схему документа поле `version int`. Напишите код обновления баланса пользователя: запрос должен обновлять документ только при условии совпадения версии (`db.collection.UpdateOne(ctx, bson.M{"_id": id, "version": currentVersion}, bson.M{"$inc": bson.M{"balance": amount, "version": 1}})`). Обработайте случай, если запись была изменена параллельным процессом (возвращено 0 измененных документов).
561. **Сложный пайплайн агрегации (Aggregation Pipeline)**: Напишите аналитический запрос для коллекции заказов `orders`. Напишите пайплайн агрегации, состоящий из стадий `$match` (фильтрация по дате), `$unwind` (раскрытие массива товаров), `$group` (группировка по категориям с вычислением суммарной стоимости и среднего количества), `$sort` (сортировка по убыванию объема продаж) и `$project` (переименование полей). Считайте результаты через курсор `mongo.Cursor`.

#### Подраздел 44.2: ClickHouse — Высокопроизводительная аналитическая запись (Задачи 562–567)

*ClickHouse спроектирован для моментальной обработки миллиардов строк, но требует специфического подхода к записи: буферизации данных и использования бинарных протоколов.*

562. **Бинарное подключение к ClickHouse**: Установите современный нативный драйвер ClickHouse `github.com/ClickHouse/clickhouse-go/v2`. Напишите код подключения к БД через нативный TCP-порт (обычно `9000`), используя бинарный протокол. Объясните в комментариях преимущества бинарного протокола перед HTTP-интерфейсом при передаче больших объемов данных.
563. **Пакетная запись (Batch Insertion)**: ClickHouse крайне неэффективно обрабатывает частые поштучные вставки. Напишите высокопроизводительный буферизатор логов в Go:
    * Программа должна накапливать логи во внутреннем слайсе памяти.
    * При достижении 50 000 логов (или раз в 5 секунд) запускать фоновую запись.
    * Выполнять вставку пакетом через методы `db.PrepareBatch(ctx, "INSERT INTO logs ...")` и последовательные вызовы `batch.Append(...)` с последующим отправлением пакета через `batch.Send()`.
564. **Асинхронные вставки (Async Inserts)**: Начиная с версии 21.11, ClickHouse умеет буферизовать вставки на своей стороне. Настройте параметры подключения в вашем Go-драйвере, передав опции `async_insert=1` и `wait_for_async_insert=0`. Напишите бенчмарк сравнения скорости обычной поштучной вставки и асинхронной вставки.
565. **Сопоставление сложных типов данных**: Создайте таблицу логов со сложными типами данных: `DateTime64(3)`, `IPv4`, `Array(String)`, `Map(String, String)`. Напишите код записи структуры лога из Go в ClickHouse. Обеспечьте правильную конвертацию типов данных Go (например, передачу `net.IP` для колонок IP-адресов и срезов слайсов для массивов ClickHouse).
566. **Потоковое чтение результатов**: Напишите аналитический запрос к ClickHouse (например, вычисление 95-го и 99-го перцентилей времени ответа API по часам). Считайте миллионы строк результатов из базы порциями с помощью метода `db.Query` и последовательного сканирования строк, не перегружая оперативную память приложения.
567. **ReplacingMergeTree и дедупликация**: При повторных вставках пакетов (например, после сетевых сбоев) в ClickHouse могут образовываться дубликаты строк. Создайте таблицу на движке `ReplacingMergeTree`. Напишите код записи событий с уникальным идентификатором и версией (timestamp), а также напишите запрос чтения данных, использующий ключевое слово `FINAL` или агрегацию для получения строго уникальных актуальных состояний.

#### Подраздел 44.3: Elasticsearch / OpenSearch — Полнотекстовый поиск (Задачи 568–571)

*Поисковые движки обеспечивают релевантный поиск по нечетким совпадениям. Вы научитесь настраивать маппинги, собирать сложные поисковые запросы и использовать Bulk API.*

568. **Создание индекса и маппинга**: Подключите официальный клиент Elasticsearch для Go: `github.com/elastic/go-elasticsearch/v8`. Напишите код инициализации клиента. Создайте индекс `products` и явно передайте JSON-схему маппинга (mapping), настроив текстовые поля на использование анализатора русской морфологии (`"analyzer": "russian"`).
569. **Сложный полнотекстовый поиск (Bool Query)**: Реализуйте поисковую строку для каталога товаров. Напишите функцию, которая принимает поисковый запрос от пользователя и собирает сложный JSON-запрос для Elasticsearch:
    * Секция `must`: текстовый поиск по полям `title` и `description` с поддержкой нечеткого соответствия (`"fuzziness": "AUTO"`).
    * Секция `filter`: ограничение по диапазону цен (`range`) и категории товара (`term`).
    * Секция `highlight`: подсветка найденных слов в результатах выдачи.
570. **Пакетное индексирование через Bulk API**: Для импорта тысяч товаров в поисковую систему поштучные запросы не подходят. Напишите код пакетного импорта с помощью утилиты `esutil.NewBulkIndexer` [570]. Настройте автоматическую отправку пакетов (флаги `FlushBytes` и `FlushInterval`) [570], а также добавьте обработчики коллбэков успешного индексирования и ошибок (`OnSuccess`, `OnFailure`) для каждого отдельного документа [570].
571. **Агрегации (Faceting)**: При поиске товаров в интернет-магазинах пользователю нужно выводить боковые фильтры с количеством товаров в каждой категории. Напишите поисковый запрос, содержащий секцию `aggs` (aggregations). Реализуйте группировку результатов по брендам (`terms` агрегация) и ценовым диапазонам (`histogram` агрегация). Распакуйте результаты агрегаций из JSON-ответа Elasticsearch в структуры Go.

#### Подраздел 44.4: Change Data Capture (CDC) — Логическая репликация (Задачи 572–575)

*CDC-системы отслеживают изменения в базе данных на лету и транслируют их в другие системы (например, Kafka), гарантируя консистентность данных.*

572. **Подключение к репликационному слоту PostgreSQL**:
    * Настройте локальный PostgreSQL: установите параметр `wal_level = logical`.
    * Создайте публикацию `CREATE PUBLICATION my_pub FOR ALL TABLES`.
    * Напишите Go-код, который открывает специализированное подключение к PostgreSQL в режиме репликации с помощью пакета `github.com/jackc/pgx/v5/pgconn` (передав параметр `replication=database` в строке подключения) [572].
    * Создайте логический слот репликации с помощью метода `pgconn.CreateReplicationSlot` [572], указав плагин вывода `pgoutput`.
573. **Низкоуровневый разбор протокола `pgoutput`**: Напишите код, который в бесконечном цикле считывает сырой поток сообщений WAL из открытого слота репликации с помощью `pgconn.StartReplication`. Напишите парсер байт, который идентифицирует типы сообщений протокола `pgoutput`:
    * `'B'` (Begin) — начало транзакции.
    * `'R'` (Relation) — метаданные схемы таблицы (имена колонок и их типы).
    * `'I'` (Insert) — вставка новой строки (содержит значения колонок).
    * `'U'` (Update) — изменение строки.
    * `'D'` (Delete) — удаление строки.
    * `'C'` (Commit) — фиксация транзакции.
574. **Построение CDC-пайплайна**: Объедините ваш парсер `pgoutput` и продюсера Kafka (из раздела №36). Напишите полноценного CDC-демона: при изменении строки в таблице `users` в PostgreSQL, демон должен мгновенно перехватить это изменение, преобразовать его в структурированное JSON-событие `"UserChanged"` и отправить в топик Kafka.
575. **Управление подтверждениями LSN (Log Sequence Number)**: Если ваш CDC-демон упадет и перезапустится, он должен продолжить чтение WAL строго с того места, на котором остановился, не дублируя события. Напишите код периодической отправки подтверждений LSN (Standby Status Update) обратно в PostgreSQL. Демон должен сохранять максимальный успешно обработанный и отправленный в Kafka LSN и раз в 10 секунд отправлять статус-сообщение серверу PostgreSQL, подтверждая, что эти сегменты WAL можно безопасно очистить с диска.
