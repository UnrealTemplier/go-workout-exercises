### Тема 152: MongoDB — Документоориентированная БД
*MongoDB — это гибкая NoSQL БД с поддержкой ACID-транзакций (с версии 4.0), rich query language и powerful aggregation pipeline.*

1571. **Подключение и ping:** Используйте `go.mongodb.org/mongo-driver` для подключения к MongoDB. Используйте `client.Ping()` с context и timeout.

1572. **Connection string parsing:** Изучите все параметры connection string: `replicaSet`, `authSource`, `readPreference`, `w`, `maxPoolSize`. Используйте `mongo.Options` для programmatic configuration.

1573. **Connection pooling:** Настройте `SetPoolMonitor` для отслеживания событий пула соединений (created, closed, failed). Мониторинг connection leaks.

1574. **Insert operations:** Используйте `InsertOne` и `InsertMany`. Изучите `_id` поле — автогенерация `ObjectID` vs кастомные ID.

1575. **ObjectID структура:** Изучите 12-байтовую структуру ObjectID: timestamp (4 bytes) + random (5 bytes) + counter (3 bytes). Извлеките timestamp через `ObjectID.Timestamp()`.

1576. **Find operations:** Используйте `Find` и `FindOne` с `bson.D` filters. Поймите разницу между `bson.D` (ordered document) и `bson.M` (unordered map).

1577. **Query operators:** Используйте `$eq`, `$gt`, `$lt`, `$in`, `$nin`, `$and`, `$or`, `$not`, `$exists`, `$type`. Постройте сложные queries.

1578. **Projection:** Используйте projection для возврата только нужных полей: `options.Find().SetProjection(bson.D{{"name", 1}, {"_id", 0}})`.

1579. **Update operations:** Используйте `UpdateOne`, `UpdateMany`, `ReplaceOne`. Изучите операторы `$set`, `$unset`, `$inc`, `$push`, `$pull`, `$addToSet`.

1580. **Upsert:** Используйте `options.Update().SetUpsert(true)` для "создать или обновить". Изучите `UpsertedID` в результате.

1581. **Array operations:** Используйте `$push` с `$each`, `$slice`, `$position`. Используйте `$pull` для удаления элементов по условию.

1582. **Delete operations:** Используйте `DeleteOne`, `DeleteMany`. Поймите разницу между `DeleteMany({})` и `Drop()`.

1583. **Bulk operations:** Используйте `BulkWrite` для выполнения множества операций в одном round-trip. Ordered vs Unordered bulk operations.

1584. **Cursor handling:** Используйте `cursor.Next()` в цикле с `defer cursor.Close()`. Поймите, почему нельзя забыть закрыть cursor.

1585. **Decode в структуру:** Используйте `cursor.Decode(&struct)` с `bson` тегами. Изучите `omitempty`, `inline`, `minsize` теги.

### Тема 153: MongoDB — Aggregation Pipeline
*Aggregation pipeline — это мощнейший инструмент для обработки данных в MongoDB.*

1586. **$match stage:** Используйте `$match` для фильтрации документов в начале pipeline (должен быть первым для использования индексов).

1587. **$project stage:** Используйте `$project` для трансформации полей, вычисляемых полей, вложенных полей.

1588. **$group stage:** Используйте `$group` для агрегации по `_id` с `$sum`, `$avg`, `$min`, `$max`, `$push`, `$addToSet`.

1589. **$sort, $skip, $limit:** Реализуйте пагинацию через `$sort` + `$skip` + `$limit`. Поймите, почему `$skip` на больших offset'ах медленный.

1590. **$lookup (JOIN):** Используйте `$lookup` для left outer join между коллекциями. Изучите equijoin vs correlated subquery синтаксис.

1591. **$unwind:** Используйте `$unwind` для "разворачивания" массивов в отдельные документы. Поймите `preserveNullAndEmptyArrays`.

1592. **$addFields:** Используйте `$addFields` для добавления вычисляемых полей без удаления существующих.

1593. **$facet:** Используйте `$facet` для выполнения нескольких aggregations в одном запросе (например, для facet-фильтров в e-commerce).

1594. **$bucket и $bucketAuto:** Используйте для создания гистограмм и диапазонов.

1595. **$graphLookup:** Используйте для рекурсивного обхода графов (например, иерархия категорий, org chart).

1596. **$merge и $out:** Используйте `$out` для записи результата в новую коллекцию, `$merge` для upsert в существующую.

1597. **Window functions:** Используйте `$setWindowFields` (MongoDB 5.0+) для window operations: `$rank`, `$denseRank`, `$documentNumber`, `$shift`.

1598. **Date operations:** Используйте `$year`, `$month`, `$dayOfMonth`, `$dateToString`, `$dateAdd`, `$dateDiff` для работы с датами.

1599. **Conditional expressions:** Используйте `$cond`, `$switch`, `$ifNull` для условной логики в aggregations.

1600. **Aggregation performance:** Используйте `explain()` для анализа плана выполнения. Поймите, какие stages используют индексы.

### Тема 154: MongoDB — Индексы и оптимизация
1601. **Single field index:** Создайте индекс через `collection.Indexes().CreateOne()`. Поймите направление (1 vs -1).

1602. **Compound index:** Создайте индекс на несколько полей. Изучите правило ESR (Equality, Sort, Range) для оптимального порядка.

1603. **Multikey index:** Создайте индекс на массив поле. Поймите ограничения (нельзя индексировать два массивных поля одновременно).

1604. **Text index:** Создайте text index для full-text search. Используйте `$text` с `$search` и `$language`.

1605. **Geospatial index:** Создайте `2dsphere` индекс для geo-запросов. Используйте `$near`, `$geoWithin`, `$geoIntersects`.

1606. **TTL index:** Создайте индекс с `expireAfterSeconds` для автоматического удаления документов (например, сессии, одноразовые токены).

1607. **Wildcard index:** Создайте индекс `$**` для работы с динамической схемой. Поймите overhead.

1608. **Partial index:** Создайте индекс с `partialFilterExpression` для индексации только подмножества документов (снижение размера индекса).

1609. **Sparse index:** Создайте индекс, включающий только документы с существующим полем.

1610. **Unique index:** Создайте уникальный индекс с обработкой `mongo.IsDuplicateKeyError()`.

1611. **Covered queries:** Постройте запрос, который полностью покрывается индексом (no fetch from storage).

1612. **Index intersection:** Поймите, как MongoDB может использовать несколько индексов для одного запроса.

1613. **Profiling:** Включите `db.setProfilingLevel(2)` для логирования всех slow queries. Анализируйте через `system.profile`.

1614. **Explain plans:** Используйте `collection.Aggregate(..., options.Aggregate().SetComment("..."))` и читайте explain output.

### Тема 155: MongoDB — Транзакции, Change Streams и продвинутые возможности
1615. **Multi-document transactions:** Используйте `session.StartTransaction()`, `session.CommitTransaction()`, `session.AbortTransaction()`. Требует replica set.

1616. **Transaction retry logic:** Реализуйте retry при `TransientTransactionError` и `UnknownTransactionCommitResult`.

1617. **Read/Write concerns:** Изучите `w: majority`, `j: true`, `readConcern: snapshot` для strong consistency в транзакциях.

1618. **Causal consistency:** Используйте `session.OperationTime` для причинно-следственной согласованности между операциями.

1619. **Change Streams:** Используйте `collection.Watch()` для real-time подписки на изменения. Поймите resume tokens.

1620. **Change Stream filters:** Используйте `$match` в pipeline для фильтрации событий (например, только inserts в определённую коллекцию).

1621. **Full document lookup:** Используйте `options.ChangeStream().SetFullDocument(options.UpdateLookup)` для получения полного документа после update.

1622. **Change Stream resume:** Реализуйте resumable change stream с сохранением resume token в БД.

1623. **GridFS:** Используйте `gridfs` для хранения больших файлов (>16MB). Изучите chunks и files коллекции.

1624. **Schema validation:** Создайте коллекцию с `$jsonSchema` validator для enforcement схемы на уровне БД.

1625. **Schema design patterns:**
    * **Embedding** (one-to-few): вложенные документы
    * **Referencing** (one-to-many): ObjectID references

    * **Preallocation** для known-size arrays
    * **Outlier pattern** для выбивающихся документов

1626. **Replica sets:** Поднимите 3-нодовый replica set в Docker. Изучите primary/secondary, read preference, failover.

1627. **Sharding:** Настройте sharded cluster с config servers и mongos. Изучите shard key selection (hashed vs ranged).

1628. **Atlas Search:** Используйте Atlas Search (на основе Lucene) для advanced full-text search с facets, highlighting, autocomplete.

### 💡 Золотые правила работы с продвинутыми БД:

#### MongoDB:
1. **Schema design first.** В отличие от SQL, в MongoDB схема определяется паттернами доступа. Embed когда читаете вместе, reference когда читаете отдельно.

2. **Compound indexes — ваше всё.** 90% slow queries в MongoDB решаются правильным compound index. Помните правило ESR (Equality, Sort, Range).

3. **Transactions только когда нужны.** MongoDB transactions имеют overhead. Для большинства use cases достаточно single-document atomicity.

4. **Change Streams для real-time.** Не делайте polling. Используйте Change Streams для event-driven architecture.

5. **Aggregation pipeline — мощный, но опасный.** Сложные pipelines могут быть медленнее, чем application-side processing. Всегда проверяйте `explain()`.

#### ClickHouse:
1. **Batch everything.** ClickHouse оптимизирован для batch inserts (тысячи-миллионы строк). Single-row inserts — это антипаттерн (в 100-1000x медленнее).

2. **Выбирайте правильный MergeTree.** 80% use cases покрываются MergeTree, ReplacingMergeTree, AggregatingMergeTree. Поймите их trade-offs.

3. **Sorting key — это главное.** Первые поля в ORDER BY должны быть в WHERE clause большинства запросов. Иначе full scan.

4. **Materialized views для real-time.** MV — это "триггеры для аналитики". Используйте их для pre-aggregation при ingest.

5. **ClickHouse не для OLTP.** Не используйте ClickHouse для transactional workload'ов с частыми updates. Это read-optimized БД.

#### Elasticsearch:
1. **Mapping first, data later.** Dynamic mapping в production — это техдолг. Всегда определяйте explicit mapping.

2. **Text vs Keyword.** 90% ошибок новичков — использование `text` для filtering/aggregations. Используйте `keyword` для точных совпадений.

3. **Bulk API обязателен.** Single-document indexing в 100x медленнее. Используйте `BulkIndexer` с оптимальным flush interval.

4. **ILM для time-series.** Автоматический rollover, shrink, delete по возрасту. Без ILM вы утонете в management overhead.

5. **Filter context > Query context.** В bool query используйте `filter` для того, что не влияет на score (кэшируется, быстрее).

#### CDC:
1. **Replication slots требуют мониторинга.** Неухоженный slot заполнит диск primary БД. Мониторьте `pg_replication_slots`.

2. **LSN tracking обязателен.** Без сохранения LSN вы потеряете события при рестарте.

3. **Schema evolution — это боль.** Готовьтесь к ALTER TABLE в source БД. Relation messages в pgoutput — ваш друг.

4. **Outbox pattern для reliable events.** Если нужна гарантия доставки вместе с бизнес-транзакцией — используйте outbox, а не direct publish.

5. **Тестируйте failure scenarios.** Что будет, если consumer упадёт на час? Если Kafka недоступен? Если schema изменится?

#### Общие правила:
1. **Right tool for the job.** Не пытайтесь использовать одну БД для всего. PostgreSQL для OLTP, ClickHouse для OLAP, Elasticsearch для поиска, MongoDB для гибкой схемы, Redis для кэша.

2. **Мониторинг обязателен.** Каждая БД должна экспортировать метрики в Prometheus: connection pool usage, query latency, replication lag, disk usage.

3. **Backups тестируйте.** Backup без restore test — это не backup. Регулярно тестируйте восстановление.

4. **Schema migrations в CI.** Используйте golang-migrate или goose для управления схемой. Миграции должны быть в том же PR, что и код.

5. **Connection pooling.**PgBouncer для PostgreSQL, connection pools в драйверах для MongoDB/ClickHouse. Без pooling вы исчерпаете connections.
