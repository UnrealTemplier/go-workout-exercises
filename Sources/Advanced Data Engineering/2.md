### 20. Продвинутая работа с данными (MongoDB, ClickHouse, Elasticsearch, CDC)

#### 20.1 MongoDB (транзакции, агрегации, change streams)
651. **Подключение и базовый CRUD с драйвером `mongo-go-driver`.** Подключитесь к MongoDB, создайте коллекцию `users`, вставьте один документ, найдите его по `_id`, обновите поле, удалите.
652. **Вставка многих документов и пакетные операции.** Реализуйте bulk-вставку 10 000 случайных документов заказов с вложенными массивами позиций. Оцените производительность с `InsertMany` против обычного цикла.
653. **Транзакции на нескольких коллекциях.** Создайте две коллекции: `accounts` и `transactions`. В рамках транзакции спишите сумму с одного счёта и зачислите на другой, атомарно создав документ транзакции. Проверьте откат при ошибке.
654. **Aggregation Pipeline.** Постройте конвейер для расчёта общей суммы продаж по категориям товаров за последний месяц. Используйте `$match`, `$unwind`, `$group`, `$sort`.
655. **Индексы и анализ производительности запросов.** Создайте составной индекс по полям `user_id` и `created_at`. Выполните запрос с фильтром и сортировкой, используя `explain("executionStats")` для проверки покрытия индекса.
656. **Change Streams для реактивной обработки.** Подпишитесь на Change Stream коллекции `orders`. При появлении нового заказа логируйте его ID и сумму. Обработайте возобновление потока при обрыве соединения, используя `resumeAfter`.
657. **Схема валидации.** Создайте коллекцию с JSON Schema, ограничивающей обязательные поля и типы (например, `email` должен быть строкой и соответствовать regex). Попытайтесь вставить невалидный документ и обработайте ошибку.
658. **TTL-индексы для автоматического удаления.** Создайте TTL-индекс на поле `expireAt`. Вставьте документы с временем истечения, убедитесь, что они удаляются через указанный промежуток.

#### 20.2 ClickHouse (аналитическая СУБД, batch-запись)
659. **Подключение через HTTP-интерфейс и выполнение запроса.** Используйте `clickhouse-go` v2. Создайте таблицу `hits` с движком `MergeTree`, партицированием по месяцу `toYYYYMM(event_time)`. Выполните простую вставку и `SELECT count()`.
660. **Пакетная вставка через нативный протокол.** Реализуйте запись 1 миллиона строк аналитических событий (клики) с помощью `Append` в батч драйвера. Оптимизируйте: настройте размер батча, параллельные вставки.
661. **Материализованные представления и агрегация.** Создайте материализованное представление `hits_daily`, которое агрегирует данные из `hits` по дням и источникам. Выполните вставку и проверьте, что представление обновилось.
662. **Nullable и LowCardinality.** Спроектируйте таблицу с колонками `LowCardinality(String)` для статусов и `Nullable(Int32)` для опционального кода ответа. Сравните потребление памяти с обычным `String`.
663. **Массивы и вложенные структуры.** Создайте таблицу с колонкой типа `Array(Tuple(String, Float64))` для хранения корзины товаров. Выполните запрос с `arrayJoin` для разворачивания массива.
664. **Сэмплирование и SAMPLE-ключ.** Настройте `SAMPLE BY` по хэшу пользователя. Выполните запрос с `SAMPLE 0.1` для приблизительной аналитики на 10% данных, сравните скорость с полным сканированием.
665. **Тюнинг слияния кусков и фоновые операции.** Настройте параметры `merge_with_ttl_timeout`, `max_bytes_to_merge_at_max_space_in_pool`. Наблюдайте за фоновыми слияниями через `system.merges`.

#### 20.3 Elasticsearch (поисковые движки)
666. **Индексация документов с маппингом.** Подключитесь к Elasticsearch через `olivere/elastic` или официальный клиент. Создайте индекс `products` с явным маппингом полей (текст с анализатором, keyword, float). Индексируйте 1000 товаров.
667. **Полнотекстовый поиск с ранжированием.** Выполните запрос `match` по полю `description`. Добавьте `fuzziness`, `minimum_should_match`, `boost` для разных полей. Объясните, как работает BM25.
668. **Агрегации: terms, histogram, nested.** Подсчитайте количество товаров по категориям (terms agg). Постройте гистограмму цен с интервалом 10. Используйте `nested` агрегацию для работы с вложенными документами (например, варианты товара).
669. **Обновление по запросу и скрипты.** Увеличьте цену всех товаров определённой категории на 10% с помощью `update_by_query` и Painless скрипта. Проверьте атомарность.
670. **Шардирование, репликация и восстановление.** Настройте индекс с 3 primary shards и 2 replicas. Симулируйте падение узла, проверьте доступность данных. Выполните `_cat/recovery`.
671. **Снапшоты и резервное копирование.** Зарегистрируйте snapshot repository (например, fs). Создайте snapshot индекса, удалите индекс, восстановите из snapshot.
672. **Performance tuning: refresh_interval, translog, кэши.** Измерьте скорость индексации при `refresh_interval=-1`. Настройте `translog` durability. После массовой загрузки включите refresh. Оцените влияние на поисковые запросы.

#### 20.4 CDC PostgreSQL (логическая репликация)
673. **Настройка логической репликации и создание слота.** Настройте PostgreSQL: `wal_level=logical`. Создайте публикацию `pub_users` для таблицы `users`. Создайте слот репликации `slot_users` через `pgoutput`.
674. **Чтение изменений через pgoutput и их обработка.** Используйте библиотеку `pgx` или `wal-listener`. Подключитесь к слоту, читайте сообщения репликации (insert, update, delete). Десериализуйте `pgoutput.Message` в структуру и логируйте.
675. **Построение микросервиса, реагирующего на изменения.** Реализуйте микросервис, который слушает слот репликации, при появлении новой записи в `users` отправляет приветственное письмо (заглушка) и обновляет кэш Redis. Учтите обработку ошибок и перезапуск слота с сохранением LSN.
