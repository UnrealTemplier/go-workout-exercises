### 10. gRPC и микросервисы

#### 10.1 Protobuf и генерация кода
396. Установите `protoc` и плагины `protoc-gen-go` и `protoc-gen-go-grpc`. Создайте простой `.proto`-файл с сервисом `Greeter` и методом `SayHello`.
397. Добавьте в сообщение вложенные поля, `enum` и поле с `repeated`. Сгенерируйте Go-код.
398. Используйте `google.protobuf.Timestamp` и `google.protobuf.Duration` в своих сообщениях. Научитесь преобразовывать их в `time.Time` и `time.Duration`.
399. Определите сервис с потоковыми RPC: client streaming, server streaming, bidirectional streaming. Сгенерируйте код и изучите интерфейсы.

#### 10.2 Простейший gRPC-сервер и клиент
400. Реализуйте сервер `Greeter`: метод `SayHello` возвращает приветствие с переданным именем. Запустите сервер на порту 50051.
401. Напишите консольный клиент, который вызывает `SayHello` и выводит ответ. Добавьте таймаут через `context.WithTimeout`.
402. Добавьте серверу метод `GetUser(id int32) returns User`. Реализуйте его на сервере, возвращая тестовые данные. Клиент вызывает его и выводит поля.

#### 10.3 Потоковые вызовы
403. Server streaming: реализуйте метод `ListUsers(stream UserService_ListUsersServer)`, который отправляет нескольких пользователей по одному. Клиент читает поток до EOF.
404. Client streaming: метод `CreateUsers(stream UserService_CreateUsersServer)` — клиент отправляет несколько пользователей, сервер собирает их и возвращает количество созданных.
405. Bidirectional streaming: чат-сервис `Chat(stream ChatService_ChatServer)`, где клиенты и сервер обмениваются сообщениями в реальном времени. Реализуйте эхо-сервер и клиента, отправляющего несколько сообщений.

#### 10.4 Обработка ошибок и статусы
406. Верните из серверного метода `codes.NotFound` с детальным сообщением, если пользователь не найден. Клиент проверяет статус-код с помощью `status.FromError`.
407. Используйте богатые детали ошибки (`google.rpc.Status`): при ошибке валидации прикрепите к статусу `BadRequest` с информацией о поле, вызвавшем ошибку.
408. Обработайте `status.Code` на клиенте и реализуйте повторные попытки при `Unavailable` (с exponential backoff).

#### 10.5 Interceptors (перехватчики)
409. Unary interceptor для логирования каждого запроса: метод, длительность, статус. Подключите его к серверу.
410. Stream interceptor для трекинга потоковых сообщений (логирование начала и конца потока).
411. Client interceptor, который добавляет в метаданные заголовок `x-request-id` со сгенерированным UUID.
412. Серверный interceptor для аутентификации: проверяет JWT-токен в метаданных и отклоняет запрос с `Unauthenticated`, если токен невалиден.

#### 10.6 Микросервисы: service discovery и балансировка
413. Запустите два экземпляра одного gRPC-сервиса на разных портах. Напишите клиент с ручным списком адресов и простым round-robin (выбор следующего адреса).
414. Используйте `dns` резолвер gRPC: зарегистрируйте несколько адресов для имени в `/etc/hosts` (или локальном DNS) и проверьте балансировку с `grpc.Dial("dns:///service:50051")`.
415. Подключите балансировщик на стороне клиента с `round_robin` (через `google.golang.org/grpc/balancer`). Запустите 3 сервера, клиент должен равномерно распределять запросы.
416. Интегрируйте Consul или etcd (можно в Docker) для динамического обнаружения сервисов. Клиент подписывается на изменения и обновляет список адресов.

#### 10.7 Устойчивость и паттерны
417. Реализуйте client-side circuit breaker: если сервер возвращает ошибки подряд, клиент временно прекращает вызовы. Используйте библиотеку `gobreaker` или самодельный пороговый счётчик.
418. Добавьте retry с exponential backoff и jitter: настройте политику повторных попыток через перехватчик клиента.
419. Настройте deadline propagation: сервер, получая запрос с дедлайном, передаёт его остаток в исходящий вызов к другому сервису.
420. Реализуйте health check: добавьте серверу реализацию `grpc_health_v1` и проверяйте его состояние из клиента перед запросами.

#### 10.8 Трейсинг и наблюдаемость
421. Интегрируйте OpenTelemetry: инструментируйте сервер и клиент для трассировки запросов. Передавайте trace context через метаданные gRPC.
422. Экспортируйте трассы в Jaeger (локально в Docker) и проанализируйте цепочку вызовов между двумя микросервисами.
423. Добавьте метрики (Prometheus) для gRPC методов: количество запросов, длительность, ошибки. Используйте перехватчики для сбора.

#### 10.9 Продвинутые темы
424. Реализуйте асинхронную обработку: клиент отправляет запрос, сервер возвращает `operation_id`, клиент опрашивает статус операции другим RPC.
425. Используйте серверную рефлексию (`grpc.reflection.v1alpha.ServerReflection`) для удобной отладки с `grpcurl`.
426. Настройте mTLS между сервисами: клиент и сервер обмениваются сертификатами, проверяют друг друга.
427. Создайте gRPC-gateway: сгенерируйте REST-прокси для вашего сервиса и предоставьте доступ через HTTP/JSON параллельно с gRPC.
428. Реализуйте переключение между REST и gRPC в одном приложении с помощью `grpc-gateway` и `ServeMux`.
429. Соберите несколько сервисов в docker-compose: `users`, `orders`, `gateway`. Настройте их взаимодействие по gRPC с healthcheck и зависимостями.
430. Напишите интеграционный тест, который поднимает все сервисы (можно с testcontainers), выполняет полный пользовательский сценарий и проверяет корректность данных.
