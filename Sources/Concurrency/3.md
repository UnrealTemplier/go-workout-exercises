Конкурентность (concurrency) — это визитная карточка Go. Это то, ради чего многие переходят на этот язык. Но это и самая сложная тема, полная подводных камней: гонки данных (data races), утечки горутин (goroutine leaks), дедлоки (deadlocks) и нюансы работы с памятью.

Здесь **65 упражнений** (с 281 по 345), которые проведут тебя от создания первой горутины до сложных паттернов и каверзных собеседованийческих кейсов.

### Блок 25: Паттерны конкурентности (Concurrency Patterns)
*Цель: Применить комбинации каналов и горутин для решения архитектурных задач.*

330. **Generator:** Напиши функцию, которая возвращает канал и генерирует в нем числа Фибоначчи бесконечно.
331. **Fan-Out:** Создай один канал с задачами (числами). Запусти 3 горутины-обработчика (воркера), которые читают из этого канала и выводят результат с своим ID.
332. **Fan-In:** Создай две функции-генератора, возвращающие каналы. Напиши функцию `merge`, которая читает из обоих каналов и отправляет данные в один общий выходной канал.
333. **Pipeline:** Создай 3 стадии. Стадия 1 генерирует числа. Стадия 2 возводит их в квадрат (читает из канала 1, пишет в канал 2). Стадия 3 печатает результат (читает из канала 2).
334. **Worker Pool (Пул воркеров):** Создай очередь заданий (канал на 100 элементов). Запусти фиксированное количество воркеров (например, 5), которые читают задания и "обрабатывают" (sleep random time). Дождись выполнения всех заданий через `WaitGroup`.
335. **Tee (Разветвитель):** Напиши функцию, которая читает из одного канала и дублирует данные в два независимых выходных канала.
336. **Rate Limiting (Ограничение скорости):** Используй `time.Tick` (например, каждые 200ms) для ограничения частоты обработки запросов. Запросы поступают быстрее, но обрабатываются только по тику.
337. **Done Channel Pattern (Устаревший, но важный):** Реализуй отмену горутины через закрытие специального канала `done chan struct{}` (до эры `context`).
338. **Semaphor Pattern:** Используй буферизированный канал `make(chan struct{}, 3)` для ограничения количества одновременно работающих горутин (максимум 3).
339. **[Высокая сложность] Publish/Subscribe (Шина событий):** Создай структуру `Broker`. Метод `Subscribe()` возвращает новый канал. Метод `Publish(msg)` рассылает сообщение всем подписчикам (горутина бродкастит во все каналы). Реализуй отписку.

### Блок 26: Сложные, каверзные и комплексные случаи
*Цель: Подготовка к реальным багам и вопросам на собеседованиях.*

341. **[Утечка горутин 2]:** Напиши код, где получатель ждет данные из канала, но отправитель завершился, не закрыв канал. Получатель заблокируется навсегда. Исправь, закрывая канал через `defer`.
342. **[Захват переменной в цикле (Go < 1.22)]:** Напиши цикл, создающий горутины `for i := 0; i < 3; i++ { go func() { fmt.Println(i) }() }`. В старых версиях Go выведет "3 3 3". (Если используешь Go 1.22+, создай структуру с полем и передай её по указателю, чтобы сэмулировать ту же проблему). Исправь через передачу аргумента.
343. **[Разделяемая мапа (Concurrent Map Write)]:** Запусти 10 горутин, пишущих в одну `map[int]int`. Поймай фатальную ошибку `concurrent map writes`. Исправь с помощью `sync.Mutex` (создай `SafeMap` структуру).
344. **[Канал каналов (Channel of Channels):** Напиши функцию, которая возвращает канал каналов. Используй это, чтобы динамически создавать новые каналы для ответов (request-reply pattern).
345. **[Финальное испытание — Concurrency Safe Cache]:** Реализуй структуру `Cache` с методами `Get(key string) (interface{}, bool)` и `Set(key string, val interface{}, ttl time.Duration)`. Внутри храни данные в мапе. Защити мапу `sync.RWMutex`. Реализуй автоматическое удаление устаревших записей (TTL) с помощью фоновой горутины, которая раз в секунду чистит кэш, или лениво при `Get`. Обработай корректное завершение фоновой горутины через `context.Context`.
