### 26. Безопасность инфраструктуры и SecOps (Supply Chain, Network Hardening, Seccomp)

#### 26.1 Защита цепочки поставок (Supply Chain Security)
791. **Запуск `govulncheck` локально.** Установите `govulncheck`, просканируйте свой модуль на известные уязвимости. Проанализируйте вывод и исправьте найденные уязвимости (обновлением версий).
792. **Интеграция `govulncheck` в CI/CD.** Добавьте шаг `govulncheck ./...` в GitHub Actions или GitLab CI. Настройте падение пайплайна при обнаружении уязвимостей высокого уровня.
793. **Генерация SBOM (Software Bill of Materials).** Используйте `syft` или встроенную поддержку Go (`go version -m <binary>` и `go.sum`) для создания списка зависимостей. Экспортируйте SBOM в формате SPDX/CycloneDX.
794. **Сканирование SBOM на уязвимости.** Запустите `grype` на сгенерированном SBOM, проанализируйте результат. Настройте автоматическое сканирование SBOM при каждой сборке.
795. **Подписание и верификация модулей.** Изучите механизм Go Checksum Database (`sum.golang.org`). Настройте `GONOSUMCHECK` для приватных модулей. Подпишите свой модуль с помощью `cosign` и проверьте подпись при сборке.
796. **Блокировка зависимостей с известными уязвимостями.** Настройте инструмент (например, `osv-scanner` с фильтром) так, чтобы CI падал при наличии уязвимостей с CVSS выше 7.0 в зависимостях.
797. **Вендоринг для заморозки зависимостей.** Выполните `go mod vendor`, закоммитьте папку `vendor/` в репозиторий. Настройте сборку с флагом `-mod=vendor`, гарантируя отсутствие сетевых запросов при сборке.
798. **Мониторинг транзитивных зависимостей.** Настройте Dependabot или Renovate для автоматического обновления зависимостей. Проанализируйте Pull Request с обновлением, проверяя тесты и уязвимости.

#### 26.2 Защита сетевых сокетов от Slowloris и других атак
799. **Базовые таймауты сокета.** Напишите TCP-сервер, который устанавливает `SetReadDeadline`, `SetWriteDeadline` для каждого соединения. Проверьте, что медленный клиент отключается по тайм-ауту.
800. **Настройка HTTP-сервера с защитными таймаутами.** Сконфигурируйте `http.Server` с параметрами: `ReadTimeout: 5s`, `ReadHeaderTimeout: 2s`, `WriteTimeout: 10s`, `IdleTimeout: 30s`. Проверьте, что Slowloris-атака (медленная отправка заголовков) блокируется.
801. **Ограничение размера заголовков.** Установите `http.MaxBytesReader` для ограничения размера тела запроса. Для заголовков используйте `http.Server.MaxHeaderBytes`. Протестируйте запрос с гигантскими заголовками.
802. **Лимит одновременных соединений через семафор.** Реализуйте middleware-обёртку над `http.Handler`, ограничивающую количество параллельно обрабатываемых запросов. При превышении лимита возвращайте `503 Service Unavailable`.
803. **Системные лимиты через `ulimit` и `sysctl`.** Настройте `ulimit -n 65535` для увеличения количества открытых файлов. Установите `net.core.somaxconn=4096`, `net.ipv4.tcp_max_syn_backlog=8192` для защиты от SYN-флуда.
804. **Включение TCP SYN Cookies.** Включите `net.ipv4.tcp_syncookies=1`. Объясните, как это помогает противостоять SYN flood без использования большого объёма памяти.
805. **Использование `SO_REUSEPORT` для распределения нагрузки.** Напишите программу, которая создаёт несколько слушающих сокетов с `SO_REUSEPORT`, и ядро равномерно распределяет соединения между ними. Проверьте масштабируемость.

#### 26.3 Seccomp, capabilities и контейнерная безопасность
806. **Создание Seccomp профиля для Go-приложения.** С помощью `strace` определите системные вызовы, используемые вашим сервером. Создайте seccomp-профиль, разрешающий только их. Запустите приложение с этим профилем через `docker run --security-opt seccomp=profile.json`.
807. **Запуск с минимальными capabilities.** В Dockerfile задайте `USER nonroot`, удалите все capabilities, кроме необходимых (`NET_BIND_SERVICE` для портов <1024). Проверьте, что приложение не может выполнить `CAP_SYS_ADMIN` операции.
808. **AppArmor профиль для Go-сервиса.** Создайте простой AppArmor профиль, ограничивающий доступ к файловой системе (только чтение конфигурационного файла). Загрузите профиль и запустите сервис в enforce mode.
809. **Воспроизводимые сборки (Reproducible Builds).** Соберите бинарник с флагами `-trimpath` и `-ldflags="-buildid="`. Убедитесь, что два последовательных запуска дают идентичный хэш (с точностью до `mod_timestamp`). Настройте CI для проверки детерминированности сборки.
810. **Интеграция с Fail2Ban для защиты SSH/HTTP.** Настройте Fail2Ban на анализ логов вашего Go-приложения (например, неудачные попытки аутентификации) и временную блокировку IP через iptables.
