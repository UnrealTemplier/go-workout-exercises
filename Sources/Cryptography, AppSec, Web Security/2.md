### 19. Криптография и безопасность приложений (AppSec / Web Security)

#### 19.1 Симметричное шифрование (AES-GCM, AES-CBC, потоковые шифры)
626. **Генерация случайных ключей и nonce.** Используя `crypto/rand`, сгенерируйте 256-битный ключ для AES-256 и 96-битный nonce для GCM. Запишите их в файл в hex-кодировке. Прочитайте обратно.
627. **Шифрование и расшифровка AES-GCM.** Реализуйте функции `Encrypt(plaintext, key []byte) (ciphertext []byte, err error)` и `Decrypt(ciphertext, key []byte) (plaintext []byte, err error)` с использованием `crypto/aes` и `crypto/cipher`. Nonce генерируйте случайно и предваряйте им шифротекст.
628. **Потоковое шифрование больших файлов.** Зашифруйте большой файл (>100MB) с использованием AES-CTR. Реализуйте потоковое чтение/запись через `cipher.StreamWriter` и `cipher.StreamReader`, не загружая весь файл в память.
629. **Детектирование подделки (аутентификация).** Зашифруйте сообщение через AES-GCM, затем измените один байт в шифротексте (имитация атаки) и попытайтесь расшифровать. Убедитесь, что `Decrypt` возвращает ошибку `cipher.ErrAuthenticationFailed`.
630. **AES-CBC с HMAC (Encrypt-then-MAC).** Реализуйте шифрование через AES-CBC вручную (с PKCS#7 padding), а затем вычислите HMAC-SHA256 от шифротекста. Ключи для AES и HMAC должны быть разными (выведите их из мастер-ключа через HKDF). Проверьте порядок: сначала проверяйте HMAC, потом расшифровывайте.

#### 19.2 Асимметричное шифрование и подпись (RSA, ECDSA, Ed25519)
631. **Генерация пары ключей RSA.** Сгенерируйте 2048-битный RSA-ключ, сохраните приватный ключ в PEM-файл с паролем, публичный — в открытый PEM. Прочитайте ключи обратно.
632. **Шифрование RSA-OAEP.** Используйте публичный ключ RSA для шифрования сообщения (короткого, например, ключа AES) с помощью `crypto/rsa.EncryptOAEP`. Расшифруйте приватным ключом. Продемонстрируйте, что для больших данных это неэффективно — используйте гибридное шифрование: RSA для ключа, AES для данных.
633. **Цифровая подпись Ed25519.** Сгенерируйте пару ключей Ed25519 (`ed25519.GenerateKey`). Подпишите сообщение и проверьте подпись. Измените сообщение — подпись не должна пройти проверку.
634. **ECDSA на кривой P-256.** Реализуйте подпись и проверку с `ecdsa`. Сравните размер подписи и скорость с Ed25519 (бенчмарк).
635. **Иерархический детерминированный ключ (HKDF).** Используйте `golang.org/x/crypto/hkdf` для вывода нескольких криптографических ключей из одного мастер-секрета (например, ключ для шифрования и ключ для MAC). Продемонстрируйте на AES и HMAC.

#### 19.3 Хэширование паролей (bcrypt, Argon2)
636. **bcrypt: хэширование и проверка.** Захешируйте пароль с bcrypt (cost=12). Проверьте пароль функцией `bcrypt.CompareHashAndPassword`. Покажите, что разные хэши одного пароля не равны, но проверка проходит.
637. **Argon2id: защита от GPU-атак.** Реализуйте хэширование паролей с помощью `golang.org/x/crypto/argon2`. Настройте параметры: memory=64MB, iterations=3, parallelism=4. Сгенерируйте случайную соль. Создайте строку хэша в формате PHC (Password Hashing Competition) и функцию проверки.
638. **Сравнение bcrypt и Argon2 по времени и памяти.** Напишите бенчмарк, который замеряет время хэширования и верификации для bcrypt (cost=10) и Argon2id (разные параметры). Выберите оптимальные параметры для интерактивной аутентификации.
639. **Защита от тайминг-атак.** Реализуйте собственную (уязвимую) функцию сравнения строк через `==` и безопасную через `crypto/subtle.ConstantTimeCompare`. Покажите разницу в поведении через измерение времени (искусственно, с пояснением опасности).

#### 19.4 Современные токены: PASETO
640. **Создание локального токена PASETO (v2.local).** Используйте библиотеку `aidantwoods/go-paseto` (или аналог). Создайте симметричный ключ, зашифруйте payload (JSON с `user_id`, `exp`). Расшифруйте и проверьте.
641. **Публичный токен PASETO (v2.public).** Сгенерируйте пару Ed25519, подпишите токен с утверждениями (claims). Проверьте подпись публичным ключом. Покажите, что без приватного ключа невозможно создать валидный токен.
642. **Сравнение JWT и PASETO.** Напишите пример создания JWT с HS256 и с RS256. Покажите уязвимость JWT: подпись `alg=none` (если библиотека это позволяет) или путаница алгоритмов. Продемонстрируйте, как PASETO избавлен от этих проблем.
643. **PASETO с footer.** Добавьте в токен footer (незашифрованные, но аутентифицированные данные), например, `kid` (Key ID). При проверке токена убедитесь, что footer совпадает с ожидаемым.

#### 19.5 OAuth2 и OpenID Connect (OIDC)
644. **Реализация OAuth2 Authorization Code Flow (конфиденциальный клиент).** Напишите HTTP-сервер, который перенаправляет пользователя на Google/Facebook, получает callback с кодом, обменивает код на токен через `golang.org/x/oauth2`. Сохраните access и refresh токены.
645. **Проверка ID Token (OIDC).** При аутентификации через Google получите ID Token. Проверьте JWT-подпись с помощью `JWK` (JSON Web Key Set), полученных с `https://accounts.google.com/.well-known/openid-configuration`. Используйте `github.com/coreos/go-oidc`.
646. **Реализация собственного OAuth2-сервера (минимального).** Создайте сервер, выдающий access token по client credentials grant. Используйте библиотеку `go-oauth2/oauth2`. Защитите ресурс, требующий валидный токен.
647. **Refresh Token Rotation.** Реализуйте механизм: при использовании refresh token выпускается новый access token и новый refresh token, старый инвалидируется. Обнаружьте повторное использование refresh token и отзовите все токены пользователя.

#### 19.6 Защита от уязвимостей API
648. **Ограничение размера тела запроса.** Реализуйте HTTP middleware, который ограничивает размер тела запроса (например, 1MB) с помощью `http.MaxBytesReader`. При превышении возвращайте `413 Request Entity Too Large` до того, как тело будет полностью прочитано.
649. **Защита от SSRF.** Напишите HTTP-клиент, который принимает URL от пользователя и загружает ресурс. Реализуйте защиту: запретите доступ к внутренним IP-адресам (127.0.0.0/8, 10.0.0.0/8, 169.254.0.0/16), проверяйте DNS-резолвинг, запрещайте редиректы на внутренние адреса. Используйте кастомный `Dialer`.
650. **Защита от XML External Entity (XXE) и бомб.** Реализуйте XML-парсер (например, `encoding/xml`), который принимает пользовательский XML. Покажите, как злоумышленник может включить внешнюю сущность (если бы это было возможно). Затем продемонстрируйте безопасную конфигурацию: запрет внешних сущностей и DTD (через `xml.Decoder` с `Strict: true` и отсутствием `Entity`).
