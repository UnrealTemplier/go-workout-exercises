## Часть XXIII. Deploy, CI/CD, Docker, Kubernetes

### 123. Docker — основы и Go-приложения

**Упражнение 23.1.** Напиши **базовый Dockerfile** для Go-приложения: `FROM golang:1.24-alpine AS builder`, `WORKDIR /app`, `COPY go.mod go.sum .`, `RUN go mod download`, `COPY . .`, `RUN CGO_ENABLED=0 GOOS=linux go build -o main ./cmd/app`. Собери: `docker build -t myapp:v1 .`. Запусти: `docker run -p 8080:8080 myapp:v1`.

**Упражнение 23.2.** Оптимизируй Dockerfile через **multi-stage build**: stage 1 — builder (`golang:1.24-alpine`), stage 2 — `FROM scratch` или `gcr.io/distroless/static`. Копируй только бинарник: `COPY --from=builder /app/main /main`. `ENTRYPOINT ["/main"]`. Сравни размер: 300MB → 5MB.

**Упражнение 23.3.** Добавь **non-root user**: `RUN adduser -D -u 1000 appuser`, `USER appuser`. Покажи, что root в контейнере — security risk (container escape). Проверь `whoami` внутри контейнера.

**Упражнение 23.4.** Добавь **health check**: `HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1`. Docker автоматически перезапускает unhealthy контейнер.

**Упражнение 23.5.** Настрой **.dockerignore**: исключи `*.md`, `.git/`, `vendor/`, `*_test.go`, `.env`, `docker-compose.yml`. Покажи, что уменьшает build context и ускоряет сборку.

**Упражнение 23.6.** Напиши **Dockerfile с BuildKit cache mounts**: `RUN --mount=type=cache,target=/go/pkg/mod go mod download`. Кэшируй `go mod download` между сборками даже при изменении кода. Ускорь CI сборку в 10 раз.

**Упражнение 23.7.** Напиши **Dockerfile с secrets**: `RUN --mount=type=secret,id=github_token cat /run/secrets/github_token`. Используй `docker build --secret id=github_token,env=GITHUB_TOKEN`. Покажи, что secrets не попадают в image layers (безопасно).

**Упражнение 23.8.** Собери **cross-platform image**: `docker buildx build --platform linux/amd64,linux/arm64 -t myapp:v1 --push`. Используй `buildx` с QEMU эмуляцией или нативными builder'ами. Покажи multi-arch manifest.

**Упражнение 23.9.** Оптимизируй **image layers**: минимизируй количество `RUN` команд (но не жертвуй читаемостью). Используй `&&` для объединения. Покажи `docker history myapp:v1` — каждый слой добавляет размер.

**Упражнение 23.10.** Напиши **docker-compose.yml** для локальной разработки: `app` (Go, hot reload через `air` или `fresh`), `postgres`, `redis`, `jaeger`. Volumes: `./:/app` для live code sync. Networks: `backend`. Покажи `docker-compose up`.

### 124. Docker — продвинутые техники

**Упражнение 23.11.** Настрой **Docker network**: `docker network create mynet`. Запусти `app` и `postgres` в одной сети. Обращайся по имени контейнера: `postgres:5432`. Покажи DNS resolution в Docker.

**Упражнение 23.12.** Настрой **Docker volumes**: named volume `postgres_data` для persistence. `docker run -v postgres_data:/var/lib/postgresql/data`. Покажи, что данные сохраняются при удалении контейнера.

**Упражнение 23.13.** Настрой **bind mounts vs volumes**: bind mount `./config:/app/config` для development (live sync). named volume для production data. tmpfs mount `/tmp` для sensitive data (не пишется на диск).

**Упражнение 23.14.** Напиши **Docker Compose override**: `docker-compose.yml` (production), `docker-compose.override.yml` (development, автоматически подхватывается), `docker-compose.test.yml` (CI). Покажи `docker-compose -f docker-compose.yml -f docker-compose.test.yml up`.

**Упражнение 23.15.** Настрой **resource limits**: `deploy.resources.limits.memory: 512M`, `deploy.resources.limits.cpus: '1.0'`, `deploy.resources.reservations.memory: 256M`. Покажи OOM Killer при превышении memory limit.

**Упражнение 23.16.** Настрой **restart policy**: `restart: unless-stopped` (development), `restart: always` (production), `restart: on-failure:3` (CI). Покажи поведение при `docker stop` vs crash.

**Упражнение 23.17.** Напиши **init-контейнер**: `migrations` контейнер запускается перед `app`, выполняет `golang-migrate`, завершается. `app` зависит от `migrations` (`depends_on` + condition). Покажи job pattern в Compose.

**Упражнение 23.18.** Настрой **log rotation**: `logging.driver: "json-file"`, `logging.options.max-size: "10m"`, `logging.options.max-file: "3"`. Предотвращи заполнение диска логами. Альтернатива: `logging.driver: fluentd` для centralized logging.

**Упражнение 23.19.** Настрой **Docker security**: `--security-opt=no-new-privileges`, `--cap-drop=ALL`, `--cap-add=NET_BIND_SERVICE` (если нужен порт <1024), `--read-only` root filesystem + tmpfs для `/tmp`. Покажи hardened container.

**Упражнение 23.20.** Сканируй **vulnerabilities**: `docker scan myapp:v1` (Snyk) или `trivy image myapp:v1`. Проанализируй отчёт. Обнови base image, удали ненужные пакеты. Покажи CI gate: `CRITICAL` CVE = build failure.

### 125. CI/CD — GitHub Actions

**Упражнение 23.21.** Создай **базовый workflow**: `.github/workflows/ci.yml`. Triggers: `on: [push, pull_request]`. Jobs: `test` (checkout, setup Go, `go test -race -cover`), `build` (depends on test, `go build`). Покажи green check на PR.

**Упражнение 23.22.** Добавь **matrix strategy**: `strategy: matrix: go-version: ['1.22', '1.23', '1.24'], os: [ubuntu-latest, windows-latest]`. Покажи параллельный запуск на всех комбинациях.

**Упражнение 23.23.** Добавь **cache**: `actions/cache@v4` для `~/go/pkg/mod` и `~/.cache/go-build`. Ключ: `go-mod-${{ hashFiles('go.sum') }}`. Покажи ускорение CI с 5 минут до 1 минуты.

**Упражнение 23.24.** Добавь **lint**: `golangci-lint` через `golangci/golangci-lint-action@v6`. Конфиг `.golangci.yml`: `linters: [errcheck, gosimple, govet, ineffassign, staticcheck, typecheck, unused]`. Gate: lint failure = build failure.

**Упражнение 23.25.** Добавь **security scan**: `gosec` (SAST), `nancy` (dependency vulnerabilities), `trivy` (container scan). Gate: `HIGH`/`CRITICAL` = failure. Покажи security-first pipeline.

**Упражнение 23.26.** Добавь **coverage reporting**: `go test -coverprofile=coverage.out -covermode=atomic`. `go tool cover -html=coverage.out -o coverage.html`. Upload to Codecov/Coveralls. Gate: coverage < 80% = failure (или warning).

**Упражнение 23.27.** Добавь **Docker build and push**: `docker/login-action` → `docker/build-push-action`. Tag: `ghcr.io/${{ github.repository }}:${{ github.sha }}`, `ghcr.io/${{ github.repository }}:latest`. Push to GitHub Container Registry.

**Упражнение 23.28.** Добавь **semantic versioning**: `semantic-release` или `go-semantic-release`. Автоматический `git tag` + GitHub Release на merge в `main`. Docker tag: `v1.2.3`, `v1.2`, `v1`. Покажи automated changelog.

**Упражнение 23.29.** Добавь **multi-environment deployment**: `dev` (auto on PR merge), `staging` (auto on tag `v*-rc*`), `production` (manual approval). GitHub Environments + protection rules. Покажи promotion pipeline.

**Упражнение 23.30.** Добавь **infrastructure as code validation**: `terraform validate`, `terraform plan` (comment on PR). `kubeval` / `kubeconform` для Kubernetes manifests. Gate: invalid config = build failure.

### 126. CI/CD — GitLab CI, Jenkins, ArgoCD

**Упражнение 23.31.** Перепиши pipeline на **GitLab CI**: `.gitlab-ci.yml`. Stages: `test`, `build`, `deploy`. `image: golang:1.24`. Cache: `key: "$CI_COMMIT_REF_SLUG"`, paths: `/go/pkg/mod`. Покажи similarity/difference с GitHub Actions.

**Упражнение 23.32.** Настрой **GitLab CI with runners**: shared runners vs specific runners (tagged `docker`, `k8s`). Self-hosted runner on Kubernetes (`gitlab-runner` Helm chart). Покажи scaling runners.

**Упражнение 23.33.** Настрой **Jenkins pipeline** (declarative): `Jenkinsfile`. Stages: `Checkout`, `Test`, `Build`, `Deploy`. Agents: `docker` agent `golang:1.24`. Shared library for common steps. Покажи enterprise CI.

**Упражнение 23.34.** Настрой **ArgoCD** (GitOps): `Application` CRD. Source: Git repo with K8s manifests. Destination: `https://kubernetes.default.svc`, namespace `production`. Sync policy: `automated` (prune, self-heal). Покажи declarative continuous delivery.

**Упражнение 23.35.** Настрой **ArgoCD App of Apps**: root `Application` manages other `Application`s. `apps/dev/`, `apps/staging/`, `apps/prod/`. Покажи managing multiple environments from single repo.

**Упражнение 23.36.** Настрой **Argo Rollouts**: `Rollout` CRD (replacement for `Deployment`). Strategies: `Canary` (1% → 10% → 50% → 100%), `BlueGreen` (active/preview). Analysis: `prometheus` query for auto-promotion/rollback. Покажи progressive delivery.

**Упражнение 23.37.** Настрой **Flux CD** (alternative to ArgoCD): `GitRepository` + `Kustomization` + `ImagePolicy` + `ImageUpdateAutomation`. Автоматическое обновление image tag в Git при новом Docker image. Покажи GitOps with Flux.

**Упражнение 23.38.** Настрой **Tekton** (cloud-native CI/CD): `Task`, `TaskRun`, `Pipeline`, `PipelineRun`. Reusable tasks: `git-clone`, `buildah`, `kubectl-deploy`. Покажи Kubernetes-native CI/CD.

### 127. Kubernetes — основы и Go-приложения

**Упражнение 23.39.** Напиши **Deployment manifest**: `apiVersion: apps/v1`, `kind: Deployment`. `replicas: 3`, `selector: matchLabels: app: myapp`. `template: spec: containers: - name: app, image: myapp:v1, ports: - containerPort: 8080`. Примени: `kubectl apply -f deployment.yml`.

**Упражнение 23.40.** Напиши **Service manifest**: `kind: Service`, `type: ClusterIP`, `selector: app: myapp`, `ports: - port: 80, targetPort: 8080`. Покажи internal load balancing между pods.

**Упражнение 23.41.** Напиши **ConfigMap**: `kind: ConfigMap`, `data: DATABASE_URL: postgres://...`, `LOG_LEVEL: info`. Подключи в pod: `envFrom: - configMapRef: name: app-config`. Покажи externalized configuration.

**Упражнение 23.42.** Напиши **Secret**: `kind: Secret`, `type: Opaque`, `stringData: DB_PASSWORD: secret123`. Base64 encoding автоматический. Подключи: `env: - name: DB_PASSWORD, valueFrom: secretKeyRef: name: app-secrets, key: DB_PASSWORD`. Покажи secrets management (но не для production — use external secrets operator).

**Упражнение 23.43.** Напиши **PersistentVolumeClaim**: `kind: PersistentVolumeClaim`, `accessModes: ReadWriteOnce`, `resources: requests: storage: 10Gi`. Подключи к pod для stateful data. Покажи, что Deployment pods — stateless, PVC — stateful.

**Упражнение 23.44.** Напиши **Job**: `kind: Job`, `template: spec: restartPolicy: OnFailure`, `containers: - command: ["./migrate", "up"]`. Запускается один раз, до completion. Покажи database migrations as K8s Job.

**Упражнение 23.45.** Напиши **CronJob**: `kind: CronJob`, `schedule: "0 2 * * *"` (daily at 2 AM). `jobTemplate` для backup, cleanup, report generation. Покажи scheduled tasks in Kubernetes.

**Упражнение 23.46.** Напиши **Liveness и Readiness пробы**: `livenessProbe: httpGet: path: /healthz, port: 8080, initialDelaySeconds: 10, periodSeconds: 5`. `readinessProbe: httpGet: path: /ready, port: 8080`. Покажи разницу: liveness = restart pod, readiness = remove from service endpoints.

**Упражнение 23.47.** Напиши **Startup probe**: `startupProbe: httpGet: path: /healthz, port: 8080, failureThreshold: 30, periodSeconds: 10` (5 минут на старт). Отключает liveness/readiness до success. Покажи для slow-starting applications.

**Упражнение 23.48.** Настрой **resource requests/limits**: `resources: requests: memory: "256Mi", cpu: "250m"`, `limits: memory: "512Mi", cpu: "500m"`. Покажи QoS classes: `Guaranteed` (requests=limits), `Burstable` (requests<limits), `BestEffort` (none).

### 128. Kubernetes — продвинутые техники

**Упражнение 23.49.** Настрой **HorizontalPodAutoscaler (HPA)**: `apiVersion: autoscaling/v2`, `metrics: - type: Resource, resource: name: cpu, target: type: Utilization, averageUtilization: 70`. Scale 3 → 10 pods. Покажи autoscaling.

**Упражнение 23.50.** Настрой **VerticalPodAutoscaler (VPA)**: `updateMode: "Auto"` или `"Off"` (recommendation only). Автоматически adjusts requests/limits based on actual usage. Покажи difference с HPA (scale up pod vs scale out pods).

**Упражнение 23.51.** Настрой **PodDisruptionBudget (PDB)**: `minAvailable: 2` или `maxUnavailable: 1`. Защита от voluntary disruptions: node drain, cluster upgrade. Покажи, что ensures availability during maintenance.

**Упражнение 23.52.** Настрой **Affinity/Anti-affinity**: `podAntiAffinity: preferredDuringSchedulingIgnoredDuringExecution` — распредели pods across nodes. `podAffinity` — co-locate related pods. `nodeAffinity` — run on specific nodes (GPU, SSD). Покажи topology spread.

**Упражнение 23.53.** Настрой **Taints и Tolerations**: `node taint: dedicated=gpu:NoSchedule`. Pod с `toleration: key: dedicated, operator: Equal, value: gpu, effect: NoSchedule` может запланироваться на GPU node. Покажи dedicated node pools.

**Упражнение 23.54.** Настрой **NetworkPolicy**: `kind: NetworkPolicy`, `podSelector: matchLabels: app: database`, `policyTypes: [Ingress]`, `ingress: - from: - podSelector: matchLabels: app: backend`, `ports: - protocol: TCP, port: 5432`. Покажи zero-trust network segmentation.

**Упражнение 23.55.** Настрой **ServiceAccount + RBAC**: `kind: ServiceAccount`, `kind: Role` (permissions in namespace), `kind: RoleBinding` (bind SA to Role). Покажи principle of least privilege for pods.

**Упражнение 23.56.** Настрой **Ingress**: `kind: Ingress`, `spec: rules: - host: api.example.com, http: paths: - path: /, pathType: Prefix, backend: service: name: myapp, port: number: 80`. TLS: `spec: tls: - hosts: [api.example.com], secretName: api-tls`. Покажи external access.

**Упражнение 23.57.** Настрой **Ingress Controller** (nginx/traefik): Helm install. `LoadBalancer` service (cloud) or `NodePort` (bare metal). Cert-manager for automatic TLS (Let's Encrypt). Покажи complete ingress stack.

**Упражнение 23.58.** Настрой **Custom Resource Definition (CRD)**: `kind: CustomResourceDefinition`, `spec: group: example.com, versions: - name: v1, served: true, storage: true, schema: ...`. Напиши **Operator** на Go (`controller-runtime`): watches CR, reconciles state. Покажи Kubernetes-native automation.

### 129. Kubernetes — Stateful и операторы

**Упражнение 23.59.** Настрой **StatefulSet**: `kind: StatefulSet`, `serviceName: postgres`, `replicas: 3`, `volumeClaimTemplates: - metadata: name: data, spec: accessModes: [ReadWriteOnce], resources: requests: storage: 10Gi`. Stable network identity: `postgres-0`, `postgres-1`, `postgres-2`. Покажи для databases.

**Упражнение 23.60.** Настрой **Headless Service**: `clusterIP: None`. DNS: `postgres-0.postgres.default.svc.cluster.local`. Используй для StatefulSet peer discovery. Покажи, как pods находят друг друга.

**Упражнение 23.61.** Настрой **DaemonSet**: `kind: DaemonSet`. Запускает по одному pod на каждом node. Используй для: log collectors (Fluent Bit), monitoring agents (node-exporter), CNI plugins. Покажи node-level services.

**Упражнение 23.62.** Настрой **Init Containers**: `initContainers: - name: wait-for-db, image: busybox, command: ['sh', '-c', 'until nc -z postgres 5432; do sleep 2; done']`. Запускается перед основным контейнером, должен завершиться успешно. Покажи dependency management.

**Упражнение 23.63.** Настрой **Sidecar Pattern**: основной контейнер `app` + sidecar `nginx` (reverse proxy) или `envoy` (service mesh). Shared `emptyDir` volume для Unix socket communication. Покажи separation of concerns.

**Упражнение 23.64.** Настрой **Ambassador Pattern**: sidecar проксирует внешние сервисы. `app` обращается к `localhost:5432`, sidecar маршрутизирует на `postgres.external:5432` с TLS, retry, circuit breaker. Покажи transparent proxying.

**Упражнение 23.65.** Настрой **Adapter Pattern**: sidecar преобразует интерфейс. `app` пишет metrics в файл, sidecar `prometheus-exporter` читает файл, exposes `/metrics`. Покажи interface adaptation.

### 130. Kubernetes — Helm и Kustomize

**Упражнение 23.66.** Напиши **Helm Chart**: `helm create myapp`. Структура: `Chart.yaml`, `values.yaml`, `templates/`. Параметризуй: `replicaCount`, `image.tag`, `resources`, `ingress.enabled`. Установи: `helm install myapp ./myapp -f values-production.yaml`.

**Упражнение 23.67.** Напиши **Helm Chart с dependencies**: `dependencies: - name: postgresql, version: 12.x.x, repository: https://charts.bitnami.com/bitnami`. `helm dependency update`. Покажи composite applications.

**Упражнение 23.68.** Напиши **Helm Chart с hooks**: `annotations: "helm.sh/hook": pre-install, "helm.sh/hook-weight": "1"`. Job для database migrations перед установкой. `post-upgrade` для cache warming. Покажи lifecycle hooks.

**Упражнение 23.69.** Напиши **Kustomize overlay**: `base/` (common resources), `overlays/dev/` (development patches), `overlays/prod/` (production patches: replicas, resources, TLS). `kustomization.yml` с `resources`, `patchesStrategicMerge`, `configMapGenerator`. Покажи `kubectl apply -k overlays/prod`.

**Упражнение 23.70.** Сравни **Helm vs Kustomize**: Helm — templating (Go templates), package management, releases. Kustomize — patching, no templating, native in kubectl. Покажи, когда что использовать (Helm for packaged apps, Kustomize for own manifests).

### 131. Kubernetes — Service Mesh и Security

**Упражнение 23.71.** Установи **Istio**: `istioctl install`. Enable sidecar injection: `kubectl label namespace default istio-injection=enabled`. Покажи automatic Envoy sidecar injection.

**Упражнение 23.72.** Настрой **Istio Traffic Management**: `VirtualService` для routing (weight-based: 90% v1, 10% v2). `DestinationRule` для subsets (version labels). `Gateway` for external access. Покажи canary deployment with Istio.

**Упражнение 23.73.** Настрой **Istio mTLS**: `PeerAuthentication` with `mtls: mode: STRICT`. All service-to-service communication encrypted and authenticated. `DestinationRule` with `trafficPolicy: tls: mode: ISTIO_MUTUAL`. Покажи zero-trust network.

**Упражнение 23.74.** Настрой **Istio Authorization**: `AuthorizationPolicy` — allow/deny based on source (service account), operation (GET /api/users), conditions (JWT claims). Покажи L7 authorization.

**Упражнение 23.75.** Настрой **Istio Observability**: Kiali (topology), Grafana (metrics), Jaeger (tracing). `Telemetry` resource for custom metrics. Покажи unified observability without application changes.

**Упражнение 23.76.** Установи **Cert-manager**: `ClusterIssuer` for Let's Encrypt (production/staging). `Certificate` resource automatically requests and renews TLS certificates. `Ingress` or `Gateway` references secret. Покажи automated TLS.

**Упражнение 23.77.** Настрой **External Secrets Operator**: `ExternalSecret` syncs secrets from AWS Secrets Manager / Azure Key Vault / HashiCorp Vault to Kubernetes Secrets. Автоматическая ротация. Покажи no secrets in Git.

**Упражнение 23.78.** Настрой **OPA Gatekeeper**: `ConstraintTemplate` (Rego policy), `Constraint` (apply to resources). Пример: `K8sRequiredLabels` — все namespaces must have `cost-center`. `K8sPSP` — no privileged containers. Покажи policy-as-code.

### 132. Kubernetes — Production Operations

**Упражнение 23.79.** Настрой **Pod Security Standards**: `restricted` profile (enforced), `baseline` (warn), `privileged` (audit). `PodSecurity` admission controller. Покажи security hardening without OPA.

**Упражнение 23.80.** Настрой **Falco**: runtime security. Rules: `Unexpected outbound connection`, `Write to /etc`, `Privilege escalation`. Alerts to Slack/PagerDuty. Покажи threat detection.

**Упражнение 23.81.** Настрой **Velero**: backup and restore. `Backup` resource: cluster state + PV snapshots. `Schedule` for automated backups. Disaster recovery: restore to new cluster. Покажи DR testing.

**Упражнение 23.82.** Настрой **Cluster Autoscaler**: scales node groups based on pending pods. `minSize: 3`, `maxSize: 100`. Integration with cloud provider (AWS ASG, GKE node pools). Покажи cost optimization.

**Упражнение 23.83.** Настрой **Karpenter** (alternative to Cluster Autoscaler): provisioner per workload type. `NodePool` with `requirements` (instance types, architecture, capacity type: spot/on-demand). Faster scaling, better cost optimization. Покажи modern autoscaling.

**Упражнение 23.84.** Настрой **Cost Monitoring**: Kubecost / OpenCost. Per-namespace, per-deployment, per-pod cost allocation. Showback / chargeback. Recommendations: right-sizing, spot instances. Покажи FinOps for Kubernetes.

**Упражнение 23.85.** Настрой **GitOps at Scale**: `ApplicationSet` (ArgoCD) — generates `Application` per environment, per cluster, per tenant. Matrix generator: `clusters × environments`. Покажи managing 100+ clusters.

**Упражнение 23.86.** Настрой **Multi-Cluster**: `kind: Cluster` (CAPI — Cluster API). Management cluster provisions workload clusters. Federated services, global load balancing, disaster recovery. Покажи fleet management.

**Упражнение 23.87.** Настрой **Edge/K3s**: lightweight Kubernetes for IoT/edge. `k3s` single binary, SQLite instead of etcd, Traefik ingress. Deploy to Raspberry Pi cluster. Покажи Kubernetes everywhere.

**Упражнение 23.88.** Настрой **Local Development**: `kind` (Kubernetes in Docker) or `k3d` (k3s in Docker). `tilt` or `devspace` for live reload. `telepresence` for remote cluster development. Покажи inner loop optimization.

**Упражнение 23.89.** Настрой **E2E Testing in Kubernetes**: ` kuttl` or `helm test`. Spin up test namespace, deploy app + dependencies, run tests, cleanup. CI integration: `kind` cluster in GitHub Actions. Покажи testing in production-like environment.

**Упражнение 23.90.** Спроектируй **полный production pipeline**:
- Developer pushes code → GitHub Actions: lint, test, build, scan
- Merge to `main` → build Docker image, push to registry, update Helm chart
- ArgoCD detects change → sync to staging cluster
- Automated tests in staging → promote to production
- Argo Rollouts: canary 1% → 10% → 50% → 100%
- Monitoring: SLO verification, automatic rollback on degradation
- Incident response: PagerDuty, runbook, post-mortem

### Ключевые моменты для освоения деплоя и операций:

1. **Immutable Infrastructure**: не меняй running containers. Собери новый image, deploy, старый — terminate. Rollback = deploy previous image. Никаких `kubectl exec` для hotfix'ов.

2. **GitOps**: Git = single source of truth. Всё declarative, всё versioned. ArgoCD/Flux обеспечивают convergence (cluster state = desired state). Self-healing, audit trail, easy rollback.

3. **Security by Default**: non-root containers, read-only root FS, minimal base images (distroless/scratch), no secrets in images, mTLS, network policies, RBAC, Pod Security Standards, Falco runtime detection.

4. **Observability in Production**: если нельзя наблюдать — нельзя управлять. Metrics, logs, traces, alerts, runbooks — часть deployment, не после.

5. **Progressive Delivery**: canary, blue-green, feature flags. Не deploy'и на 100% сразу. Автоматический rollback по SLO degradation. Reduce blast radius.

6. **Platform Engineering**: internal developer platform (IDP). Self-service: `kubectl apply` → Git PR → automated pipeline. Golden paths, paved roads. Developers focus on code, platform team on infrastructure.

7. **Cost Awareness**: right-sizing, spot instances, autoscaling, FinOps. Every resource has owner and cost. Optimize continuously.

8. **Disaster Recovery**: regular DR drills, backup testing, documented runbooks. RPO/RTO defined and tested. Multi-region, multi-cloud if needed.

9. **Developer Experience**: local development (kind, tilt), fast feedback loop (< 5 min from push to deploy in dev), good documentation, paved paths. Happy developers = productive developers.

10. **Continuous Improvement**: post-mortems without blame, blameless culture, learning from incidents. SRE practices: error budgets, SLO-driven development, chaos engineering.
