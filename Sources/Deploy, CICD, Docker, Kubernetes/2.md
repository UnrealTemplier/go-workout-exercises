### 15. Deploy, CI/CD, Docker, Kubernetes

531. Напишите `Dockerfile` для Go-приложения с multi-stage сборкой: первый stage собирает бинарник, второй — минимальный образ на `scratch` или `alpine`.
532. Оптимизируйте размер образа: используйте `FROM scratch`, копируйте только бинарник и необходимые сертификаты. Проверьте размер через `docker images`.
533. Закрепите версии зависимостей в `go.sum`, используйте кэширование слоёв (сначала копируйте `go.mod` и `go.sum`, затем `go mod download`, потом исходники).
534. Создайте `docker-compose.yml`, который поднимает ваше Go-приложение, PostgreSQL и Redis. Настройте healthcheck для БД и зависимость запуска.
535. Реализуйте конфигурацию приложения через переменные окружения, пробрасываемые из `docker-compose` (DB_HOST, REDIS_ADDR).
536. Соберите образ и запустите интеграционные тесты внутри контейнера (отдельный stage для тестов).
537. Напишите `Makefile` с командами `build`, `test`, `lint`, `docker-build`, `docker-run`.
538. Настройте GitHub Actions (или GitLab CI): пайплайн запускает линтер (`golangci-lint`), тесты с race detector, сборку образа и пуш в Docker Hub при пуше в main.
539. Добавьте в CI этап проверки уязвимостей: `govulncheck` и сканирование Docker-образа (`trivy`).
540. Автоматизируйте версионирование: при пуше тега `v*` запускайте goreleaser для сборки бинарников под разные платформы и создания GitHub Release.
541. Создайте Kubernetes манифесты: `Deployment`, `Service`, `ConfigMap` для вашего приложения. Настройте количество реплик и ресурсы (requests/limits).
542. Добавьте `readinessProbe` и `livenessProbe` в Deployment: проверяйте HTTP-эндпоинты `/health/ready` и `/health/live`.
543. Настройте `HorizontalPodAutoscaler` по CPU и памяти, проверьте масштабирование нагрузочным тестом.
544. Используйте `Init Containers` для выполнения миграций БД перед запуском основного приложения.
545. Разверните приложение в локальном Kubernetes (minikube/kind) и проверьте доступ через `kubectl port-forward`.
546. Управляйте секретами: создайте Kubernetes Secret для пароля БД и монтируйте его как переменную окружения в поде.
547. Напишите Helm-чарт для вашего приложения с параметризацией образа, реплик, ресурсов и ingress.
548. Установите ingress-контроллер (nginx) и настройте Ingress-ресурс для маршрутизации внешнего трафика к вашему сервису.
549. Настройте TLS-termination на ingress с использованием `cert-manager` для автоматического получения Let's Encrypt сертификатов.
550. Создайте полный CI/CD пайплайн: push в main → сборка образа → деплой в staging-кластер → acceptance-тесты → promotion в production (ручное подтверждение).
551. Используйте стратегию `RollingUpdate` с `maxSurge` и `maxUnavailable` для zero-downtime деплоя.
552. Реализуйте сбор метрик и логов из подов: подключите Prometheus для сбора метрик и Grafana Loki для логов. Настройте дашборд в Grafana, отображающий состояние деплоя.
553. Настройте алерты в Prometheus AlertManager: если количество подов падает ниже заданного или растёт процент 5xx.
554. Подготовьте приложение к запуску в облаке (AWS ECS или GCP Cloud Run): создайте соответствующий конфигурационный файл (task definition / service.yaml).
555. Реализуйте GitOps-подход: храните Kubernetes манифесты в отдельном репозитории, настройте ArgoCD или Flux для автоматической синхронизации состояния кластера с репозиторием.
