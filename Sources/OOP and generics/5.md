Go — язык с уникальным подходом к ООП (здесь нет классов и наследования, зато есть структуры, встраивание и интерфейсы) и мощной, но прагматичной реализацией дженериков (появились в Go 1.18).

Продолжаем нашу нумерацию. Ниже **30 мощных упражнений** (с 223 по 252), которые научат тебя проектировать архитектуру приложения в стиле Go и писать универсальный типобезопасный код.

### Блок 15. Объектно-Ориентированный Дизайн в Go (223–237)
Учимся мыслить объектами без классов. Инкапсуляция, композиция и паттерны.

223. **Инкапсуляция (Private/Public):** Создай пакет `bank`. В нём структуру `account` (с маленькой буквы) с приватным полем `balance float64`. Напиши публичную функцию `NewAccount(initialBalance float64) *account`, которая выступает конструктором.
224. **Геттеры и действия:** Добавь к `account` методы `Balance() float64` (геттер), `Deposit(amount float64)` и `Withdraw(amount float64) error`. Убедись, что снять денег больше, чем есть на балансе, нельзя.
225. **Значения vs Указатели (Сюрпризы):** Напиши для структуры метод с *value receiver* (`func (a account) Print()`) и метод с *pointer receiver* (`func (a *account) Modify()`). В `main` создай значение `acc := bank.NewAccount(...)` (допустим, он возвращает значение, а не указатель). Вызови `acc.Modify()`. Осознай, что Go "под капотом" сам берет указатель `(&acc).Modify()`. 
226. **Nil-ресиверы:** Создай структуру `Node` (элемент связного списка). Напиши метод `func (n *Node) PrintValue()`. Внутри метода в самом начале напиши `if n == nil { fmt.Println("nil"); return }`. В `main` объяви `var n *Node = nil` и вызови `n.PrintValue()`. Убедись, что паники нет! (В Go методы можно безопасно вызывать у `nil`-указателей, если внутри есть проверка).
227. **"Наследование" через композицию (Embedding):** Создай структуру `CreditAccount`. Встрой в неё структуру `account` (из упр. 223) анонимным полем. Добавь поле `CreditLimit float64`.
228. **Переопределение методов (Shadowing):** Для `CreditAccount` напиши *свой* метод `Withdraw(amount float64) error`, который позволяет уходить в минус до уровня `CreditLimit`, вызывая оригинальный метод (например, через прямое изменение баланса или вызов `c.account.Withdraw`, если бы поле было доступно).
229. **Полиморфизм и Интерфейсы:** Создай интерфейс `PaymentProcessor` с методом `ProcessPayment(amount float64) error`. Реализуй его для структур `CreditCard` и `PayPal`. Напиши функцию `Checkout(p PaymentProcessor, amount float64)`.
230. **Method Values (Значения методов):** Создай структуру `Greeter{Name string}` с методом `Greet()`. Присвой метод переменной: `f := myGreeter.Greet` (без скобок!). Вызови `f()`. Заметь, что состояние (значение полей структуры) "захватилось" в эту переменную.
231. **Method Expressions (Выражения методов):** Для той же структуры сохрани метод от самого типа: `f := Greeter.Greet` (или `(*Greeter).Greet`). Теперь вызови его, передав экземпляр структуры параметром: `f(myGreeter)`. Это показывает, что методы в Go — это просто функции, где структура передается первым неявным аргументом.
232. **Паттерн Builder (Строитель):** Создай структуру `ServerConfig` (host, port, timeout, maxConns). Напиши "текучий интерфейс" (fluent interface) для её сборки: методы `WithHost(h string)`, `WithPort(p int)` и т.д., возвращающие указатель на самого себя (`*ServerConfig`). В конце вызови `b.WithHost("...").WithPort(80).Build()`.
233. **Паттерн Functional Options (Функциональные опции - золотой стандарт Go):** Перепиши упр. 232 по-гошному. Создай тип `type ServerOption func(*ServerConfig)`. Напиши функции `WithHost(h string) ServerOption`. Конструктор должен выглядеть так: `NewServer(opts ...ServerOption) *ServerConfig`. Внутри конструктора примени все опции в цикле `for _, opt := range opts { opt(cfg) }`.
234. **Паттерн Strategy:** Напиши структуру `Sorter` с полем `strategy func([]int)`. Напиши методы для сортировки пузырьком и быстрой сортировки, меняй стратегию на лету в `main`.
235. **Внутреннее состояние (State):** Реализуй конечный автомат (FSM) для симуляции светофора. Структура `TrafficLight` должна иметь метод `Next()`, который меняет внутреннее состояние и выводит текущий цвет.
236. **Анти-паттерн "Большой интерфейс":** Создай интерфейс `GodObject` с 10 методами. Затем разбей его на 5 маленьких интерфейсов по 1-2 метода (ISP - Interface Segregation Principle). Почувствуй разницу в удобстве мокирования.
237. **Делегирование через интерфейсы:** Структура `App` встраивает анонимно интерфейс `Logger`. При инициализации `App` передай туда конкретную реализацию логгера. Попробуй вызвать методы интерфейса напрямую от объекта приложения: `app.Info("start")`.

### Блок 16. Дженерики (Обобщенное программирование) (238–252)
Пишем код, независимый от типов, без потери производительности и строгой типизации.

238. **Первый дженерик:** Напиши обобщенную функцию `PrintAnything[T any](val T)`, которая принимает значение любого типа и выводит его. Сравни с использованием `interface{}`.
239. **Ограничение `comparable`:** Напиши функцию `FindIndex[T comparable](slice []T, target T) int`, которая ищет элемент в срезе и возвращает его индекс (или -1). Пойми, почему тут нужен `comparable`, а не `any` (чтобы работал оператор `==`).
240. **Кастомное ограничение (Union Type):** Создай интерфейс `Number`, который разрешает только типы `int`, `int64` и `float64` (`type Number interface { int | int64 | float64 }`). Напиши функцию `Sum[T Number](a, b T) T`.
241. **Символ тильды (`~`):** Создай свой тип `type MyInt int`. Попробуй передать переменную этого типа в функцию `Sum` из упр. 240. Получишь ошибку. Исправь интерфейс `Number`, добавив `~` (`~int | ...`), чтобы разрешить использование любых типов, базовым для которых является `int`.
242. **Вывод типов (Type Inference):** Вызови функцию `Sum` из упр. 240 двумя способами: с явным указанием типа `Sum[float64](1.5, 2.5)` и без него `Sum(1.5, 2.5)` — позволь компилятору самому догадаться.
243. **Обобщенный Стек (Generic Struct):** Напиши структуру `Stack[T any]`, представляющую LIFO стек. Внутри храни данные в слайсе `[]T`. Напиши методы `Push(val T)` и `Pop() (T, error)`.
244. **Обобщенная Мапа (Кэш):** Реализуй простую структуру `Cache[K comparable, V any]` с мапой внутри и методами `Set(k K, v V)` и `Get(k K) (V, bool)`.
245. **Сюрприз дженериков (Ограничение на методы):** Попытайся добавить в свой `Stack[T]` новый метод, который принимает свой собственный, независимый generic-параметр `func (s *Stack[T]) Map[U any](fn func(T) U) Stack[U]`. Убедись, что Go **не разрешает** generic-методы на структурах (только функции могут вводить новые параметры типов).
246. **Обходной путь (Map для Слайса):** Реализуй функциональность из упр. 245 в виде отдельной функции: `MapSlice[T, U any](slice []T, fn func(T) U) []U`. Это паттерн Map из функционального программирования.
247. **Filter (Функциональный паттерн):** Напиши дженерик-функцию `Filter[T any](slice []T, predicate func(T) bool) []T`. Отфильтруй с помощью неё срез чисел (только четные) и срез строк (только длиной > 3).
248. **Дженерик-Интерфейсы:** Создай интерфейс `Processor[T any]` с методом `Process(data T) T`. Создай структуру, реализующую `Processor[string]` (например, переводит текст в верхний регистр) и структуру для `Processor[int]` (например, умножает на 2).
249. **Пакет `slices` (Стандартная библиотека):** С версии Go 1.21 в стандартной библиотеке есть пакет `slices`. Импортируй его. Создай срез строк, отсортируй его через `slices.Sort(s)`. Проверь наличие элемента через `slices.Contains(s, "go")`. Посмотри исходный код этих функций в IDE — они написаны на дженериках!
250. **Пакет `maps` (Стандартная библиотека):** Импортируй стандартный пакет `maps`. Используй `maps.Clone()` для глубокого (shallow) копирования мапы. Посмотри, как красиво работают дженерики "из коробки".
251. **Сложное ограничение (Constraint с методами):** Напиши функцию `Stringify[T fmt.Stringer](slice []T) []string`, которая принимает срез любых объектов, реализующих метод `String()`, и возвращает срез готовых строк.
252. **Продвинутый Type Inference (Constraint Type Inference):** *Сложное!* Напиши функцию `CloneSlice[S ~[]E, E any](s S) S`. Она принимает срез типа `S` (который является слайсом элементов `E`). Смысл: если ты передашь в нее свой кастомный тип `type MySlice []int`, функция вернет именно `MySlice`, а не просто `[]int`. Это магия сложного вывода типов в Go.

---
**Совет к этому блоку:** Особое внимание удели паттерну **Functional Options (упр. 233)** — это визитная карточка профессионального кода на Go. А дженерики используй без фанатизма: правило Go-сообщества гласит — *"Пиши код без дженериков, пока дублирование кода не станет слишком болезненным"*.
