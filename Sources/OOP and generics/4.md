Отличная работа! Темы объектно-ориентированного программирования (ООП) и дженериков (Generics) — это то, что отличает просто знающего синтаксис человека от настоящего Go-разработчика.

Важно помнить главное философское отличие Go от языков вроде Java или C#: **в Go нет классического наследования и классов**. Вместо этого используется композиция (встраивание структур) и полиморфизм через интерфейсы. Дженерики, появившиеся в Go 1.18, добавили языку долгожданную параметрическую полиморфность, но с оглядкой на безопасность и производительность.

Ниже представлены **65 новых упражнений (с 221 по 285)**, которые научат вас мыслить идиоматично в рамках ООП и дженериков.

### Тема 24: ООП в Go — Основы (Методы, получатели, инкапсуляция)
221. Создайте структуру `Counter` с приватным полем `value int` (вынесите её в отдельный пакет `counter`, чтобы поле было действительно приватным для `main`).
222. Добавьте к `Counter` методы `Increment()` и `Decrement()` с **pointer receiver** (`*Counter`), чтобы они могли изменять состояние структуры.
223. Добавьте метод `Value()` с **value receiver** для безопасного чтения текущего состояния.
224. Создайте структуру `Rectangle` с полями `width` и `height`. Напишите для неё методы `Area()` и `Perimeter()`.
225. Изучите авто-взятие адреса: создайте переменную `r Rectangle` (не указатель) и попробуйте вызвать `r.Area()`, если метод требует `*Rectangle`. Объясните, как компилятор делает это за вас.
226. Изучите обратный случай: можно ли вызвать метод с value receiver у указателя на структуру? Проверьте на практике.
227. Создайте фабричный метод (конструктор) `NewRectangle(w, h float64) *Rectangle`, который валидирует входные данные (ширина и высота > 0) и возвращает `error`, если они невалидны.
228. Реализуйте инкапсуляцию: создайте пакет `bank` со структурой `Account`. Сделайте поле `balance` приватным. Добавьте методы `Deposit()` и `Withdraw()`, которые не дают балансу уйти в минус (возвращая ошибку при нехватке средств).
229. Создайте приватный метод (начинается с маленькой буквы) внутри структуры и вызовите его из публичного метода этой же структуры.
230. Создайте структуру `User` с полями `Email` и `PasswordHash`. Сделайте сеттер `SetPassword(raw string)`, который внутри хэширует пароль (используйте `crypto/sha256`) перед сохранением, чтобы сырой пароль никогда не хранился в памяти.
231. Изучите "Aliasing" типов. Создайте тип `type MyInt int` и добавьте к нему метод. Попробуйте вызвать этот метод у обычной переменной типа `int`. Убедитесь, что так нельзя, и поймите, почему это защищает от случайного изменения поведения встроенных типов.
232. Создайте тип `type MyTime time.Time` и добавьте к нему метод `IsWeekend() bool`.
233. Напишите метод `String()` (реализация интерфейса `fmt.Stringer`), который форматирует структуру `User` в красивый вид вида `User: <Email>`.
234. Создайте структуру `File` и добавьте к ней методы `Open()`, `Read()`, `Close()`. Используйте `pointer receiver` для всех методов, изменяющих состояние (например, флаг `isOpen`).
235. Попробуйте изменить приватное поле структуры из другого пакета с помощью пакета `unsafe` и пакета `reflect`. Поймите, почему это антипаттерн и как Go защищает границы пакетов на этапе компиляции.

### Тема 26: Дженерики — Основы (Функции и Constraints)
251. Напишите параметризованную функцию `Min[T cmp.Ordered](a, b T) T` (используя пакет `cmp` из Go 1.21+), которая возвращает меньшее из двух значений.
252. Изучите пакет `constraints`. Используйте `constraints.Integer` вместо `Ordered`, чтобы функция `Sum[T constraints.Integer]` работала только с целыми числами.
253. Напишите функцию `Map[T, U any](s []T, f func(T) U) []U`, которая применяет функцию к каждому элементу слайса (классическая функция из функционального программирования).
254. Напишите функцию `Filter[T any](s []T, f func(T) bool) []T`, которая оставляет только те элементы, для которых предикат вернул `true`.
255. Создайте параметризованную функцию `Contains[T comparable](s []T, val T) bool`. Почему здесь обязательно нужен constraint `comparable`? Что будет, если убрать его?
256. Напишите дженерик-функцию `Keys[K comparable, V any](m map[K]V) []K`, которая возвращает слайс всех ключей мапы.
257. Напишите дженерик-функцию `Values[K comparable, V any](m map[K]V) []V`.
258. Создайте свой кастомный constraint. Например, `type Number interface { ~int | ~float64 }`. Объясните, зачем нужен символ тильды `~` (tilde) и как он разрешает использование кастомных типов (aliased types).
259. Напишите параметризованную функцию `Reverse[T any](s []T) []T`, которая разворачивает слайс любого типа in-place.
260. Используйте дженерики для создания функции `Unique[T comparable](s []T) []T`, которая удаляет дубликаты из слайса с сохранением порядка.
261. Напишите функцию `Reduce[T, U any](s []T, initial U, f func(U, T) U) U` (свертка списка). Используйте её для подсчета суммы или конкатенации строк.
262. Попробуйте передать в дженерик-функцию структуру, которая не удовлетворяет constraint (например, слайс в `Contains`). Изучите понятную ошибку компилятора.
263. Напишите параметризованную функцию `Ptr[T any](val T) *T`, которая возвращает указатель на переданное значение. Это очень удобный хелпер для тестов и заполнения структур.
264. Напишите функцию `PrintAny[T any](val T)`, которая принимает любой тип и использует `reflect` для вывода информации о нём. Сравните это с использованием пустого интерфейса `any`.

---
**Совет по изучению:**
* **В ООП:** Всегда задавайте себе вопрос: "Нужен ли здесь pointer receiver?". Если структура маленькая (например, пара `int`-ов или время) и не меняет своего состояния — используйте value receiver. Если структура большая или имеет мьютексы/файловые дескрипторы — только pointer receiver.
* **В Дженериках:** В Go есть негласное правило: "Не используйте дженерики, пока не почувствуете боль от их отсутствия". Сначала пишите код под конкретные типы (`int`, `string`), и только когда вам придется копипастить один и тот же алгоритм для разных типов — выносите его в дженерик-функцию. Излишняя абстракция в Go не приветствуется.
