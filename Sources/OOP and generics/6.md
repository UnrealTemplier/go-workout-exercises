Ниже представлено продолжение практического курса интенсивных тренировок. Этот блок содержит **30 детально проработанных упражнений** (задачи 203–232), которые помогут вам освоить особенности объектно-ориентированного программирования в стиле Go (без классов, но с богатыми возможностями композиции и инкапсуляции) и современное обобщенное программирование (дженерики), появившееся в языке начиная с версии 1.18.

### Раздел 17: Объектно-ориентированное программирование (ООП) в Go (Задачи 203–217)

*В Go нет классов и наследования, но есть структуры, методы, композиция и интерфейсы. Эти упражнения помогут вам перестроить мышление под идиоматичное ООП в Go.*

203. **Методы для неконкретных типов (алиасов)**: Создайте кастомный тип на базе встроенного: `type MyDuration int`. Напишите для него метод `ToMinutes() float64` и `ToSeconds() int`. Проверьте вызов методов на переменной этого типа. Объясните, почему нельзя объявлять методы для базовых типов (например, напрямую для `int`) или для типов из чужих пакетов.
204. **Приемники (Receivers) и `nil`-получатели**: Напишите структуру `Node` с полем `Value int` и методом `GetValue() int`. Настройте метод так, чтобы получатель (receiver) был указателем (`n *Node`). Добавьте проверку `if n == nil { return 0 }`. Создайте переменную `var n *Node` (она равна `nil`) и попробуйте вызвать `n.GetValue()`. Убедитесь, что в Go вызов метода на `nil`-указателе возможен и не всегда приводит к панике (в отличие от других языков).
205. **Инкапсуляция (Скрытие данных)**: Создайте пакет `bank`. Внутри пакета объявите структуру `Account` с приватным (неэкспортируемым) полем `balance float64`. Напишите публичные методы `Deposit(amount float64)` и `Withdraw(amount float64) error` для изменения баланса с валидацией, а также метод-геттер `Balance() float64`. Попробуйте получить доступ к полю `balance` напрямую из пакета `main` и зафиксируйте ошибку компиляции.
206. **Композиция вместо наследования**: Создайте структуру `Engine` с методом `Start()`. Создайте структуру `Car`, встроив в неё `Engine` анонимно. Продемонстрируйте вызов метода `car.Start()`. Объясните, как композиция заменяет наследование классов.
207. **Конфликты имен при композиции**: Создайте две структуры: `GPS` (с методом `GetCoordinates()`) и `MobilePhone` (с методом `GetCoordinates()`). Создайте структуру `SmartCar`, встроив в неё обе эти структуры. Попробуйте вызвать `smartCar.GetCoordinates()`. Разберитесь в ошибке компиляции (ambiguous selector) и решите её, вызвав методы явно через имена встроенных типов.
208. **Автоматическое приведение получателя**: Создайте структуру `Point` с методом-указателем `MoveX(dx int)` и методом-значением `GetX() int`. 
    * Создайте значение переменной `p := Point{X: 1}` и вызовите `p.MoveX(5)`.
    * Создайте указатель `pPtr := &Point{X: 1}` и вызовите `pPtr.GetX()`.
    Объясните, как компилятор Go автоматически подставляет взятие адреса (`&`) или разыменование (`*`) для удобного вызова методов.
209. **Инкапсулированные конструкторы**: В пакете `user` создайте приватную структуру `member`. Напишите экспортируемую функцию-конструктор `NewMember(email string) (*member, error)`, которая проверяет email на наличие символа `@`. Если валидация не пройдена, возвращайте ошибку. Попробуйте создать экземпляр `member` в обход конструктора из пакета `main`.
210. **Полиморфная фабрика**: Создайте интерфейс `PaymentMethod` с методом `Pay(amount float64)`. Реализуйте его для структур `CreditCard` и `PayPal`. Напишите функцию-фабрику `GetPaymentMethod(methodType string) PaymentMethod`. Продемонстрируйте полиморфизм, обрабатывая платежи без знания конкретной реализации платежной системы.
211. **Паттерн "Стратегия" (Strategy)**: Создайте структуру `TextProcessor` с полем `formatter Formatter` (интерфейс с методом `Format(string) string`). Реализуйте две стратегии форматирования: `JSONFormatter` и `PlainTextFormatter`. Напишите метод `Process(text string)` в `TextProcessor`, который использует текущую стратегию. Продемонстрируйте динамическую смену стратегии во время работы программы.
212. **Паттерн "Декоратор" (Decorator)**: Создайте интерфейс `Notifier` с методом `Send(msg string)`. Создайте базовый `EmailNotifier`. Напишите декоратор `LoggingNotifierDecorator`, который содержит внутри себя `Notifier`, логирует время отправки сообщения в консоль, а затем вызывает метод `Send` обернутого объекта.
213. **Принцип подстановки Барбары Лисков (LSP)**: Напишите программу, демонстрирующую соблюдение LSP. Создайте интерфейс `Bird` с методом `Fly()`. Попробуйте реализовать его для структуры `Ostrich` (страус). Объясните в комментариях, почему страус, возвращающий ошибку или панику в методе `Fly`, нарушает принцип LSP, и как правильно перепроектировать интерфейсы (например, разделить на `Bird` и `FlyingBird`).
214. **Интерфейсы: Динамический тип и значение**: Создайте пустой интерфейс `var val any`. Присвойте ему значение `42`. С помощью пакета `reflect` или форматирования `%T` и `%v` выведите динамический тип и динамическое значение переменной `val`. Повторите процедуру, присвоив переменной строку.
215. **Внедрение зависимостей (Dependency Injection)**: Создайте структуру `UserService`, которая для работы требует доступ к базе данных. Вместо конкретной структуры базы данных добавьте в `UserService` поле типа-интерфейса `DatabaseReader` (с методом `GetUserByID`). Напишите тест или демонстрационный код, куда передается "моковая" (mock) реализация интерфейса базы данных.
216. **Stateless-сервисы**: Создайте пустую структуру `MathService struct{}` без единого поля. Напишите для неё методы `Add(a, b int) int` и `Subtract(a, b int) int`. Объясните, зачем нужны такие структуры (организация пространства имен и реализация интерфейсов без хранения состояния).
217. **Интерфейс `error` как объект ООП**: Создайте кастомный тип `type SystemError string`, реализующий интерфейс `error`. Напишите для него метод-получатель, который возвращает строку ошибки в верхнем регистре. Используйте `Type Assertion`, чтобы проверить, является ли возвращенная из функции ошибка именно вашей ошибкой `SystemError`.

### Раздел 18: Обобщенное программирование (Дженерики) (Задачи 218–232)

*Дженерики позволяют писать гибкий, переиспользуемый код без потери строгой типизации и лишних приведений типов (Type Assertions).*

218. **Простейший дженерик (Сравнение)**: Напишите обобщенную функцию `Max[T cmp.Ordered](a, b T) T`, которая принимает два значения любого сравниваемого типа и возвращает наибольшее из них. Протестируйте функцию на типах `int`, `float64` и `string` (используйте пакет `cmp` из стандартной библиотеки).
219. **Ограничение `comparable`**: Напишите обобщенную функцию `IsEqual[T comparable](a, b T) bool`, проверяющую равенство двух элементов. Объясните, какие типы данных удовлетворяют ограничению `comparable` (а какие — нет, например, слайсы и мапы).
220. **Использование стандартных ограничений**: Напишите обобщенную функцию `Sum[T int | float64](a, b T) T`. Попробуйте передать туда строки и зафиксируйте ошибку компиляции.
221. **Кастомные интерфейсы-ограничения**: Объявите интерфейс-ограничение `Numeric`:
    ```go
    type Numeric interface {
        ~int | ~int64 | ~float64
    }
    ```
    Напишите функцию `Multiply[T Numeric](a, b T) T`. Объясните в комментариях роль знака тильды `~` (поддержка производных кастомных типов, например `type MyInt int`).
222. **Эксперимент без тильды `~`**: Уберите знак тильды `~` из ограничения `Numeric` в предыдущей задаче. Создайте кастомный тип `type SpecialInt int` и попробуйте передать переменную этого типа в функцию `Multiply`. Зафиксируйте ошибку компиляции. Верните тильду на место и проверьте результат.
223. **Обобщенный поиск в срезе**: Напишите обобщенную функцию `FindIndex[T comparable](slice []T, target T) int`, которая ищет элемент в срезе и возвращает его индекс (или `-1`, если элемент не найден).
224. **Обобщенный фильтр (Filter)**: Напишите функцию `Filter[T any](slice []T, predicate func(T) bool) []T`. Функция должна возвращать новый срез, содержащий только элементы, для которых функция `predicate` вернула `true`. Протестируйте на срезе чисел (фильтрация четных) и срезе строк (фильтрация строк длиннее 5 символов).
225. **Обобщенное преобразование (Map)**: Напишите функцию `Map[T, U any](slice []T, f func(T) U) []U`. Функция должна преобразовывать срез одного типа в срез другого типа с помощью функции `f`. Протестируйте, преобразовав срез целых чисел в срез их строковых представлений.
226. **Обобщенная структура (Контейнер)**: Создайте обобщенную структуру `Pair[K, V any]` с полями `First K` и `Second V`. Напишите для неё метод `GetValues() (K, V)`. Инициализируйте пару со типами `[string, int]` и пару со типами `[bool, float64]`.
227. **Ограничения на методы структур**: Попробуйте написать обычную структуру `Calculator struct{}` и добавить ей обобщенный метод `func (c Calculator) Sum[T Numeric](a, b T) T`. Зафиксируйте ошибку компиляции. Изучите важнейшее ограничение Go: **методы структур не могут иметь собственные параметры типов (type parameters)**. Перепишите код так, чтобы сам тип структуры был обобщенным: `type Calculator[T Numeric] struct{}`.
228. **Обобщенный Стек (Stack)**: Реализуйте структуру `Stack[T any]` на базе среза. Напишите методы `Push(val T)`, `Pop() (T, bool)` и `Len() int`. Проверьте работу стека для хранения структур `User` и обычных чисел `int`.
229. **Обобщенный двусвязный список**: Создайте структуру `ListNode[T any]` с полями `Value T`, `Next *ListNode[T]`, `Prev *ListNode[T]`. Создайте структуру `LinkedList[T any]` с методами добавления элемента в конец и обхода списка.
230. **Получение ключей мапы**: Напишите обобщенную функцию `GetKeys[K comparable, V any](m map[K]V) []K`, которая принимает мапу с любыми ключами и значениями и возвращает срез всех ключей мапы.
231. **Объединение методов и типов в ограничениях**: Создайте интерфейс-ограничение `StringableNumeric`, который требует, чтобы тип наследовал ограничение `Numeric` (из задачи №221) **и** реализовывал метод `String() string`. Напишите функцию, использующую это ограничение.
232. **Дженерики против Интерфейсов**: Напишите в комментариях к коду подробное эссе-сравнение. Объясните разницу между:
    * Полиморфизмом на основе интерфейсов (полиморфизм времени выполнения / runtime polymorphism, динамическая диспетчеризация).
    * Полиморфизмом на основе дженериков (полиморфизм времени компиляции / compile-time polymorphism, генерация кода/мономорфизация). 
    Приведите примеры задач, где уместно использовать только интерфейсы, и задач, где дженерики подходят гораздо лучше.
