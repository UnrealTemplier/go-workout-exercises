Отличное направление! В Go нет классического наследования (как в Java или C++), но есть мощная композиция, встраивание (embedding) и методы. А дженерики (появившиеся в Go 1.18) позволяют писать по-настоящему переиспользуемый код без потери типобезопасности.

### Блок 18: ООП в Go (Методы, Встраивание, Инкапсуляция)
*Цель: Освоить объектно-ориентированный подход через призму Go (Композиция вместо наследования, Method Sets, теневание).*

249. Создай структуру `Rectangle` с полями `Width, Height float64`. Напиши для нее метод `Area()` с value receiver. Вызови метод.
250. Создай метод `Scale(factor float64)` для `Rectangle` с pointer receiver, который умножает ширину и высоту на `factor`. Проверь, что оригинал изменился.
251. **[Каверзный кейс]** Создай интерфейс `Geometry` с методом `Area()`. Попробуй присвоить переменной типа `Geometry` значение `Rectangle` (а не указатель). Пойми, почему метод `Scale` не входит в интерфейс для значения (Method Sets: `*T` включает методы `T` и `*T`, а `T` включает только методы `T`).
252. Напиши метод для кастомного типа. Объяви `type MyString string`. Напиши метод `IsPalindrome()` для `MyString`. (Покажи, что методы можно добавлять к любым именованным типам в рамках одного пакета).
253. Создай структуру `Engine` с методом `Start()`. Создай структуру `Car`, которая *анонимно встраивает* `Engine`. Вызови `car.Start()` напрямую у структуры `Car` (встраивание полей и методов).
254. **[Теневание (Shadowing)]** В структуре `Car` из предыдущего задания добавь свой собственный метод `Start()`, который выводит "Car starting...", а затем вызывает встроенный метод `c.Engine.Start()`. (Переопределение методов).
255. **[Каверзный кейс]** Создай структуру `A` с полем `Name string` и структуру `B`, встраивающую `A`. У `B` тоже есть поле `Name`. Создай экземпляр `B`. Выведи `b.Name` и `b.A.Name` (покажи, как работает разрешение конфликтов имен при встраивании).
256. **Инкапсуляция:** Создай структуру `BankAccount` с приватным полем `balance int`. Напиши конструктор `NewBankAccount(initial int) *BankAccount` и методы `Deposit`, `Withdraw` (с проверкой баланса) и `GetBalance`.
257. Напиши структуру `Validator` с приватным полем `errors []string` и публичным методом `AddError(msg string)`. Метод `HasErrors()` должен возвращать `bool`, а `Errors()` — срез строк. (Имитация паттерна строитель/валидатор).
258. **[Каверзный кейс]** Создай указатель на структуру, равный `nil` (`var u *User = nil`). Вызови метод `u.Print()` (где `Print` — это value receiver, который просто выводит "User"). Поймай панику (nil pointer dereference). Измени `Print` на pointer receiver и добавь проверку `if u == nil` в начале метода. Вызови снова — паники быть не должно.
259. **[Каверзный кейс]** Создай мапу `m := map[string]User{}` (где `User` — структура). Попробуй вызвать метод с pointer receiver у элемента мапы `m["a"].ChangeName("Bob")`. Поймай ошибку компиляции (элементы мапы не адресуемы). Объясни, почему так, и найди решение (например, хранить в мапе указатели `map[string]*User`).
260. Реализуй паттерн "Декоратор" через встраивание: базовый интерфейс `DataSource`, реализация `FileDataSource`, и декоратор `CompressionDecorator`, который встраивает `DataSource` и оборачивает метод `WriteData`.
261. **[Высокая сложность]** Создай структуру `Logger` с методом `Log(msg string)`. Встрой `Logger` в структуру `Service`. Добавь метод в `Service`, который делает какую-то работу и пишет лог через встроенный `Logger`.
262. Множественное встраивание: создай структуры `Flying` и `Walking` с методами `Fly()` и `Walk()`. Создай структуру `Bird`, встраивающую обе. Вызови оба метода.

### Блок 19: Дженерики (Generics)
*Цель: Научиться писать обобщенные функции и типы, понимать constraints (ограничения) и типизацию во время компиляции.*

263. Напиши дженерик-функцию `Print[T any](val T)`, которая просто выводит значение через `fmt.Println`. Вызови её с числом, строкой и структурой.
264. Напиши дженерик-функцию `Map[T any, V any](slice []T, fn func(T) V) []V`, которая применяет функцию `fn` к каждому элементу слайса и возвращает новый слайс.
265. Напиши дженерик-функцию `Filter[T any](slice []T, fn func(T) bool) []T`, которая оставляет только те элементы, для которых `fn` вернула `true`.
266. Напиши дженерик-функцию `Contains[T comparable](slice []T, target T) bool`, которая ищет элемент в слайсе. Обрати внимание на контрейнт `comparable` (допускает только сравнимые типы).
267. Напиши дженерик-функцию `Sum[T int | float64](slice []T) T`, которая суммирует числа. Используй inline constraint (объединение типов прямо в сигнатуре).
268. Вынеси ограничение в отдельный интерфейс: `type Number interface { int | int64 | float64 }`. Напиши функцию `Multiply[T Number](a, b T) T`.
269. **[Каверзный кейс]** Создай свой тип `type MyInt int`. Попробуй передать слайс `[]MyInt` в функцию `Sum` из предыдущего задания (где ограничение `int | float64`). Поймай ошибку. Исправь ограничение, добавив тильду: `~int | ~float64`.
270. Создай дженерик-структуру (контейнер) `Stack[T any]` с методами `Push` и `Pop`. Создай стек для `int` и стек для `string`.
271. Напиши метод для дженерик-структуры: добавь метод `IsEmpty()` для `Stack[T]`.
272. Создай дженерик-мапу: `type GenericMap[K comparable, V any] map[K]V`. Напиши функцию `GetKeys[K comparable, V any](m GenericMap[K, V]) []K`, которая возвращает все ключи.
273. Напиши дженерик-функцию `Reverse[T any](slice []T)`, которая переворачивает слайс на месте (без выделения новой памяти).
274. **[Каверзный кейс]** Выведение типов (Type Inference): вызови функцию `Contains[T comparable](slice []T, target T)` без явного указания типа `Contains[int](...)`. Убедись, что компилятор сам понял тип. Затем попробуй передать в функцию, ожидающую `int`, значение `int64` без приведения типов (поймай ошибку).
275. Явное инстанцирование: вызови `Print[int]("hello")` (передача аргумента не того типа при явном указании дженерика). Поймай ошибку компиляции.
276. Создай дженерик-функцию `MergeMaps[K comparable, V any](m1, m2 map[K]V) map[K]V`, которая объединяет две мапы (при конфликте ключей выигрывает вторая мапа).
277. Напиши функцию `AreEqual[T comparable](a, b T) bool`. Используй её для сравнения двух слайсов (слайсы сравнимы через `==`, если их элементы сравнимы).
278. **[Высокая сложность]** Напиши дженерик-функцию `Partition[T any](slice []T, predicate func(T) bool) ([]T, []T)`, которая разделяет слайс на два: те, что прошли проверку, и те, что нет.
279. **[Высокая сложность]** Создай интерфейс `Stringer` с методом `String() string`. Напиши дженерик-функцию `ToString[T Stringer](val T) string`. Передай в неё структуру, реализующую этот интерфейс.
280. **[Финальное испытание по дженерикам]** Реализуй простой Generic Repository. Создай тип `Repository[T any]` с методами `Save(item T)`, `GetByID(id int) (T, error)` и `GetAll() []T`. Внутри репозитория храни данные в слайсе `[]T`. Создай репозиторий для структур `User` и `Product`, добавь и извлеки данные.
