## Часть XII. Объектно-ориентированное программирование в Go

### 30. Методы и receivers

**Упражнение 12.1.** Объяви тип `Point` с методом `Distance(other Point) float64` (**value receiver**). Вычисли расстояние между двумя точками. Покажи, что метод можно вызвать и на значении, и на указателе (Go автоматически разыменовывает/берёт адрес).

**Упражнение 12.2.** Объяви тип `Counter` с методом `Increment()` (**pointer receiver**). Создай переменную `var c Counter` (не указатель), вызови `c.Increment()`. Покажи, что Go автоматически передаёт адрес для pointer receiver. Убедись, что оригинал изменился.

**Упражнение 12.3.** Объяви тип `Rectangle` с методами `Area() float64` (**value receiver**) и `Scale(factor float64)` (**pointer receiver**). Покажи, что `Area` работает на value и pointer, а `Scale` требует addressable value или указатель. Объясни **method set** `T` vs `*T`.

**Упражнение 12.4.** Создай **defined type** `type MyString string`. Объяви метод `(s MyString) IsPalindrome() bool`. Покажи, что методы можно объявлять только на типы, определённые в **том же пакете**. Попробуй добавить метод к `int` — получи ошибку компиляции.

**Упражнение 12.5.** Создай **method value**: `p := Point{3, 4}; distanceFromP := p.Distance`. Вызови `distanceFromP(otherPoint)`. Объясни, что method value захватывает получателя (`p` копируется в замыкание).

**Упражнение 12.6.** Создай **method expression**: `dist := Point.Distance`. Вызови `dist(p, otherPoint)`. Объясни разницу: method expression не захватывает получателя, а требует его первым аргументом.

**Упражнение 12.7.** Реализуй метод на **nil pointer receiver**: `type Tree struct { Value int; Left, Right *Tree }`, метод `(t *Tree) Sum() int`. Вызови `(nil).Sum()` — покажи, что если метод проверяет `if t == nil { return 0 }`, это **безопасно**. Объясни, почему в Go это возможно (nil — валидный receiver, если не разыменовывается).

**Упражнение 12.8.** Реализуй метод на **nil slice**: `type IntSlice []int`, метод `(s IntSlice) Sum() int`. Вызови `(IntSlice(nil)).Sum()` — покажи, что nil slice ведёт себя как пустой слайс внутри метода.

**Упражнение 12.9.** Объяви метод `String() string` для типа `T` и **отдельно** для `*T` с разной реализацией. Создай переменные `var t T` и `var p *T`, присвой интерфейсу `fmt.Stringer`. Покажи, какой метод выбирается в каждом случае и почему.

**Упражнение 12.10.** Реализуй **method chaining** (fluent interface): `type Point struct { x, y float64 }`, методы `WithX(x float64) *Point`, `WithY(y float64) *Point`, `String() string`. Каждый метод возвращает `*Point` для цепочки: `p.WithX(10).WithY(20).String()`.

**Упражнение 12.11.** Объяви два типа `Dog` и `Cat` с одинаковым методом `Speak() string`. Напиши функцию `MakeSound(speaker interface{ Speak() string })`, принимающую любой тип с методом `Speak`. Покажи **ad-hoc interface** (неявный интерфейс) в действии.

**Упражнение 12.12.** Объяви тип `Handler func(string) string`. Создай метод `(h Handler) Process(s string) string`. Покажи, что **функциональные типы** тоже могут иметь методы, и `Handler` удовлетворяет интерфейсу с методом `Process`.

### 31. Встраивание (Embedding) и композиция

**Упражнение 12.13.** Создай структуру `CustomReader`, **встроив** в неё `bytes.Buffer`. Покажи, что методы `Buffer` (`Write`, `WriteString`, `Bytes` и т.д.) **продвигаются** (promoted) и доступны напрямую на `CustomReader`.

**Упражнение 12.14.** Создай структуру `SafeCounter`, встроив `*sync.Mutex`. Покажи, что методы `Lock`/`Unlock` продвигаются. Напиши метод `Inc()` с защитой мьютекса. Объясни, почему встраивается именно `*sync.Mutex`, а не `sync.Mutex`.

**Упражнение 12.15.** Создай структуру, встраивающую два типа с **одинаковым полем** `Name`. Попробуй обратиться к `.Name` — получи ошибку **ambiguous selector**. Исправь через явное указание: `s.TypeA.Name` vs `s.TypeB.Name`.

**Упражнение 12.16.** Встрой интерфейс `io.Reader` в структуру `MyProcessor`. Покажи, что `MyProcessor` **автоматически удовлетворяет** `io.Reader`, если встроенное поле инициализировано типом, реализующим `io.Reader`.

**Упражнение 12.17.** Создай структуру с встроенным **указателем** `*Item`. Покажи, что если `Item == nil`, доступ к **promoted полям** вызывает панику. А вызов promoted метода — панику только если метод разыменовывает получателя без проверки.

**Упражнение 12.18.** Создай цепочку встраивания: `A` встраивает `B`, `B` встраивает `C`. `C` имеет метод `Hello()`. Покажи, что `Hello` доступен напрямую на `A` (**deep promotion**).

**Упражнение 12.19.** Создай структуру, встраивающую `io.Reader`. Переопредели метод `Read` на внешней структуре (например, добавь логирование). Покажи, что **собственный метод имеет приоритет** над promoted.

**Упражнение 12.20.** Сравни **embedding** и **explicit composition**: создай два варианта `Logger` (один с `embed io.Writer`, другой с полем `writer io.Writer`). Покажи разницу в доступе к методам, полям и удовлетворении интерфейсов.

**Упражнение 12.21.** Используй `reflect.TypeOf` на структуре с embedded полем. Покажи, что embedded struct видно как отдельное поле с именем типа, у которого `Anonymous = true`.

**Упражнение 12.22.** Реализуй **"mixin" паттерн**: создай несколько маленьких структур (`LoggerMixin` с методом `Log`, `MetricsMixin` с методом `Record`) и встрой их в большую структуру `Service`. Покажи, как Service получает все методы миксинов.

### 34. Каверзные случаи ООП в Go

**Упражнение 12.39.** Создай `SafeCounter` с **value receiver** на методе `Inc()`: `func (c SafeCounter) Inc() { c.mu.Lock(); ... }`. Покажи, что `sync.Mutex` **копируется** при вызове, и синхронизация **не работает** (data race). Исправь на pointer receiver.

**Упражнение 12.40.** Создай `var p *Point = nil; var i fmt.Stringer = p`. Проверь `i == nil` (**false**!). Объясни внутреннее устройство интерфейса: интерфейс не nil, потому что **type descriptor** присутствует (`*Point`), а value — nil.

**Упражнение 12.41.** Создай тип `T` с методом `Value() string` (**value receiver**). Покажи, что `T` удовлетворяет интерфейсу `Valuer`, а `*T` тоже удовлетворяет. Затем добавь метод `PointerMethod()` **только** для `*T`. Покажи, что `T` **больше не удовлетворяет** интерфейсу с `PointerMethod`. Объясни **method set** правила.

**Упражнение 12.42.** Создай структуру `Container` с встроенным `*Item` (nil). Вызови promoted метод `Item.Method()` — получи панику. Затем добавь в `Item.Method()` проверку на nil receiver — покажи, что паники нет, если метод безопасен. Объясни разницу между nil pointer в интерфейсе и nil embedded pointer.

**Упражнение 12.43.** Создай структуру с **собственным** полем `Name` и **встроенным** типом, тоже имеющим поле `Name`. Покажи **shadowing**: доступ к собственному `Name` через `.Name`, к встроенному — через `.EmbeddedType.Name`.

**Упражнение 12.44.** Создай два интерфейса `A` и `B` с одинаковым методом `M()`. Создай интерфейс `C`, встраивающий `A` и `B`. Покажи, что это нормально (method sets объединяются). Затем создай `A` и `B` с методами `M()` с **разными сигнатурами** — покажи ошибку компиляции.

**Упражнение 12.45.** Создай иерархию: интерфейс `Animal` с методом `Speak()`, интерфейс `Pet` встраивает `Animal` и добавляет `Play()`. Создай `Dog`, реализующий `Pet`. Сделай type assertion `Animal` → `Pet` (downcast) и `Pet` → `Animal` (upcast). Объясни, что Go не проверяет иерархию во время компиляции для assertions — только во время выполнения.

### 36. Constraints и type sets

**Упражнение 13.13.** Создай constraint `Number`:
```go
type Number interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64 |
    ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 |
    ~float32 | ~float64
}
```
Используй в `Sum[T Number](nums ...T) T`. Объясни, зачем нужен `~` (tilde, **type approximation**).

**Упражнение 13.14.** Создай `type MyInt int`. Покажи, что `Sum[MyInt]` работает только если constraint содержит `~int`, а не просто `int`. Без `~` — ошибка компиляции. Объясни разницу.

**Упражнение 13.15.** Создай constraint `Integer` с `~int | ~int8 | ... | ~uint64` (без float). Используй для generic-функции битовых операций: `BitwiseAnd[T Integer](a, b T) T`.

**Упражнение 13.16.** Используй `comparable` constraint: создай generic `Set[T comparable]` (реализация позже). Покажи, что можно использовать `struct` с comparable полями как элемент, но **нельзя** `[]byte` (слайс не comparable).

**Упражнение 13.17.** Создай constraint через embedding:
```go
type OrderedStringer interface {
    constraints.Ordered
    fmt.Stringer
}
```
Напиши `PrintSorted[T OrderedStringer](items []T)`, которая сортирует (используя `<`) и выводит через `String()`.

**Упражнение 13.18.** Создай constraint с **union типов и методом**:
```go
type StringOrInt interface {
    ~string | ~int
    String() string
}
```
Объясни, что метод должен быть доступен для **всех** типов в union (иначе ошибка компиляции при использовании).

**Упражнение 13.19.** Создай constraint для byte-слайсов и строк:
```go
type BytesOrString interface {
    ~[]byte | ~string
}
```
Напиши `Len[T BytesOrString](v T) int`, возвращающий `len(v)`. Покажи, что `len` работает для обоих типов без приведения.

**Упражнение 13.20.** Создай constraint `MapKey` как `comparable`. Напиши `Keys[K MapKey, V any](m map[K]V) []K`, извлекающий все ключи мапы в слайс.

**Упражнение 13.21.** Создай constraint, требующий и `constraints.Ordered`, и кастомный метод:
```go
type NamedOrdered interface {
    constraints.Ordered
    Name() string
}
```
Покажи, что тип должен удовлетворять **обоим** требованиям.

**Упражнение 13.22.** Покажи разницу между `any` и `comparable` на примере: `SearchAny[T any](slice []T, item T)` не может использовать `==`, а `SearchComparable[T comparable]` может. Объясни, когда что использовать.

**Упражнение 13.23.** Создай `type MyFloat float64`. Покажи, что constraint с `~float64` принимает `MyFloat`, а без `~` — только строго `float64`. Объясни **underlying type** concept.

**Упражнение 13.24.** Создай constraint с интерфейсом, имеющим метод: `type Closer interface { Close() error }`. Напиши `CloseAll[T Closer](items []T) []error`, закрывающий всё и собирающий ошибки.

### 38. Продвинутые дженерики и каверзные случаи

**Упражнение 13.43.** Покажи **type inference**: вызови `Max(3, 5)` без явного `[int]`. Покажи, когда inference работает. Затем попробуй `Max(3, int64(5))` — покажи, что inference **не может** выбрать общий тип (mismatched types).

**Упражнение 13.44.** Напиши generic-функцию с **variadic** параметром: `Sum[T Number](nums ...T) T`. Вызови `Sum(1, 2, 3, 4)` и `Sum[int](1, 2, 3)`.

**Упражнение 13.45.** Покажи, что **type switch не работает** с type parameter напрямую:
```go
func TypeName[T any](v T) string {
    switch v.(type) { // ОШИБКА!
    }
}
```
Обход: `switch any(v).(type)`. Объясни, почему так (type parameter — не конкретный тип во время компиляции для type switch).

**Упражнение 13.46.** Напиши generic-функцию с constraint, требующим метод:
```go
type Stringer interface { String() string }
func PrintString[T Stringer](v T) { fmt.Println(v.String()) }
```
Передай тип без метода `String()` — получи ошибку компиляции. Покажи, что constraint может включать **method set**.

**Упражнение 13.47.** Напиши функцию `Zero[T any]() T`, возвращающую zero value для любого типа:
```go
func Zero[T any]() T {
    var z T
    return z
}
```
Покажи, что для `int` вернёт `0`, для `string` — `""`, для `*int` — `nil`, для `struct` — zero-valued struct.

**Упражнение 13.48.** Покажи, что нельзя вернуть `nil` для type parameter `T`:
```go
func Maybe[T any](ok bool, v T) (T, error) {
    if !ok {
        return nil, errors.New("fail") // ОШИБКА: nil не типа T
    }
    return v, nil
}
```
Исправь через `var zero T; return zero, err`.

**Упражнение 13.49.** Покажи, что generic `append` имеет тот же эффект **shared underlying array**: создай функцию `AppendAll[T any](s []T, items ...T) []T`, возвращающую `append(s, items...)`. В `main` создай слайс с `len == cap`, передай в функцию, измени возвращённый слайс — покажи, что оригинал **не** изменился (реаллокация). Затем с `cap > len` — покажи, что оригинал **изменился** (тот же массив).

**Упражнение 13.50.** Сериализуй generic-тип `Stack[int]` в JSON через `encoding/json`. Затем десериализуй обратно. Объясни, почему это работает: JSON-пакет видит **concrete type** во время выполнения через reflection, а type parameter — это compile-time концепция.

**Упражнение 13.51.** Напиши generic-функцию, где **анонимная функция** замыкает переменные и использует type parameter:
```go
func Map[T, U any](s []T, fn func(T) U) []U {
    // fn может замыкать переменные извне
}
```
Покажи, что замыкания работают с generics без ограничений.

**Упражнение 13.52.** Напиши **generic метод** на generic типе:
```go
func (s *Stack[T]) Clone() *Stack[T] {
    // создаёт независимую копию
}
```
Покажи, что методы generic типа **наследуют** параметры типа структуры и могут их использовать.

**Упражнение 13.53.** Напиши `CountOccurrences[T comparable](s []T) map[T]int`. Покажи, что `comparable` даёт операторы `==` и `!=`, но не `<` или `>`.

**Упражнение 13.54.** Создай constraint для **всех целых типов** с `~` (tilde):
```go
type AnyInteger interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64 |
    ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr
}
```
Напиши `BitwiseOr[T AnyInteger](a, b T) T`. Покажи, что `AnyInteger` включает и signed, и unsigned.

**Упражнение 13.55.** Реализуй **type-safe enum** через дженерики:
```go
type Enum[T comparable] struct {
    value T
    valid bool
}
func NewEnum[T comparable](v T) Enum[T] { ... }
func (e Enum[T]) IsValid() bool { ... }
func (e Enum[T]) Value() T { ... }
```
Покажи, что это даёт **type safety**: `Enum[Status]` и `Enum[Role]` — разные типы, их нельзя перепутать.

### Ключевые моменты для осознанного прохождения новых блоков:

**ООП:**
1. **Embedding ≠ наследование** — в Go нет наследования, есть композиция. Promoted fields/methods — синтаксический сахар, а не подклассы.
2. **Value receiver + Mutex = data race** — классическая ловушка. Всегда используй pointer receiver для синхронизированных структур.
3. **Nil interface ≠ nil** — если присвоил `var i fmt.Stringer = (*Point)(nil)`, то `i != nil`. Это потому что интерфейс хранит `(type: *Point, value: nil)`.
4. **Method set** — `T` получает все value receiver методы, `*T` получает все методы (и value, и pointer). Это определяет, какие интерфейсы удовлетворяет тип.

**Дженерики:**
1. **`~` (tilde)** — разрешает использовать типы с тем же underlying type. Без `~` — только строго указанный тип.
2. **`any` vs `comparable`** — `any` не даёт `==`, `comparable` даёт. Для map keys и `==` всегда используй `comparable`.
3. **Zero value** — `var z T` внутри generic функции создаёт zero value для любого типа. Это идиоматичный способ вернуть "пустое" значение.
4. **Type inference** — Go выводит `T` из аргументов функции, но не из возвращаемого значения. Если inference не работает — указывай явно: `Fn[int](args)`.
5. **Generic типы и JSON** — сериализация работает, потому что во время выполнения generic тип конкретизирован (concrete type). Reflection видит `Stack[int]`, а не абстрактный `Stack[T]`.
