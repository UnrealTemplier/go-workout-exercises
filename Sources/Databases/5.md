Базы данных — это сердце любого серьезного бэкенда. В мире Go балом правят чистый SQL (в отличие от других языков, где доминируют ORM) и высочайшая производительность. Для PostgreSQL мы изучим как стандартный `database/sql`, так и современный драйвер `pgx`. А для кэширования и быстрых данных возьмем Redis.

Продолжаем нашу нумерацию. Впереди **35 мощных упражнений** (с 366 по 400), которые сделают из тебя уверенного инженера баз данных на Go.

*(Для этих упражнений потребуется установленный локально или в Docker PostgreSQL и Redis).*

### Блок 27. Реляционные БД: PostgreSQL и `database/sql` (366–380)
Стандартная библиотека и основы работы с SQL.

366. **Подключение (Ping):** Установи драйвер `github.com/lib/pq`. Напиши код, который подключается к локальной базе PostgreSQL через `sql.Open("postgres", "postgres://user:pass@localhost:5432/db?sslmode=disable")`. Обязательно вызови `db.Ping()`, чтобы убедиться, что соединение реально установлено (сам `Open` не стучится в базу!).
367. **DDL (Создание таблиц):** Используй `db.Exec()`, чтобы создать таблицу `users` с полями `id (SERIAL PRIMARY KEY)`, `name (VARCHAR)`, `age (INT)` и `created_at (TIMESTAMP)`.
368. **Защита от SQL-инъекций (База):** Попробуй вставить данные, конкатенируя строку (например, `INSERT INTO users (name) VALUES ('" + name + "')`). Пойми, насколько это опасно. Перепиши запрос с использованием плейсхолдеров: `INSERT INTO users ... VALUES ($1, $2)`.
369. **Возврат ID (RETURNING):** Вставь нового пользователя. Поскольку `id` генерируется базой, используй `db.QueryRow("INSERT ... RETURNING id").Scan(&id)`, чтобы сразу получить ID созданной записи.
370. **Чтение одной записи:** Запроси пользователя по ID через `db.QueryRow`. Считай данные в переменные через `Scan(&id, &name, &age)`.
371. **Каверзный случай: sql.ErrNoRows:** Запроси из упр. 370 несуществующий ID. Убедись, что `Scan` возвращает ошибку. Сравни её строго: `if errors.Is(err, sql.ErrNoRows) { fmt.Println("Юзер не найден") }`.
372. **Чтение множества записей:** Используй `db.Query("SELECT ...")` для получения всех юзеров. В цикле `for rows.Next() { ... }` считай их в срез структур `[]User`. Обязательно добавь `defer rows.Close()` сразу после `Query`.
373. **Скрытая ловушка `rows.Err()`:** После цикла `rows.Next()` добавь проверку `if err := rows.Err(); err != nil`. Узнай из документации, почему цикл мог прерваться досрочно (например, из-за обрыва сети), и почему эта проверка **обязательна**.
374. **NULL значения:** Добавь в базу юзера, у которого `age = NULL`. Попытайся считать его в обычный `int` и получи панику/ошибку. Исправь это, считывая значение в специальный тип `sql.NullInt64` (или в указатель `*int`).
375. **Транзакции (ACID):** Начни транзакцию через `tx, err := db.Begin()`. Выполни два запроса: спиши деньги у одного юзера и добавь другому. Если на любом этапе ошибка — `tx.Rollback()`. Если всё ок — `tx.Commit()`. 
376. **Транзакции и Defer:** Улучши код из упр. 375. Добавь `defer tx.Rollback()` сразу после `Begin`. (Если транзакция уже была закоммичена, Rollback безопасно проигнорируется, а вот в случае паники — спасет базу от зависших блокировок).
377. **Таймаут запроса (Контекст):** Используй `db.QueryContext(ctx, "SELECT pg_sleep(2)")`. Передай контекст с таймаутом в 1 секунду. Убедись, что запрос прерывается на стороне Go и возвращает ошибку таймаута.
378. **Пул соединений (Connection Pool):** Настрой пул "под капотом" стандартной библиотеки: задай `db.SetMaxOpenConns(20)` (макс. соединений), `db.SetMaxIdleConns(5)` (кол-во спящих) и `db.SetConnMaxLifetime(time.Minute * 5)`. 
379. **Ускорение с sqlx:** Установи `github.com/jmoiron/sqlx`. Перепиши упр. 372 (чтение множества записей), используя `db.Select(&users, "SELECT ...")`. Насладись тем, как `sqlx` сам матчит колонки БД с тегами `db:"..."` в твоей структуре без ручного `Scan`.
380. **Миграции:** Установи CLI-утилиту `golang-migrate/migrate`. Создай файлы `up.sql` (создание таблицы) и `down.sql` (дроп таблицы). Напиши скрипт или команду для накатки и отката миграций. Никогда не создавай таблицы через `db.Exec` в продакшен-коде!

### Блок 28. Мощь PostgreSQL с драйвером `pgx` (381–387)
`pgx` — это де-факто стандарт для PostgreSQL в Go на сегодня. Он умеет то, чего не умеет стандартный `database/sql`.

381. **Нативный pgx:** Установи `github.com/jackc/pgx/v5`. Подключись к базе через `pgxpool.New(ctx, connString)`. Обрати внимание, что `pgx` использует контекст везде, с самого первого вызова.
382. **Работа с JSONB:** Создай в базе колонку типа `JSONB`. В Go создай вложенную структуру. При вставке передай её напрямую (pgx сам сериализует её в JSON, если правильно настроить, или используй ручной Marshal). При чтении распарси JSONB обратно в структуру.
383. **Массивы в БД:** Создай в базе колонку `tags text[]`. Передай из Go обычный срез `[]string{"go", "backend", "sql"}`. `pgx` нативно поддерживает массивы Postgres, в отличие от `lib/pq`.
384. **Пакетная вставка (Batching):** Тебе нужно вставить 1000 записей. Вместо 1000 отдельных `INSERT` запросов, создай `batch := &pgx.Batch{}`. В цикле добавь запросы через `batch.Queue()`. Выполни их одним махом через `pool.SendBatch()`. Замерь разницу в скорости!
385. **Сверхбыстрая вставка (CopyFrom):** Используй метод `pool.CopyFrom()`. Загрузи в базу 100 000 записей за доли секунды, используя бинарный протокол копирования Postgres (идеально для импорта CSV/логов).
386. **Listen / Notify (Очереди на минималках):** Открой одно соединение и запусти `conn.WaitForNotification(ctx)` в горутине — она будет заблокирована в ожидании. В другой горутине (или из консоли psql) сделай `NOTIFY my_channel, 'hello_from_go'`. Убедись, что первая горутина получила сообщение.
387. **Паттерн Repository (Архитектура):** Создай интерфейс `UserRepository` с методами `Create`, `GetByID`. Напиши структуру `PostgresRepo`, которая принимает `*pgxpool.Pool` и реализует этот интерфейс. Это основа тестируемого кода.

### Блок 29. Redis: Сверхбыстрые данные в оперативной памяти (388–400)
Кэш, счетчики, сессии и примитивы распределенных систем.

388. **Подключение к Redis:** Установи `github.com/redis/go-redis/v9`. Настрой клиент `redis.NewClient`. Проверь связь через `client.Ping(ctx)`.
389. **Базовый Set/Get и redis.Nil:** Сохрани строковое значение по ключу: `client.Set(ctx, "mykey", "hello", 0)`. Прочитай его. Затем попробуй прочитать несуществующий ключ и обработай ошибку `errors.Is(err, redis.Nil)`.
390. **TTL (Время жизни):** Сохрани ключ с таймаутом (expiration) в 3 секунды. Прочитай его (убедись, что он есть), сделай `time.Sleep(4 * time.Second)`, попробуй прочитать снова и убедись, что он удален.
391. **Кэширование структур:** Redis хранит только строки/байты. Сериализуй структуру `User` в JSON (`json.Marshal`) и сохрани в Redis. Прочитай и десериализуй обратно.
392. **Счетчики (Incr / Decr):** Реализуй счетчик просмотров статьи. Используй `client.Incr(ctx, "article:123:views")`. (В отличие от реляционной БД с транзакциями, в Redis `Incr` атомарен и работает за наносекунды).
393. **Хэши (Hashes):** Сохрани профиль пользователя не как JSON, а как Redis Hash. Используй `client.HSet(ctx, "user:1", "name", "Ivan", "age", 25)`. Прочитай только возраст через `HGet`, а затем все поля сразу через `HGetAll`.
394. **Списки (Lists - Очередь):** Используй Redis как очередь задач. Сделай `LPush` (добавление в начало списка) трех строк. Из другой горутины читай их через `RPop` (взятие с конца), пока список не опустеет.
395. **Множества (Sets - Уникальность):** Тебе нужно хранить уникальные IP посетителей. Сделай 10 вызовов `SAdd` с одним и тем же IP и 5 с другим. Сделай `SCard` (количество). Убедись, что размер сета = 2.
396. **Конвейер (Pipeline):** Тебе нужно сделать 1000 операций `Set`. Вызови `pipe := client.Pipeline()`, в цикле сделай 1000 `pipe.Set(...)`, а в конце один раз `pipe.Exec(ctx)`. Это отправит все команды в одном TCP-пакете.
397. **Транзакции в Redis:** Redis поддерживает транзакции (они не такие строгие, как в SQL). Используй `client.TxPipeline()`, чтобы выполнить несколько команд. Если хоть одна упадет, остальные не откатятся (особенность Redis), но они гарантированно выполнятся друг за другом, не прерываясь командами других клиентов.
398. **Паттерн Cache-Aside (Интеграция):** Напиши функцию `GetUser(id)`. Алгоритм:
    1. Ищем юзера в Redis. Если есть — возвращаем (Cache Hit).
    2. Если нет (Cache Miss) — идем в PostgreSQL (сделай мок функции).
    3. Кладем результат из БД в Redis с TTL = 10 минут.
    4. Возвращаем результат.
399. **Распределенная блокировка (Distributed Lock):** У тебя 3 инстанса приложения, и крон-задачу должен выполнить только один. Используй `client.SetNX(ctx, "cron_lock", "locked", 10*time.Second)` (Set if Not eXists). Тот инстанс, которому Redis ответит `true`, выполняет задачу. Остальные пропускают.
400. **Rate Limiter (Ограничитель запросов):** Напиши Middleware для HTTP-сервера (из предыдущего блока). При каждом запросе увеличивай счетчик по ключу `rate:limit:IP` через `Incr`. Если это первый запрос — ставь `Expire` в 1 минуту. Если значение счетчика > 60 — возвращай `http.StatusTooManyRequests`.

---
**Совет к этому блоку:** При работе с базами данных (и SQL, и Redis) всегда помни о **закрытии ресурсов** (`defer rows.Close()`), **таймаутах** (всегда используй методы с `Context`) и **пулах соединений**. База данных — это самое узкое горлышко любого приложения, и то, как твой Go-код с ней общается, напрямую определяет, "ляжет" твой бэкенд под нагрузкой или нет.
