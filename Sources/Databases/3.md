Работа с базами данных — это то, с чем Go справляется великолепно благодаря интерфейсу `database/sql` и великой экосистеме драйверов. Для PostgreSQL текущим стандартом является `pgx`, а для Redis — `go-redis`.

Здесь **37 упражнений** (с 386 по 422), которые проведут тебя от первого подключения до транзакций, пула соединений и распределенных блокировок. Для выполнения этих задач тебе понадобится поднять локально PostgreSQL и Redis (например, через Docker).

### Блок 33: PostgreSQL — Подключение и базовые запросы
*Цель: Научиться подключаться к БД, управлять пулом соединений и выполнять простые запросы.*

386. Установи драйвер `github.com/jackc/pgx/v5` (и пакет `github.com/jackc/pgx/v5/stdlib` для работы через стандартный `database/sql`). Создай строку подключения (DSN - Data Source Name) и установи соединение с базой `testdb`.
387. Выполни `db.PingContext(ctx)`, чтобы проверить, что соединение с БД действительно установлено. Обработай ошибку.
388. Создай таблицу `users` (id SERIAL PRIMARY KEY, name TEXT, age INT, created_at TIMESTAMP). Используй `db.ExecContext` для выполнения DDL запроса.
389. Вставь новую запись в таблицу `users` используя `db.ExecContext`. Обрати внимание, как экранировать переменные (плейсхолдеры `$1, $2` в PostgreSQL, а не `?`).
390. **[Каверзный кейс]** Извлеки `id` только что созданной записи. Вместо `ExecContext` используй `db.QueryRowContext` с запросом `INSERT INTO ... RETURNING id`. Отскань результат в переменную.
391. Выбери одного пользователя по `id` с помощью `QueryRowContext`. Используй метод `Scan` для чтения колонок в переменные.
392. Выбери всех пользователей старше 18 лет с помощью `QueryContext`. Используй цикл `for rows.Next()` и `rows.Scan()` для чтения каждой строки. Обязательно добавь `defer rows.Close()`.
393. **[Каверзный кейс]** Напиши `QueryContext`, но забудь вызвать `rows.Close()`. Запусти код в цикле 1000 раз. Используя `runtime.NumGoroutine()`, покажи, как утекает память и горутины (исчерпание пула соединений). Исправь код.
394. Обработай ошибку `sql.ErrNoRows` при поиске пользователя, которого нет в базе. Верни кастомную ошибку `ErrUserNotFound`.
395. Настрой пул соединений: установи `db.SetMaxOpenConns(10)`, `db.SetMaxIdleConns(5)`, `db.SetConnMaxLifetime(time.Hour)`. Объясни, почему дефолтные значения (бесконечные коннекты) могут быть вредны для БД.
396. Удали пользователя по `id` (`DELETE FROM users WHERE id = $1`). Проверь, сколько строк было удалено, используя метод `result.RowsAffected()`.

### Блок 34: PostgreSQL — Транзакции и Prepared Statements
*Цель: Обеспечить целостность данных (ACID) и оптимизировать частые запросы.*

397. Начни транзакцию с помощью `db.BeginTx(ctx, nil)`. Внутри транзакции выполни два `INSERT`. Сделай `tx.Commit()` в конце.
398. **[Каверзный кейс]** Внутри транзакции из предыдущего задания сымитируй ошибку (например, деление на ноль или неверный SQL) после первого `INSERT`. Используй `defer tx.Rollback()` сразу после `BeginTx`. Убедись, что если произошла ошибка, транзакция откатывается, а если успех — `Rollback` возвращает `sql.ErrTxDone` (которую можно проигнорировать).
399. Реализуй перевод денег между двумя счетами (таблица `accounts` с полем `balance`). В одной транзакции уменьши баланс одного счета и увеличь баланс другого. Если на первом счете не хватает денег — откатывай транзакцию (`Rollback`).
400. Создай Prepared Statement (`db.PrepareContext`) для частого запроса `SELECT name FROM users WHERE id = $1`. Вызови его несколько раз в цикле с разными `id`.
401. **[Каверзный кейс]** Используй `pgx.Conn` напрямую (без `database/sql`), чтобы выполнить батч-вставку (Batch). Вставь 1000 записей за один сетевой обмен с БД вместо 1000 отдельных `INSERT`. Оцени разницу в скорости.
402. **[Высокая сложность]** Реализуй уровень изоляции транзакций. Создай транзакцию с `sql.LevelSerializable`. Запусти две горутины, которые одновременно пытаются изменить баланс одного счета. Поймай ошибку сериализации (serialization failure) и реализуй логику повторной попытки (retry).

### Блок 35: PostgreSQL — Маппинг, NULL-значения и JSON
*Цель: Решить проблему сканирования сложных типов данных и NULL-значений из БД.*

403. Добавь в таблицу `users` колонку `bio TEXT` (которая может быть `NULL`). Попробуй отсканировать её в обычную `string` (поймай ошибку сканирования `NULL` в string). Используй тип `sql.NullString` для решения проблемы.
404. Используй указатели (`*string`, `*int`) для сканирования `NULL`-значений вместо `sql.NullString`. Объясни плюсы и минусы обоих подходов.
405. Создай таблицу `events` с колонкой `data JSONB`. Вставь в неё JSON-объект, используя структуру Go и `[]byte`.
406. Прочитай `JSONB` данные из БД и десериализуй их обратно в структуру Go.
407. Используй библиотеку `github.com/jmoiron/sqlx`. Выведи данные из таблицы `users` сразу в слайс структур `[]User` с помощью `db.SelectContext(&users, query)`. Оцени, насколько меньше стало boilerplate-кода по сравнению с ручным `Scan`.
408. **[Каверзный кейс]** Используй `sqlx.NamedExec` для вставки данных, когда плейсхолдеры называются по именам полей структуры (`INSERT INTO users (name, age) VALUES (:name, :age)`).

### Блок 36: Redis — Основы кэширования и ключи
*Цель: Подключиться к Redis, освоить базовые типы данных (строки) и TTL.*

409. Установи `github.com/redis/go-redis/v9`. Создай клиента `redis.NewClient`. Проверь соединение с помощью `client.Ping(ctx)`.
410. Запиши значение по ключу: `client.Set(ctx, "user:1:name", "Alice", 0)`.
411. Прочитай значение: `client.Get(ctx, "user:1:name").Result()`. Обработай ошибку `redis.Nil` (которая означает, что ключ не найден).
412. Установи время жизни (TTL) для ключа при записи (`10 * time.Second`). Выведи значение, подожди 11 секунд, попробуй вывести снова (убедись, что ключ исчез).
413. Используй `client.Incr(ctx, "page_views")` для атомарного инкремента счетчика просмотров. Запусти 100 горутин, инкрементирующих счетчик, и убедись, что в итоге будет ровно 100.
414. **[Каверзный кейс]** Используй паттерн "Cache Aside". Напиши функцию `GetUser(id int)`, которая сначала проверяет Redis. Если данных в кэше нет, делает запрос в PostgreSQL, сохраняет результат в Redis (с TTL) и возвращает пользователю.
415. Удали набор ключей по маске (например, `user:*`). Внимание: использование `KEYS user:*` в production блокирует Redis. Используй безопасную команду `SCAN` для итерации и удаления.

### Блок 37: Redis — Сложные структуры данных
*Цель: Использовать Redis не только как key-value хранилище, но и как структуру данных в памяти.*

416. **List:** Используй `client.LPush` и `client.RPop`. Реализуй простую очередь задач (клади строки в список слева, забирай справа).
417. **Hash:** Используй `client.HSet`. Сохрани объект пользователя (имя, возраст, email) в одном хэше с ключом `user:1`. Выведи все поля (`HGetAll`).
418. **Set:** Используй `client.SAdd` для хранения тегов. Добавь теги к двум разным постам. Используй `client.SInter` для нахождения общих тегов у этих постов (пересечение множеств).
419. **Sorted Set:** Используй `client.ZAdd` для создания таблицы лидеров (игроки и их очки). Выведи топ-3 игрока с наибольшим количеством очков (`client.ZRevRangeWithScores`).
420. **Expiration:** Установи TTL на конкретное поле внутри Hash (до Redis 7.2 это было невозможно через стандартные команды. Используй структуру данных в виде строки JSON с `SET ... EX`, чтобы сэмулировать TTL для одного поля, или обнови до Redis 7.2+ и используй `HEXPIRE`).

### Блок 38: Продвинутый Redis (Пайплайны, Pub/Sub, Блокировки)
*Цель: Оптимизация производительности и паттерны распределенных систем.*

421. **[Каверзный кейс — Пайплайны]** Запиши 1000 ключей в Redis. Сначала сделай это в цикле 1000 раз через `client.Set`. Затем сделай то же самое через `client.Pipeline` (одним сетевым запросом). Измерь время выполнения `time.Since()` и оцени разницу.
422. **[Pub/Sub]** Напиши две программы (или две горутины). Первая подписывается на канал `client.Subscribe(ctx, "news")` и читает сообщения в бесконечном цикле. Вторая публикует сообщение `client.Publish(ctx, "news", "Hello")`.
423. **[Высокая сложность — Распределенная блокировка (Distributed Lock)]** Реализуй безопасную блокировку с помощью `SET lock_key 1 NX PX 10000` (Set if Not eXists, с истечением 10с). Запусти две горутины, пытающиеся захватить блокировку. Вторая должна ждать или получать ошибку. (Дополнительно: изучи библиотеку Redsync для корректной реализации алгоритма Redlock).
424. **[Транзакции в Redis (MULTI/EXEC)]** Используй `client.TxPipeline`. В одной транзакции инкрементируй счетчик и добавь элемент в список. Если инкремент пройдет, а добавление в список упадет — откатись.
425. **[Финальное испытание — Rate Limiter на Redis]** Реализуй ограничитель скорости (Token Bucket или Sliding Window) для HTTP-сервера. При каждом запросе к API используй Redis для подсчета запросов от конкретного IP-адреса за последнюю минуту. Если запросов больше 10 — возвращай `429 Too Many Requests`.
