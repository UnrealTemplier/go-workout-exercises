### Раздел 26: Работа с реляционными базами данных (PostgreSQL) (Задачи 306–318)

*Реляционные СУБД требуют строгого контроля за пулом соединений, безопасного форматирования запросов для предотвращения SQL-инъекций и корректного управления транзакциями.*

306. **Подключение к PostgreSQL**: Инициализируйте новый Go-модуль. Подключите драйвер PostgreSQL (например, `github.com/jackc/pgx/v5/stdlib` для интеграции с `database/sql` или традиционный `github.com/lib/pq`). Напишите код подключения к БД через `sql.Open` и выполните проверку связи с помощью `db.Ping()`. Обеспечьте закрытие пула соединений через `defer db.Close()`.
307. **Создание схемы данных**: Напишите функцию, которая при старте приложения создает таблицу `users` в PostgreSQL с помощью `db.Exec`. Таблица должна содержать поля: `id` (SERIAL PRIMARY KEY), `name` (VARCHAR), `email` (VARCHAR UNIQUE), `age` (INT), `bio` (TEXT) и `created_at` (TIMESTAMP).
308. **Безопасная вставка (INSERT) с плейсхолдерами**: Напишите функцию добавления нового пользователя в базу данных. Передайте имя, email и возраст в качестве аргументов. Используйте плейсхолдеры `$1`, `$2`, `$3` вместо конкатенации строк, чтобы предотвратить угрозу SQL-инъекций [308].
309. **Получение автоинкрементного ID (`RETURNING`)**: Измените ваш INSERT-запрос так, чтобы PostgreSQL автоматически возвращал ID только что созданной записи с помощью конструкции `RETURNING id`. Считайте этот ID в переменную с помощью метода `db.QueryRow().Scan(&insertedID)`.
310. **Получение списка записей (`Query`)**: Напишите функцию получения всех пользователей, чей возраст превышает заданный лимит.
    * Используйте метод `db.Query`.
    * Напишите цикл `for rows.Next() { ... }` для обхода результатов.
    * Сделайте `rows.Scan` для распаковки данных в структуру `User`.
    * Обработайте возможную ошибку после цикла с помощью `rows.Err()`.
    * Обязательно вызовите `rows.Close()` через `defer` сразу после открытия запроса.
311. **Обработка значений NULL**: В базе данных поле `bio` у некоторых пользователей может быть не заполнено (`NULL`). Попробуйте считать такую запись в обычную строковую переменную `var bio string`. Посмотрите на ошибку сканирования. Решите проблему двумя способами:
    * Использованием типа `sql.NullString` в структуре.
    * Считыванием значения в указатель на строку `*string`.
312. **Утечка соединений (Connection Leak)**: Напишите функцию, которая делает запрос `db.Query`, но намеренно не закрывает `rows` через `Close()`. Запустите эту функцию в цикле 100 раз подряд. Обратите внимание, как после нескольких итераций программа зависает, так как пул соединений исчерпан. Напишите комментарий, как этого избегать.
313. **Настройка пула соединений (Connection Pool Configuration)**: Настройте параметры пула соединений вашего объекта `db`:
    * Максимальное количество открытых соединений (`SetMaxOpenConns`).
    * Максимальное количество простаивающих соединений (`SetMaxIdleConns`).
    * Максимальное время жизни соединения (`SetConnMaxLifetime`).
    Опишите в комментариях, как эти настройки помогают балансировать нагрузку на СУБД.
314. **Транзакции (Transactions)**: Напишите симуляцию банковского перевода. У вас есть таблица `accounts` с балансами. Начните транзакцию с помощью `db.BeginTx(ctx, nil)`. Сделайте списание с одного счета и начисление на другой. Если при каком-то из действий возникла ошибка, вызовите `tx.Rollback()`. Если всё прошло успешно, примените изменения через `tx.Commit()`.
315. **Подготовленные запросы (Prepared Statements)**: Напишите код, который выполняет 1000 вставок записей в цикле. Вместо вызова `db.Exec` на каждой итерации, подготовьте шаблон запроса один раз с помощью `db.Prepare()`, а затем в цикле вызывайте метод `stmt.Exec()`. Сравните время выполнения запросов с подготовкой и без неё.
316. **Хранение сложных объектов (JSONB)**: Создайте таблицу `orders` с полем `metadata` типа `JSONB`. Напишите структуру `OrderMetadata` в Go (с полями `Tags []string`, `DiscountCode string`). Напишите код записи этой структуры в БД (сериализовав её в срез байт JSON) и обратного считывания из базы напрямую в структуру.
317. **Ознакомление с ORM (GORM)**: Установите библиотеку GORM (`github.com/go-gorm/gorm`). Напишите код инициализации подключения через GORM, объявите модель пользователя, выполните автомиграцию схемы данных (`db.AutoMigrate`), создайте запись и сделайте выборку. Напишите комментарий со сравнением подходов `database/sql` vs GORM (производительность, сложность отладки, удобство).
318. **Обработка специфических ошибок БД**: Напишите обработчик ошибки дублирования уникального значения (например, при попытке зарегистрировать пользователя с уже существующим email). Используйте проверку типа ошибки драйвера (например, приведя ошибку к типу `*pgconn.PgError` при использовании драйвера `pgx`), чтобы извлечь код ошибки PostgreSQL `23505` (unique_violation) и вернуть клиенту понятное сообщение.

### Раздел 27: Интеграция с NoSQL и Кэшированием (Redis) (Задачи 319–330)

*Redis используется как быстрое key-value хранилище в оперативной памяти. Задачи помогут освоить работу с типами данных Redis, механизмами TTL, паттерном Cache-Aside и оптимизацией запросов.*

319. **Подключение к Redis**: Установите клиент `go-redis` версии 9 (`github.com/redis/go-redis/v9`). Напишите код подключения к локальному серверу Redis через `redis.NewClient`. Выполните команду `Ping` с передачей контекста и выведите ответ в консоль.
320. **Запись и чтение строк (SET/GET)**: Напишите функцию кэширования текстовых данных. Запишите в Redis ключ `"session_token"` со значением `"user_123_active"`. Установите время жизни ключа (TTL) равным 10 секундам. Прочитайте значение ключа и выведите его на экран. Подождите 11 секунд и попробуйте прочитать ключ снова.
321. **Обработка отсутствия ключа**: При попытке получить несуществующий ключ клиент `go-redis` возвращает специальную ошибку. Напишите проверку: если возвращаемая ошибка равна `redis.Nil`, выведите сообщение `"Ключ не найден в кэше"`, иначе обработайте сетевую ошибку.
322. **Сериализация структур для Redis**: Redis хранит строки или байты. Напишите функции `SaveUserToCache(ctx context.Context, u User)` и `GetUserFromCache(ctx context.Context, id string) (*User, error)`. Внутри функций сериализуйте структуру в JSON-строку при записи и десериализуйте обратно при чтении.
323. **Работа со структурами через Hashes**: Redis поддерживает тип данных Hash, позволяющий работать с отдельными полями объекта без полной его перезаписи. Используйте команды `HSet`, `HGet` и `HGetAll` для хранения и чтения профиля пользователя.
324. **Паттерн Кэширования "Cache-Aside"**: Напишите комплексную функцию `GetUserData(ctx context.Context, id int) (*User, error)`:
    * Функция проверяет наличие данных о пользователе в Redis (ключ `user:id`).
    * Если данные есть в кэше, она десериализует их и мгновенно возвращает результат (cache hit).
    * Если данных в кэше нет (cache miss), она делает SELECT-запрос к PostgreSQL, сохраняет полученные данные в Redis с TTL 5 минут и возвращает результат пользователю.
325. **Очередь задач на списках Redis (LPUSH/RPOP)**: Реализуйте простейшую очередь на структурах данных Redis. Напишите одну горутину (Producer), которая раз в секунду добавляет ID задач в конец списка Redis с помощью `LPush`. Напишите вторую горутину (Consumer), которая забирает эти задачи с помощью `RPop` или блокирующего чтения `BRPop`.
326. **Множества для проверки уникальности (Sets)**: Напишите счетчик уникальных посетителей сайта. Используйте структуру данных Set в Redis и команды `SAdd` (добавление IP-адреса посетителя) и `SCard` (получение общего количества уникальных адресов).
327. **Пакетные запросы (Pipeline)**: Если вам нужно отправить много команд в Redis, отправка каждой команды по отдельности создает накладные расходы на сетевые запросы (RTT). Напишите код, который записывает 1000 ключей в Redis двумя способами:
    * Обычными последовательными вызовами `client.Set`.
    * С использованием `client.Pipeline()` (когда все команды собираются в пакет и отправляются за один сетевой запрос).
    Замерьте и сравните время выполнения обоих вариантов.
328. **Распределенная блокировка (Distributed Lock)**: В распределенных системах мьютексы внутри программы не работают на уровне нескольких серверов. Реализуйте распределенную блокировку на Redis:
    * Захват блокировки: вызов команды `SetNX` (Set if Not Exists) с определенным ключом, уникальным токеном (UUID) в качестве значения и TTL 5 секунд.
    * Если блокировка успешно захвачена — выполните работу.
    * Освобождение блокировки: напишите Lua-скрипт (или выполните команду), который безопасно удаляет ключ только в том случае, если значение в Redis по-прежнему совпадает с вашим UUID (чтобы случайно не удалить чужую блокировку, если ваша истекла по таймауту).
329. **Pub/Sub в Redis**: Напишите два независимых приложения (или две горутины):
    * Издатель (Publisher) раз в секунду отправляет системные метрики в канал `"system_events"` через `client.Publish`.
    * Подписчик (Subscriber) слушает этот канал через `client.Subscribe` и выводит получаемые метрики на экран в реальном времени.
330. **Инвалидация кэша**: Напишите функцию обновления баланса пользователя в PostgreSQL. Чтобы избежать ситуации "грязного чтения" (когда в базе данных баланс уже обновился, а в кэше Redis висит старое значение), добавьте в функцию обязательное удаление соответствующего ключа из Redis (`client.Del`) в рамках одной логической операции обновления данных.
