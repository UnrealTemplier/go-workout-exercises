### 8. Работа с базами данных (PostgreSQL и Redis)

#### 8.1 Подключение, пул соединений и первые запросы к PostgreSQL
321. Установите драйвер `pgx` (или `lib/pq`), подключитесь к локальному PostgreSQL с использованием `database/sql`. Проверьте соединение `db.Ping()`.
322. Создайте таблицу `users` (id SERIAL PRIMARY KEY, name TEXT, email TEXT UNIQUE, created_at TIMESTAMPTZ) через `db.Exec`.
323. Вставьте одного пользователя с параметризованным запросом (`$1`, `$2`), избегая SQL-инъекций.
324. Вставьте несколько пользователей транзакционно: если email дублируется, откатите всю группу.
325. Извлеките всех пользователей в слайс структур, используя `rows.Scan`. Выведите их в консоль.
326. Реализуйте функцию `GetUserByID(id int) (User, error)`, возвращающую `sql.ErrNoRows`, если пользователь не найден.
327. Обновите email пользователя по ID. Если пользователь не найден, верните ошибку.
328. Удалите пользователя и проверьте количество затронутых строк (`rowsAffected`).

#### 8.2 Продвинутый SQL и pgx
329. Используйте `pgxpool` для управления пулом соединений, настройте максимальное количество соединений.
330. Выполните batch-вставку 1000 пользователей с помощью `pgx.Batch` и COPY-протокола.
331. Реализуйте постраничную пагинацию (LIMIT/OFFSET) и курсорную пагинацию (по ID или created_at).
332. Добавьте полнотекстовый поиск: создайте столбец `tsv TSVECTOR`, триггер для автообновления и выполните поиск с `ts_query`.
333. Используйте `sqlx` для упрощённого сканирования структур: `Select`, `Get`, `NamedExec`.
334. Обработайте NULL-поля: добавьте поле `bio TEXT` с возможным NULL, используйте `sql.NullString` или указатели.

#### 8.3 Миграции
335. Установите `golang-migrate`, создайте первую миграцию, добавляющую таблицу `posts`.
336. Напишите миграцию, добавляющую столбец `updated_at` с автоматическим обновлением.
337. Откатите миграцию, проверьте, что изменения исчезли, затем снова накатите.

#### 8.4 Транзакции и конкурентный доступ
338. Переведите деньги между двумя счетами в одной транзакции: списание с одного и зачисление на другой.
339. Продемонстрируйте уровень изоляции `SERIALIZABLE`: попробуйте конкурентно обновить одну запись и получите ошибку сериализации.
340. Реализуйте пессимистичную блокировку строки с `SELECT ... FOR UPDATE`, чтобы предотвратить гонку при бронировании билетов.

#### 8.5 Redis: строки, ключи, TTL
341. Подключитесь к Redis с помощью `go-redis`. Установите ключ `greeting` со значением и TTL 30 секунд.
342. Проверьте существование ключа, получите его значение и обработайте `redis.Nil`.
343. Увеличьте счётчик (`INCR`) и атомарно получите новое значение.
344. Сохраните JSON-объект в виде строки и прочитайте обратно, распарсив в структуру.

#### 8.6 Redis-структуры данных
345. Хэши: сохраните поля пользователя (name, email) в хэш `user:1`, прочитайте все поля (`HGETALL`).
346. Списки: реализуйте очередь заданий: `LPUSH` для добавления, `BRPOP` для блокирующего извлечения.
347. Множества: добавьте теги к статье (`SADD`), получите все теги (`SMEMBERS`), найдите пересечение множеств (`SINTER`).
348. Сортированные множества: сохраните рейтинг игроков (`ZADD`), получите топ-10 (`ZREVRANGE WITHSCORES`).
349. Реализуйте простой кэш с TTL: перед запросом к PostgreSQL проверяйте Redis, если промах — загружайте из БД и сохраняйте в Redis.

#### 8.7 Pub/Sub, транзакции и Lua
350. Создайте канал Pub/Sub: подписчик в одной горутине получает сообщения, издатель в другой отправляет.
351. Транзакции Redis: атомарно обновите два ключа с помощью `MULTI/EXEC` (или `TxPipelined`).
352. Pipeline: выполните пачку команд без ожидания ответа после каждой, затем считайте все ответы.
353. Напишите Lua-скрипт, который атомарно проверяет баланс и списывает сумму, если достаточно средств. Выполните его через `Eval`.

#### 8.8 Интеграция и продвинутые сценарии
354. Rate limiter на Redis: используйте скользящее окно или token bucket для ограничения числа запросов от пользователя.
355. Распределённая блокировка: захватите ключ с `SETNX` и TTL, выполните критическую секцию, освободите блокировку.
356. Реализуйте сохранение сессии пользователя в Redis с TTL, обновляемым при каждом запросе.
357. Используйте Redis для хранения состояния WebSocket-соединений (связь user_id с идентификаторами сокетов).
358. Настройте кластер Redis и подключитесь через `redis.NewClusterClient`. Выполните базовые операции.
359. Обработайте таймауты и отмену контекста: передавайте `context.Context` во все операции с БД и Redis.
360. Напишите тесты для слоя работы с БД: используйте тестовую базу или `testcontainers-go` для поднятия реального PostgreSQL в контейнере.
