### 25. Облачные архитектуры и Service Mesh (Cloud-Native Go)

#### 25.1 Envelope Encryption и KMS
771. **Envelope Encryption вручную.** Сгенерируйте DEK (Data Encryption Key) AES-256, зашифруйте им файл. Затем зашифруйте DEK с помощью KEK (Key Encryption Key), хранящегося локально (эмуляция KMS). Сохраните зашифрованный DEK и зашифрованный файл вместе.
772. **Расшифровка через Envelope Encryption.** Прочитайте зашифрованный DEK, расшифруйте его KEK, затем расшифруйте файл. Реализуйте прозрачную обёртку `Encrypt(plain io.Reader, kek []byte) (io.Reader, error)` и `Decrypt(encrypted io.Reader, kek []byte) (io.Reader, error)`.
773. **Интеграция с AWS KMS.** Используя `aws-sdk-go-v2`, создайте ключ KMS (Customer Master Key). Зашифруйте небольшой секрет (например, пароль БД) напрямую через `Encrypt` API KMS, затем расшифруйте.
774. **Envelope Encryption с AWS KMS.** Сгенерируйте DEK через KMS (`GenerateDataKey`), который возвращает открытый и зашифрованный DEK. Зашифруйте файл открытым DEK, сохраните зашифрованный DEK. При расшифровке сначала расшифруйте DEK через KMS, затем файл.
775. **Ротация ключей KMS.** Настройте автоматическую ротацию ключа в AWS KMS (или эмуляцию через версионирование). Реализуйте механизм, при котором старые DEK расшифровываются старой версией ключа, но новые шифруются новой версией.

#### 25.2 Multipart Upload в S3/GCS
776. **Multipart Upload в S3 (MinIO для локального тестирования).** Используя `aws-sdk-go-v2`, загрузите файл размером 15 МБ тремя частями по 5 МБ. Инициируйте multipart upload, загрузите части, завершите операцию (`CompleteMultipartUpload`).
777. **Параллельная загрузка частей с контролем конкурентности.** Реализуйте загрузку 10 частей параллельно с ограничением на количество одновременных загрузок (семафор). Обработайте ошибки отдельных частей с возможностью повторной загрузки.
778. **Resume Multipart Upload после сбоя.** Эмулируйте обрыв сети, сохранив `UploadId`. Реализуйте функцию, которая возобновляет загрузку с незавершённых частей (запрос `ListParts`, проверка уже загруженных, догрузка остальных).
779. **Генерация Pre-signed URL для S3.** Создайте временную ссылку (на 1 час) для скачивания объекта из S3 без публичного доступа к бакету. Используйте `PresignClient`.

#### 25.3 gRPC Client-side Keepalive и Graceful Connection Draining
780. **gRPC Keepalive на стороне клиента.** Настройте `keepalive.ClientParameters`: `Time: 10s`, `Timeout: 3s`, `PermitWithoutStream: true`. Проверьте, что при обрыве сети клиент обнаруживает мёртвое соединение и переподключается.
781. **gRPC Graceful Draining на сервере.** При получении `SIGTERM` сервер вызывает `GracefulStop()`: перестаёт принимать новые запросы, но завершает текущие стримы. Клиенты должны корректно переключиться на другие экземпляры.
782. **gRPC Client-side Load Balancing с Draining.** Настройте клиент с DNS-резолвером и round-robin балансировкой. При graceful draining сервер отправляет GOAWAY, и клиент исключает его из списка доступных адресов. Убедитесь в отсутствии ошибок на клиенте.

#### 25.4 Service Mesh (Istio) и распределённая трассировка
783. **Развёртывание Go-сервиса в Istio.** Задеплойте простой HTTP-сервис в Kubernetes с Istio. Настройте `VirtualService` для маршрутизации по префиксу. Проверьте доступ через ingress gateway.
784. **Retry и Timeout на уровне Service Mesh.** В `VirtualService` настройте retry (3 попытки, таймаут 2с) для запросов к downstream-сервису. Симулируйте ошибки и убедитесь, что Istio повторяет запросы.
785. **Circuit Breaking через Istio.** Настройте `DestinationRule` с `connectionPool` и `outlierDetection` (например, ejection при 5xx в течение 30с). Проверьте, что проблемный под временно исключается из балансировки.
786. **Сквозная трассировка W3C через Istio.** Включите tracing в Istio (Jaeger). В вашем Go-сервисе пробрасывайте заголовки `traceparent` и `tracestate` (через OpenTelemetry). Убедитесь, что цепочка вызовов от ingress до БД видна в Jaeger.
787. **Совместимость с B3 (Zipkin).** Настройте ваш сервис на приём и передачу B3-заголовков (`x-b3-traceid`, `x-b3-spanid`, `x-b3-sampled`) для совместимости с Zipkin/старыми системами.
788. **mTLS в Istio и проверка сертификатов.** Включите `PeerAuthentication` в режиме `STRICT`. Убедитесь, что трафик между сервисами шифруется (проверка через `istioctl authn tls-check` или tcpdump).

#### 25.5 Облачные best practices
789. **Graceful Shutdown в Kubernetes.** Настройте `terminationGracePeriodSeconds`, `preStop` hook, который переводит сервис в draining mode (health check возвращает 503) и ждёт завершения активных соединений. Проверьте zero-downtime деплой.
790. **Итоговое Cloud-Native упражнение.** Реализуйте сервис, который:
- Принимает файлы от клиентов,
- Шифрует их через Envelope Encryption с AWS KMS,
- Загружает в S3 через Multipart Upload с параллельными частями,
- Возвращает Pre-signed URL.
Сервис развёрнут в Kubernetes с Istio, имеет gRPC-эндпоинты с keepalive и graceful draining, сквозную трассировку W3C и политики retry/circuit breaking на уровне mesh.
