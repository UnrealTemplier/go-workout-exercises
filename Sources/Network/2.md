### 7. Работа с сетью (TCP, UDP, HTTP, WebSocket, API, DNS, TLS)

#### 7.1 Основы TCP и UDP
291. Создайте TCP-сервер на `localhost:8080`, который принимает соединения и отправляет «Hello, client!» каждому подключившемуся.
292. Реализуйте TCP-клиент, который подключается к вашему серверу, читает сообщение и выводит его.
293. Сделайте эхо-сервер TCP: всё, что клиент отправляет, сервер возвращает обратно. Клиент читает ответы в цикле.
294. Добавьте обработку множества одновременных клиентов на сервере с помощью горутин. Каждый клиент получает уникальный ID.
295. Реализуйте простой чат: сервер принимает сообщения от любого клиента и рассылает их всем остальным (broadcast).
296. UDP-сервер и клиент: сервер слушает на UDP-порту, клиент отправляет дейтаграмму с текстом, сервер отвечает.
297. Напишите сканер TCP-портов: проверьте, открыт ли список портов на заданном хосте (с использованием таймаута).

#### 7.2 HTTP-сервер и клиент (базовый уровень)
298. Запустите HTTP-сервер с одним обработчиком `/`, возвращающим «Hello, World!».
299. Добавьте маршруты `/hello`, `/time`, `/json` с разными ответами (текст, текущее время, JSON-структура).
300. Реализуйте HTTP-клиент, делающий GET-запрос к публичному API (например, `https://api.github.com`) и выводящий статус ответа.
301. Отправьте POST-запрос с JSON-телом на свой сервер. Сервер должен распарсить тело в структуру и вернуть её обратно с подтверждением.
302. Напишите сервер, который обслуживает статические файлы из папки `./static` (используйте `http.FileServer`).
303. Реализуйте middleware для логирования всех входящих запросов (метод, URL, длительность выполнения).

#### 7.3 Продвинутый HTTP: роутинг, параметры, middleware
304. Создайте REST API для управления списком задач (in-memory): `GET /tasks`, `POST /tasks`, `GET /tasks/{id}`, `DELETE /tasks/{id}`. Используйте стандартный `http.ServeMux` с поддержкой методов.
305. Добавьте обработку параметров запроса (`?status=done`) и пагинацию (`?page=1&limit=10`).
306. Напишите middleware для аутентификации по токену в заголовке `Authorization`.
307. Цепочка middleware: оберните обработчик в middleware логирования, аутентификации и восстановления после паники.
308. Создайте сервер, который поддерживает Graceful Shutdown: при получении `SIGINT` он завершает приём новых запросов, дожидается выполнения текущих и завершает работу.
309. Настройте HTTPS-сервер с самоподписанным сертификатом (используя `http.ListenAndServeTLS` и сгенерированные ключи).

#### 7.4 JSON API и работа с данными
310. Сериализуйте сложную структуру (вложенные объекты, слайсы) в JSON и отправьте как ответ сервера. Клиент должен десериализовать её и красиво вывести.
311. Реализуйте API с валидацией входных данных: при создании задачи проверяйте, что поле `title` не пустое, возвращайте ошибку 400 с описанием.
312. Добавьте версионирование API: `/api/v1/tasks` и `/api/v2/tasks` с разными форматами ответа. Используйте один сервер.
313. Обработайте загрузку файла на сервер через multipart/form-data, сохраните файл в папку `uploads` и верните URL для доступа.
314. Реализуйте HTTP-клиент с таймаутом и повторными попытками: если запрос не удался, повторить до 3 раз с экспоненциальной задержкой.

#### 7.5 Продвинутые сетевые протоколы и технологии
315. Напишите простой прокси-сервер: принимает HTTP-запросы, перенаправляет их на целевой сервер, возвращает ответ клиенту.
316. Реализуйте WebSocket-сервер: клиенты подключаются, могут отправлять сообщения, а сервер транслирует их всем (простой чат на WebSocket). Используйте `golang.org/x/net/websocket` или `gorilla/websocket`.
317. Создайте gRPC-сервис с методом `SayHello` и клиент на Go. Опишите `.proto` файл, сгенерируйте код и проверьте взаимодействие.
318. Выполните DNS-запрос: программа принимает доменное имя, получает все A-записи и выводит IP-адреса. Обработайте ошибки.
319. Напишите программу, которая подключается к серверу по TLS, проверяет сертификат и выводит его детали (subject, issuer, срок действия).
320. Создайте нагрузочный тест: HTTP-клиент, который конкурентно отправляет N запросов на сервер (с горутинами) и собирает статистику (количество успешных, ошибок, среднее время ответа).
