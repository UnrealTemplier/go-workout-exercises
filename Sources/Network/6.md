Ниже представлен новый обширный блок, состоящий из **28 практических упражнений по работе с сетью** (задачи 278–305). Этот раздел охватывает как низкоуровневое сетевое программирование (работа с TCP и UDP сокетами), так и прикладной уровень — создание надежных HTTP-клиентов и современных высокопроизводительных HTTP-серверов с использованием возможностей последних версий Go.

### Раздел 23: Сетевое программирование низкого уровня (TCP и UDP) (Задачи 278–287)

*Работа на уровне транспортного протокола позволяет понять, как устроены сетевые соединения под капотом, как управлять буферами обмена и как обеспечивать одновременную работу с тысячами клиентов.*

278. **Простейший TCP Echo-сервер**: Напишите программу, которая слушает порт `8080` по протоколу TCP с помощью `net.Listen`. При подключении клиента сервер должен войти в бесконечный цикл, считывать входящие данные и отправлять их обратно клиенту (эхо). Закройте соединение, когда клиент отключится.
279. **Простейший TCP-клиент**: Напишите клиентское приложение, которое подключается к вашему Echo-серверу с помощью `net.Dial("tcp", "localhost:8080")`. Клиент должен считать строку из консоли (`os.Stdin`), отправить её на сервер, дождаться ответа от сервера, вывести его на экран и завершить работу.
280. **Многопоточный TCP-сервер**: Перепишите задачу №278 так, чтобы сервер мог обрабатывать множество клиентов одновременно. Каждое новое соединение, возвращаемое методом `listener.Accept()`, должно передаваться в отдельную горутину `go handleConnection(conn net.Conn)`. Проверьте работу сервера, подключившись к нему из нескольких терминалов одновременно (например, с помощью утилиты `nc localhost 8080` или `telnet`).
281. **Конкурентный сканер портов (Port Scanner)**: Напишите утилиту, которая сканирует порты на локальном хосте (диапазон от 1 до 1024). Программа должна пытаться установить TCP-соединение с каждым портом. Чтобы сканирование не длилось вечно, используйте пул воркеров (задачи №265) для ограничения количества параллельных проверок и таймаут соединения (например, 100 миллисекунд с помощью `net.DialTimeout`).
282. **Таймауты на TCP-сокетах**: Напишите сервер, который принимает соединение, но умышленно ничего не отвечает клиенту. В коде клиента установите дедлайн на чтение данных: `conn.SetReadDeadline(time.Now().Add(2 * time.Second))`. Убедитесь, что клиент не зависает навсегда, а завершает работу по таймауту, корректно обработав сетевую ошибку.
283. **Простой UDP-сервер и клиент**: UDP работает без установления соединения. Напишите UDP-сервер с помощью `net.ListenUDP` и клиент с помощью `net.DialUDP` (или `net.WriteToUDP`). Сервер должен принимать дейтаграммы от клиента, переводить текст в верхний регистр и отправлять обратно. Объясните в комментариях ключевые отличия работы с UDP от TCP в коде Go.
284. **Буферизованное чтение из TCP**: При передаче больших объемов данных по TCP они могут приходить частями (фрагментация). Напишите TCP-клиент, который отправляет файл размером 10 МБ, и сервер, который принимает этот файл. На сервере используйте `bufio.NewReader` для эффективного буферизованного чтения порциями, а не считывайте весь файл целиком в оперативную память.
285. **TCP Чат-сервер**: Напишите полноценный чат-сервер.
    * Несколько клиентов могут подключаться по TCP.
    * При подключении сервер запрашивает имя клиента.
    * Любое сообщение, отправленное одним из клиентов, должно транслироваться всем остальным активным участникам чата.
    * Используйте горутины и каналы для безопасной синхронизации списка клиентов и рассылки сообщений.
286. **Плавная остановка TCP-сервера**: Напишите TCP-сервер, который при получении сигнала прерывания (Ctrl+C) перестает принимать новые соединения (`listener.Close()`), но дает активным клиентам 5 секунд на завершение текущих сессий перед принудительным закрытием их сокетов.
287. **Кастомный бинарный протокол (TLV)**: Напишите TCP-сервер и клиент, общающиеся по собственному простейшему бинарному протоколу формата Type-Length-Value (TLV). Сначала клиент отправляет 1 байт (тип сообщения), затем 4 байта в формате Big Endian (длина сообщения), а затем само сообщение. Сервер должен корректно распарсить этот поток байт с использованием пакета `encoding/binary`.

### Раздел 24: HTTP-клиенты (HTTP Client) (Задачи 288–296)

*Создание HTTP-запросов, обработка ответов, настройка таймаутов и кастомизация транспортного уровня — базовые навыки для интеграции сервисов.*

288. **Базовый GET-запрос**: Напишите программу, которая выполняет GET-запрос к публичному тестовому API (например, `https://jsonplaceholder.typicode.com/posts/1`) с помощью `http.Get`. Считайте тело ответа, преобразуйте его в строку и выведите в консоль.
289. **Подводный камень: Утечка соединений**: Измените предыдущую программу так, чтобы она выполняла 1000 GET-запросов в цикле. Забудьте вызвать `resp.Body.Close()`. Посмотрите, как программа быстро исчерпывает лимит открытых дескрипторов файлов ОС и падает. Напишите правильный вариант с `defer resp.Body.Close()` сразу после проверки на ошибку.
290. **POST-запрос с отправкой JSON**: Создайте структуру `Post` с полями `Title`, `Body`, `UserID`. Сериализуйте её в JSON. Отправьте POST-запрос на тестовый URL с помощью `http.Post` или создав кастомный запрос через `http.NewRequest`. Убедитесь, что вы правильно установили заголовок `Content-Type: application/json`.
291. **Опасность `http.DefaultClient`**: Напишите комментарий-объяснение, почему использование стандартного `http.Get` или `http.DefaultClient` крайне опасно на высоконагруженном продакшене (подсказка: отсутствие таймаутов по умолчанию может привести к зависанию горутин при сетевых сбоях). Напишите код инициализации безопасного клиента `http.Client` с жестким таймаутом в 3 секунды.
292. **Параметры запроса и заголовки**: Напишите программу, которая выполняет запрос, добавляя кастомные HTTP-заголовки (например, `Authorization: Bearer my_token`) и Query-параметры (например, `?page=2&limit=10`). Для сборки URL с параметрами используйте структуру `net/url` и её методы.
293. **Обработка ошибок и статус-кодов**: Выполните запрос к несуществующему домену и обработайте возникающую сетевую ошибку. Выполните запрос к существующему домену, но по некорректному адресу (чтобы получить статус `404 Not Found`). Напишите корректную обработку статус-кодов ответов (проверку `resp.StatusCode`).
294. **Кастомный транспорт (`RoundTripper`)**: Напишите Middleware для HTTP-клиента. Для этого создайте структуру, реализующую интерфейс `http.RoundTripper`. Данный транспорт должен перехватывать все исходящие запросы вашего клиента, автоматически замерять время их выполнения и выводить его в лог, после чего делегировать выполнение стандартному транспорту `http.DefaultTransport`.
295. **Скачивание файла с прогресс-баром**: Напишите утилиту, которая скачивает крупный файл (например, архив или картинку) по HTTP. Программа не должна загружать файл в память целиком — используйте `io.Copy`, чтобы записывать данные напрямую в файл на диске по мере скачивания. Реализуйте простой вывод прогресса (сколько процентов скачано) в консоль в реальном времени.
296. **Конкурентный сбор данных**: У вас есть срез из 10 различных URL-адресов. Напишите программу, которая параллельно отправляет GET-запросы ко всем этим адресам с помощью горутин. Соберите результаты (статус-коды и тела ответов) в потокобезопасную мапу или верните их в основной поток через каналы.

### Раздел 25: HTTP-серверы (HTTP Server) (Задачи 297–305)

*Разработка REST API, маршрутизация запросов, валидация данных, обработка ошибок на сервере и организация Middleware-фильтров.*

297. **Простейший веб-сервер**: Напишите HTTP-сервер, который при обращении на корень `/` возвращает текстовое сообщение `"Добро пожаловать в веб-сервер на Go!"`. Запустите его на порту `8080` с помощью `http.ListenAndServe`. Проверьте работу через браузер.
298. **Прием и валидация JSON**: Напишите API-обработчик `/register`. Он должен принимать только POST-запросы с телом в формате JSON, содержащим поля `Username` и `Password`. Используйте `json.NewDecoder` для парсинга тела запроса. Если поля пустые или запрос отправлен методом GET, верните клиенту ошибку `400 Bad Request` с описанием проблемы.
299. **Формирование JSON-ответов**: Напишите обработчик `/status`, который возвращает клиенту JSON-объект вида `{"status": "ok", "uptime": "120s"}`. Убедитесь, что вы отправляете правильный заголовок ответа `w.Header().Set("Content-Type", "application/json")` и статус-код `200 OK` перед записью тела.
300. **Современная маршрутизация (Go 1.22+)**: В версии Go 1.22 стандартный маршрутизатор `http.ServeMux` получил встроенную поддержку методов и параметров пути. Напишите сервер с использованием нового синтаксиса маршрутов:
    * `GET /users` — список пользователей.
    * `GET /users/{id}` — получение конкретного пользователя. Извлеките параметр `{id}` из пути с помощью метода `req.PathValue("id")`.
    * `POST /users` — создание пользователя.
301. **Логирующий Middleware**: Напишите функцию-декоратор (Middleware) для вашего сервера. Она должна оборачивать любые HTTP-обработчики и записывать в лог: метод запроса, запрашиваемый путь, IP-адрес клиента и время, затраченное на обработку запроса.
302. **Middleware для авторизации**: Напишите Middleware, которое проверяет наличие заголовка `Authorization` со значением `Bearer secret_token`. Если заголовок отсутствует или токен неверный, Middleware должно сразу прерывать запрос и возвращать клиенту статус `401 Unauthorized`. В противном случае — передавать управление следующему обработчику.
303. **Защита от паники (Recovery Middleware)**: Если в каком-то HTTP-обработчике вашего сервера случайно произойдет деление на ноль или разыменование `nil`-указателя, стандартный сервер Go не упадет, но соединение оборвется без ответа. Напишите Middleware, которое с помощью `recover()` перехватывает любые паники внутри обработчиков, логирует ошибку и аккуратно возвращает клиенту валидный JSON-ответ со статусом `500 Internal Server Error`.
304. **Graceful Shutdown HTTP-сервера**: Напишите HTTP-сервер, который запускается в отдельной горутине. Основной поток должен слушать сигналы завершения работы ОС (Ctrl+C). При получении сигнала вызовите метод `server.Shutdown(context.Background())`. Убедитесь, что сервер прекращает принимать новые запросы, но дает активным клиентам завершить скачивание/загрузку данных перед полной остановкой процесса.
305. **Простейший HTTP Reverse-Proxy**: Напишите прокси-сервер на стандартной библиотеке. Сервер должен слушать порт `8080`, перехватывать все входящие запросы, пересылать их на какой-то другой работающий веб-сервер (например, `localhost:9090` или внешний API), получать оттуда ответы и полностью возвращать их клиенту (включая заголовки и статус-коды).
