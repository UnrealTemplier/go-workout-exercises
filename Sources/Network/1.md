## Часть XV. Работа с сетью

### 48. TCP-серверы и клиенты

**Упражнение 15.1.** Напиши **TCP-эхо-сервер**: `net.Listen("tcp", ":8080")`, принимай соединение `Accept()`, читай строку через `bufio.Reader`, пиши её обратно с префиксом `"Echo: "`. Закрой соединение после одного ответа.

**Упражнение 15.2.** Напиши **TCP-клиент**: `net.Dial("tcp", "localhost:8080")`, отправь строку `"Hello\n"`, прочитай ответ через `bufio.Reader` и выведи.

**Упражнение 15.3.** Модифицируй сервер из 15.1: обрабатывай каждое соединение в **отдельной горутине**. Сервер должен принимать множество клиентов одновременно без блокировки.

**Упражнение 15.4.** Напиши **line-delimited protocol**: сервер читает строки (`ReadString('\n')`), парсит команду (`"ADD 5 3"` → `8`, `"MUL 4 2"` → `8`), отправляет результат. Клиент отправляет команды интерактивно (чтение из `os.Stdin`).

**Упражнение 15.5.** Напиши **length-prefixed protocol**: перед отправкой данных пиши 4 байта (uint32, big-endian) с длиной, затем payload. Сервер читает сначала 4 байта, затем ровно `length` байт. Это надёжнее, чем `\n`.

**Упражнение 15.6.** Напиши **TCP-сервер с таймаутами**: `conn.SetReadDeadline(time.Now().Add(5 * time.Second))`. Если клиент молчит дольше — закрой соединение с ошибкой `"timeout"`.

**Упражнение 15.7.** Напиши **TCP-чат-сервер**: храни `map[net.Conn]bool` (активные клиенты) с `sync.Mutex`. При получении сообщения от одного клиента — broadcast'ь его всем остальным. Напиши клиент, который читает сообщения в одной горутине и пишет в другой.

**Упражнение 15.8.** Напиши **TCP-прокси**: сервер слушает `:8080`, при соединении устанавливает второе соединение к `target:9090` и копирует данные в обе стороны (`io.Copy` в двух горутинах). Закрой оба соединения при разрыве любого.

**Упражнение 15.9.** Напиши **TCP-клиент с reconnect**: если соединение разорвано, жди 100ms, 200ms, 400ms... (экспоненциальный backoff) до 5 попыток, затем верни ошибку. Используй `context` для отмены ожидания.

**Упражнение 15.10.** Напиши **TCP heartbeat**: клиент каждые 3 секунды отправляет `"PING"`, сервер отвечает `"PONG"`. Если сервер не получил PING за 10 секунд — закрой соединение. Если клиент не получил PONG — переподключись.

**Упражнение 15.11.** Напиши **concurrent TCP-клиент**: создай 100 соединений к серверу, каждое отправляет 1000 сообщений. Используй `sync.WaitGroup` + семафор для ограничения одновременных соединений (например, 10).

**Упражнение 15.12.** Напиши **TCP-сервер с ограничением соединений** (semaphore): `sem := make(chan struct{}, 50)`. Каждое новое соединение захватывает слот. Если слотов нет — немедленно закрой `conn` с ошибкой `"server busy"`.

**Упражнение 15.13.** Напиши **TCP port scanner**: сканируй порты 1–1024 на `localhost`. Для каждого порта `net.DialTimeout("tcp", addr, 100ms)`. Выведи открытые порты. Ускорь через конкурентность ( semaphore на 50 горутин).

**Упражнение 15.14.** Напиши **TCP multiplexer**: сервер слушает один порт. Первый байт соединения определяет протокол: `0x01` → эхо-сервис, `0x02` → time-сервис (отправляет текущее время), `0x03` → статус. Прочитай 1 байт, затем делегируй обработку.

**Упражнение 15.15.** Напиши **TCP graceful shutdown**: сервер слушает сигнал `os.Interrupt`, при получении вызывает `listener.Close()`. Используй `sync.WaitGroup` для ожидания завершения активных соединений. Новые соединения не принимаются, старые обрабатываются до конца.

**Упражнение 15.16.** Напиши **TCP-файловый сервер**: клиент отправляет имя файла, сервер открывает файл и отправляет его содержимое через `io.Copy(conn, file)`. Клиент записывает в локальный файл. Обработай ошибки (файл не найден).

**Упражнение 15.17.** Напиши **TCP reverse shell** (учебный): сервер отправляет команду, клиент выполняет её через `exec.Command`, возвращает stdout+stderr. Используй `bufio.Scanner` для чтения команд и `io.Copy` для вывода.

**Упражнение 15.18.** Напиши **TCP load tester**: клиент устанавливает N соединений и отправляет M сообщений в секунду каждое. Измерь: latency (время ответа), throughput (сообщений/сек), ошибки соединения. Выведи статистику.

**Упражнение 15.19.** Напиши **TCP keep-alive настройки**: `tcpConn, _ := conn.(*net.TCPConn); tcpConn.SetKeepAlive(true); tcpConn.SetKeepAlivePeriod(3 * time.Minute)`. Объясни разницу между TCP keep-alive и application-level heartbeat.

**Упражнение 15.20.** Напиши **TCP-logger**: сервер принимает соединения от множества клиентов, каждый клиент отправляет лог-сообщения. Сервер пишет их в общий файл с префиксом `[IP:PORT]`. Используй `sync.Mutex` для синхронизации записи в файл.

### 49. UDP

**Упражнение 15.21.** Напиши **UDP-эхо-сервер**: `net.ListenUDP("udp", addr)`. Читай `ReadFromUDP`, отправляй обратно тому же адресу через `WriteToUDP`. Покажи, что UDP — connectionless, и один сервер обрабатывает всех клиентов в одном потоке.

**Упражнение 15.22.** Напиши **UDP-клиент**: отправь сообщение серверу, прочитай ответ с таймаутом (`SetReadDeadline`). Обработай потерю пакета (таймаут без ответа).

**Упражнение 15.23.** Напиши **UDP DNS-like resolver** (учебный): клиент отправляет доменное имя, сервер возвращает "IP-адрес" (заглушку). Покажи, что UDP подходит для коротких запрос-ответов.

**Упражнение 15.24.** Напиши **"Reliable UDP"** (упрощённый): клиент отправляет пакет с sequence number, ждёт ACK в течение 500ms. Если ACK не пришёл — ретрансмит (3 попытки). Сервер отправляет ACK на каждый пакет.

**Упражнение 15.25.** Напиши **UDP broadcast** клиент: `net.DialUDP("udp", nil, &net.UDPAddr{IP: net.IPv4bcast, Port: 9999})`. Отправь broadcast-сообщение. Напиши сервер, который слушает broadcast и отвечает. Обсуди, когда broadcast уместен, а когда — multicast.

### 50. HTTP-сервер (net/http)

**Упражнение 15.26.** Напиши простейший HTTP-сервер: `http.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) { fmt.Fprint(w, "Hello") })`. Запусти `http.ListenAndServe(":8080", nil)`.

**Упражнение 15.27.** Напиши **handler с query-параметрами**: `GET /search?q=golang&limit=10`. Извлеки `q` и `limit` через `r.URL.Query().Get()`. Верни JSON с результатами (заглушками).

**Упражнение 15.28.** Напиши **handler с path-параметрами** без фреймворков: `GET /users/123/profile`. Используй `strings.TrimPrefix(r.URL.Path, "/users/")` + `strings.Split` для извлечения `id`. Верни `"user_id": 123`.

**Упражнение 15.29.** Напиши **JSON API handler**: `POST /api/users`. Прочитай тело `r.Body` (`json.NewDecoder(r.Body).Decode(&user)`), валидируй (имя не пустое, возраст > 0), верни `201 Created` с созданным JSON. Не забудь `defer r.Body.Close()`.

**Упражнение 15.30.** Напиши **REST API** с полным CRUD (in-memory `map[int]User` + `sync.RWMutex`):
- `GET /users` — список
- `GET /users/{id}` — один пользователь
- `POST /users` — создать
- `PUT /users/{id}` — обновить
- `DELETE /users/{id}` — удалить

**Упражнение 15.31.** Напиши **HTTP middleware** `LoggingMiddleware(next http.Handler) http.Handler`, который логирует метод, путь, статус-код и время выполнения. Используй `http.HandlerFunc` и оборачивай handler.

**Упражнение 15.32.** Напиши **middleware chain**: `LoggingMiddleware → AuthMiddleware → RateLimitMiddleware → Handler`. Покажи композицию: `chain := Logging(RateLimit(Auth(handler)))`.

**Упражнение 15.33.** Напиши **Auth middleware**: проверяй заголовок `Authorization: Bearer <token>`. Если токен неверен — верни `401 Unauthorized`. Если верен — добавь `user_id` в `context.Context` через `context.WithValue` и передай дальше.

**Упражнение 15.34.** Напиши **Request ID middleware**: генерируй UUID (или `rand`) для каждого запроса, добавь в контекст. Все логи внутри handler'а должны включать этот ID. Добавь заголовок `X-Request-ID` в ответ.

**Упражнение 15.35.** Напиши **CORS middleware**: добавь заголовки `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`. Обработай `OPTIONS` preflight-запросы.

**Упражнение 15.36.** Напиши **Rate Limiting middleware** (per IP): используй `map[string]*rateLimiter` с `sync.RWMutex`. Ограничь до 10 запросов/секунду с одного IP. Если лимит превышен — `429 Too Many Requests`.

**Упражнение 15.37.** Напиши **HTTP Basic Auth middleware**: проверяй `Authorization: Basic <base64>`. Декодируй через `base64.StdEncoding.DecodeString`. Если логин/пароль неверны — `401` с заголовком `WWW-Authenticate: Basic realm="Restricted"`.

**Упражнение 15.38.** Напиши **custom http.ResponseWriter** для захвата статус-кода: `type responseRecorder struct { status int; http.ResponseWriter }`. Переопредели `WriteHeader`. Используй в middleware для логирования реального статуса (даже если handler его не пишет явно, по умолчанию 200).

**Упражнение 15.39.** Напиши **file server**: `http.FileServer(http.Dir("./static"))`. Настрой обработку `/static/` через `http.StripPrefix`. Проверь доступ к файлам, попробуй directory traversal (`../../etc/passwd`) — покажи, что `http.FileServer` защищён от этого.

**Упражнение 15.40.** Напиши **upload handler**: `POST /upload`. Парсь `multipart/form-data` через `r.ParseMultipartForm(10 << 20)` (10MB). Сохрани загруженный файл на диск. Верни имя сохранённого файла.

**Упражнение 15.41.** Напиши **streaming response**: handler читает большой файл и пишет его в `http.ResponseWriter` через `io.Copy`. Не загружай файл целиком в память. Добавь `Content-Type: application/octet-stream` и `Content-Disposition`.

**Упражнение 15.42.** Напиши **Server-Sent Events (SSE)**: handler с заголовком `Content-Type: text/event-stream`. В цикле отправляй `data: {"time": "..."}\n\n` каждую секунду. Используй `http.Flusher` для сброса буфера. Клиент — `curl` или браузер.

**Упражнение 15.43.** Напиши **HTTP graceful shutdown**: `http.Server` + `srv.Shutdown(ctx)` с `context.WithTimeout(5s)`. При `SIGINT` — заверши текущие запросы, но не принимай новые. Используй `signal.NotifyContext`.

**Упражнение 15.44.** Напиши **health check endpoint**: `GET /health` возвращает `{"status": "ok"}`. Добавь проверку зависимостей (например, доступность in-memory store). Если store недоступен — `503 Service Unavailable`.

**Упражнение 15.45.** Напиши **custom ServeMux**: реализуй `http.Handler` с `map[string]http.Handler` и методом `Handle(pattern string, handler http.Handler)`. Обработай `404` для неизвестных путей. Покажи, что `http.ServeMux` — это тоже просто `http.Handler`.

**Упражнение 15.46.** Напиши **HTTP handler с `http.Hijacker`**: "upgrade" соединения до raw TCP. После хиджека отправь произвольное сообщение по TCP и закрой. Объясни, когда это нужно (WebSocket вручную, проксирование).

**Упражнение 15.47.** Напиши **reverse proxy** (упрощённый): `httputil.ReverseProxy` с `Director`, перенаправляющий запросы на `http://localhost:9090`. Добавь логирование upstream latency.

**Упражнение 15.48.** Напиши **API Gateway** (упрощённый): маршрутизация `/users/*` → `localhost:9001`, `/orders/*` → `localhost:9002`. Используй `httputil.ReverseProxy` + `http.NewServeMux`. Добавь единый logging middleware.

**Упражнение 15.49.** Напиши **HTTP handler с `io.Pipe`**: создай `pr, pw := io.Pipe()`. Запусти горутину, которая пишет в `pw` (генерирует данные). В handler'е читай из `pr` и копируй в `http.ResponseWriter`. Покажи streaming без временных файлов.

**Упражнение 15.50.** Напиши **HTTP handler с ошибкой и partial write**: handler пишет заголовок `200`, затем часть тела, затем паникует. Покажи, что `http.ResponseWriter` не позволяет изменить статус после первого `Write`. Обсуди, почему важно проверять ошибки до первого Write.

### 51. HTTP-клиент

**Упражнение 15.51.** Напиши простой HTTP-клиент: `resp, err := http.Get("https://api.github.com/users/golang")`. Прочитай `resp.Body`, декодируй JSON в структуру. Не забудь `defer resp.Body.Close()`.

**Упражнение 15.53.** Напиши `POST`-запрос с JSON: создай `bytes.NewReader(jsonData)`, `http.NewRequest("POST", url, body)`. Установи `Content-Type: application/json`. Отправь, прочитай статус.

**Упражнение 15.54.** Напиши `POST` с `application/x-www-form-urlencoded`: используй `url.Values` и `strings.NewReader(values.Encode())`. Отправь на тестовый сервер.

**Упражнение 15.55.** Напиши **HTTP-клиент с таймаутом**: `http.Client{Timeout: 5 * time.Second}`. Покажи, что `http.DefaultClient` **не имеет таймаута** (бесконечное ожидание). Это опасно в production.

**Упражнение 15.56.** Напиши **HTTP-клиент с `context.WithTimeout`**: `ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)`. Передай в `req.WithContext(ctx)`. Покажи, что запрос прерывается при таймауте.

**Упражнение 15.57.** Напиши **retry logic** для HTTP-клиента: при ошибке сети или статусе `5xx` — повтори запрос с exponential backoff (100ms, 200ms, 400ms, max 3 попытки). Используй `context` для ограничения общего времени.

**Упражнение 15.58.** Напиши **параллельные HTTP-запросы**: список URL. Для каждого URL запусти горутину с `http.Get`. Собери результаты через канал. Используй `sync.WaitGroup` или `errgroup` для ожидания.

**Упражнение 15.59.** Напиши **HTTP-загрузчик файла**: `http.Get` по URL, `io.Copy` в локальный файл. Покажи прогресс: в отдельной горутине читай `resp.ContentLength` и сколько байт скопировано (через `io.TeeReader` или `io.Reader` обёртку).

**Упражнение 15.60.** Напиши **HTTP-клиент с кастомными заголовками**: `req.Header.Set("User-Agent", "MyBot/1.0")`, `req.Header.Set("Authorization", "Bearer ...")`. Покажи, что `http.DefaultClient` использует дефолтный User-Agent.

**Упражнение 15.61.** Напиши **HTTP-клиент с CookieJar**: `jar, _ := cookiejar.New(nil); client := &http.Client{Jar: jar}`. Сделай два запроса к серверу, устанавливающему cookie. Покажи, что второй запрос автоматически отправляет cookie.

**Упражнение 15.62.** Напиши **HTTP-прокси клиент**: `proxyURL, _ := url.Parse("http://proxy:8080"); transport := &http.Transport{Proxy: http.ProxyURL(proxyURL)}; client := &http.Client{Transport: transport}`.

**Упражнение 15.63.** Напиши **HTTP-клиент с `http.Transport` tuning**: настрой `MaxIdleConns`, `MaxIdleConnsPerHost`, `IdleConnTimeout`, `DisableKeepAlives`. Объясни, зачем нужен connection pool и keep-alive.

**Упражнение 15.64.** Напиши **HTTP-клиент с `io.TeeReader`**: читай ответ и одновременно пиши его в `os.Stdout` (для отладки) и в файл (для сохранения). Используй `io.TeeReader(resp.Body, file)` + `io.Copy`.

**Упражнение 15.65.** Напиши **HTTP HEAD-запрос**: `http.Head(url)`. Получи только заголовки без тела. Используй для проверки существования ресурса или получения `Content-Length` перед загрузкой.

### 54. Комплексные сетевые задачи

**Упражнение 15.76.** Напиши **HTTP Crawler** (BFS): начинай с корневого URL, извлекай все ссылки (`href`) из HTML через `regexp` или `golang.org/x/net/html`. Ограничь глубину 2. Используй `sync.WaitGroup` + семафор (10 одновременных запросов). Сохраняй посещённые URL в `sync.Map`.

**Упражнение 15.77.** Напиши **HTTP Load Balancer** (round-robin): слушает `:8080`, имеет пул бэкендов (`localhost:9001`, `9002`, `9003`). Каждый новый запрос идёт на следующий бэкенд (атомарный счётчик). Используй `httputil.ReverseProxy` + `sync/atomic`.

**Упражнение 15.78.** Напиши **HTTP Cache Proxy**: слушает `:8080`, проверяет кеш (`map[string]cachedResponse` + `sync.RWMutex`) перед проксированием. Если ответ в кеше и не протух — верни из кеша. Иначе — проксируй, сохрани в кеш с TTL. Используй `Cache-Control` заголовки.

**Упражнение 15.79.** Напиши **TCP Load Balancer** (round-robin): слушает TCP `:8080`, принимает соединение, выбирает бэкенд из пула, устанавливает соединение к нему, копирует данные в обе стороны (`io.Copy` в двух горутинах). Обработай отключение бэкенда.

**Упражнение 15.80.** Напиши **"Mirror" HTTP-сервер**: каждый входящий запрос дублируется на два бэкенда (primary и secondary). Ответ клиенту — от primary. Secondary — "fire and forget" в горутине. Используй для shadow-трафика.

**Упражнение 15.81.** Напиши **WebSocket echo-сервер** (используй `golang.org/x/net/websocket` или `github.com/gorilla/websocket`): клиент отправляет сообщение, сервер возвращает его обратно. Покажи, что WebSocket — это full-duplex поверх HTTP.

**Упражнение 15.82.** Напиши **WebSocket broadcast чат**: сервер хранит все WebSocket-соединения. При получении сообщения от одного клиента — рассылает всем остальным. Используй `sync.Mutex` для защиты списка соединений.

**Упражнение 15.83.** Напиши **Circuit Breaker для HTTP-клиента** (упрощённый): три состояния (`Closed`, `Open`, `HalfOpen`). Считай ошибки (5xx, timeout). При 5 ошибок подряд — `Open` (быстрый fail). Через 10s — `HalfOpen`, один пробный запрос. Если успех — `Closed`. Используй `sync/atomic` + `time.Now()`.

**Упражнение 15.84.** Напиши **Metrics middleware** (Prometheus-style): счётчики `requests_total`, `request_duration_seconds`. Используй `atomic` для счётчиков и `sync.Map` для хранилища. Endpoint `/metrics` возвращает текст в формате Prometheus.

**Упражнение 15.86.** Напиши **HTTP API с sorting и filtering**: `GET /items?sort=price&order=desc&category=books&min_price=10`. Реализуй парсинг query-параметров, фильтрацию слайса, сортировку через `sort.Slice`.

### Ключевые моменты для освоения сети:

1. **Всегда закрывай `resp.Body`** — даже если не читаешь. Используй `defer resp.Body.Close()` сразу после проверки ошибки. Для drain'а непрочитанного тела — `io.Copy(io.Discard, resp.Body)`.
2. **Никогда не используй `http.DefaultClient` в production** — у него нет таймаута. Создавай `&http.Client{Timeout: 10 * time.Second}`.
3. **TCP — потоковый протокол** — нет гарантий, что `Read` вернёт ровно то, что отправил `Write` одного сообщения. Используй length-prefix или `\n` для framing.
4. **Context в HTTP** — `req.WithContext(ctx)` позволяет отменить запрос. При shutdown сервера — `srv.Shutdown(ctx)` корректно завершает активные соединения.
5. **Graceful shutdown** — всегда обрабатывай `os.Interrupt` для серверов. Используй `signal.NotifyContext` + `http.Server.Shutdown`.
6. **Middleware** — композиция `http.Handler` — мощный паттерн. Помни: middleware выполняется в порядке обёртки (последний добавленный — первым обрабатывает запрос).
7. **WebSocket и Hijack** — для real-time коммуникации. Но если нужен только server→client push — рассмотри SSE (проще, работает поверх HTTP).
