Работа с сетью — это стихия Go. Язык изначально создавался для бэкенда, облачных технологий и микросервисов, поэтому стандартная библиотека (особенно пакеты `net` и `net/http`) невероятно мощна и самодостаточна. Сторонние веб-фреймворки в Go часто не нужны, всё делается «из коробки».

Мы продолжаем с **326-го упражнения**. Впереди **40 интенсивных задач**, охватывающих всё: от сырых TCP-сокетов до написания и тестирования полноценного REST API.

### Блок 23. Низкоуровневая сеть: TCP и UDP (326–332)
Понимаем, как компьютеры общаются на уровне транспортных протоколов, до всяких HTTP.

326. **TCP-сервер (Echo):** Используй `net.Listen("tcp", ":8080")`. Напиши цикл, который принимает подключения (`Accept()`). При подключении читай данные из соединения и отправляй их обратно клиенту (эхо). (Для теста используй утилиту `telnet` или `nc` в консоли).
327. **TCP-клиент:** Напиши отдельную программу. Используй `net.Dial("tcp", "localhost:8080")`. Отправь строку на сервер из упр. 326, прочитай ответ и выведи в консоль.
328. **Конкурентный сервер:** В сервере из 326 вызов `Accept()` блокирует цикл. Оберни обработку каждого соединения в отдельную горутину `go handleConnection(conn)`. Запусти два клиента одновременно и убедись, что сервер работает с обоими параллельно.
329. **TCP-Чат (Broadcasting):** Усложни сервер. Сохраняй все активные `net.Conn` в мапу. Если один клиент присылает сообщение, сервер должен рассылать его всем остальным клиентам из мапы (используй `sync.Mutex` для защиты мапы!).
330. **UDP-сервер:** UDP работает без установки соединения. Используй `net.ListenUDP`. Читай данные через `ReadFromUDP` (получишь байты и адрес отправителя) и отправляй ответ через `WriteToUDP`.
331. **UDP-клиент:** Напиши клиента для упр. 330 через `net.DialUDP`. Обрати внимание, что в UDP нет потока, сообщения передаются отдельными датаграммами.
332. **Таймауты сокетов:** В TCP-клиенте используй метод `conn.SetDeadline(time.Now().Add(2 * time.Second))`. Убедись, что если сервер долго не отвечает, клиент завершается с ошибкой `i/o timeout`.

### Блок 24. HTTP-клиент: Запросы и Парсинг (333–342)
Учимся ходить во внешний мир (к чужим API, сайтам и сервисам).

333. **Базовый GET-запрос:** Используй `http.Get("https://jsonplaceholder.typicode.com/posts/1")`. Прочитай тело ответа через `io.ReadAll` и выведи статус-код (`resp.StatusCode`).
334. **Смертельный грех — забытый Close:** Убедись, что в упр. 333 ты написал `defer resp.Body.Close()`. Без этого соединения не возвращаются в пул, и программа со временем падает от нехватки памяти или файловых дескрипторов. Вызывай `Close()` всегда, даже если читаешь не всё!
335. **Таймаут клиента:** Глобальный `http.Get` не имеет таймаута (он может висеть вечно). Создай свой клиент: `client := &http.Client{Timeout: 3 * time.Second}`. Сделай запрос через `client.Get(...)`.
336. **POST-запрос с JSON:** Закодируй структуру в JSON. Отправь POST-запрос на `https://jsonplaceholder.typicode.com/posts` с помощью `http.Post`. Укажи Content-Type `application/json`.
337. **Кастомный запрос (Custom Headers):** Тебе нужно передать токен авторизации. Используй `req, err := http.NewRequest("GET", url, nil)`. Добавь заголовок: `req.Header.Set("Authorization", "Bearer my-token")`. Выполни запрос через `client.Do(req)`.
338. **Отмена запроса через Context:** Создай `context.WithTimeout` на 10 миллисекунд. Передай его в запрос через `http.NewRequestWithContext(ctx, ...)`. Запусти и убедись, что запрос прерывается из-за нехватки времени.
339. **Query-параметры:** Не клей URL руками (как `?name=Ivan&age=20`). Используй `url.Values{}`. Добавь параметры, затем приклей их к запросу: `req.URL.RawQuery = q.Encode()`.
340. **Потоковый парсинг JSON:** Вместо того чтобы выгружать весь ответ в память через `io.ReadAll`, распарси JSON прямо из потока: `json.NewDecoder(resp.Body).Decode(&myStruct)`. Это сэкономит кучу оперативной памяти при больших ответах.
341. **Скачивание файла:** Сделай GET-запрос к любой картинке в интернете. Создай пустой файл `os.Create("image.jpg")`. Перекачай данные напрямую без загрузки в память: `io.Copy(file, resp.Body)`.
342. **Тонкая настройка пула соединений (Transport):** Создай свой `http.Transport` с параметром `MaxIdleConnsPerHost: 100`. Передай его в `http.Client`. Полезно для высоконагруженных сервисов, делающих сотни запросов к одному API.

### Блок 25. HTTP-сервер: Пишем свой REST API (343–355)
От простого обработчика до роутинга и правильного старта/стопа.

343. **Hello Web:** Напиши простейший сервер. Используй `http.HandleFunc("/", handler)`. Внутри функции напиши `w.Write([]byte("Hello, Web!"))`. Запусти `http.ListenAndServe(":8080", nil)`.
344. **Мультиплексор (ServeMux):** Использовать глобальный роутер (`nil` в `ListenAndServe`) — плохая практика (могут вклиниться сторонние пакеты). Создай `mux := http.NewServeMux()`. Зарегистрируй пути на нём и передай `mux` в `ListenAndServe`.
345. **Новый роутинг (Go 1.22+):** Начиная с Go 1.22 стандартный роутер стал мощным. Зарегистрируй роут с указанием метода и переменной пути: `mux.HandleFunc("GET /users/{id}", handler)`. Внутри функции достань `id` через `r.PathValue("id")`.
346. **Чтение Request:** Выведи в консоль информацию о входящем запросе: `r.Method`, `r.URL.Path`, `r.UserAgent()`.
347. **Чтение Query и Headers:** В обработчике `/search?q=golang&limit=10` достань параметры через `r.URL.Query().Get("q")`. Достань кастомный заголовок `X-Request-Id`.
348. **Парсинг JSON-тела:** Напиши роут `POST /users`. Внутри используй `json.NewDecoder(r.Body).Decode(&user)`. Верни клиенту статус 400 (`http.Error`), если JSON оказался невалидным.
349. **Отправка JSON-ответа:** Верни клиенту структуру в виде JSON. Обязательно установи заголовок `w.Header().Set("Content-Type", "application/json")`, статус `w.WriteHeader(http.StatusCreated)` и только потом пиши тело (через `json.NewEncoder`).
350. **Раздача статики:** Создай папку `static` с файлом `index.html`. Используй `http.FileServer(http.Dir("static"))`, чтобы твой сервер отдавал файлы прямо в браузер.
351. **Контекст запроса (Отключение клиента):** Внутри хендлера запусти долгую операцию (цикл на 5 секунд). Если клиент закроет вкладку до конца операции, `r.Context().Done()` закроется. Напиши `select`, который прервёт вычисления и сэкономит ресурсы сервера.
352. **Кастомный `http.Server`:** Вместо `ListenAndServe` создай структуру `srv := &http.Server{Addr: ":8080", Handler: mux, ReadTimeout: 5 * time.Second, WriteTimeout: 10 * time.Second}`. Это защитит сервер от "медленных клиентов" (Slowloris attack).
353. **Graceful Shutdown (Мягкая остановка):** В `main` запусти `srv.ListenAndServe()` в горутине. В основной горутине жди сигнала `SIGINT` (Ctrl+C). При получении сигнала вызови `srv.Shutdown(ctx)`, чтобы сервер перестал принимать новые запросы, но дообработал текущие.

### Блок 26. Middleware, Тестирование и Продвинутые темы (354–365)
Создаем продакшен-ready архитектуру веб-приложения.

354. **Первая Middleware (Логирование):** Middleware — это паттерн декоратора (функция принимает хендлер и возвращает хендлер). Напиши функцию `LoggingMiddleware`, которая замеряет время начала запроса, вызывает `next.ServeHTTP(w, r)` и логирует время выполнения, метод и URL. Оберни в неё свой роутер.
355. **Auth Middleware:** Напиши мидлварь, которая проверяет заголовок `Authorization`. Если токена нет — сразу отвечает `http.StatusUnauthorized` (401) и **не вызывает** `next.ServeHTTP`.
356. **Тестирование Хендлера (`httptest`):** Импортируй `net/http/httptest`. Создай фейковый запрос `httptest.NewRequest`. Создай `rec := httptest.NewRecorder()`. Передай их в свой хендлер. Проверь `rec.Code` (ожидаем 200) и `rec.Body.String()`.
357. **Тестирование Сервера целиком:** Используй `ts := httptest.NewServer(mux)` в тестах. Он поднимет сервер на случайном локальном порту (узнать можно через `ts.URL`). Сделай к нему реальный `http.Get` и проверь ответ. Не забудь `ts.Close()`.
358. **CORS Middleware:** Браузеры блокируют кросс-доменные запросы. Напиши Middleware, которая добавляет ко всем ответам заголовки `Access-Control-Allow-Origin: *` и обрабатывает метод `OPTIONS`.
359. **Rate Limiting Middleware:** Используй пакет `golang.org/x/time/rate`. Создай мидлварь, которая позволяет делать не более 10 запросов в секунду (на весь сервер или по IP). Если лимит превышен — отвечай `429 Too Many Requests`.
360. **Panic Recovery Middleware:** Если в хендлере случится паника (например, обращение к nil-слайсу), весь сервер не упадет (Go сам восстановит горутину), но клиент просто получит пустой ответ. Напиши Middleware, которая делает `defer func(){ if err := recover(); ... }()`, логирует панику и красиво отдает клиенту "500 Internal Server Error".
361. **Поднятие HTTPS (TLS):** Сгенерируй самоподписанные сертификаты (утилита `openssl` или `mkcert`). Подними сервер, используя `srv.ListenAndServeTLS("cert.pem", "key.pem")`. Перейди в браузере по `https://localhost:8080`.
362. **Single Page Application (SPA):** Напиши хендлер, который для всех неизвестных путей (включая `/login`, `/profile`, которых нет физически на диске, но они есть во Vue/React роутинге) отдает файл `index.html`.
363. **WebSockets (Основы):** Установи библиотеку (например, `github.com/gorilla/websocket`). Напиши хендлер, который апгрейдит HTTP-соединение до веб-сокета (`Upgrader.Upgrade`) и запускает эхо-цикл обмена сообщениями.
364. **Перехватчик соединения (Hijacking):** *Сложное!* Используй интерфейс `http.Hijacker`, чтобы получить сырой `net.Conn` прямо из `http.ResponseWriter`. Напиши в него свой кастомный протокол, в обход HTTP. (Так "под капотом" работает апгрейд до WebSockets).
365. **HTTP-клиент: Retry-механизм:** Напиши обертку над своим HTTP-клиентом. Если `client.Do(req)` возвращает ошибку или статус 500+, обертка должна повторить запрос еще 3 раза с экспоненциальной задержкой (Exponential Backoff: 1с, 2с, 4с), прежде чем сдаться.

---
**Совет к этому блоку:** Особое внимание удели **упр. 351 (Контекст запроса)** и **упр. 353 (Graceful Shutdown)**. Это именно те вещи, которые отличают «школьную поделку» от высоконагруженного промышленного сервиса. Сервер должен уважать ресурсы и никогда не обрывать соединения грубо при перезапуске!
