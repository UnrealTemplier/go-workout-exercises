## Блок 7. `reflect` — законы, динамика и оптимизация

### Уровень 1. Законы рефлексии и базовые операции
91. **Законы рефлексии в действии.** Напишите универсальную функцию `Inspect(v any)`, которая проходит по цепочке: `any` → `reflect.TypeOf` → `reflect.ValueOf` → `Kind()` → `Elem()` (если указатель). Для каждого шага выводите, что получилось. Объясните, почему `ValueOf` на `nil`-интерфейсе возвращает «пустой» `reflect.Value`, а `TypeOf` — `nil`.
92. **Settability и адресуемость.** Напишите программу, которая демонстрирует панику при `reflect.ValueOf(x).SetInt(42)` и корректную работу при `reflect.ValueOf(&x).Elem().SetInt(42)`. Объясните разницу между `CanAddr`, `CanSet` и почему `ValueOf` по значению возвращает неадресуемую копию.
93. **Структурные теги.** Создайте структуру с полями, помеченными кастомными тегами: `db:"column_name" validate:"required,min=5"`. Напишите парсер, который извлекает эти теги через `reflect.Type.Field(i).Tag` и валидирует значения полей без использования `encoding/json`. Объясните, почему теги — это просто строки, и как `reflect` их не интерпретирует.
94. **Динамическое создание слайса.** Используйте `reflect.MakeSlice`, `reflect.Append` и `reflect.Value.Index` для построения `[]int` динамически. Сравните с нативным `append` в бенчмарке. Объясните, почему `reflect.Append` аллоцирует каждый раз, если capacity не задана заранее.
95. **Динамическое создание map.** Создайте `map[string]int` через `reflect.MakeMap`, заполните через `SetMapIndex`, обойдите через `MapRange`. Объясните, почему `MapRange` не позволяет модифицировать map во время итерации (runtime проверка), и как это отличается от `for range` в нативном Go.

### Уровень 2. Динамические вызовы и функции
96. **Динамический вызов метода.** Напишите диспетчер: по имени метода (строка) и `any` (получатель) вызывайте метод через `reflect.Type.MethodByName` + `Value.Method(i).Call`. Сравните latency с `type switch` на конкретные типы. Объясните, когда `reflect` оправдан, а когда — нет.
97. **Создание функции через `reflect.MakeFunc`.** Реализуйте generic proxy-обёртку: функция, принимающая `reflect.Type` сигнатуры и возвращающая `reflect.Value`, которая перед вызовом логирует аргументы, а после — результат. Объясните, как рантайм генерирует stub для такой функции и почему это медленнее нативного вызова.
98. **Динамические типы: `PtrTo`, `SliceOf`, `MapOf`.** Создайте тип `*[]map[string]int` полностью через `reflect` (без литералов типов). Объясните, почему `reflect` позволяет создавать составные типы, но не позволяет создавать именованные типы (`type MyInt int`) и методы к ним.
99. **`reflect.StructOf` и ограничения.** Создайте динамическую структуру с полями `Name string` и `Age int` через `reflect.StructOf`. Создайте экземпляр, заполните поля. Объясните, почему полученный тип не может иметь методы, почему embedding не поддерживается полноценно, и как это ограничивает применение.

### Уровень 3. Продвинутые паттерны и опасности
100. **Доступ к неэкспортируемым полям через `reflect` + `unsafe`.** Напишите функцию, которая читает и пишет `unexported` поле структуры, используя `reflect.Value` для получения адреса и `unsafe.Pointer` для обхода защиты. Объясните, почему это **UB** (undefined behavior) при moving GC и внутренних изменениях layout.
101. **Циклические структуры и `reflect.DeepEqual`.** Создайте связный список, указывающий сам на себя. Покажите, что `reflect.DeepEqual` с `visited` map корректно обрабатывает цикл, а ваш собственный рекурсивный обход через `reflect` без `visited` — падает с `stack overflow`. Напишите безопасный обход.
102. **`reflect.DeepEqual` vs кастомный компаратор.** Напишите бенчмарк: сравнение двух больших структур с `time.Time` через `reflect.DeepEqual` и через generated `Equal`. Объясните, почему `DeepEqual` медленный (аллокации, рекурсия, interface dispatch) и почему в production предпочитают codegen.
103. **Оптимизация рефлексии: убирание аллокаций.** Напишите функцию, которая через `reflect.Value.Interface()` возвращает `any` и передаёт его дальше. Покажите через `go test -benchmem`, что это аллоцирует. Перепишите через `type switch` на конкретные типы — покажите нулевые аллокации. Объясните, когда компилятор не может devirtualize вызов.

### Уровень 4. Интеграция и runtime
104. **Рефлексия и GC: `ValueOf` на стеке vs куче.** Напишите программу, которая передаёт локальную переменную в `reflect.ValueOf`. Покажите через `go build -gcflags="-m"`, что `reflect.ValueOf` иногда заставляет переменную убегать в кучу (escape analysis). Объясните, почему `ValueOf` требует, чтобы данные жили достаточно долго.
105. **Реализация «ленивого» `json.Marshaler` через reflect.** Напишите кодировщик struct-to-JSON через `reflect`, который обходит только экспортируемые поля и учитывает теги `json:"..."`. Сравните с `encoding/json` по скорости. Объясните, почему стандартный пакет использует `reflect` + codegen (`typeEncoder`) для кэширования.

## Блок 8. `go/ast`, `go/parser` и статический анализ

### Уровень 1. Парсинг и обход дерева
106. **Базовый парсинг.** Напишите программу, которая принимает `.go`-файл, парсит его через `go/parser.ParseFile` и выводит все top-level объявления: `FuncDecl`, `GenDecl` (type, var, const, import). Объясните, что такое `*ast.File` и `*token.FileSet`.
107. **Обход AST.** Используя `ast.Inspect`, найдите все `CallExpr` в файле и выведите имя вызываемой функции. Объясните разницу между `ast.Inspect` (функция-замыкание) и `ast.Walk` (интерфейс `Visitor`).
108. **Позиции и токены.** Напишите инструмент, который для каждого `ast.Ident` выводит его позицию в файле (`token.Pos` → `fset.Position`). Объясните, почему `Pos` — это смещение в `FileSet`, а не строка/колонка напрямую.

### Уровень 2. Линтеры на `go/ast`
109. **Простой линтер: запрет `fmt.Println`.** Напишите анализатор, который находит вызовы `fmt.Println` (или `log.Println`) в коде и выдаёт предупреждение. Используйте `go/ast` без `go/analysis`. Объясните, как различить `fmt.Println` от `myfmt.Println` через селектор (`ast.SelectorExpr`).
110. **Линтер: копирование `sync.Mutex`.** Напишите анализатор, который находит структуры, содержащие `sync.Mutex` или `sync.RWMutex`, и проверяет, что они никогда не передаются по значению (в присваиваниях, аргументах функций, range). Используйте `go/ast` + `go/types` для определения типа поля.
111. **Линтер: непроверенные ошибки.** Напишите анализатор, который находит присваивания `err := foo()` и проверяет, что переменная `err` используется далее в том же блоке (не `_`). Используйте `go/ast` и учтите named returns, reassign (`err = foo()`), и shadowing. Объясните, почему `go/types` нужен для точного отслеживания scope.
112. **Cyclomatic complexity lite.** Напишите visitor, который считает количество `if`, `for`, `switch`, `&&`, `||` в функции и предупреждает, если сложность > 10. Объясните, как `ast.BinaryExpr` с `&&`/`||` влияет на сложность.

### Уровень 3. `go/analysis` и типизация
113. **Фреймворк `go/analysis`.** Перепишите линтер из упр. 109 с использованием `golang.org/x/tools/go/analysis`. Объясните структуру `analysis.Analyzer`: `Run`, `Pass`, `Reportf`, `Fact`. Покажите, как запустить через `singlechecker.Main` и `multichecker`.
114. **Мультичекер.** Соберите 3 линтера (из упр. 109, 110, 111) в один бинарник через `multichecker`. Объясните, как `golangci-lint` использует этот же подход для объединения hundreds of checks.
115. **Использование `go/types`.** Напишите инструмент, который для любого `ast.Ident` определяет его объект (`types.Object`) — переменная, константа, функция, тип. Объясните разницу между `ast.Ident` (имя в коде) и `types.Object` (семантическая сущность).
116. **Анализ импортов.** Напишите инструмент, который сканирует пакет и проверяет, что нет запрещённых импортов (например, `unsafe`, `syscall`, `net/rpc`). Объясните, как `ast.File.Imports` даёт `ast.ImportSpec`, и почему нужно сравнивать `Path.Value` (строка с кавычками).

### Уровень 4. Сложный анализ и модификация AST
117. **Построение графа вызовов.** Напишите инструмент, который строит `caller → callee` граф для всех функций в пакете. Объясните, как различать вызовы методов (`SelectorExpr.X.Method`), функций пакета (`SelectorExpr` с `Ident`) и встроенные вызовы (`CallExpr.Fun` — `Ident`).
118. **Dead code detector.** Напишите инструмент, который находит функции, не вызываемые ни из одного `CallExpr` пакета (кроме `main` и `init`). Объясните ограничения: reflection (`reflect.Value.Call`), `go generate`, cgo, build tags, вызовы через `func` value.
119. **Модификация AST и форматирование.** Напишите инструмент, который автоматически добавляет комментарий `// TODO: review (complexity > 20)` перед функциями с высокой цикломатической сложностью. Используйте `astutil.AddNamedImport` (если нужно) и `go/printer.Fprint` для вывода. Объясните, почему `go/format` предпочтительнее ручного `Fprint`.
120. **Извлечение интерфейса (Extract Interface).** Напишите инструмент, который для данного типа (`*ast.TypeSpec`) находит все методы (включая pointer receiver) и генерирует объявление `interface` с этими методами. Объясните, как `ast.FuncDecl.Recv` определяет получателя.

## Блок 9. Кодогенерация: `go generate`, шаблоны и AST

### Уровень 1. `go generate` и текстовые шаблоны
121. **Генератор геттеров.** Напишите генератор, который по struct с тегом `gen:"getter"` генерирует методы `GetXxx()` для каждого поля. Используйте `go generate` + `text/template`. Объясните механику: `//go:generate go run ./cmd/gengetters.go`, как `go generate` просто выполняет команды в комментариях.
122. **Свой `stringer`.** Для типа `type Status int` с константами `StatusPending`, `StatusDone` напишите генератор, который создаёт метод `String() string` через `map[Status]string`. Используйте `go/ast` для парсинга констант и `text/template` для вывода. Объясните, почему `stringer` из `golang.org/x/tools` использует `go/constant` для вычисления значений `iota`.
123. **Генератор reverse-lookup для констант.** Напишите генератор, который для `const` блока создаёт функцию `ParseStatus(s string) (Status, error)` и `AllStatuses() []Status`. Используйте `go/ast` для чтения и `text/template` для генерации.

### Уровень 2. Генерация через AST (а не шаблоны)
124. **Генерация конструкторов (Builder pattern).** Напишите tool, который по struct `Config` с полями генерирует функции `WithXxx(value Type) Option` и `NewConfig(opts ...Option) *Config`. Генерируйте код через `go/ast` (создание `ast.FuncDecl`, `ast.StructType`) и `go/printer`. Объясните, почему AST-генерация безопаснее шаблонов (сохраняет валидность Go-кода), но сложнее.
125. **Генератор mock-интерфейсов (упрощённый `mockgen`).** Напишите tool, который принимает `.go`-файл с интерфейсом и генерирует `struct MockXxx` с методами-заглушками, возвращающими zero values. Используйте `go/ast` для парсинга `ast.InterfaceType` и `text/template` для вывода.
126. **Генератор `Equal` и `Hash`.** Напишите генератор, который для struct с простыми полями генерирует метод `Equal(other T) bool` (поэлементное сравнение) и `Hash() uint64`. Объясните, почему generated code в 10-100× быстрее `reflect.DeepEqual`.

### Уровень 3. Интеграция и оптимизация
127. **Zero-allocation сериализация (codegen).** Напишите генератор `MarshalBinary`/`UnmarshalBinary` для фиксированных структур (без slices/maps, только примитивы). Генерируйте прямое чтение/запись в `[]byte` через `binary.LittleEndian`. Объясните, почему generated code быстрее `encoding/binary` с `reflect`.
128. **Генератор SQL-CRUD (упрощённый).** На входе struct с тегами `db:"column_name"`, на выходе код с методами `Insert(db *sql.DB)`, `Scan(rows *sql.Rows)`. Используйте `text/template`. Объясните, почему `sqlc` и подобные инструменты используют именно AST + типизацию, а не просто regex.
129. **Генератор DI-контейнера (упрощённый).** Сканируйте пакет, находите конструкторы (`func NewXxx(...) *Xxx`), стройте граф зависимостей по типам параметров, генерируйте `func InitializeApp() *App` с правильным порядком вызовов. Используйте `go/ast` + `go/types`. Объясните, как `dig`/`wire` решают проблему циклических зависимостей.

### Уровень 4. Продвинутое метапрограммирование
130. **AST-based instrumentation.** Напишите tool, который принимает Go-файл, и для каждой функции добавляет `defer func(start time.Time) { log.Printf("%s took %v", name, time.Since(start)) }(time.Now())`. Используйте `go/ast` для создания `ast.DeferStmt` и `ast.CallExpr`. Объясните, как `astutil` упрощает вставку узлов, и почему `go/printer` сохраняет исходные комментарии.
131. **Генератор enum-валидатора.** Напишите tool, который для типа `type Role int` с константами генерирует метод `IsValid() bool`, проверяющий, что значение входит в допустимый диапазон. Используйте `go/constant` для вычисления значений `iota` во время генерации.
132. **Генерация HTTP-обработчиков по спеке.** Создайте YAML-спеку (метод, путь, request/response struct). Напишите генератор, который создаёт Go-код: интерфейс сервиса, middleware-обёртки, chi/gin-роуты и типы request/response. Объясните, почему `go-swagger`/`oapi-codegen` используют `text/template` + `go/ast` в комбинации.

## Как встроить в общий план

**Рекомендуемый порядок прохождения всех 4 блоков:**

1. **Блок 7 (reflect)** — начните после Блока 1 (GMP) и Блока 4 (unsafe). `reflect` активно использует `unsafe` под капотом, а понимание escape analysis из Блока 2 поможет объяснить аллокации в `ValueOf`.
2. **Блок 8 (AST)** — требует уверенного знания синтаксиса Go и типовой системы. Проходите после Блока 7, чтобы понимать, что `go/types` — это «type checker», а `go/ast` — только синтаксис.
3. **Блок 9 (codegen)** — финальный блок. Использует всё: `go/ast` для чтения, `text/template` или `go/printer` для вывода, `go generate` для оркестрации. Параллельно смотрите, как устроены `stringer`, `mockgen`, `wire`.

**Ключевые инструменты для этих упражнений:**
```bash
go/ast, go/parser, go/token, go/printer, go/types
golang.org/x/tools/go/analysis
golang.org/x/tools/go/ast/astutil
go generate ./...
go test -benchmem -memprofile=mem.out
```

**Что делать с результатами:**
- Для упр. 106–120: соберите свои линтеры в один репозиторий с `cmd/my-linter/main.go` и `multichecker`.
- Для упр. 121–132: создайте библиотеку `codegen` с CLI-tool, который принимает `--input` и `--output`.

Если нужно — могу детально расписать **любое конкретное упражнение** с шаблоном кода, или выдать финальный блок на тему *«Каналы в рантайме, netpoller, sync.Pool, runtime timers и memory model»*.
