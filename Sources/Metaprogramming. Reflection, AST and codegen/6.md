### Раздел 42: Метапрограммирование: Рефлексия, AST и кодогенерация (Задачи 516–535)

#### Подраздел 42.1: Продвинутая рефлексия (`reflect`) (Задачи 516–522)

*Рефлексия позволяет исследовать типы и значения объектов во время выполнения программы, динамически изменять их и вызывать методы, обходя ограничения компиляции.*

516. **Законы рефлексии в действии**: Напишите программу, иллюстрирующую три закона рефлексии Go:
    * Закон 1: Переход от интерфейсного значения к объекту рефлексии (`reflect.Type`, `reflect.Value`).
    * Закон 2: Переход от объекта рефлексии обратно к интерфейсному значению (метод `.Interface()`).
    * Закон 3: Возможность изменения объекта рефлексии. Попробуйте вызвать метод `.SetString()` на `reflect.ValueOf(str)` и зафиксируйте панику. Исправьте ошибку, получив адрес переменной и перейдя к элементу: `reflect.ValueOf(&str).Elem()`, проверив перед изменением свойство `.CanSet()`.
517. **Динамическое заполнение структур**: Напишите обобщенную функцию `PopulateStruct(obj any, data map[string]any) error`. Функция должна с помощью рефлексии обходить поля структуры `obj` (переданной по указателю) и заполнять их значениями из мапы `data`, если имена ключей совпадают с именами полей или значениями тегов `db` (например, `db:"user_id"`). Обеспечьте базовую конвертацию несовместимых числовых типов (например, `int` из мапы в `int64` структуры).
518. **Динамический вызов методов**: Напишите структуру `Calculator` с методами `Add(a, b int) int` и `Multiply(a, b int) int`. Напишите универсальный раннер, который принимает объект калькулятора, имя метода в виде строки `"Multiply"` и слайс аргументов `[]any{2, 5}`. С помощью рефлексии найдите метод через `Value.MethodByName`, соберите слайс `[]reflect.Value` параметров, выполните вызов через `Call()` и выведите возвращенное значение.
519. **Динамическое создание коллекций**: Напишите функцию `CreateAndFillSlice(elemType reflect.Type, size int) any`. Функция должна с помощью рефлексии динамически создавать срез переданного типа нужного размера (метод `reflect.MakeSlice`), заполнять его дефолтными тестовыми значениями и возвращать результат в виде пустого интерфейса `any`.
520. **Оптимизация рефлексивных аллокаций**: Работа с рефлексией в критических путях высоконагруженных систем может сильно замедлять работу из-за частых аллокаций в куче.
    * Напишите бенчмарк сравнения прямого доступа к полю структуры и доступа через рефлексивный метод `FieldByName`.
    * Оптимизируйте рефлексивный доступ: напишите кэш типов, который при первом обращении сохраняет смещения полей структуры (`Field.Index`), чтобы в дальнейшем получать значения полей мгновенно по индексу, минуя ресурсоемкий поиск по строковому имени. Сравните результаты бенчмарков.
521. **Динамическое конструирование типов**: Напишите программу, которая во время выполнения собирает абсолютно новый тип структуры из динамического описания (среза полей). Используйте функцию `reflect.StructOf` [521], передав туда описание полей (имена, типы, теги) [521]. Создайте экземпляр этой динамической структуры, запишите в неё данные и сериализуйте в JSON-строку.
522. **Рефлексия и `unsafe` для извлечения адреса**: Напишите программу, которая с помощью рефлексии получает доступ к базовому массиву данных среза `[]int`. Получите адрес начала данных в памяти с помощью метода `Value.Pointer()` (или `Value.UnsafeAddr()`). Преобразуйте его в unsafe-указатель и измените значение элемента массива напрямую в обход методов среза.

#### Подраздел 42.2: Анализ AST и написание линтеров (Задачи 523–529)

*Анализ абстрактного синтаксического дерева (AST) позволяет исследовать код как структуру данных, что необходимо для создания собственных линтеров, анализаторов и инструментов рефакторинга.*

523. **Парсинг Go-файла в AST**: Создайте файл `target.go` с простым кодом (объявление структуры, пара функций). Напишите парсер, который с помощью пакетов `go/parser` [523] и `go/token` [523] разбирает этот файл в синтаксическое дерево `*ast.File` [523]. Выведите структуру дерева на экран в виде красивого форматированного текста с помощью функции `ast.Print` [523].
524. **Обход дерева синтаксического анализа**: Используя функцию `ast.Inspect` [524], напишите скрипт, который обходит все узлы AST-дерева разобранного Go-файла. Подсчитайте и выведите на экран: общее количество функций, количество структур и количество объявленных интерфейсов в файле.
525. **Линтер: Обнаружение проигнорированных ошибок**: Напишите кастомный статический анализатор (линтер). Линтер должен сканировать AST-дерево файла и искать вызовы функций, которые возвращают тип `error`, но вызывающий код полностью игнорирует этот возврат (например, не присваивает результат переменной или присваивает его пустому идентификатору `_` без последующей проверки на `nil`). Выводите предупреждения с указанием имени файла и номера строки (используя `token.FileSet`).
526. **Линтер: Контроль именования функций**: Напишите линтер, который проверяет все экспортируемые (начинающиеся с заглавной буквы) функции в пакете на соответствие правилам хорошего тона Go: функции не должны начинаться с префикса `Get` (например, вместо `GetPrice()` должно быть просто `Price()`). Выводите предупреждения для всех нарушителей.
527. **Линтер: Борьба с "голыми" возвратами (Naked Returns)**: Использование "голых" операторов `return` в длинных функциях ухудшает читаемость. Напишите линтер, который анализирует все узлы функций `*ast.FuncDecl`. Если длина тела функции превышает 15 строк, а внутри используется оператор `return` без явного указания возвращаемых аргументов при наличии именованных возвращаемых значений, линтер должен генерировать предупреждение.
528. **Линтер: Проверка закрытия ресурсов (`defer Close`)**: Напишите анализатор кода. Он должен находить все вызовы функций открытия файлов `os.Open` или создания сетевых сокетов и проверять, есть ли в рамках текущего блока кода соответствующий вызов `defer` для закрытия этого ресурса (вызова метода `Close()`). Если вызова нет, линтер должен ругаться.
529. **Модификация исходного кода на уровне AST**: Напишите инструмент автоматического рефакторинга. Программа должна распарсить Go-файл в AST, обойти его структуру, найти все вызовы стандартной функции вывода `fmt.Println` и автоматически заменить их на вызовы логгера `log.Println` (изменив имя пакета и функции в узле AST). После модификации запишите измененное синтаксическое дерево обратно в файл на диск, применив форматирование с помощью пакета `go/format`.

#### Подраздел 42.3: Генерация кода и `go generate` (Задачи 530–535)

*Кодогенерация избавляет от написания рутинного шаблонного кода, генерируя строго типизированные структуры и методы на основе метаданных во время сборки.*

530. **Основы `go generate`**: Создайте файл `main.go`. Добавьте в него специальный комментарий-директиву: `//go:generate echo "Запущена генерация кода!"` [530]. Запустите процесс генерации из терминала с помощью команды `go generate ./...` [530] и убедитесь, что скрипт успешно перехватывает директиву и выполняет указанную консольную команду [530].
531. **Генератор String-представлений Enums (Собственный `stringer`)**: 
    * Напишите файл `status.go`, содержащий тип-энум `type Status int` и блок констант `StatusIdle`, `StatusRunning`, `StatusFailed`.
    * Напишите утилиту кодогенерации, которая с помощью AST парсит этот файл, находит все константы типа `Status` и автоматически генерирует вспомогательный файл `status_string.go` с реализацией метода `String() string` (используя массив или мапу имен для быстрого возврата строкового представления константы).
    * Привяжите генератор к файлу `status.go` с помощью директивы `//go:generate`.
532. **Генерация типизированных коллекций через `text/template`**: Напишите генератор строго типизированных множеств (Set). Напишите шаблон кода для структуры множества в виде текста с использованием пакета `text/template` [532]. Напишите утилиту, которая принимает на вход имя типа (например, `User` или `Order`) и на основе шаблона генерирует готовый файл коллекции (например, `user_set.go` с методами `Add`, `Remove`, `Contains`), заменяя параметры шаблона на реальное имя типа.
533. **Кодогенерация Go-структур по JSON-схеме**: Напишите скрипт, который считывает входящий JSON-файл, описывающий схему базы данных или структуру API-ответа (например, имена полей и их типы). Скрипт должен автоматически сгенерировать валидный файл кода Go (`models.go`) с объявлением соответствующих структур и корректно расставленными тегами для JSON-сериализации (`json:"field_name"`).
534. **Генератор Декораторов (Decorator Generator)**: Напишите утилиту автоматического декорирования. Утилита должна сканировать любой указанный интерфейс Go (например, `Repository` с методами `Save` и `Delete`), извлекать сигнатуры методов с помощью AST и генерировать для этого интерфейса готовую структуру-декоратор, которая оборачивает каждый вызов метода интерфейса в замер времени выполнения (метрики) и логирование ошибок.
555. **Интеграция кодогенератора в CI/CD и Makefile**: Создайте Makefile для вашего проекта. Настройте команду сборки `build` так, чтобы перед компиляцией бинарного файла Go обязательно принудительно выполнялась команда `go generate ./...`. Напишите проверку для CI-пайплайна (из раздела №39): если сгенерированные файлы не соответствуют актуальным схемам (например, разработчик изменил энум, но забыл запустить `go generate`), пайплайн должен завершаться ошибкой.
