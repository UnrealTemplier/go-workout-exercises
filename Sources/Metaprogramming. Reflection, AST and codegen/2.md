### 18. Метапрограммирование: Рефлексия, AST и Кодогенерация

#### 18.1 Продвинутая рефлексия (reflect)
601. **Три закона рефлексии в действии.** Продемонстрируйте: (1) из `interface{}` можно получить `reflect.Value`; (2) из `reflect.Value` можно получить `interface{}`; (3) для изменения объекта нужно передать `reflect.Value`, ссылающийся на адресуемое значение. Напишите примеры на каждый закон.
602. **Динамическое создание объектов.** Используя `reflect.New` и `reflect.MakeSlice`, создайте слайс заданного типа, переданного через `reflect.Type`. Заполните его значениями и верните как `interface{}`.
603. **Универсальный сеттер.** Напишите функцию, которая принимает указатель на структуру, имя поля в виде строки и значение. Используя рефлексию, установите значение поля (с обработкой ошибок типов и несуществующих полей).
604. **Вызов методов по имени.** Создайте структуру с несколькими методами. Напишите функцию `CallMethod(obj interface{}, methodName string, args ...interface{}) ([]interface{}, error)`, которая ищет метод, проверяет аргументы и вызывает его.
605. **Копирование структуры через рефлексию.** Реализуйте глубокое копирование структуры (включая вложенные слайсы и структуры) с помощью `reflect`, без использования сериализации/десериализации.
606. **Сравнение двух значений через рефлексию.** Напишите функцию `DeepEqualReflect(a, b interface{}) bool`, которая сравнивает значения разных типов, обрабатывая указатели, слайсы, мапы и структуры рекурсивно.
607. **Избегание аллокаций при рефлексии.** Покажите, что `reflect.ValueOf(x).Interface()` выделяет память (аллоцирует копию). Используйте трюки с `unsafe.Pointer` для доступа к значению без аллокации (там, где это безопасно, только для примеров). Сравните бенчмарком.
608. **Рефлексия и дженерики: мост.** Напишите обобщённую функцию, которая использует рефлексию для проверки, что тип реализует интерфейс, и если да, вызывает один из его методов. Покажите, где дженерики не могут заменить рефлексию (например, итерация по полям).
609. **Создание карты с динамическими типами ключей и значений.** Напишите функцию, которая по заданным `reflect.Type` ключа и значения создаёт и возвращает пустую `map[K]V` через рефлексию. Добавьте в неё элементы.
610. **Рефлексивный проход по графу объектов.** Создайте функцию, которая обходит структуру (и вложенные структуры, слайсы, мапы) и заменяет все строки на их заглавные версии (uppercase) с помощью `reflect`.

#### 18.2 Анализ кода и AST (go/parser, go/ast, go/types)
611. **Парсинг Go-файла в AST.** Напишите программу, которая принимает путь к `.go` файлу, парсит его с помощью `go/parser.ParseFile` и выводит список всех объявленных функций с именами и номерами строк.
612. **Поиск неиспользуемых переменных (начальный линтер).** Пройдите по AST функции и найдите все объявления переменных (`ast.GenDecl` с токеном `VAR` или `:=`), которые не используются далее в теле функции. Выведите предупреждения.
613. **Проверка именования экспортируемых идентификаторов.** Напишите линтер, который проверяет, что все экспортируемые функции, методы и типы имеют комментарий в формате `// FuncName does something.`. Используйте `go/ast.Inspect`.
614. **Анализ цикломатической сложности.** Рассчитайте цикломатическую сложность каждой функции в файле на основе AST (подсчёт `if`, `for`, `range`, `case`, `&&`, `||` и т.д.). Выведите функции с высокой сложностью.
615. **Детектор глобальных переменных.** Найдите в AST пакета объявления переменных на уровне пакета (`GenDecl` с `VAR` или `CONST`). Выведите предупреждение об их наличии (если не константа).
616. **Поиск использования `panic` без явной необходимости.** Проинспектируйте AST и найдите все вызовы `panic`, которые не находятся внутри тестовых функций (имя функции начинается с `Test`). Предложите заменять их на возврат ошибок.
617. **Сбор информации о типах с помощью `go/types`.** Загрузите пакет с помощью `packages.Load`, получите `*types.Package`. Для каждой функции выведите типы всех аргументов и возвращаемых значений в строковом представлении.
618. **Поиск потенциальных утечек горутин.** Найдите в AST все вызовы `go func()` и проверьте, что внутри горутины есть чтение из `context.Context` или канала для возможности завершения. Выведите предупреждение, если нет.

#### 18.3 Кодогенерация (go generate и текстовые шаблоны)
619. **Генерация String() метода для типа.** Напишите генератор, который по заданной структуре (в файле с директивой `//go:generate`) создаёт файл с методом `String() string`, печатающим все поля. Используйте `text/template`.
620. **Генерация builder-паттерна для структуры.** Создайте генератор, который по структуре генерирует структуру-строитель (Builder) с методами `Set<Field>` и `Build()`. Шаблон должен обрабатывать поля разных типов.
621. **Генерация JSON-сериализации без рефлексии.** Напишите кодогенератор, который для каждой структуры генерирует `MarshalJSON` и `UnmarshalJSON`, напрямую обращаясь к полям, чтобы избежать рефлексии. Сравните производительность с `encoding/json`.
622. **Генерация mock-объектов для интерфейсов.** Реализуйте упрощённый аналог `mockgen`: программа читает файл, находит интерфейс, генерирует структуру-мок с методами, которые записывают факт вызова и возвращают предопределённые значения.
623. **Использование `go generate` для внедрения версии и времени сборки.** Напишите генератор, который создаёт файл `version_gen.go` с константами `Version` и `BuildTime`, извлечёнными из `git describe` и текущего времени. Подключите генерацию в `go generate`.
624. **Генерация enum-подобного типа с методами.** Создайте генератор, который по срезу строк генерирует тип `int` с константами (`const ( A MyEnum = iota; B; C )`) и метод `String() string`, возвращающий строковое представление.
625. **Создание собственного препроцессора аннотаций.** Напишите инструмент, который сканирует комментарии вида `// @inject Logger` в структурах и генерирует файл с функцией, создающей экземпляр структуры с проставленными зависимостями (DI-контейнер).
