Метапрограммирование — это когда код пишет код или анализирует сам себя. В Go нет макросов (как в Rust или C++), но есть мощный пакет `reflect`, строгий парсер `go/ast` и механизм `go generate`. Это инструменты для создания ORM, моков, линтеров и кодогенераторов.

Завершаем твой тренинг **30 упражнениями** (с 751 по 780), которые научат тебя "читать" исходный код программно и генерировать boilerplate-код.

---

### Блок 83: Пакет `reflect` (Законы рефлексии)
*Цель: Научиться.inspectить типы и значения в рантайме, динамически вызывать методы и модифицировать данные.*

751. **[База]** Напиши функцию `Inspect(v interface{})`, которая принимает любой аргумент. Используй `reflect.TypeOf` и `reflect.ValueOf`, чтобы вывести имя типа, категорию (Kind: struct, int, string) и значение.
752. **[Законы рефлексии]** Рефлексия идет от `interface{}`. Объясни, почему передача значения по указателю (`&v`) дает больше возможностей. Выведи `Elem()` указателя, чтобы получить реальное значение.
753. **[Чтение структуры]** Передай структуру в функцию. Используй `reflect.ValueOf(v).NumField()` и `Field(i)`, чтобы вывести имена всех полей и их значения.
754. **[Чтение тегов]** Получи `reflect.Type` структуры. Используй `Field(i).Tag.Get("json")`, чтобы вывести значения JSON-тегов.
755. **[Модификация полей]** Передай указатель на структуру в функцию. Используй `reflect.ValueOf(v).Elem()`. Измени значение первого поля (`Field(0).Set(...)`). *Важно: поля должны быть экспортируемыми (с большой буквы).*
756. **[Каверзный кейс — Unexported fields]** Попробуй изменить приватное поле (с маленькой буквы) через `Set`. Поймай панику `reflect.Value.Set: value of type ... is not assignable`. Изучи, почему `CanSet()` возвращает `false` для приватных полей.
757. **[Динамический вызов методов]** Создай структуру с методом `Shout(msg string) string`. Получи метод через `reflect.ValueOf(v).MethodByName("Shout")`. Подготовь аргументы как `[]reflect.Value` и вызови `method.Call(args)`. Выведи результат.
758. **[Проверка интерфейсов]** Используй `reflect.TypeOf(v).Implements(reflect.TypeOf((*fmt.Stringer)(nil)).Elem())`, чтобы проверить, реализует ли переданный объект интерфейс `Stringer`.
759. **[Создание слайсов и мап]** Используй `reflect.MakeSlice` и `reflect.MakeMapWithSize`, чтобы динамически создать слайс `[]int` и мапу `map[string]int` без явного указания типов в коде. Заполни их значениями через `reflect.Append` и `SetMapIndex`.
760. **[Производительность]** Напиши бенчмарк: прямой вызов функции vs вызов через `reflect.Call`. Оцени разницу в скорости (рефлексия медленнее в 10-100 раз).
761. **[Оптимизация — MethodByName]** Вместо `MethodByName` используй кэширование индекса метода (`Type.Method(i).Index`), чтобы не искать по строке каждый раз.
762. **[Высокая сложность — Глубокое копирование]** Напиши функцию `DeepCopy(src, dst interface{})`, которая с помощью рефлексии рекурсивно копирует структуру, включая слайсы и мапы, выделяя под них новую память.

### Блок 84: AST (Abstract Syntax Tree) — Статический анализ кода
*Цель: Разбирать исходный код Go как дерево, искать паттерны и писать свои линтеры.*
*Пакеты: `go/parser`, `go/ast`, `go/token`*

763. Напиши программу, которая читает `.go` файл, использует `parser.ParseFile` для получения AST-дерева. Выведи дерево в консоль с помощью `ast.Print(fset, tree)`.
764. Используй `ast.Inspect(tree, func(n ast.Node) bool { ... })`, чтобы найти все узлы типа `*ast.FuncDecl` (объявления функций). Выведи имена всех функций в файле.
765. Найди все узлы `*ast.StructType`. Выведи имена всех структур и список их полей.
766. **[Простой линтер — Запрет fmt.Println]** Напиши утилиту, которая обходит AST и ищет вызовы `fmt.Println`. Если вызов найден — выводи предупреждение с номером строки (`fset.Position(n.Pos())`).
767. **[Линтер — Проверка комментариев]** Найди все экспортируемые функции (имя начинается с большой буквы). Проверь, есть ли у них узел `Doc` (комментарий над функцией). Если нет — выводи ошибку "Exported function must have a doc comment".
768. **[Анализ импортов]** Найди узел `*ast.ImportSpec`. Выведи все пути импорта. Проверь, используется ли импортированный пакет в файле (поиск селекторов `*ast.SelectorExpr`).
769. **[Каверзный кейс — Вычисление констант]** В AST найди объявление `const x = 10 + 5`. Узел `*ast.BinaryExpr` содержит операцию. Напиши рекурсивную функцию-эвалюатор, которая посчитает результат выражения (`10 + 5 = 15`), используя `ast.BasicLit` и `ast.BinaryExpr`.
770. **[go/analysis]** Используй пакет `golang.org/x/tools/go/analysis` для написания полноценного плагина-линтера (анализатора). Создай `Analyzer` и запусти его через `singlechecker.Main(analyzer)`.
771. **[Модификация AST]** Добавь новый импорт (`"fmt"`) в AST файла, который его не имел. Используй `astutil.AddImport`. Запиши измененное дерево обратно в файл с помощью `printer.Fprint`.
772. **[Высокая сложность — Детектор утечек]** Напиши линтер, который ищет `os.Open(...)` или `os.Create(...)` и проверяет, есть ли в теле той же функции вызов `defer ...Close()`. Если нет — репорти об утечке файлового дескриптора.

### Блок 85: Кодогенерация (`go generate` и `text/template`)
*Цель: Автоматизировать написание рутинного кода (моки, DTO, конвертеры).*

773. Напиши в коде директиву `//go:generate echo "Hello"`. Запусти `go generate ./...`. Убедись, что команда выполнилась.
774. **[Шаблонизатор]** Напиши `.go` файл с пакетом `main`, который использует `text/template`. Сгенерируй текст Go-кода со структурой и методами на основе переданной в шаблон мапы `map[string]string{"Name": "User", "Field": "ID"}`.
775. **[Генерация в файл]** В генераторе из предыдущего задания создай файл (`os.Create("generated.go")`) и запиши в него результат шаблонизации.
776. **[Использование AST для кодогена]** Напиши генератор, который парсит входной `.go` файл (через `parser`), находит все структуры с тегом `//go:generate-methods`, и для каждой структуры генерирует файл `_gen.go` с геттерами (Get) и сеттерами (Set) для каждого поля.
777. **[Каверзный кейс — Форматирование]** Сгенерированный код может быть криво отформатирован. В генераторе после записи в файл вызови `format.Source(bytes)` из пакета `go/format` и перезапиши файл красивым кодом.
778. **[Генерация интерфейсов]** Напиши генератор, который принимает структуру и генерирует интерфейс, содержащий все её публичные методы. (Аналог того, как работает `mockery`).
779. **[Генерация моков]** Расширь предыдущий генератор. Для сгенерированного интерфейса создай структуру `MockName`, которая хранит мапу `map[string]func(args) returns` и реализует методы интерфейса, вызывая коллбэки из мапы.
780. **[Финальное испытание — Мини-ORM]**
    Напиши кодогенератор `genorm`.
    - Создай структуру `User` с тегами `db:"column_name"` и `pk:"true"`.
    - Над структурой добавь комментарий `//go:generate go run ../genorm -type=User`.
    - Генератор должен:
      1. Через AST найти структуру `User` и её поля/теги.
      2. Через `text/template` сгенерировать файл `user_orm.go`.
      3. В сгенерированном файле должны быть методы `Insert()` (генерирует SQL `INSERT INTO ...`), `FindById(id int)` (генерирует `SELECT ... WHERE id = $1` и маппит результат в структуру через `rows.Scan`).
    - Запусти `go generate`, скомпилируй основной код и убедись, что методы работают с реальной БД.
