WebSockets и GraphQL — это современные технологии для построения интерактивных и гибких API. В Go для WebSockets стандартом является библиотека `gorilla/websocket`, а для GraphQL — генератор кода `gqlgen`.

Завершаем твой тренинг **18 упражнениями** (с 508 по 525). Они охватывают апгрейд HTTP-соединений, паттерн Hub для чатов и решение проблемы N+1 в GraphQL через DataLoaders.

### Блок 53: WebSockets — Real-time коммуникация
*Цель: Научиться превращать HTTP-запрос в постоянное двустороннее соединение и управлять жизненным циклом подключений.*

508. Установи `github.com/gorilla/websocket`. Напиши HTTP-обработчик, который использует `websocket.Upgrader` для апгрейда HTTP-запроса в WebSocket-соединение.
509. Реализуй Echo-сервер: в бесконечном цикле читай сообщение от клиента (`conn.ReadMessage`) и отправляй его обратно (`conn.WriteMessage`).
510. Напиши WebSocket-клиента на Go (используй `websocket.Dial`). Подключись к своему серверу, отправь строку и выведи ответ.
511. **[Паттерн Hub/Client (Чат)]** Создай структуру `Hub`, которая хранит карту всех активных подключений (`map[*Client]bool`). Реализуй метод `Register` и `Broadcast` (рассылка сообщения всем клиентам).
512. **[Каверзный кейс]** У WebSocket-соединения есть лимиты на чтение и запись. Установи `conn.SetReadLimit(1024)` и отправь сообщение размером 2KB. Поймай ошибку и разрыв соединения.
513. **Ping/Pong (Keepalive):** Настрой сервер отправлять Ping каждые 30 секунд (`time.Tick`). На клиенте установи Pong-хендлер (`conn.SetPongHandler`), который обновляет таймер чтения. Если клиент не отвечает 60 секунд — сервер должен закрыть соединение (`conn.Close()`).
514. **[Каверзный кейс]** Конкурентная запись в WebSocket. Запусти 2 горутины, которые одновременно пытаются написать в один `conn`. Поймай панику/ошибку (горилла не позволяет конкурентную запись). Исправь, обернув соединение в мьютекс или создав канал для исходящих сообщений, а запись делать в одной горутине.
515. **[Высокая сложность — Комнаты (Rooms)]** Расширь свой чат. Теперь клиенты могут отправлять команду `join room1`. Hub должен поддерживать слайс комнат (мапа мап). Сообщения отправляются только клиентам в той же комнате.
516. **[Каверзный кейс — Backpressure]** Если клиент читает медленно, а сервер пишет быстро, буфер соединения переполнится. Реализуй буферизированный канал для исходящих сообщений (размер 10). Если канал полон, разрывай соединение (`closeChan <- conn`), чтобы не блокировать Hub.

### Блок 54: GraphQL — Schema, Resolvers и DataLoaders
*Цель: Освоить декларативный подход GraphQL, генерацию кода через `gqlgen` и оптимизацию запросов к БД.*

517. Установи и инициализируй `github.com/99designs/gqlgen` в новом модуле (`go run github.com/99designs/gqlgen init`).
518. В файле `graph/schema.graphqls` опиши тип `User` (id, name) и `Query` с полем `user(id: ID!): User`. Сгенерируй код. Реализуй резолвер, возвращающий захардкоженного пользователя.
519. Используй GraphQL Playground (обычно доступен на `localhost:8080` после запуска сервера). Напиши запрос на получение пользователя по ID.
520. **[Вложенные сущности]** Добавь тип `Post` (id, title, authorId). Добавь в `User` поле `posts: [Post!]!`. Реализуй резолвер для поля `posts` (метод `User_posts`), который возвращает посты конкретного пользователя.
521. **[Мутации]** Опиши `Mutation` с методом `createUser(name: String!): User!`. Реализуй логику добавления пользователя (в памяти) и возврата созданного объекта.
522. **[Каверзный кейс — N+1 Проблема]** Создай запрос `users: [User!]!` (возвращает всех пользователей). В резолвере `User_posts` сделай `SELECT * FROM posts WHERE author_id = ?` для каждого пользователя. Если пользователей 100, ты сделаешь 100 запросов к БД (N+1). Напиши тест, который это доказывает.
523. **[Высокая сложность — DataLoaders]** Реши проблему N+1. Используй `github.com/graph-gophers/dataloader` или встроенный механизм `gqlgen` dataloaders. Создай батчер, который за один тик (window) собирает все запрошенные `author_id` и делает один SQL-запрос: `SELECT * FROM posts WHERE author_id IN ($1, $2, ...)`.
524. **[Контекст и Авторизация]** Напиши middleware для HTTP-сервера GraphQL, который достает JWT-токен из заголовка `Authorization` и кладет `userID` в `context.Context`. В резолвере мутации `createPost` доставай `userID` из контекста. Если его нет — возвращай ошибку авторизации.
525. **[Subscriptions + WebSockets]** Включи поддержку Subscriptions в `gqlgen`. Опиши тип `Subscription` с полем `messageReceived: Message!`. Настрой сервер на использование WebSocket-транспорта (генерируется gqlgen). Реализуй резолвер, который слушает канал Go и отправляет сообщение клиенту, когда в канал что-то записывается (например, из другого HTTP-обработчика).
