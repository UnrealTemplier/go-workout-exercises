### 11. GraphQL и WebSockets

#### 11.1 GraphQL: сервер, схема, запросы
431. Установите `gqlgen` (или `graphql-go`), инициализируйте проект. Определите схему с типом `User` (id, name, email) и запросом `users: [User!]!`. Реализуйте резолвер, возвращающий тестовые данные.
432. Добавьте запрос с аргументом `user(id: ID!): User`. Резолвер ищет пользователя по ID. Если не найден — возвращайте `nil` (или ошибку `ErrNotFound`).
433. Реализуйте мутацию `createUser(name: String!, email: String!): User!`. Проверьте, что email уникален (in-memory), при дубликате верните ошибку с расширенным кодом.
434. Добавьте вложенный объект: тип `Post` (id, title, body, author: User!). Запрос `posts` возвращает список постов, резолвер поля `author` лениво подгружает автора (проблема N+1). Покажите проблему в логах.

#### 11.2 Продвинутый GraphQL: DataLoader, фрагменты, кастомные типы
435. Установите и внедрите `dataloaden` для пакетной загрузки пользователей. Покажите, что N+1 запросов больше нет.
436. Добавьте скаляр `DateTime` (на основе `time.Time`) и используйте его в типах. Реализуйте маршалинг/анмаршалинг.
437. Определите интерфейс `Node` с полем `id` и реализуйте его для `User` и `Post`. Добавьте запрос `node(id: ID!): Node`, возвращающий любой объект по ID. Используйте фрагменты на клиенте для получения разных полей.
438. Реализуйте мутацию с вложенным input-типом: `updateUser(id: ID!, input: UpdateUserInput!) : User!`. Проверьте валидацию (имя непустое, email корректный).

#### 11.3 GraphQL Subscriptions через WebSockets
439. Настройте транспорт WebSocket для подписок (gqlgen поддерживает `graphql-ws`). Создайте подписку `userCreated: User!`. Сервер публикует событие при создании пользователя, клиент получает уведомление в реальном времени.
440. Реализуйте простой GraphQL-клиент на Go (например, `machinebox/graphql` или `hasura/go-graphql-client`), который выполняет запросы и подписывается на события через WebSocket. Выведите поток событий в консоль.

#### 11.4 WebSockets: сервер, клиент, надежность
441. Создайте WebSocket-сервер с помощью `gorilla/websocket`. Реализуйте эхо: сервер возвращает любое полученное сообщение обратно отправителю.
442. Расширьте сервер до простого чата: несколько клиентов могут отправлять сообщения, сервер рассылает их всем подключенным (broadcast), кроме отправителя.
443. Добавьте комнаты: клиент может отправить `{"action": "join", "room": "golang"}`, после этого получает сообщения только из этой комнаты.
444. Обработайте обрыв соединения: клиент автоматически переподключается с exponential backoff (1s, 2s, 4s... до максимума). Сервер должен корректно удалять отключившихся клиентов.
445. Реализуйте ping/pong для поддержания соединения. Сервер отправляет ping каждые 30 секунд, клиент отвечает pong. Если pong не получен — сервер закрывает соединение.
