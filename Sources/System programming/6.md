Ниже представлен новый глубокий теоретико-практический блок, содержащий **20 упражнений по системному программированию, пакету `unsafe` и механизму CGO** (задачи 496–515).

Этот раздел ориентирован на **разработчиков системного уровня (System Software Engineers)**. ### Раздел 41: Системное программирование, `unsafe` и CGO (Задачи 496–515)

#### Подраздел 41.1: Работа с `unsafe` и арифметика указателей (Задачи 496–502)

*Пакет `unsafe` предоставляет доступ к низкоуровневым операциям с памятью, позволяя обходить строгую типизацию Go ради оптимизации производительности.*

496. **Приведение несовместимых типов**: Создайте срез типа `[]float64` с несколькими элементами. Используя тип `unsafe.Pointer`, преобразуйте этот срез в срез типа `[]int64` напрямую в памяти без копирования данных и выделения новой памяти. Выведите значения элементов до и после приведения и объясните, как интерпретируются биты вещественного числа в формате целочисленного типа.
497. **Изменение приватных полей структуры**: Создайте в отдельном пакете `internal` структуру `SecretConfig` со скрытым (неэкспортируемым) строковым полем `token`. Импортируйте этот пакет в `main`. Используя функцию `unsafe.Offsetof`, вычислите смещение поля `token` относительно начала структуры, получите указатель на него с помощью `unsafe.Pointer` и измените его значение напрямую из пакета `main`.
498. **Арифметика указателей**: Создайте массив `arr := [4]int32{10, 20, 30, 40}`. 
    * Получите адрес первого элемента `&arr[0]`.
    * Преобразуйте его в `uintptr`.
    * Прибавьте к этому значению размер типа `int32` с помощью `unsafe.Sizeof(arr[0])`.
    * Преобразуйте полученный результат обратно в `unsafe.Pointer` и затем в указатель `*int32`.
    * Считайте значение и убедитесь, что вы получили доступ ко второму элементу массива (`20`).
499. **Критическая ошибка работы с `uintptr`**: Напишите программу, которая преобразует указатель на объект в `uintptr` на одной строчке кода, а преобразует его обратно в `unsafe.Pointer` для чтения на другой строке спустя несколько тяжелых операций. Объясните в комментариях, почему этот код содержит серьезную уязвимость (сборщик мусора Go не отслеживает переменные типа `uintptr`, поэтому объект в куче может быть перемещен или удален из памяти до того, как вы приведете `uintptr` обратно к указателю). Исправьте код, сделав приведение на одной строке в рамках единого выражения.
500. **Проверка выравнивания структуры**: Создайте сложную структуру с полями разных базовых типов (`int8`, `string`, `bool`, `int64`). Используя функцию `unsafe.Alignof`, определите требования к выравниванию (alignment) каждого поля на вашей текущей аппаратной архитектуре. Напишите комментарий о том, как знание выравнивания помогает проектировать структуры с минимальным расходом памяти на пустое заполнение (padding).
501. **Кастинг строк без аллокаций (Go 1.20+)**: В современных версиях Go (1.20+) появились безопасные системные функции `unsafe.Slice` и `unsafe.String`. Напишите две функции:
    * Преобразование строки в срез байт `[]byte` без копирования данных с помощью `unsafe.SliceData` и `unsafe.Slice`.
    * Преобразование среза байт `[]byte` в `string` без аллокаций с помощью `unsafe.StringData` и `unsafe.String`.
    Напишите тесты производительности по сравнению со стандартным приведением `[]byte(str)` и `string(bytes)`.
502. **Статический анализатор `go vet`**: Запустите статический анализатор вашего кода с флагом проверки некорректного использования unsafe-указателей: `go vet -unsafeptr ./...`. Объясните, какие потенциально опасные конструкции в коде (например, нарушение правил преобразования `unsafe.Pointer` к `uintptr` и обратно) способен находить этот инструмент.

#### Подраздел 41.2: CGO — Интеграция с C-кодом (Задачи 503–509)

*CGO позволяет вызывать функции, написанные на языке Си, из Go-приложений, открывая доступ к огромному числу системных библиотек.*

503. **Простейший inline C-вызов**: Напишите программу, которая использует механизм CGO. Внедрите простую C-функцию `sum` прямо в псевдо-комментарий перед ключевой строкой `import "C"`:
    ```c
    // int sum(int a, int b) { return a + b; }
    import "C"
    ```
    Вызовите эту функцию из вашего Go-кода как `C.sum(5, 10)` и выведите результат.
504. **Управление памятью в CGO**: Напишите вызов стандартной функции `strlen` из библиотеки `string.h` Си.
    * Передайте строку Go в Си-код с помощью вспомогательной функции `C.CString(str)`.
    * Объясните в комментариях, почему эта функция выделяет память под строку в неуправляемой куче Си (вне видимости сборщика мусора Go).
    * Обязательно освободите выделенную память сразу после использования функции с помощью `C.free(unsafe.Pointer(cStr))`, подключив библиотеку `<stdlib.h>`.
505. **Ограничения на передачу указателей (Pointer Rules)**: Напишите в комментариях правила передачи Go-указателей в Си-код. Объясните, почему падает программа, если вы пытаетесь передать в Си-код указатель на Go-память, которая внутри себя содержит другие указатели на Go-память (механизм CGO pointer check на лету отслеживает такие ситуации для предотвращения багов при работе сборщика мусора).
506. **Накладные расходы CGO (Benchmarks)**: Напишите тест производительности (benchmark), замеряющий:
    * Скорость вызова пустой функции, написанной на Go.
    * Скорость вызова пустой функции, написанной на C через CGO.
    Проанализируйте результаты. Объясните причину накладных расходов CGO (смена контекста планировщика, сохранение регистров, переход стека g-to-m, отключение инлайнинга).
507. **Использование директив `#cgo`**: Напишите программу, которая линкуется с системной библиотекой (например, математической библиотекой `libm` в Unix). Используйте директивы компилятора в псевдо-комментариях для настройки флагов компиляции и линковки:
    ```go
    // #cgo LDFLAGS: -lm
    // #include <math.h>
    import "C"
    ```
    Вызовите функцию `C.sqrt(...)` из вашего Go-кода.
508. **Обратные вызовы (Callbacks) из C в Go**: Напишите программу, в которой Си-функция принимает указатель на функцию в качестве аргумента (коллбэк). Экспортируйте вашу Go-функцию в пространство имен Си, добавив специальный комментарий `//export MyGoCallback` над её объявлением. Передайте адрес этой экспортированной функции в Си-код.
509. **Компиляция без CGO**: Скомпилируйте ваше Go-приложение с флагом `CGO_ENABLED=0 go build`. Объясните в комментариях преимущества полностью статической сборки бинарных файлов (упрощение деплоя, отсутствие внешних динамических зависимостей от системных библиотек `glibc` / `musl`). Используйте утилиту `ldd` в Linux или `otool -L` в macOS, чтобы проверить зависимости вашего бинарника до и после отключения CGO.

#### Подраздел 41.3: Системные вызовы и работа с ОС (Задачи 510–515)

*Прямое обращение к ядру операционной системы позволяет реализовывать высокоэффективные операции ввода-вывода и низкоуровневые системные механизмы.*

510. **Базовый системный вызов (`syscall`)**: Напишите программу, которая делает низкоуровневый системный вызов к ядру операционной системы напрямую с помощью функции `syscall.Syscall`. Выполните сисколл получения ID текущего процесса (например, `syscall.SYS_GETPID` в Linux/macOS) и выведите возвращаемое значение.
511. **Отображение файлов в память (`mmap`)**: Напишите программу для высокоскоростного изменения файлов на диске:
    * Создайте файл размером 1 КБ на диске.
    * Откройте его и отобразите в виртуальную память с помощью системного вызова `syscall.Mmap` (или `unix.Mmap` из пакета `golang.org/x/sys/unix`).
    * Измените байты внутри полученного среза `[]byte` напрямую в памяти.
    * Синхронизируйте изменения с диском с помощью `syscall.Msync` и убедитесь, что файл на диске обновился без вызова стандартного `file.Write()`.
512. **Пакет `golang.org/x/sys/unix`**: Перейдите со стандартного пакета `syscall` на современный субпозиторный пакет `golang.org/x/sys/unix`. Напишите программу, которая с помощью функции `unix.Statfs` запрашивает метаданные файловой системы диска по переданному пути и вычисляет общий объем свободного места на диске в гигабайтах.
513. **Реализация простейшего Epoll (Linux-only)**: Напишите простейший сетевой цикл обработки событий (Event Loop) с использованием механизмов Linux `epoll` напрямую (через пакет `golang.org/x/sys/unix`):
    * Создайте дескриптор epoll с помощью `unix.EpollCreate1`.
    * Создайте TCP-слушатель сокета, получите его файловый дескриптор (FD) и добавьте его в epoll через `unix.EpollCtl`.
    * Запустите бесконечный цикл ожидания событий `unix.EpollWait` и выводите сообщение всякий раз, когда на сокет поступает входящее TCP-подключение.
514. **Низкоуровневая отправка сигналов ОС**: Напишите программу, которая отправляет сигнал процессам операционной системы с помощью низкоуровневого системного вызова `syscall.Kill`. Запустите параллельный процесс и принудительно завершите его, отправив сигнал `syscall.SIGKILL`.
515. **Изменение прав доступа и владельца (Chmod/Chown)**: Напишите утилиту, которая изменяет права доступа к файлу с помощью системного вызова `syscall.Chmod`. Настройте права доступа, используя числовые маски Unix (например, установив права `0644` — чтение/запись для владельца и только чтение для группы/остальных). Обработайте возможные ошибки отсутствия привилегий.
