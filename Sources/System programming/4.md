Ниже представлен **блок из 90 упражнений (с 1241 по 1330)**, который погрузит вас в системное программирование на Go. Вы научитесь работать с памятью на уровне указателей, вызывать C-код и использовать системные вызовы напрямую.

**⚠️ Предупреждение:** Эти техники обходят гарантии безопасности Go. Используйте их только когда:
- Пишете low-level библиотеки (аллокаторы, сериализаторы)
- Интегрируетесь с C/C++ кодом
- Оптимизируете критичные по производительности участки
- Работаете с OS-specific features

### Тема 123: unsafe.Pointer — Основы работы с указателями
*unsafe.Pointer — это мост между типизированными указателями Go и "сырыми" адресами памяти.*

1241. **Первое знакомство:** Создайте переменную `int`, получите её адрес как `*int`, сконвертируйте в `unsafe.Pointer`, затем в `uintptr` и выведите адрес. Сравните с `%p` форматом.

1242. **Правила конверсии:** Изучите 4 легальных способа конверсии в unsafe:
    * `*T` → `unsafe.Pointer` (и обратно)
    * `unsafe.Pointer` → `uintptr` (и обратно, но опасно!)
    * `unsafe.Pointer` → `unsafe.Pointer` другого типа
    * `reflect.SliceHeader`/`StringHeader` → `unsafe.Pointer`

1243. **Прямое приведение типов:** Создайте `float64`, получите указатель на него, приведите к `*int64` через `unsafe.Pointer` и прочитайте битовое представление числа.

1244. **Реинтерпретация памяти:** Создайте `[4]byte`, получите указатель, приведите к `*uint32` и прочитайте как одно число. Изучите endianness (little-endian на x86).

1245. **Zero-copy string conversion:** Реализуйте функцию `StringToBytes(s string) []byte` без аллокаций через `unsafe.Pointer` и `reflect.SliceHeader`. **Почему это опасно?** (строки неизменяемы!)

1246. **Zero-copy bytes to string:** Реализуйте `BytesToString(b []byte) string` без копирования. Когда это безопасно? (только если вы не модифицируете bytes после конверсии).

1247. **Struct field access:** Создайте структуру с приватным полем. Используйте `unsafe.Offsetof` и `unsafe.Pointer` для доступа к полю извне пакета.

1248. **Slice header manipulation:** Изучите структуру `reflect.SliceHeader` (Data, Len, Cap). Создайте слайс, модифицируйте его длину через unsafe и наблюдайте за последствиями.

1249. **Array to slice conversion:** Преобразуйте указатель на массив `[10]int` в слайс `[]int` без копирования через `unsafe.Slice`.

1250. **Pointer arithmetic (опасно!):** Попробуйте сделать "арифметику указателей" через конверсию `unsafe.Pointer` → `uintptr` → прибавить offset → обратно в `unsafe.Pointer`. **Почему это сломается с moving GC?**

1251. **Правильная pointer arithmetic:** Используйте `unsafe.Add(ptr, offset)` (Go 1.17+) вместо ручной арифметики. Это сохраняет GC-visibility.

1252. **Slice of structs:** Создайте слайс структур, получите указатель на первый элемент, используйте `unsafe.Add` для доступа к N-му элементу без индексации.

1253. **Type punning:** Реализуйте функцию `Float64bits(f float64) uint64` через `unsafe.Pointer` (альтернатива `math.Float64bits`).

1254. **Union type emulation:** Создайте "union" тип через структуру с одним полем `[8]byte` и методами для интерпретации как `int64`, `float64`, `[2]int32`.

1255. **Checking alignment:** Используйте `unsafe.Alignof` для проверки выравнивания типов. Создайте структуру с плохим alignment и изучите padding.

### Тема 124: unsafe — Продвинутые техники и паттерны
1256. **Generic memory copy:** Реализуйте функцию `MemCopy(dst, src unsafe.Pointer, size uintptr)` для копирования памяти между любыми типами.

1257. **Zero-allocation serialization:** Создайте бинарный сериализатор для структур, который пишет напрямую в `[]byte` через `unsafe.Pointer` без reflection.

1258. **Custom allocator (arena):** Реализуйте простой arena allocator, который аллоцирует большой блок через `make([]byte)` и выдаёт куски через `unsafe.Add`.

1259. **Reflection-free interface:** Создайте функцию, которая принимает `any`, извлекает указатель на данные через `unsafe.Pointer` и `reflect.Value`, модифицирует значение напрямую.

1260. **Struct field offset caching:** Напишите утилиту, которая кэширует offsets полей структур для быстрого доступа без reflection в runtime.

1261. **Binary protocol parsing:** Парсите бинарный сетевой протокол, читая поля напрямую из `[]byte` через `unsafe.Pointer` без `encoding/binary`.

1262. **Memory-mapped structure:** Создайте структуру, которая "наложена" на сырой `[]byte` buffer (zero-copy parsing).

1263. **Atomic operations on arbitrary types:** Используйте `sync/atomic` с `unsafe.Pointer` для атомарного обновления указателей на произвольные типы.

1264. **Custom hash function:** Реализуйте hash функцию для структур, которая читает память напрямую как `[]uint64` для скорости.

1265. **SIMD-like operations:** Обрабатывайте массивы `float32` как `[]float64` для "векторных" операций (хотя это не настоящий SIMD).

### Тема 125: unsafe — Опасности и подводные камни
1266. **Moving GC problem:** Создайте программу, где вы сохраняете `uintptr` (не `unsafe.Pointer`), запускаете GC и пытаетесь использовать сохранённый адрес. **Программа упадёт или вернёт мусор.**

1267. **Escape analysis bypass:** Попробуйте "обмануть" escape analysis через unsafe. Изучите, почему это плохая идея.

1268. **Data races через unsafe:** Создайте data race, модифицируя память через `unsafe.Pointer` из разных горутин без синхронизации. Запустите с `-race` и изучите отчёт.

1269. **Alignment issues:** Попробуйте прочитать `int64` по нечётному адресу. На некоторых архитектурах это вызовет SIGBUS.

1270. **Slice bounds через unsafe:** Модифицируйте `Len` и `Cap` слайса через `reflect.SliceHeader`. Вызовите панику при выходе за реальные границы массива.

1271. **Dangling pointers:** Создайте указатель на локальную переменную функции, верните его и используйте после возврата. В Go это работает (escape analysis), но с unsafe можно создать настоящий dangling pointer.

1272. **Type confusion:** Приведите `*int` к `*float64` и прочитайте значение. Получите NaN или мусор.

1273. **GC visibility:** Создайте объект, на который есть только ссылка через `uintptr`. Запустите GC и наблюдайте, как объект удаляется (GC не видит uintptr как указатель).

1274. **Correct uintptr usage:** Изучите легальные use cases для `uintptr`:
    * Передача в syscall (который не хранит указатель)
    * `reflect.Value.Pointer()` для логирования
    * Сравнение адресов (но используйте `==` на pointers вместо этого)

1275. **unsafe.Sizeof vs reflect:** Сравните `unsafe.Sizeof`, `reflect.Type.Size()` и реальный размер в памяти (с padding).

### Тема 126: CGO — Основы вызова C-кода
*CGO позволяет вызывать C-функции из Go и наоборот, но ценой производительности и сложности.*

1276. **Hello CGO:** Напишите простейшую программу с `import "C"` и вызовом `C.puts()`. Соберите через `go build`.

1277. **C preamble:** Используйте C-комментарий перед `import "C"` для включения C-кода: `// #include <stdio.h>\nimport "C"`.

1278. **Примитивные типы:** Передайте `int`, `float64` в C-функцию и получите результат обратно. Изучите маппинг типов (Go `int` ≠ C `int`).

1279. **Строки:** Преобразуйте Go `string` в C `*C.char` через `C.CString()`. **Важно:** освободите память через `C.free()` (используйте `defer`).

1280. **Слайсы и массивы:** Передайте Go `[]int` в C-функцию, которая модифицирует массив. Используйте `&slice[0]` для получения указателя.

1281. **Структуры:** Создайте C-структуру в preamble, используйте её из Go. Изучите alignment и padding differences.

1282. **Callback функции:** Передайте Go-функцию как callback в C (через `//export`). Изучите ограничения (нельзя захватывать переменные из окружения).

1283. **Cgo types:** Изучите специальные типы: `C.int`, `C.char`, `C.void`, `C.size_t`. Почему они нужны?

1284. **Error handling:** Обработайте ошибки из C-кода через `errno`. Используйте `C.ferror()`, `C.strerror()`.

1285. **Memory management:** Создайте C-функцию, которая аллоцирует память через `malloc`. Освободите её из Go через `C.free()`.

1286. **Global variables:** Доступ к C global variables из Go через `C.variable_name`.

### Тема 127: CGO — Продвинутое использование
1287. **Calling external C library:** Подключите внешнюю C-библиотеку (например, `libcurl` или `openssl`) через `#cgo LDFLAGS: -lcurl`.

1292. **C++ interop:** Вызовите C++ код из Go через `extern "C"` wrapper функции.

1293. **Go callbacks в C:** Создайте C-библиотеку, которая вызывает Go-функции для event handling. Используйте `//export` и `CgoHandle` для передачи контекста.

### 💡 Золотые правила системного программирования в Go:

1. **unsafe — это last resort.** Используйте только когда:
   * Производительность критична и бенчмарки доказывают необходимость
   * Интеграция с C/C++ кодом
   * Реализация низкоуровневых библиотек
   * Работа с binary protocols/serialization
   
   Для 99% задач стандартная библиотека достаточно быстра.

2. **Никогда не сохраняйте uintptr.** Всегда храните `unsafe.Pointer`. `uintptr` — это integer, GC не видит его как указатель. При GC объект может быть перемещён, и `uintptr` станет dangling pointer.

3. **Используйте unsafe.Add (Go 1.17+).** Вместо ручной арифметики `uintptr(ptr) + offset`. `unsafe.Add` сохраняет GC-visibility и корректно работает с moving GC.

4. **CGO overhead реален.** Каждый CGO вызов:
   * Переключает стеки (Go stack → OS stack)
   * Может блокировать OS thread
   * Имеет overhead ~100-1000ns
   
   Минимизируйте количество CGO вызовов, используйте batching.

5. **Освобождайте C память.** `C.CString()`, `C.CBytes()`, `C.malloc()` — все требуют `C.free()`. Используйте `defer` для гарантии очистки.

6. **Thread safety в CGO.** CGO вызовы могут выполняться в разных OS threads. Если C-библиотека не thread-safe, используйте `runtime.LockOSThread()` для привязки горутины к thread.

7. **Cross-compilation с CGO — это боль.** Требует cross-compiler toolchain для target OS/arch. Используйте Docker или готовые образы.

8. **Syscalls блокируют потоки.** Каждый syscall может заблокировать OS thread. Go runtime создаёт новые потоки при необходимости, но это overhead. Для high-throughput используйте epoll/kqueue.

9. **Epoll + goroutines = мощный combo.** Один epoll thread мониторит тысячи сокетов, горутины обрабатывают события. Это scalable модель для network servers.

10. **mmap для large files.** Не загружайте файлы больше RAM в память. Используйте mmap для zero-copy доступа. OS управляет page cache автоматически.

11. **Testing системного кода:**
    * Используйте `-race` для обнаружения data races
    * Тестируйте на разных архитектурах (x86, ARM)
    * Проверяйте alignment issues
    * Тестируйте edge cases (недостаток памяти, сигналы)

12. **Documentation обязателен.** Системный код сложно понимать. Комментируйте:
    * Почему используется unsafe/CGO
    * Safety guarantees (или их отсутствие)
    * Platform-specific behavior
    * Known limitations

13. **Isolate системный код.** Вынесите unsafe/CGO в отдельные пакеты с минимальным API. Остальной код должен быть pure Go с типобезопасностью.

14. **Benchmarking критичен.** Всегда измеряйте:
    * Производительность vs pure Go альтернативы
    * Memory allocations
    * GC overhead
    * Latency percentiles

15. **Read runtime source.** Изучите, как стандартная библиотека использует unsafe/syscall:
    * `os` пакет — wrapper над syscalls
    * `net` пакет — epoll/kqueue для network I/O
    * `sync` пакет — futex/mutex через syscalls
    * `runtime` — mmap для heap allocation
