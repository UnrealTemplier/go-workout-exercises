### Блок 80: Пакет `unsafe` и управление памятью в обход GC
*Цель: Понять, как устроена память в Go, как делать zero-copy преобразования и зачем нужен `uintptr`.*

721. Используй `unsafe.Sizeof` для вывода размера структур `int`, `string`, `slice`, `bool`. Посчитай размер пустой структуры `struct{}` (должен быть 0) и размер структуры с полем `bool` и `int64` (выравнивание/padding).
722. **[Выравнивание (Padding)]** Создай структуру `A { a bool; b int64; c bool }` и структуру `B { b int64; a bool; c bool }`. Выведи `unsafe.Sizeof` для обеих. Объясни, почему они занимают разный объем памяти (выравнивание по 8 байтам).
723. **[Zero-copy string to slice]** Напиши функцию, которая принимает `string` и возвращает `[]byte` без аллокации новой памяти (не используя `copy` или `[]byte(s)`). Используй `unsafe.StringData` (Go 1.20+) и `unsafe.Slice`. *Внимание: полученный слайс будет read-only, попытка изменения вызовет сегфолт.*
724. **[Zero-copy slice to string]** Напиши функцию, которая принимает `[]byte` и возвращает `string` без копирования (через `unsafe.String`). Это классический трюк для оптимизации логгеров.
725. **[Адресная арифметика]** Создай массив `[5]int32`. Получи указатель на 3-й элемент через `unsafe.Pointer` и сложение с `uintptr` (`unsafe.Pointer(uintptr(ptr) + 2*4)`). Измени значение по этому указателю.
726. **[Каверзный кейс — Сборщик мусора и `uintptr`]** Запиши адрес Go-объекта в `uintptr` переменную. Сделай так, чтобы объект больше не использовался в Go-коде. Вызови `runtime.GC()`. Попробуй разыменовать `uintptr` (через `unsafe.Pointer`). Пойми, почему `uintptr` — это просто число, и GC не считает его корнем (указатель мог быть перемещен или удален).
727. **[Доступ к приватным полям]** Создай структуру `time.Time` (у него есть приватные поля `wall` и `ext`). Используй `unsafe.Pointer` и смещения (`unsafe.Offsetof`), чтобы прочитать значения приватных полей напрямую.
728. **[unsafe.Add и unsafe.Slice]** Используя современный API (Go 1.17+), реализуй функцию `ReverseSlice(s []int)`, которая меняет элементы местами без использования индексов, только через `unsafe.Slice` и `unsafe.Add`.
729. **[atomic.Pointer vs unsafe.Pointer]** Изучи разницу. Используй `atomic.Pointer[T]` для безопасной конкурентной замены указателя на конфигурацию в памяти (Lock-free паттерн).
730. **[Каверзный кейс — Escape Analysis и `unsafe`]** Напиши функцию, которая возвращает `unsafe.Pointer` на локальную переменную. Запусти `go build -gcflags="-m"`. Убедись, что переменная утекла в кучу, иначе при возврате из функции стек очистился бы, и указатель стал бы висячим (dangling pointer).

### Блок 81: CGO — Вызов C-кода из Go
*Цель: Понять, как вызывать Си-библиотеки, как передавать данные между двумя рантаймами и почему "CGO is not Go".*

731. Напиши простейшую CGO-программу. В импорте `/* #include <stdio.h> */ import "C"` вызови `C.puts(C.CString("Hello from C"))`. Собери и запусти.
732. **[Накладные расходы (Overhead)]** Напиши бенчмарк: вызов пустой Go-функции в цикле vs вызов пустой C-функции в цикле. Оцени разницу во времени (CGO требует переключения стека и планировщика, ~50-100 наносекунд на вызов).
733. **[Передача строк]** Передай Go-строку в C-функцию. Помни, что `C.CString` аллоцирует память в C-куче (через `malloc`). Обязательно вызывай `C.free(unsafe.Pointer(cStr))` через `defer`.
734. **[Передача слайсов]** Передай слайс `[]int` в C-функцию, которая меняет его значения. Используй `(*C.int)(unsafe.Pointer(&slice[0]))` и длину. Убедись, что изменения видны в Go (zero-copy).
735. **[Go вызывается из C (Callbacks)]** Напиши C-функцию `void do_work(void (*cb)(int))`. В Go создай функцию `export MyCallback`. Передай её в C-функцию. (Это требует экспорта Go-функции в C через `//export`).
736. **[Каверзный кейс — Блокировка горутин]** Вызови долгую C-функцию (например, `sleep(5)`). Во время её выполнения запусти другую горутину в Go. Убедись, что поток ОС (M) заблокирован в C-коде. Посмотри через `runtime.NumGoroutine()` и `GOMAXPROCS`, как планировщик создает новый поток, чтобы не остановить работу Go-программы.
737. **[C-структуры в Go]** Опиши C-структуру в заголовочном файле. Создай её в Go, заполни поля и передай в C-функцию. Обрати внимание на правила CGO: нельзя передавать указатели на Go-память, содержащие другие указатели на Go-память, в C-код, если C-код их сохраняет.
738. **[Статическая линковка C-библиотеки]** Скомпилируй простую C-библиотеку в `.a` файл. Напиши CGO-код, который линкует её локально (через `#cgo LDFLAGS: -L./lib -lmylib`). Собери Go-бинарник.

### Блок 82: Низкоуровневые системные вызовы (Syscalls, Epoll, Mmap)
*Цель: Общаться с ядром Linux напрямую, минуя стандартную библиотеку Go.*

739. Используй пакет `syscall` (или `golang.org/x/sys/unix`). Напиши программу, которая вызывает `unix.Getpid()` и `unix.Getppid()` (ID процесса и родителя).
740. **[Прямая работа с файлами]** Открой файл через `unix.Open(path, unix.O_RDWR|unix.O_CREAT, 0666)`. Запиши в него байты через `unix.Write(fd, data)`. Прочитай через `unix.Read(fd, buf)`. Закрой через `unix.Close(fd)`.
741. **[mmap — Memory Mapped Files]** Открой файл. Используй `unix.Mmap(fd, 0, length, unix.PROT_READ|unix.PROT_WRITE, unix.MAP_SHARED)`. Измени байты прямо в возвращенном слайсе `[]byte`. Вызови `unix.Munmap(b)`. Открой файл в редакторе — изменения должны быть сохранены на диск без вызова `Write`.
742. **[Epoll: Создание инстанса]** Создай epoll-инстанс через `unix.EpollCreate1(0)`.
743. **[Epoll: Регистрация FD]** Создай неблокирующий TCP-сокет (`unix.Socket` с флагом `SOCK_NONBLOCK`). Зарегистрируй его в epoll через `unix.EpollCtl(epfd, unix.EPOLL_CTL_ADD, sockfd, &unix.EpollEvent{Events: unix.EPOLLIN, Fd: int32(sockfd)})`.
744. **[Epoll: Event Loop]** Напиши бесконечный цикл, который вызывает `unix.EpollWait(epfd, events, -1)`. Выводи в консоль, когда сокет готов к чтению. Это базовая механика того, как `net/http` работает под капотом в Go.
745. **[Каверзный кейс — Неблокирующий I/O и EAGAIN]** Попробуй прочитать из неблокирующего сокета, когда там нет данных (до события epoll). Поймай ошибку `unix.EAGAIN` (или `EWOULDBLOCK`). Объясни, что это не ошибка, а сигнал "данных пока нет".
746. **[Unix Signals]** Используй `signal.Notify` для перехвата `SIGINT`. Реализуй обработчик, который пишет в лог "Shutting down..." и завершает программу. (Под капотом Go использует `signalfd` или специализированный поток для сигналов ОС).
747. **[Termios (TTY)]** Открой `/dev/tty`. Используй `unix.IoctlGetTermios` для чтения текущих настроек терминала. Измени флаги (отключи `ECHO`), примени через `unix.IoctlSetTermios`. Напиши программу, которая читает пароль из консоли без отображения символов.
748. **[inotify (Filesystem Events)]** Используй `unix.InotifyInit1()`. Зарегистрируй директорию для слежения (`unix.InotifyAddWatch`). Читай события (создание, удаление файлов) в цикле.
749. **[Каверзный кейс — go:linkname]** Используй директиву `//go:linkname` для вызова приватной (непубличной) функции из пакета `runtime` (например, `runtime.nanotime`) без использования CGO. *Внимание: это крайне хрупкий хак, ломающийся между версиями Go, но он используется в некоторых low-level библиотеках, таких как fasthttp.*
750. **[Финальное испытание — Custom Netpoller]**
    Напиши свой собственный Echo-сервер на чистых системных вызовах Linux, без использования пакета `net` или `net/http`.
    - Используй `unix.Socket`, `unix.Bind`, `unix.Listen` для создания TCP-сервера.
    - Установи `SO_REUSEADDR` и `SOCK_NONBLOCK`.
    - Используй `epoll` (Edge Triggered режим — `EPOLLET`) для отслеживания новых соединений и входящих данных.
    - Реализуй неблокирующее чтение/запись. Обрабатывай `EAGAIN`.
    - Запусти сервер в одной горутине (или в пуле по числу CPU, шарящих один `epfd`).
    - Протестируй утилитой `nc` или `curl`.
