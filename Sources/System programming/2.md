### 17. Системное программирование, unsafe и CGO

#### 17.1 unsafe.Pointer и uintptr
576. **Преобразование между типами через unsafe.** Объявите два различных типа с одинаковой структурой памяти (например, `type A struct { X int; Y float64 }`, `type B struct { A int; B float64 }`). Преобразуйте `*A` в `*B` через `unsafe.Pointer`, измените поле и проверьте результат.
577. **Прямой доступ к полям структуры через смещения.** Используйте `unsafe.Offsetof` и `unsafe.Pointer` для чтения и модификации приватного (неэкспортируемого) поля структуры из другого пакета. Покажите опасность такого подхода.
578. **Арифметика указателей: обход слайса через unsafe.** Пройдитесь по элементам `[]int` побайтово с помощью `unsafe.Pointer` и `uintptr`, проверьте корректность значений на little/big-endian архитектуре. Обсудите, почему `uintptr` не удерживает объект от сборки мусора.
579. **Создание слайса из сырой памяти.** Выделите память через `make([]byte, 40)`, а затем интерпретируйте её как слайс из 10 `int32` с помощью `unsafe.Slice`. Запишите числа и прочитайте их обратно.
580. **Сравнение производительности обычного копирования и unsafe-копирования.** Реализуйте копирование одного слайса байт в другой через цикл и через `unsafe` (с использованием `runtime.memmove` через cgo или прямой unsafe). Сравните бенчмарком.
581. **Работа с `unsafe.String` и `unsafe.StringData`.** Создайте строку из слайса байт без копирования через `unsafe.String`, измените исходный слайс и посмотрите, изменится ли строка (нарушение иммутабельности). Обсудите последствия.

#### 17.2 CGO: вызов C-кода и интеграция
582. **Первый вызов C-функции.** Напишите простую C-функцию в комментарии `import "C"` (например, `int add(int a, int b)`), вызовите её из Go. Скомпилируйте и запустите.
583. **Передача и возврат сложных типов.** Объявите C-структуру `Point { double x; double y; }`, создайте её в Go, передайте в C-функцию, которая вычисляет расстояние от начала координат, и верните результат.
584. **Передача строк и работа с памятью.** Передайте Go-строку в C-функцию, ожидающую `const char*`. Используйте `C.CString`, не забудьте освободить память через `C.free`. Покажите утечку, если забыть освободить.
585. **Обратный вызов: передача Go-функции в C.** Экспортируйте Go-функцию с сигнатурой `//export GoCallback`, передайте её в C как callback (через `unsafe.Pointer` или `C.function_pointer`), вызовите из C обратно в Go. Обратите внимание на ограничения (нельзя блокировать горутину надолго).
586. **Накладные расходы cgo.** Напишите бенчмарк, сравнивающий вызов C-функции с пустой Go-функцией. Измерьте накладные расходы на переход между мирами. Сравните с чисто C-программой.
587. **Многопоточность и CGO.** Запустите несколько горутин, вызывающих C-функцию. Используйте `runtime.LockOSThread()` для привязки горутины к потоку, если это необходимо. Обсудите проблему планировщика Go и потоков ОС при cgo-вызовах.
588. **Безопасность данных при передаче указателей.** Покажите ошибку: передайте указатель на Go-переменную в C, сохраните его там глобально, а в Go освободите память (например, выйдите из функции). Позже C попытается обратиться по висячему указателю. Обсудите правила `cgo` о передаче указателей в C.

#### 17.3 Системные вызовы: syscall, unix, mmap, epoll
589. **Прямой системный вызов `write`.** Используя пакет `syscall` (или `golang.org/x/sys/unix`), сделайте системный вызов `SYS_WRITE` напрямую для вывода строки в stdout (fd=1). Сравните с `fmt.Print`.
590. **Работа с `mmap`.** Реализуйте чтение файла через отображение в память (`syscall.Mmap`). Прочитайте содержимое файла, измените байты в слайсе, синхронизируйте (`syscall.Msync`) и убедитесь, что изменения записаны на диск.
591. **Создание анонимного mmap.** Выделите область памяти через `mmap` с флагами `MAP_ANON|MAP_PRIVATE`, используйте её как слайс байт в Go. Сравните производительность выделения больших блоков с `make([]byte, ...)`.
592. **Использование `epoll` для асинхронного ввода-вывода.** Напишите TCP-сервер с использованием `epoll` напрямую (через `unix.EpollCreate`, `unix.EpollCtl`, `unix.EpollWait`). Реализуйте неблокирующий accept и чтение. Сравните с обычным `net` пакетом по задержке.
593. **Работа с сигналами через `syscall`.** Установите обработчик сигналов (SIGINT, SIGTERM) с помощью `syscall.Signal` или `unix.Sigaction`. Перехватите сигнал и выполните корректный shutdown, не используя `signal.Notify` (только системные вызовы).
594. **Получение информации о системе через syscall.** Выведите количество свободной памяти, загрузку CPU и другие метрики, используя `syscall.Sysctl` (на macOS/BSD) или чтение `/proc/meminfo` на Linux с парсингом, но с использованием низкоуровневых вызовов (`open`, `read`).
595. **Создание собственного буфера ввода-вывода с `O_DIRECT`.** Откройте файл с флагом `O_DIRECT` (прямой ввод-вывод без кэша ОС), выполните чтение/запись с выровненными буферами, выделенными через `mmap` или специально выровненными слайсами. Измерьте разницу с обычным файловым I/O.

#### 17.4 Смешанные продвинутые техники
596. **Ручная работа со стеком через unsafe.** Создайте функцию, которая перемещает указатель стека (только для образовательных целей, на ассемблере или через манипуляции с `unsafe`), покажите опасность.
597. **Переопределение строк на уровне памяти.** Используя unsafe, измените байты строки в куче (получите указатель на data через `reflect.StringHeader` или `unsafe.StringData`), модифицируйте их и покажите, что строка поменялась, нарушая соглашение.
598. **Реализация собственного аллокатора через `mmap` и управление памятью.** Создайте простой аллокатор, который выделяет большие блоки через `mmap` и раздаёт куски фиксированного размера, используя собственный свободный список. Сравните скорость с `new`/`make`.
599. **Интеграция с ассемблером.** Напишите небольшую функцию на ассемблере (Go asm или внешний), которая, например, меняет местами два `int64` быстрее, чем Go, и вызовите её. Используйте `unsafe.Pointer` для передачи указателей.
600. **Обход ограничений типов для сериализации.** Реализуйте универсальную функцию, которая принимает `interface{}` и через `unsafe` и рефлексию сериализует содержимое памяти структуры в слайс байт напрямую (сырой дамп). Покажите подводные камни: выравнивание, размеры, указатели.
