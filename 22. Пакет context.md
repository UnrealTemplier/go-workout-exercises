# Пакет context (Управление жизненным циклом горутин)

В этом файле собраны уникальные упражнения по теме **"Пакет context (Управление жизненным циклом горутин)"**, отсортированные по возрастанию сложности.

---

1. **Ручная отмена (`context.WithCancel`)**: Создайте контекст с возможностью отмены. Запустите фоновую горутину, которая в цикле `for` выполняет фоновую работу (например, раз в секунду). Горутина должна проверять канал `<-ctx.Done()`. В основной горутине подождите 3 секунды и вызовите функцию `cancel()`. Убедитесь, что фоновая горутина корректно завершила работу.

2. **Таймаут операции (`context.WithTimeout`)**: Напишите функцию, имитирующую тяжелый сетевой запрос, занимающий 5 секунд. Вызовите эту функцию с контекстом, у которого установлен таймаут в 2 секунды. Функция должна вернуть ошибку `context.DeadlineExceeded` по истечении таймаута.

3. **Передача метаданных (`context.WithValue`)**: Создайте цепочку вызовов функций (например, `Middleware -> Handler -> Controller`). Положите в контекст на самом верхнем уровне уникальный ID запроса (`RequestID`). Извлеките и выведите его на самом глубоком уровне в контроллере. Объясните, почему не стоит использовать контекст для передачи опциональных параметров бизнес-логики.

4. Используй `context.WithTimeout()`. Запусти HTTP-запрос (или `time.Sleep`) в горутине. Если не успевает за 2 секунды — `ctx.Done()` срабатывает, программа выводит `"timeout"`.

5. Напиши функцию `ProcessWithContext(ctx context.Context, data []int) (int, error)`, которая суммирует числа, но проверяет `ctx.Err()` в цикле. Если контекст отменён — верни ошибку немедленно.

6. **Обработка `ctx.Done()` в `select`**: Напишите горутину-генератор случайных чисел, которая бесконечно пишет числа в канал. Настройте `select` внутри генератора так, чтобы при получении сигнала из `ctx.Done()` генератор закрывал свой канал и завершал работу, предотвращая утечку ресурсов.

7. Используйте `context.Background()` и `context.TODO()`. Поймите разницу в их семантике.

8. Покажи **"context propagation"**: `main` создаёт `ctx` с таймаутом. Передаёт в функцию A, которая создаёт `ctx2, cancel := context.WithCancel(ctx)`. Отменяет `ctx2`. Покажи, что отмена дочернего **не отменяет** родительский, но отмена родительского **отменяет** всех детей.

9. **Базовый контекст**: Создай `ctx := context.Background()`. Напиши воркер, который принимает `ctx` первым аргументом (это стандарт) и крутится в `for { select { case <-ctx.Done(): return default: ... } }`.

10. Создай `context.Background()`. Создай `context.WithCancel(ctx)`. Запусти горутину, которая в бесконечном цикле проверяет `<-ctx.Done()`. Отмени горутину из `main` через 2 секунды.

11. Используй `context.WithValue()` для передачи `requestID` через цепочку вызовов. Напиши middleware, который извлекает `requestID` из `ctx` и логирует. Покажи, что значение доступно во всех дочерних функциях.

12. Создайте контекст с отменой `context.WithCancel`. Передайте его в горутину и отмените выполнение из `main`.

13. `context.WithCancel`: main отменяет контекст через 3 секунды, все горутины, получившие контекст, должны корректно завершиться.

14. Напиши **"context tree"**: создай родительский `ctx`, от него 3 дочерних `WithCancel`, от каждого — ещё по 2. Отмени родительский. Покажи, что **все** дочерние контексты отменились (через `select` на `Done()` в каждом).

15. **Обязательный вызов `cancel()`**: Напишите функцию, которая создает `context.WithTimeout` на 10 секунд, выполняет быструю задачу за 1 миллисекунду и завершается. Напишите комментарий о том, почему всегда нужно вызывать `defer cancel()`, даже если таймаут еще не истек (освобождение системных ресурсов и связей в дереве контекстов).

16. Создайте контекст с таймаутом `context.WithTimeout`. Запустите "долгую" операцию (с `time.Sleep`) и корректно обработайте `<-ctx.Done()`.

17. Напиши функцию `Or(ctx1, ctx2 context.Context) context.Context`, возвращающую контекст, который отменяется, когда отменяется **любой** из входных. Используй горутину + `select` на `ctx1.Done()` и `ctx2.Done()`.

18. **Каскадная отмена**: Создай `ctx1` (с отменой). От него создай `ctx2` (с отменой). Передай `ctx2` в воркер. Отмени **первый** контекст `ctx1`. Убедись, что `ctx2` тоже автоматически отменился.

19. Используй `context.WithDeadline()`. Установи дедлайн на `time.Now().Add(5 * time.Second)`. Покажи разницу между `deadline` и `timeout` (deadline — абсолютное время, timeout — относительное).

20. Покажи **"context leak"**: создаёшь `context.WithCancel` в цикле, но не вызываешь `cancel()`. Горутина из `WithCancel` остаётся висеть. Используй `runtime.NumGoroutine()` для демонстрации. Исправь через `defer cancel()`.

21. Используйте `context.WithDeadline`, чтобы операция прервалась в строго заданное время.

22. `context.WithTimeout`: горутина выполняет долгую работу, но если не укладывается в таймаут, должна вернуть ошибку `ctx.Err()`.

23. **Контекст в HTTP-клиенте**: Напишите простой HTTP-запрос к медленному серверу с помощью пакета `net/http`. Привяжите к HTTP-запросу контекст с таймаутом в 500 миллисекунд с помощью `http.NewRequestWithContext`. Проверьте, как клиент обрывает соединение, если сервер не ответил вовремя.

24. Напиши **"graceful shutdown with context"**: `main` создаёт `ctx` с `signal.NotifyContext`. При `Ctrl+C` — контекст отменяется. Все worker'ы читают `ctx.Done()`, завершают текущую работу, делают cleanup и выходят.

25. **Таймаут (`WithTimeout`)**: Создай `ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)`. Обязательно добавь `defer cancel()`. Воркер должен спать 3 секунды. Проверь, что `ctx.Done()` срабатывает раньше завершения работы воркера.

26. **Важнейшее правило**: Всегда вызывайте `cancel()` через `defer` сразу после создания контекста с отменой/таймаутом, чтобы избежать утечки контекста (Goroutine leak).

27. Напиши программу с `context.WithValue`, пытающуюся передать **неэкспортируемый ключ** (unexported type). Покажи, что это **best practice** для избежания коллизий ключей между пакетами. Создай `type contextKey string` в пакете.

28. `context.WithDeadline`: аналогично таймауту, но задайте конкретное время завершения.

29. Напиши функцию `SleepWithContext(ctx context.Context, d time.Duration) error`, которая спит `d` или просыпается раньше при отмене `ctx`. Используй `select` между `time.After(d)` и `ctx.Done()`.

30. Передайте значение в контекст с помощью `context.WithValue`. Извлеките его в глубокой функции без передачи аргументов. (Обсудите, почему использовать контекст для передачи бизнес-данных — это антипаттерн).

31. Используй `context.WithTimeout(ctx, 1*time.Second)`. Запусти горутину с долгой работой (sleep 5s). Горутина должна завершиться по таймауту контекста, выведя "Context cancelled".

32. **Иерархия контекстов (Пропагация отмены)**: Создайте родительский контекст с возможностью отмены. От него создайте дочерний контекст. Запустите две горутины (одну на родительском, другую на дочернем контекстах). Отмените родительский контекст. Убедитесь, что дочерний контекст отменился автоматически. Попробуйте сделать наоборот (отменить дочерний) и проверьте, повлияло ли это на родительский.

33. Напиши **"worker pool with context"**: N горутин читают задачи из канала. Если `ctx` отменён — все воркеры выходят. Задачи — это функции `func()`. Покажи, что воркеры завершаются, даже если в канале остались задачи.

34. Напишите HTTP-хендлер, который использует `req.Context()`. Если клиент разорвал соединение (отменил запрос), контекст должен автоматически закрыться, и ваша горутина должна прекратить работу.

35. **Передача данных (`WithValue`)**: Добавь в контекст UserID: `ctx = context.WithValue(ctx, "userID", 42)`. Достань его в воркере: `id := ctx.Value("userID")`.

36. Напиши **"parallel fetch with context"**: запускаешь 5 HTTP-запросов (или `time.Sleep` как симуляцию) в горутинах. Если один упал с ошибкой или таймаут — отменяй остальные через `cancel()`. Собери первую ошибку или все результаты.

37. `context.WithValue`: передайте идентификатор запроса через контекст в несколько вложенных вызовов. Логируйте его при обработке.

38. Напиши **"context deadline exceeded"** обработку: функция делает `select` между `ctx.Done()` и результатом. Если `ctx.Done()` — проверяй `ctx.Err() == context.DeadlineExceeded` vs `context.Canceled` и логируй разные сообщения.

45. **[Каверзный кейс]**: Используй `context.WithValue(ctx, "userID", 42)`. В глубоко вложенной функции извлеки значение `ctx.Value("userID")`. Объясни, почему `context.WithValue` следует использовать только для передачи запрос-специфичных данных (request-scoped), а не как глобальные переменные.

46. **Принудительная проверка в цикле**: В долгоиграющем цикле (который не использует каналы) добавь `if ctx.Err() != nil { return ctx.Err() }`, чтобы не делать лишнюю работу, если клиент отвалился.
