Упражнение #1

Оптимизированный поиск простых чисел до N с отсечением по квадратному корню

📌 Условие задачи

Поиск простых чисел: Напишите цикл, который находит все простые числа до N. Оптимизируйте его, прерывая внутренний цикл через break, когда делитель превышает квадратный корень из числа.

💡 Теоретический фундамент и концепция

Алгоритм проверки простоты числа (Trial Division):

1. Число $P > 1$ является простым, если оно не делится ни на одно целое число от $2$ до $\lfloor\sqrt{P} floor$;
2. Условие d * d <= n позволяет избежать вызова тяжелой функции math.Sqrt(float64(n)) в рантайме;
3. При нахождении первого же делителя n % d == 0 внутренний цикл немедленно прерывается через break, сокращая сложность до $O(N\sqrt{N})$.

🔍 Пошаговый ход решения и ход мысли инженера

1. Задаем границу limit = 50.
2. Внешним циклом перебираем кандидатов от 2 до limit.
3. Внутренним циклом проверяем делители d пока d*d <= n.
4. При n % d == 0 выставляем флаг isPrime = false и делаем break.
5. Собираем простые числа в результирующий срез.
📄 main.go 
package main

import "fmt"

func FindPrimes(limit int) []int {
	var primes []int

	for n := 2; n <= limit; n++ {
		isPrime := true
		// Оптимизация: проверяем делители только до sqrt(n)
		for d := 2; d*d <= n; d++ {
			if n%d == 0 {
				isPrime = false
				break // Число составное, дальнейший перебор бессмыслен
			}
		}
		if isPrime {
			primes = append(primes, n)
		}
	}

	return primes
}

func main() {
	limit := 50
	primes := FindPrimes(limit)
	fmt.Printf("Простые числа до %d (%d шт.):\n%v\n", limit, len(primes), primes)
}

⚠️ Частые грабли и ошибки новичков
  • Вычисление math.Sqrt(float64(n)) на каждой итерации внутреннего цикла: приводит к лишним преобразованиям типов и сильному замедлению.
🏢 В продакшене BigTech и на собеседованиях

Вопрос с собеседования: «Какой алгоритм поиска простых чисел быстрее Trial Division для больших $N$ ($N > 10^7$)?»

Ответ: Решето Эратосфена (Sieve of Eratosthenes) со сложностью $O(N \log \log N)$ или сегментированное решето (Segmented Sieve) с расходом памяти $O(\sqrt{N})$.

Упражнение #2

Проверка строки на палиндром методом двух указателей (Two Pointers) без аллокаций

📌 Условие задачи

Палиндром: Напишите функцию, которая с помощью цикла (без использования reverse-слайсов) проверяет, является ли строка палиндромом, сравнивая символы с начала и с конца.

💡 Теоретический фундамент и концепция

Паттерн Two Pointers (Встречные указатели):

1. Инициализируем левый индекс left := 0 и правый индекс right := len(runes) - 1;
2. На каждой итерации сравниваем символы runes[left] != runes[right];
3. При несовпадении немедленно возвращаем false;
4. Двигаем указатели навстречу друг другу: left++, right--, пока left < right;
5. Память: $O(1)$ дополнительных аллокаций для ASCII (или $O(N)$ при конвертации в []rune для Unicode).

🔍 Пошаговый ход решения и ход мысли инженера

1. Приводим строку к нижнему регистру и преобразуем в []rune для корректной поддержки UTF-8.
2. Запускаем цикл со сходящимися указателями left и right.
3. Сравниваем руны и возвращаем булев результат.
📄 main.go 
package main

import (
	"fmt"
	"strings"
	"unicode"
)

func IsPalindrome(s string) bool {
	// Очищаем от пробелов и приводим к нижнему регистру
	var runes []rune
	for _, r := range strings.ToLower(s) {
		if unicode.IsLetter(r) || unicode.IsDigit(r) {
			runes = append(runes, r)
		}
	}

	left := 0
	right := len(runes) - 1

	for left < right {
		if runes[left] != runes[right] {
			return false // Символы не совпали -> не палиндром
		}
		left++
		right--
	}

	return true
}

func main() {
	phrases := []string{
		"А роза упала на лапу Азора",
		"Madam, I'm Adam",
		"Golang Workout",
		"топот",
	}

	for _, p := range phrases {
		fmt.Printf("%-30q -> Палиндром: %t\n", p, IsPalindrome(p))
	}
}

Упражнение #3

Интерактивная игра «Угадай число» на базе бесконечного цикла for и math/rand

📌 Условие задачи

Угадай число: Сгенерируйте случайное число (пакет math/rand). В бесконечном цикле просите пользователя угадать, давая подсказки "больше" или "меньше", пока не угадает.

💡 Теоретический фундамент и концепция

Бесконечный цикл с выходом по условию:

  • for { ... } в Go — каноническая форма бесконечного цикла;
  • Инструкция break прерывает цикл при наступлении целевого события (guess == target);
  • Подсчет попыток позволяет оценивать эффективность алгоритмов бинарного поиска ($O(\log N)$ шагов).

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем генератор псевдослучайных чисел rand.New(rand.NewSource(...)).
2. Загадываем число в диапазоне $[1, 100]$.
3. В бесконечном цикле for сравниваем догадку пользователя с target.
4. Выводим подсказки «Больше» / «Меньше» и выходим через break при успехе.
📄 main.go 
package main

import (
	"fmt"
	"math/rand"
	"time"
)

func main() {
	r := rand.New(rand.NewSource(time.Now().UnixNano()))
	target := r.Intn(100) + 1 // Число от 1 до 100
	attempts := 0

	// Симуляция ввода пользователя методом бинарного поиска:
	low, high := 1, 100
	fmt.Printf("Компьютер загадал секретное число в диапазоне [1, 100]\n\n")

	for {
		attempts++
		guess := (low + high) / 2 // Бинарный поиск
		fmt.Printf("Попытка #%d: Проверяем число %d -> ", attempts, guess)

		if guess < target {
			fmt.Println("Загаданное число БОЛЬШЕ ⬆️")
			low = guess + 1
		} else if guess > target {
			fmt.Println("Загаданное число МЕНЬШЕ ⬇️")
			high = guess - 1
		} else {
			fmt.Printf("🎉 УГАДАНО! Число %d найдено за %d попыток!\n", target, attempts)
			break // Прерываем бесконечный цикл
		}
	}
}

package main

func main() {

	}

	fmt.Println()
}

package main

	"fmt"
	"strings"
)

	mockInputs := []string{"hello", "golang", "workout", "exit", "ignored"}

		if idx >= len(mockInputs) {
			break
		}

			break // Прерываем бесконечный цикл
		}

		// Выводим удвоенную строку

	}

	fmt.Println("Сервер штатно остановлен.")
}

package main

import (
	"fmt"
	"unicode"
)

type StringStats struct {
	Letters int
	Digits  int
	Spaces  int
	Others  int
}

func AnalyzeString(text string) StringStats {
	var stats StringStats

	for _, r := range text {
		switch {
		case unicode.IsLetter(r):
			stats.Letters++
		case unicode.IsDigit(r):
			stats.Digits++
		case unicode.IsSpace(r):
			stats.Spaces++
		default:
			stats.Others++
		}
	}

	return stats
}

func main() {
	sample := "Go 1.22: Релиз состоялся в 2024 году! 🚀"
	stats := AnalyzeString(sample)

	fmt.Printf("Исходный текст: %q\n", sample)
	fmt.Printf(" • Букв:    %d\n", stats.Letters)
	fmt.Printf(" • Цифр:    %d\n", stats.Digits)
	fmt.Printf(" • Пробелов:%d\n", stats.Spaces)
	fmt.Printf(" • Прочих:  %d\n", stats.Others)
}

💡 Теоретический фундамент и концепция

Эволюция Scope переменных цикла в Go:

  • Go < 1.22: Переменная цикла item выделялась один раз на весь цикл и перезаписывалась на каждом шаге. Сохранение &item приводило к тому, что все указатели вели на один и тот же адрес памяти с последним элементом!
  • Go 1.22+ (Loopvar Experiment / Standard): Каждая итерация цикла создает новую изолированную переменную item в памяти, устраняя баг «замыкания последнего значения» навсегда.

	Name string

	for i, p := range ptrs {
		fmt.Printf("Указатель ptrs[%d] -> Адрес: %p | Имя: %s\n", i, p, p.Name)
	}
}

		}
	}

	fmt.Printf("Результат: Число %d найдено в строке %d, столбце %d\n",

Упражнение #29

Итерация по строке «Hello, 世界»: байтовые смещения против рун в for range

📌 Условие задачи

💡 Теоретический фундамент и концепция

Анатомия UTF-8 итерации в for idx, r := range str:

1. idx — это смещение в байтах от начала строки в памяти;
2. r — это 4-байтовая Unicode-руна (int32);
3. ASCII символы ('H', 'e', 'l', 'l', 'o', ',', ' ') занимают по 1 байту;
4. Иероглифы '世' (U+4E16) и '界' (U+754C) кодируются 3 байтами каждый;
5. Поэтому после индекса 7 идет индекс 10 (пропуская 8 и 9).

🔍 Пошаговый ход решения и ход мысли инженера

1. Задаем строку str := "Hello, 世界".
2. В цикле for i, r := range str выводим индекс, символ, руну и размер в байтах.
📄 main.go 
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	text := "Hello, 世界"

	fmt.Printf("Строка: %q (байт: %d, рун: %d)\n\n",
		text, len(text), utf8.RuneCountInString(text))

	for idx, r := range text {
		runeLen := utf8.RuneLen(r)
		fmt.Printf("Байт #%-2d | Руна: %-4c | Код: U+%-4X | Размер: %d байт(а)\n",
			idx, r, r, runeLen)
	}
}

💡 Теоретический фундамент и концепция

Критический антипаттерн defer в цикле:

1. Инструкции defer выполняются только при возврате из окружающей функции, а НЕ при завершении итерации цикла!
2. Если в цикле на $100\,000$ итераций открывать файлы и писать defer file.Close(), все $100\,000$ дескрипторов останутся открытыми до самого конца функции $ ightarrow$ ОС выдаст ошибку too many open files (исчерпание ulimit -n);
3. Идиоматичное решение: выносить тело итерации в отдельную функцию или замыкание func() { ... }().

2. Исправляем паттерном анонимного замыкания func(f string) { defer ... }().
3. Убеждаемся в своевременном закрытии ресурсов на каждом шаге.

	fmt.Printf("1. Открытие ресурса [%s]\n", name)
	// defer выполнится немедленно при выходе из этой функции:
	defer fmt.Printf("2. Закрытие ресурса [%s] ✔\n", name)

	fmt.Printf("   -> Обработка данных [%s]...\n", name)
}

func main() {
	files := []string{"log1.txt", "log2.txt", "log3.txt"}

	fmt.Println("=== Корректная обработка файлов без утечек дескрипторов ===")
	for _, f := range files {
		// Решение: изолированный фрейм функции
		processResourceSafe(f)
	}
	fmt.Println("Все файлы успешно обработаны.")
}

Упражнение #33

Три способа суммирования среза: классический for, for range и while-стиль

📌 Условие задачи

💡 Теоретический фундамент и концепция

Сравнительный анализ трех видов цикла for:

1. for i := 0; i < len(s); i++ — прямой доступ по индексу (C-Style);
2. for _, v := range s — наиболее лаконичный и безопасный (Range-Style);
3. for i < len(s) — гибкий цикл с ручным шагом (While-Style).

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем тестовый срез []int{5, 10, 15, 20, 25}.

import "fmt"

func main() {
	s := []int{5, 10, 15, 20, 25}

	// 1. Классический C-style
	sum1 := 0
	for i := 0; i < len(s); i++ {
		sum1 += s[i]
	}

	// 2. Идиоматичный for-range
	sum2 := 0
	for _, v := range s {
		sum2 += v
	}

	// 3. While-стиль
	sum3 := 0
	k := 0
	for k < len(s) {
		sum3 += s[k]
		k++
	}

	fmt.Printf("1. C-Style:    %d\n", sum1)
	fmt.Printf("2. Range-Style: %d\n", sum2)
	fmt.Printf("3. While-Style: %d\n", sum3)
}

  • Не требует выделения дополнительной памяти ($O(1)$ по памяти);
  • Множественное присваивание arr[i], arr[j] = arr[j], arr[i] меняет элементы местами за 1 шаг без временной переменной;
  • Шаг цикла i, j = i+1, j-1 двигает границы одновременно.

package main

func ReverseInPlace(arr []int) {

		arr[i], arr[j] = arr[j], arr[i] // Атомарный swap
	}
}

	fmt.Printf("До разворота:    %v\n", numbers)

	ReverseInPlace(numbers)
	fmt.Printf("После разворота: %v\n", numbers)
}

💡 Теоретический фундамент и концепция

Копирование значений в for range:

1. На каждой итерации значение элемента копируется в локальную переменную v;
2. Операция v *= 10 модифицирует только эту временную копию v;
3. Исходная память среза nums остается нетронутой;
4. Для изменения среза необходимо адресоваться по индексу nums[i] *= 10.

package main

	for _, v := range nums {
		v *= 10 // Изменяется только локальная переменная v!
	}

	fmt.Printf("После цикла:   %v (НЕ ИЗМЕНИЛСЯ!)\n", nums)
}

Компилятор считывает значение из базового массива в регистр v, изменяет регистр и отбрасывает его на следующей итерации без инструкции записи MOVQ reg, (base + offset).

💡 Теоретический фундамент и концепция

for v := range ch по каналу:

2. Если канал пуст, цикл блокирует горутину в ожидании новых данных;
3. Цикл корректно завершается только тогда, когда канал закрыт (close(ch));

	for v := range ch {
		fmt.Printf("Получено значение: %d\n", v)
	}

	fmt.Println("Канал закрыт, цикл for range штатно завершен.")
}

	for {

Упражнение #49

📌 Условие задачи

💡 Теоретический фундамент и концепция

Копирование структур по значению (Pass by Value):

  • Переменная p в for _, p := range people является отдельной локальной копией структуры Person;
  • Изменение p.Age++ меняет только локальную копию в стеке и стирается на следующей итерации;
  • Для реального изменения данных в срезе используют прямой доступ по индексу: people[i].Age++ или срез указателей []*Person.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем структуру Person{Name string, Age int}.
2. Создаем срез []Person.
3. Показываем ошибку новичка с p.Age = 99.
4. Демонстрируем правильное исправление people[i].Age = 99.
📄 main.go 
package main

import "fmt"

type Person struct {
	Name string
	Age  int
}

func main() {
	people := []Person{
		{Name: "Иван", Age: 20},
		{Name: "Анна", Age: 25},
	}
	fmt.Printf("1. Исходный срез:   %+v\n", people)

	// ОШИБКА: p — это независимая копия структуры
	for _, p := range people {
		p.Age = 99 // Изменяется только копия!
	}
	fmt.Printf("2. После _, p :=:   %+v (НЕ изменился!)\n", people)

	// ПРАВИЛЬНО: изменение по индексу
	for i := range people {
		people[i].Age = 99 // Изменяется оригинальная структура в срезе
	}
	fmt.Printf("3. После people[i]: %+v (УСПЕШНО!)\n", people)
}

Глубокое сравнение for range по статическому массиву [5]int и динамическому срезу []int

💡 Теоретический фундамент и концепция

Разница между range arr и range slice:

1. При for _, v := range arr массив [5]int целиком копируется в заголовок range перед началом цикла;
2. При for _, v := range slice копируется только 24-байтный дескриптор SliceHeader (указатель, длина, емкость);
3. Модификация v ни в массиве, ни в срезе не затрагивает оригинал;
4. Модификация arr[i] = ... внутри for i := range arr меняет оригинальный массив, но не копию в заголовке range.

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем массив [5]int{1, 2, 3, 4, 5}.
2. Проходим for _, v := range arr и пробуем менять v.
3. Создаем срез []int{1, 2, 3, 4, 5} и повторяем проверку.
📄 main.go 
package main

import "fmt"

func main() {
	// 1. Статический массив [5]int
	arr := [5]int{1, 2, 3, 4, 5}
	for _, v := range arr {
		v *= 100 // Меняет только копию v
	}
	fmt.Printf("Массив после range: %v (значения те же)\n", arr)

	// Прямая мутация массива по индексу:
	for i := range arr {
		arr[i] *= 100
	}
	fmt.Printf("Массив после arr[i]: %v (изменен!)\n", arr)

	// 2. Срез []int
	slice := []int{10, 20, 30}
	for i := range slice {
		slice[i] *= 2
	}
	fmt.Printf("Срез после slice[i]: %v (изменен!)\n", slice)
}

Упражнение #52

Анатомия UTF-8 для «Привет, Go!»: почему string(str[i]) ломает кириллицу, а range декодирует руны

📌 Условие задачи

Range по строке (байты vs руны): Объяви строку str := "Привет, Go!". Перебери её через классический цикл for i := 0; i < len(str); i++ и выведи символы (через string(str[i])). Затем перебери её через for index, char := range str. Сравни вывод. Пойми, почему первый вариант ломает кириллицу, а range корректно читает руны, перескакивая через индексы (0, 2, 4...).

💡 Теоретический фундамент и концепция

Разбор кодирования UTF-8:

  • Слово «Привет» состоит из 6 кириллических букв по 2 байта каждая = 12 байт;
  • Символы «, Go!» занимают по 1 байту = 5 байт;
  • Всего в строке: $12 + 5 = 17$ байт и ровно 11 рун;

🔍 Пошаговый ход решения и ход мысли инженера

1. Инициализируем foundIndex := -1.
2. В цикле проверяем val == target.

package main

import "fmt"

func FindFirstIndex(slice []string, target string) int {
	foundIndex := -1

	for i, v := range slice {
		if v == target {
			foundIndex = i
			break // Элемент найден -> немедленный выход
		}
	}

	return foundIndex
}

	idx1 := FindFirstIndex(cities, "Казань")
	if idx1 != -1 {

	} else {
		fmt.Println("Город не найден")
	}

	idx2 := FindFirstIndex(cities, "Сочи")
	if idx2 != -1 {
		fmt.Printf("Город 'Сочи' найден по индексу %d\n", idx2)
	} else {
		fmt.Println("Город 'Сочи' отсутствует в списке")
	}
}

Опасность мутации среза через append во время for range и снимок длины

📌 Условие задачи

💡 Теоретический фундамент и концепция

Механика for range slice с вызовом append:

1. Выражение среза в заголовке range s вычисляется один раз перед началом цикла;
2. range фиксирует исходную длину len(s) и базовый массив;
3. Если внутри цикла вызывать s = append(s, x), len(s) внешнего среза растет, но range все равно сделает ровно столько итераций, сколько было в момент старта!
4. При превышении емкости cap(s) append выделит новый массив в куче, и любые последующие изменения по индексу s[i] = ... больше не затронут массив, по которому идет range.

2. Внутри for i, v := range s вызываем s = append(s, v*10).

func main() {
	s := []int{1, 2, 3}
	fmt.Printf("До цикла:    len = %d, cap = %d, data = %v\n\n", len(s), cap(s), s)

	// range фиксирует длину len(s) = 3 в момент входа!

		fmt.Printf("Итерация %d: v = %d | текущий len(s) = %d | срез = %v\n",
			i, v, len(s), s)
	}

	fmt.Printf("\nПосле цикла: len = %d, cap = %d, data = %v\n", len(s), cap(s), s)
}

1. var nilSlice []int = nil имеет len == 0 и указатель 0x0;

💡 Теоретический фундамент и концепция

Безопасность delete во время итерации по map:

1. В Go вызов встроенной функции delete(m, key) внутри for range m является полностью безопасным и определенным;

3. В отличие от Java (ConcurrentModificationException) или C++ (инвалидация итераторов), в Go итератор корректно продолжает обход оставшихся элементов.

🔍 Пошаговый ход решения и ход мысли инженера

Сбор среза указателей []*int в цикле for range: эволюция Go < 1.22 vs Go 1.22+

📌 Условие задачи

Каверзный баг цикла (до Go 1.22): (Похоже на упр. 64 из прошлого списка, но с фокусом на указатели). Создай срез []*int. Запусти for _, v := range []int{1, 2, 3}. 💡 Теоретический фундамент и концепция

Глубокий анализ изменения Loop Variables в Go 1.22:

  • В Go 1.21 и ранее переменная v создавалась один раз на весь цикл, и на каждой итерации в одну и ту же ячейку памяти перезаписывалось новое значение. Сохранение &v сохраняло указатель на одну и ту же ячейку $ ightarrow$ результат [3, 3, 3];
  • В Go 1.22+ спецификация языка изменилась: переменная v создается заново на каждой итерации $ ightarrow$ каждый указатель &v ссылается на свою уникальную область памяти $ ightarrow$ результат [1, 2, 3].

🔍 Пошаговый ход решения и ход мысли инженера

1. Создаем срез []int{1, 2, 3}.
2. В цикле сохраняем &v в []*int.
3. Распечатываем адреса и разыменованные значения *ptr.

	for _, v := range numbers {
		pointers = append(pointers, &v)
	}

	fmt.Println("Собранные указатели (Go 1.22+):")
	for i, ptr := range pointers {
		fmt.Printf("pointers[%d] -> Адрес: %p | Значение: %d\n", i, ptr, *ptr)
	}
}

Упражнение #61

Алгоритмический парсер скобочной последовательности ()[]{} на стеке (Stack Parser)

📌 Условие задачи

Парсер скобок: Напишите алгоритм, который проходит по строке с помощью цикла и проверяет, правильно ли расставлены скобки ()[]{} (используйте слайс как стек, push и pop элементы, прерывая цикл при ошибке).

💡 Теоретический фундамент и концепция

Алгоритм проверки правильной скобочной последовательности (Valid Parentheses):

1. Используем срез []rune как стек (LIFO);
2. При встрече открывающей скобки ((, [, {) делаем stack = append(stack, r) (Push);
3. При встрече закрывающей скобки:
  • Если стек пуст $ ightarrow$ скобка не сбалансирована (false);
  • Снимаем верхний элемент top := stack[len(stack)-1] (Pop) и проверяем соответствие пар;
4. В конце строка валидна, если стек полностью пуст (len(stack) == 0).

🔍 Пошаговый ход решения и ход мысли инженера

1. Пишем функцию IsValidParentheses(s string) bool.
2. Реализуем стек на срезе.
3. Тестируем валидные и невалидные строки.
📄 main.go 
package main

import "fmt"

func IsValidParentheses(s string) bool {
	var stack []rune
	matching := map[rune]rune{
		')': '(',
		']': '[',
		'}': '{',
	}

	for _, r := range s {
		switch r {
		case '(', '[', '{':
			// Push в стек
			stack = append(stack, r)
		case ')', ']', '}':
			// Проверяем соответствие закрывающей скобки
			if len(stack) == 0 {
				return false // Нет открывающей скобки
			}
			top := stack[len(stack)-1]
			stack = stack[:len(stack)-1] // Pop из стека

			if top != matching[r] {
				return false // Несовпадение типов скобок
			}
		}
	}

	return len(stack) == 0
}

func main() {
	tests := []string{
		"({[]})",
		"()[]{}",
		"(]",
		"([)]",
		"{[()]}",
		"(((",
	}

	for _, t := range tests {
		fmt.Printf("Строка %-10q -> Сбалансирована: %t\n", t, IsValidParentheses(t))
	}
}

Упражнение #64

Промышленная пагинация (Batching / Chunking) списка из 100 элементов по 10 штук через срезы

📌 Условие задачи

Напиши программу, которая реализует пагинацию через цикл: есть список из 100 элементов, выводи их порциями по 10 штук. Используй цикл for start := 0; start < len(items); start += 10 с срезом items[start:end].

💡 Теоретический фундамент и концепция

Паттерн Batching (Пакетная обработка данных / Chunking):

  • Необходим для высоконагруженных API, работы с базами данных (Batch Insert / Batch Query) и очередей сообщений (Kafka / RabbitMQ);
  • Цикл с шагом размера страницы start += pageSize;
  • Расчет верхней границы пакета: end := min(start + pageSize, len(items));
  • Срез items[start:end] создается за $O(1)$ без выделения новой памяти.

🔍 Пошаговый ход решения и ход мысли инженера

1. Генерируем срез из 100 элементов (ID от 1 до 100).
2. Задаем размер порции pageSize = 10.
3. В цикле for start := 0; start < len(items); start += pageSize вырезаем куски items[start:end].
4. Выводим каждую страницу.
📄 main.go 
package main

import "fmt"

func minInt(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func main() {
	// Генерация 100 записей:
	totalItems := 100
	items := make([]int, totalItems)
	for i := 0; i < totalItems; i++ {
		items[i] = i + 1
	}

	pageSize := 10
	pageNumber := 1

	fmt.Printf("=== ПАГИНАЦИЯ %d ЭЛЕМЕНТОВ ПО %d ШТУК В ПАКЕТЕ ===\n\n",
		totalItems, pageSize)

	for start := 0; start < len(items); start += pageSize {
		end := minInt(start+pageSize, len(items))
		chunk := items[start:end]

		fmt.Printf("Страница #%2d (индексы [%2d..%2d]) -> Элементы: %v\n",
			pageNumber, start, end-1, chunk)
		pageNumber++
	}

	fmt.Println("\nВсе страницы успешно обработаны!")
}
